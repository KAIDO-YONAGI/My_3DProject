## 1. 目标与边界

### 1.1 项目目标

项目面向 2～5 人短回合物理乱斗。玩家在战斗平台上通过移动、跳跃、冲刺、推挤、拾取和投掷争夺胜利。随机道具、障碍物和全局事件持续改变场地状态，让每局比赛形成不同的对抗节奏。

近期目标是完成一个可玩的垂直切片，具备完整回合流程、清晰操作反馈、基础机器人、随机道具和全局事件，并产出可运行构建、演示视频、README 和架构图。

联机目标采用固定 Tick 状态模型、服务器权威同步、远端快照插值和有限客户端预测。联机研发在单机闭环和展示质量完成后开始。

### 1.2 核心交付

- 一张圆形或近圆形竞技场。
- 2～5 人比赛规则。
- 移动、跳跃、冲刺和推挤。
- 生命值、掉落、死亡、复活、计分、结算和重开。
- 一个使用玩家输入格式的基础机器人。
- 2～3 种颜色药水效果。
- 一种可拾取、投掷和踢动的爆炸物。
- 一种全局事件，首选酸雨。
- 可运行构建、60～90 秒视频、README 和架构图。
- 服务器权威联机样片和弱网指标。

### 1.3 后续范围

以下内容在核心闭环稳定后单独安排：

- 精彩片段自动回放。
- 任意网格实时破坏。
- 多张正式地图。
- 复杂背包、道具合成和长期养成。
- 匹配、大厅、账号和正式服务器编排。
- 完整物理回滚和跨平台确定性模拟。

## 2. 玩法设计

### 2.1 核心循环

```text
玩家进入竞技场
  → 回合倒计时
  → 移动、跳跃、冲刺和推挤
  → 道具刷新与全局事件
  → 伤害、掉落和淘汰
  → 计分与复活
  → 回合结算
  → 达到胜利条件后比赛结算
  → 重新开始
```

首版使用固定目标分数作为胜利条件。目标分数、最大回合数、复活次数和回合时长由配置数据管理。

### 2.2 淘汰与计分

玩家通过生命值耗尽或掉出场地进入淘汰流程。

计分归属采用最近有效作用记录：

1. 直接伤害致死归属最后一次有效攻击者。
2. 玩家受到推挤后在归属时间窗内掉落，得分归属最近有效推挤者。
3. 全局事件和纯环境因素造成的淘汰归入环境统计。
4. 多人连续作用时，以最后一次满足有效条件的作用为准。
5. 同时淘汰按服务器 Tick 内的统一结算顺序处理。

### 2.3 地图节奏

首版使用一张基础竞技场，通过尺寸、障碍物和事件区域形成两种节奏：

- 紧凑区域强调直接推搡、冲刺和快速掉落。
- 开阔区域容纳药水、爆炸物、障碍物和事件安全区。

场地包含出生点、复活点、KillZone、道具刷新点、事件区域和可配置障碍物。

### 2.4 角色动作

角色动作包含：

- 地面移动和朝向控制。
- 跳跃、落地和空中控制。
- 冲刺、冷却和命中判定。
- 受击、击退和失控恢复。
- 拾取、持有、投掷和踢动。
- 死亡、复活保护和结算状态。

角色运动采用受约束状态模型。速度、加速度、冲刺距离、击退上限和空中控制均由集中配置管理。

## 3. 道具与全局事件

### 3.1 药水

首版药水从以下效果中选择 2～3 种：

| 效果 | 玩法作用 | 关键参数 |
|---|---|---|
| 加速 | 提高移动速度或冲刺能力 | 持续时间、倍率、叠加规则 |
| 中毒 | 周期性降低生命值 | 持续时间、间隔、单次伤害 |
| 致盲 | 降低视野或增加画面干扰 | 持续时间、强度、表现方式 |

药水通过颜色区分。玩家饮用前只获得颜色信息，效果在使用后揭示。颜色池、效果池和随机映射由配置数据管理。

药水效果具有统一生命周期：

```text
生成
  → 拾取
  → 使用
  → 效果生效
  → 效果结束
  → 清理
```

同类效果的刷新、叠加和覆盖规则在玩法规格阶段统一确定。

### 3.2 爆炸投掷物

爆炸物承担物理互动和局势制造两种职责。

```text
Spawned
  → Free
  → Held
  → Thrown
  → Free
  → Exploded
  → Recycled
```

核心行为：

- 在场地刷新点随机出现。
- 玩家可以推动、踢动、拾取和投掷。
- 倒计时结束后产生范围伤害和击退。
- 最近有效持有者或投掷者参与伤害归属。
- 爆炸可以触发预制平台状态或临时危险区域。
- 回收时清理速度、持有者、倒计时、碰撞状态和表现状态。

### 3.3 全局事件

首个全局事件采用酸雨。

酸雨包含三个阶段：

1. 预警阶段显示危险提示和安全区域。
2. 生效阶段周期性伤害暴露区域中的玩家。
3. 结束阶段恢复场地状态并清理事件效果。

酸雨的触发时间、持续时间、伤害间隔、伤害值和安全区由配置数据管理。

怪物入场作为后续事件。怪物使用独立状态机生成移动输入和攻击意图，与玩家和机器人共用玩法模拟入口。

### 3.4 障碍物

首版障碍物用于分割移动路线、制造推挤死角和保护事件安全区。障碍物状态由回合控制器统一重置。

后续障碍物可以加入移动、旋转、升降和临时消失等行为。

## 4. 当前工程基础

### 4.1 Unity 工程

- Unity 版本为 `2022.3.62f3c1`。
- 主要脚本位于 `Assets/Core/Scripts/`。
- 场景位于 `Assets/Core/Scenes/`。
- Prefab 位于 `Assets/Core/Prefabs/`。
- 当前 Build Settings 场景列表需要在工程基线阶段配置。

### 4.2 网络原型

当前工程具备自定义 UDP 客户端和独立 C# UDP 服务端原型。

原型能力包括：

- 客户端加入和离开。
- 客户端位置发送。
- 服务端玩家登记和位置广播。
- Unity 主线程消息消费。

新玩法建立独立状态模型和原型场景。网络阶段由 Unity Server Build 运行玩法模拟，通过 Unity Transport 2.x 传输输入帧和状态快照。

## 6. 总体架构

### 6.1 单机架构

```text
输入设备 / 机器人 / 回放
          ↓
      InputFrame
          ↓
  固定 Tick 玩法模拟
          ↓
      GameState
          ↓
  Unity 表现与反馈
```

### 6.2 联机架构

```text
客户端输入
  → InputFrame
  → Unity Transport
  → Unity Server Build
  → 固定 Tick 权威模拟
  → StateSnapshot
  → Unity Transport
  → 客户端快照缓冲
  → 远端插值 / 本地预测校正
  → Unity 表现
```

### 6.3 模块职责

| 模块 | 职责 | 输出 |
|---|---|---|
| 输入采集 | 读取设备状态并生成动作意图 | `InputFrame` |
| 机器人 | 根据可见状态生成动作意图 | `InputFrame` |
| 玩法模拟 | 推进角色、道具、事件和回合 | `GameState` |
| 回合系统 | 管理倒计时、计分、胜负和重开 | `RoundState` |
| 道具系统 | 管理药水和爆炸物生命周期 | `ItemState` |
| 事件系统 | 管理酸雨阶段和区域效果 | `EventState` |
| 表现层 | 将状态映射到 Unity 对象 | 画面、声音和 UI |
| 网络服务端 | 接收输入并生成权威快照 | `StateSnapshot` |
| 网络客户端 | 发送输入、缓存快照和校正 | 可显示状态 |
| 指标系统 | 采集模拟和网络数据 | 调试面板和日志 |

## 7. 状态模型

### 7.1 输入帧

输入帧包含：

- 玩家标识。
- 输入序号。
- 目标 Tick。
- 移动方向。
- 跳跃、冲刺、拾取、投掷和使用动作位。
- 瞄准方向或投掷方向。

真人玩家、机器人、回放和网络输入使用相同格式。

### 7.2 玩家状态

玩家状态包含：

- 位置、旋转和速度。
- 地面状态和动作状态。
- 生命值和生存状态。
- 冲刺冷却和受击状态。
- 药水效果和持续时间。
- 持有道具。
- 最近有效作用者和归属时间。
- 当前分数和复活状态。

### 7.3 道具状态

道具状态包含：

- 道具类型和实例标识。
- 位置、旋转、线速度和角速度。
- 生命周期状态。
- 持有者和最近作用者。
- 倒计时和冷却。
- 药水效果类型或爆炸参数。

### 7.4 回合状态

回合状态包含：

- 当前阶段。
- 当前 Tick 和阶段计时。
- 玩家分数。
- 目标分数。
- 当前胜者。
- 复活队列。
- 全局事件状态。

### 7.5 随机数

道具刷新、药水效果映射和事件触发使用可记录随机种子。回放和服务器模拟从同一随机状态推进。

## 8. 固定 Tick 模拟

### 8.1 Tick 流程

每个 Tick 按固定顺序执行：

1. 收集本 Tick 输入。
2. 更新回合状态。
3. 更新玩家移动和动作。
4. 更新玩家碰撞、推挤和伤害。
5. 更新道具持有、投掷和物理状态。
6. 更新药水效果。
7. 更新全局事件。
8. 处理死亡、掉落、归属和计分。
9. 生成事件记录。
10. 输出新的 `GameState`。

统一顺序用于控制同时命中、同时淘汰和多人争抢道具的结算结果。

### 8.2 表现更新

Unity 表现层在渲染帧读取模拟状态：

- 本地单机状态直接映射。
- 远端网络状态通过快照插值映射。
- 动画和音效由状态变化与事件记录触发。
- UI 读取回合状态、玩家状态和效果状态。

### 8.3 回放验证

状态记录保存输入帧、随机种子和关键事件。回放验证关注：

- 分数。
- 胜者。
- 淘汰顺序。
- 道具关键状态。
- 回合结束 Tick。

浮点数路线以相同运行环境中的关键状态一致作为验收口径。

## 9. 服务器权威同步

### 9.1 服务器职责

服务器负责：

- 连接和玩家映射。
- 输入帧接收、校验和缓存。
- 固定 Tick 玩法模拟。
- 玩家移动、道具物理和事件推进。
- 伤害、淘汰、计分和胜负结算。
- 状态快照生成和发送。
- 断线超时和玩家移除。

### 9.2 客户端职责

客户端负责：

- 采集和发送输入帧。
- 缓存服务器状态快照。
- 插值远端玩家和道具。
- 预测本地角色移动。
- 接收权威状态并重放待确认输入。
- 播放动画、音效、粒子和 UI。

### 9.3 协议范围

联机样片包含以下消息：

- 连接请求和连接确认。
- 玩家加入和离开。
- 输入帧。
- 状态快照。
- 回合开始、复活、结算和重开。
- 道具刷新、拾取、投掷、爆炸和回收。
- 药水效果应用和结束。
- 全局事件阶段。
- 心跳、超时和错误信息。

协议定义包含消息类型、协议版本、序号、Tick、最大长度、字段范围和解析失败处理。

### 9.4 快照插值

服务器以固定频率发送状态快照。客户端按服务器 Tick 排序并写入快照缓冲。

远端玩家和动态道具使用：

```text
快照接收
  → Tick 排序
  → 插值缓冲
  → 目标显示时间
  → 位置、旋转和状态插值
```

离散状态包括死亡、爆炸、拾取、释放和回合转换，由快照状态变化或权威事件触发。

### 9.5 本地预测与校正

本地预测覆盖移动、跳跃和冲刺。

校正流程：

1. 客户端保存已发送输入。
2. 服务器快照携带已处理输入序号。
3. 客户端恢复服务器权威玩家状态。
4. 客户端移除已确认输入。
5. 客户端重放待确认输入。
6. 表现层根据误差采用平滑收敛或立即校正。

道具物理、伤害、淘汰、得分和胜负使用服务器权威结果。

## 10. 对象生命周期

### 10.1 生命周期类型

需要统一管理的对象包括：

- 玩家角色。
- 药水。
- 爆炸投掷物。
- 障碍物动态状态。
- 酸雨区域和表现对象。

### 10.2 重置清单

对象回收和回合重开时重置：

- 位置、旋转和父节点。
- 线速度和角速度。
- Rigidbody 状态和碰撞状态。
- 持有者和最近作用者。
- 倒计时、冷却和临时效果。
- Collider、Renderer、粒子和音效。
- 事件订阅和延迟回调。
- 插值缓存和客户端表现状态。

### 10.3 对象池

对象生命周期稳定后接入 `UnityEngine.Pool.ObjectPool<T>`。对象池承担实例复用，权威状态仍由玩法模拟和服务器决定。

池容量根据场景中的同时活跃数量设置，并记录峰值使用量。

## 17. 风险与控制

### 17.1 范围扩张

风险：玩法、展示、联机和回放同时推进，阶段交付持续延后。

控制：每个阶段只保留一个主要交付，候选功能进入后续列表。

### 17.2 物理结果失控

风险：角色和道具完全依赖自由刚体后出现高速、穿透和难以判读的结果。

控制：角色使用受约束运动模型，速度和击退设置上限，道具使用明确生命周期。

### 17.3 平台破坏成本

风险：任意网格破坏增加物理、同步、导航和重置复杂度。

控制：首版使用预制破坏状态、临时缺口和危险区域。

### 17.4 随机效果可读性

风险：药水和事件同时出现后，玩家难以理解状态变化。

控制：首版限制效果数量，提供持续时间、颜色和命中反馈。

### 17.5 浮点回放误差

风险：浮点数和 PhysX 使完整逐帧结果产生误差。

控制：回放验收关注关键状态和误差范围，持续记录随机种子和事件顺序。

### 17.6 联机操作延迟

风险：服务器权威移动和抓取产生明显回显延迟。

控制：先完成快照插值，再对本地角色移动加入预测和校正，道具保持服务器权威。

### 17.7 网络对象状态残留

风险：断线、回收和重开后保留持有者、效果或插值缓存。

控制：统一生命周期和重置清单，覆盖正常流程和失败场景。
