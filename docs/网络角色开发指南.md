# 单机与联机角色开发指南

更新时间：2026-09-30

本文是当前项目角色系统的开发说明，重点说明单机流程、Mirror 联机流程，以及旧 UDP 方案如何迁移为当前的 Mirror + KCP 方案。

## 1. 总体原则

当前项目把单机角色和联机角色分成两条链路：

1. 单机角色由 `PersistentScene/LocalPlayer` 使用本地模型和本地摄像机。
2. 联机角色由 `Player_Network` 作为网络根对象，模型由 `PersistentScene/Managers/NetworkCharacterManager` 按角色编号加载。
3. `Player_Network` 不保存具体角色模型，不把本地模型直接当成远程模型。
4. `CharacterForSync` 下的专用预制体是联机模型来源；所有客户端必须保持相同的角色编号和数组顺序。
5. 管理器配置在编辑器场景中完成，不使用运行时生成管理器，也不使用 `DontDestroyOnLoad` 管理网络角色。

这样可以保证：单机开发可以自由替换本地模型和摄像机，联机开发则只同步角色编号、位置和动作所需状态。

## 2. 场景和预制体结构

### 2.1 单机结构

```text
PersistentScene
├─ LocalPlayer
│  ├─ 本地角色模型
│  ├─ CharacterController
│  ├─ PlayerCharacterController
│  └─ 本地 Camera / AudioListener
└─ SceneChanger
```

单机角色的模型、动画、摄像机和输入配置都由 `LocalPlayer` 负责。单机角色不依赖 `NetworkIdentity`、`NetworkCharacterSync` 或 `NetworkCharacterManager`。

### 2.2 联机结构

```text
PersistentScene
├─ Managers
│  └─ NetworkCharacterManager
└─ SceneChanger

NetworkManager.prefab
└─ playerPrefab -> Player_Network.prefab

Player_Network.prefab
├─ NetworkIdentity
├─ NetworkTransformReliable
├─ CharacterController
├─ PlayerCharacterController
└─ NetworkCharacterSync
```

联机角色模型不直接放在 `Player_Network` 下面。运行时由 `NetworkCharacterManager` 从 `characterPrefabs[]` 中按编号实例化到网络根对象下面。

## 3. 各模块职责和 Mirror API

| 模块 | 类型/API | 职责 |
|---|---|---|
| `NetworkManager` | Mirror `NetworkManager` | 管理服务器、客户端、连接、玩家对象生成；通过 `playerPrefab` 指定网络玩家预制体 |
| `KcpTransport` | `kcp2k.KcpTransport` | 使用 KCP 传输层承载 UDP 通信，当前端口为 `7777` |
| `NetworkIdentity` | Mirror `NetworkIdentity` | 标识网络对象，建立对象的服务器权限、客户端副本和网络生命周期 |
| `NetworkTransformReliable` | Mirror 组件 | 同步玩家根对象的位置和旋转；当前不再手写位置 UDP 包 |
| `PlayerCharacterController` | 普通 `MonoBehaviour` | 只让本地拥有权玩家读取输入并驱动移动；远程副本不读取本地输入 |
| `NetworkCharacterSync` | `NetworkBehaviour` | 通过 `SyncVar` 同步角色编号，通过 `Command` 接收本地玩家请求 |
| `NetworkCharacterManager` | 场景中的普通 `MonoBehaviour` | 持有联机模型数组，按角色编号实例化和销毁可视模型，并绑定摄像机和动画 |
| `CharacterController` | Unity 组件 | 提供角色碰撞和移动所需的运动体；挂在 `Player_Network` 根对象上 |

## 4. 联机角色编号链路

当前代码中的核心调用链是：

```text
本地选择角色
    ↓
NetworkCharacterSync.SetLocalCharacter(id)
    ↓
非服务器端调用 CmdSetCharacter(id)
    ↓
服务器验证角色编号并写入 characterId
    ↓
[SyncVar] characterId 同步到所有客户端
    ↓
OnCharacterIdChanged(oldId, newId)
    ↓
NetworkCharacterManager.ApplyCharacter(player, newId)
    ↓
从 characterPrefabs[newId] 实例化 CharacterForSync 预制体
```

`NetworkCharacterManager` 不发送模型文件，也不发送模型名称。网络上只传角色编号；每个客户端根据本地相同的编号表加载自己的模型资源。

当前 `NetworkCharacterManager` 的配置为：

```text
characterPrefabs[0] -> 娜娜莉（华丽飞踢）_Sync.prefab
characterPrefabs[1] -> 娜娜莉（学园之星）_Sync.prefab
defaultCharacterId  -> 0
```

如果增加或调整角色，所有客户端和服务端使用的项目资源必须保持相同的数组顺序。

## 5. 单机开发流程

### 5.1 启动和验证

1. 打开 `PersistentScene`。
2. 在 `LocalPlayer` 上配置本地模型、动画、`CharacterController` 和摄像机。
3. 用 Additive 场景框架加载需要的游戏场景。
4. 点击 Play。
5. 确认本地角色显示、摄像机跟随、输入移动和动画播放正常。

### 5.2 单机修改规则

- 更换单机模型：修改 `LocalPlayer` 的本地模型引用。
- 更换单机摄像机：修改 `LocalPlayer` 下的摄像机，不要修改 `NetworkCharacterManager`。
- 调整本地移动：修改 `PlayerCharacterController`、`CharacterMotor` 或单机输入配置。
- 调整单机动画：修改本地模型 Animator 和动画配置。
- 单机角色不需要添加 `NetworkIdentity`。
- 单机角色不应依赖 `NetworkCharacterSync`。

## 6. 联机开发流程

### 6.1 编辑器配置

1. 打开 `PersistentScene`。
2. 选中 `Managers/NetworkCharacterManager`。
3. 在 `characterPrefabs` 中配置所有联机模型预制体。
4. 确认这些预制体来自 `CharacterForSync`，而不是单机模型目录。
5. 确认 `defaultCharacterId` 在数组范围内。
6. 打开 `NetworkManager.prefab`，确认 `playerPrefab` 指向 `Player_Network.prefab`。
7. 打开 `Player_Network.prefab`，确认根对象有 `NetworkIdentity`、`NetworkTransformReliable`、`CharacterController`、`PlayerCharacterController`、`NetworkCharacterSync`。

### 6.2 运行流程

1. 服务端启动 `NetworkManager`。
2. 客户端连接 KCP 地址和端口。
3. Mirror 根据 `playerPrefab` 生成 `Player_Network`。
4. 服务端在 `OnStartServer` 中设置默认角色编号。
5. `NetworkCharacterSync` 的 `characterId` 同步到各客户端。
6. 每个客户端的 `NetworkCharacterManager` 按编号实例化本地 `CharacterForSync` 模型。
7. 本地拥有权对象读取输入，远程对象只接收网络同步的位置、旋转和角色编号。

### 6.3 角色切换流程

角色切换时只调用：

```csharp
networkCharacterSync.SetLocalCharacter(characterId);
```

不要直接在客户端修改私有 `characterId`，也不要直接销毁和创建远程模型。服务器会验证编号，`SyncVar` 会把结果同步到其他客户端，统一由 `OnCharacterIdChanged` 触发模型替换。

## 7. 从旧 UDP 方案迁移到当前方案

当前工程没有独立的自定义 UDP Socket、角色编号数据包或 `NetworkMessage`。这里的 UDP 是 KCP 的底层承载方式，业务层使用 Mirror API。

| 旧 UDP 责任 | 当前实现 | 对应代码/配置 |
|---|---|---|
| 创建 UDP 连接 | Mirror 创建服务器和客户端连接 | `NetworkManager` |
| UDP 监听端口 | KCP 监听 UDP 端口 | `KcpTransport.port = 7777` |
| 自定义连接状态 | Mirror 网络生命周期 | `NetworkIdentity`、`NetworkManager` |
| 客户端发送角色编号包 | 客户端调用 Command | `NetworkCharacterSync.CmdSetCharacter(int)` |
| 服务端保存当前编号 | 服务器写入同步字段 | `NetworkCharacterSync.characterId` |
| 服务端广播编号 | Mirror 自动同步 `SyncVar` | `[SyncVar(hook = ...)]` |
| 客户端收到编号后回调 | SyncVar hook | `OnCharacterIdChanged` |
| 远程客户端按编号加载模型 | 场景管理器查数组并实例化 | `NetworkCharacterManager.ApplyCharacter` |
| 本地角色编号到模型的映射 | 编辑器数组配置 | `NetworkCharacterManager.characterPrefabs[]` |
| 自定义位置包 | Mirror 组件同步 | `NetworkTransformReliable` |

因此，迁移后的等价关系是：

```text
UDP 角色编号包
    -> CmdSetCharacter(int)

UDP 广播角色编号
    -> SyncVar characterId

UDP 收包后加载模型
    -> OnCharacterIdChanged
    -> NetworkCharacterManager.ApplyCharacter

UDP 位置包
    -> NetworkTransformReliable
```

### 7.1 迁移时保留了什么

- 角色编号仍然是跨客户端同步的核心数据。
- 远端仍然根据编号加载本地资源。
- 角色模型资源不通过网络传输。
- 本地和远程模型可以使用不同的对象实例。
- 服务器仍然是角色编号的最终确认方。

### 7.2 迁移时替换了什么

- 自定义 UDP 连接替换为 `NetworkManager + KcpTransport`。
- 自定义编号包替换为 `Command + SyncVar`。
- 自定义位置包替换为 `NetworkTransformReliable`。
- 自定义远程模型创建逻辑集中到场景中的 `NetworkCharacterManager`。

## 8. 后续开发规则

### 新增角色

1. 创建联机专用 `CharacterForSync` 预制体。
2. 确认预制体只包含模型、Animator 和联机展示所需组件，不添加本地玩家输入逻辑。
3. 把预制体加入 `PersistentScene/Managers/NetworkCharacterManager.characterPrefabs`。
4. 为所有客户端保持相同编号。
5. 在 `NetworkCharacterManager.ApplyCharacter` 中确认新模型能正确绑定 Animator。

### 新增需要同步的数据

1. 先判断数据是否属于玩家状态。
2. 使用 `SyncVar` 同步最终状态。
3. 使用 `[Command]` 接收本地玩家请求。
4. 只在服务器验证并写入最终值。
5. 使用 SyncVar hook 驱动客户端表现。
6. 不为普通状态重新创建一套 UDP Socket。

### 修改移动

- 本地输入和移动计算放在 `PlayerCharacterController`、`CharacterMotor`。
- 网络位置同步交给 `NetworkTransformReliable`。
- 不要让远程对象执行本地输入。
- 不要把摄像机放进远程模型预制体。

## 9. 常见问题定位

| 现象 | 优先检查 |
|---|---|
| Play 后单机角色消失 | `PersistentScene/LocalPlayer` 是否存在，Additive 场景是否正确加载，是否误删本地模型 |
| 联机角色没有模型 | `NetworkCharacterManager` 是否在 `PersistentScene`，数组是否为空，编号是否越界 |
| 远程显示了单机模型 | `characterPrefabs[]` 是否误配了 `LocalPlayer` 使用的预制体 |
| 角色可以显示但不能动 | `Player_Network` 是否有 `CharacterController` 和 `PlayerCharacterController`，对象是否是本地拥有权 |
| 角色切换不同步 | 是否通过 `SetLocalCharacter`，服务器是否接受编号，客户端数组顺序是否一致 |
| 摄像机跟随错误 | `NetworkCharacterManager` 是否只给本地对象启用 Camera、AudioListener、ThirdPersonCamera |
| 远程对象重复生成模型 | 是否在其他脚本中手动实例化模型；模型实例化必须集中到 `NetworkCharacterManager` |

## 10. 最小验收清单

- 单机 Play 时 `LocalPlayer` 显示并可移动。
- 联机服务端和两个客户端均能加入。
- 每个客户端都生成 `Player_Network`。
- 本地角色使用自己的模型和摄像机。
- 远程角色使用 `CharacterForSync` 模型。
- 客户端修改角色编号后，服务器和另一个客户端显示相同编号对应的模型。
- 远程角色不读取本地输入。
- 场景中没有运行时生成的 `NetworkCharacterManager`。
- 不依赖 `DontDestroyOnLoad` 保存网络管理器。
