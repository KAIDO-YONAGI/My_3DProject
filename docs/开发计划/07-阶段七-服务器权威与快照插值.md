# 阶段七：Mirror 服务器权威与快照插值
> 前置：阶段六完成；交付：双客户端可连续完成整局的 Mirror 联机样片
## 1. Mirror 工程接入
复用现有 Mirror NetworkManager、KCP Transport 和客户端场景框架，保留现有 additive 场景加载链路，不为了迁移位置权威强行改写场景所有权。玩家对象可由对应客户端拥有，以便提交输入请求；对象所有权不代表位置、旋转或玩法结果由客户端决定。机器人和共享道具保持服务器权限。
服务器使用 Unity Server Build，不创建摄像机等客户端表现，也不读取本地设备输入；它消费各连接提交并通过验证的 `InputFrame`，独占推进权威模拟。客户端与服务器共享协议数据结构和模拟规则，玩法模拟程序集不依赖 Unity 表现层。
### 现有组件的迁移职责
以下为计划改造项，不表示当前代码已实现：

| 现有入口 | 迁移要求 |
|---|---|
| `PlayerCharacterController` | 拆开设备输入、模拟和表现；专用服务器不读取设备输入，但必须运行角色模拟，不能继续因 Server Build 路径而跳过运动。阶段七联网客户端只采集输入和显示状态，离线模式保留本地模拟。 |
| `CharacterMotor` | 使用阶段六的显式状态、世界方向和固定步长，由服务器调用运动与碰撞；不依赖客户端相机、模型或 Animator。 |
| `ThirdPersonCamera` | 保留本地跟随与环绕，将朝向作为输入意图；不直接旋转权威玩家根节点。 |
| `NetworkTransformReliable` | 停止玩家 `ClientToServer` 位置上行；玩家最终使用自定义快照接收与插值，不与旧组件并行写入 Transform。 |
| `NetworkCharacterManager` | 客户端继续装配模型与动画；服务器的碰撞与模拟不依赖仅客户端生成的角色外观。 |
| `NetworkCharacterSync` / 网络输入桥 | 保留已有角色选择职责，新增或独立接入输入校验、队列和快照协议；不能把角色选择 Command 当作运动协议。 |

服务器进入玩法前须加载对应竞技场与碰撞体，完成模拟就绪检查后才消费输入。协议或 Prefab 改动后同时重建匹配版本的客户端和 Server Build，避免用旧构建验证新协议。
## 2. 输入与服务器 Tick
客户端通过 Command 或自定义 NetworkMessage 上传带协议版本、输入序号、目标 Tick 和输入帧的消息。输入只描述移动、朝向、跳跃、冲刺和玩法操作意图，不允许以客户端 Transform、任意位置、速度或碰撞结论覆盖服务器状态。服务器验证连接与玩家映射、序号、Tick 范围、移动向量、朝向范围、动作位、输入频率和包体长度，并限制每条连接的队列容量。
客户端根据服务器时钟估计为输入分配目标 Tick，允许配置的有限提前量；服务器决定实际可消费窗口，不能被客户端 Tick 加速。输入传输明确可靠通道或有界冗余重发策略，单次动作不因重发重复执行，历史和重发队列均有上限。
服务器每 Tick 为每名玩家选择输入，缺失输入使用明确策略，推进权威 `GameState`，由服务器上的受约束角色运动和碰撞步骤决定位置、旋转、速度、接地、击退和命中，再处理道具、酸雨、伤害、淘汰、计分和胜负。模拟完成后更新已处理输入序号并生成权威快照。禁止服务器继续转发客户端上报 Transform 作为玩家最终位置。
### 输入选择与确认语义
每玩家每服务器 Tick 至多消费一帧有效输入，额外消息不增加模拟次数或移动时长。重复输入丢弃；过期、过度超前、含非有限数值或越界动作的输入拒绝或限流。缺帧时只在配置的短暂宽限内沿用移动等持续输入，随后回到中性输入；跳跃、拾取、投掷等单次动作不得沿用。
输入确认发生在该 Tick 模拟结束后，不是收到包时。明确连续确认水位与最终丢弃输入的处理，避免跨过仍待处理的低序号输入，也避免丢包导致客户端历史永久无法清理；未执行动作不得被确认成已执行。按连接记录拒绝原因，输入队列容量和可接受 Tick 窗口均进入配置。
## 3. 快照与 Mirror 组件
权威快照包含服务器 Tick、快照序号、各玩家最近已处理输入序号、客户端预测重演所需的运动状态、远端显示状态、道具状态、回合状态和事件状态。只在字段确属低频且不会形成双重事实来源时使用 SyncVar；高频连续状态使用自定义快照，不把大量物理字段拆成可靠 RPC。快照丢失时以后续完整状态恢复，离散事件具备去重或可恢复状态。
快照还需携带比赛/回合代次和角色重置标识，以区分普通更新与死亡、复活、传送、场景重载。输入确认和运动状态必须对应同一次已完成模拟，客户端不能用接收时间代替服务器 Tick。
远端玩家、爆炸物和移动障碍物按服务器 Tick 排序并写入快照缓冲，在目标显示 Tick 上插值；本地拥有者在阶段七先应用服务器确认状态，不提前假设预测已完成。死亡、复活、拾取、爆炸、药水和回合转换使用可靠事件或可恢复状态。
玩家权威位置不使用 `NetworkTransform` 的客户端上行同步。`NetworkTransform` 仅可用于经验证、不承载玩法权威的简单展示对象；阶段七可使用服务器方向同步作临时展示验证，但不能与自定义快照或其他组件同时写同一玩家 Transform。`NetworkRigidbody` 不作为首版核心物理同步方案，共享物理由服务器计算，客户端显示服务器快照。
临时 `ServerToClient` 验证只检查服务器确实能移动角色，不作为阶段七最终验收方案；进入阶段八前必须完成玩家自定义快照链路并移除重复 Transform 写入者。
## 4. 加入、Late Join 与断线
```text
连接 → 协议和容量验证 → 创建玩家标识 → 发送当前 GameState
→ 进入快照流 → 参与后续回合
```
Late Join 必须获得当前 Tick、回合、玩家、活跃道具、药水、酸雨和平台状态。主动离开和超时断线统一清理玩家、持有道具、药水来源、归属记录、观察者关系和临时对象。
## 5. 完成标准与测试
□ KCP Server Build 可独立启动；
□ 两个客户端可加入同一比赛；
□ 输入经过服务器校验，客户端无法通过提交 Transform 改写服务器玩家位置；
□ 位置、旋转、速度、碰撞和命中由服务器模拟决定；
□ 服务器模拟不依赖本地输入、相机、客户端模型，且玩法碰撞体已就绪；
□ 两客户端连续多局结果一致；
□ 远端角色和道具插值稳定；
□ Late Join 状态完整；
□ 主动离开与异常断线清理完整；
□ 随后扩展到五客户端；
□ Tick、快照、输入和带宽可观测。
测试同时加入、逐个加入、回合中 Late Join、结算时 Late Join、主动离开、进程关闭、持有爆炸物离开、药水期间离开、快照重复、乱序和间隔波动。额外测试伪造位置/速度字段、过量或超前输入、重复跳跃事件和输入队列溢出；确认拒绝或限流后权威状态仍只由服务器模拟产生。Mirror 权限、可靠事件幂等和对象生命周期作为独立验收项。
