## 目标与顺序

策划名称为 **Kaboom Crew /《轰趴大乱斗》**，玩法定位是 2～5 人短回合物理乱斗。战斗平台同时承担落脚点、可破坏地形和玩家相互作用的场地。

技术主线贯穿同一场景：爆炸切断结构连接，地形失去支撑并分组坍塌，碎片撞击玩家和炸弹，触发击退与连锁爆炸，玩家在运动碎片上站立、行走和跳离。结构算法与快照同步内核使用普通 C# 编写，通过正确性测试和性能实验解释实现与取舍。

阶段一至五按 [MVP 编码教程](MVP编码教程/README.md) 完成最小玩法闭环：移动、跳跃、投掷、结构破坏、动态支撑、伤害、回合重开和中途加入。基础验收使用一个服务器和两个独立客户端，具体操作与记录口径以第 11、12 章为准。

阶段六至八扩展玩法、规模、测量和预测校正。冲刺推挤、颜色药水、炸弹拾取与踢动、酸雨、机器人和比赛规则在这些阶段组织实施。专项中的高级设计按扩展目标接入。

## 当前工程与教学路线

当前工程从 `InitialScene` 加载常驻场景与玩法场景。拥有者客户端通过 `PlayerCharacterController` 调用 `CharacterMotor.Tick`，`NetworkTransformReliable` 按 `ClientToServer` 方向同步运动，`CharacterMotionSync` 同步动画所需的运动表现数据。现有调用链与源码入口见 [00 导读](MVP编码教程/00-从当前项目开始.md)。

教程在同一 Unity 工程的 `Assets/MvpTutorial/` 中创建独立竞技场。客户端上传操作，服务器 `MvpWorld` 推进玩法，自写 `Wire`、`Replica` 和 `MvpView` 完成状态编码、缓存与显示。两条路线各自组装网络管理器、场景和运动入口。

Mirror 负责连接、网络对象身份、权限、消息收发和对象创建销毁。教学主线中的职责如下：

| 部分 | 职责 |
| --- | --- |
| 独立结构核心 | 断边、支撑判断、连通分组、受影响区域重算 |
| 独立同步核心 | 编码量化、基线差量、对象分包、快照缓冲、播放时间与恢复 |
| Unity 适配层 | 碰撞查询、刚体模拟、角色接触、几何重建与视觉表现 |
| Mirror 接入层 | 连接、身份、请求权限、消息、网络对象生命周期 |
| 服务器玩法层 | 请求裁定、伤害、击退、支撑关系、淘汰、计分、回合结算 |

核心使用普通 C# 数据和业务编号，在独立控制台中测试。Unity 组件引用保存在适配层。主线用 `MvpInput` 上传操作，服务器写入玩法状态，客户端读取快照与事件。

教学服务器每秒模拟 30 次，每两 Tick 发送一次运动状态。普通客户端以落后最新状态 3 Tick 为目标播放世界；Host 直接显示服务器物理对象。爆炸事件与结构、运动按对应服务器 Tick 协调。

## 阶段一 规则与结构核心

**按顺序阅读：** [01 数据与职责](MVP编码教程/01-数据与职责.md) → [02 结构图](MVP编码教程/02-结构图.md)。结构扩展查 [结构数据与算法](MVP编码教程/专项设计/结构破坏与动态碎片.md#结构数据)。

**实施：**

- 按第 01 章定义对象、块、回合、Tick、拓扑版本、完整基线编号与输入校验，结合章节例子追清字段用途。
- 用 24 个节点和 37 条连接构造平台，固定支撑保存为节点属性，连接保存断开标记。
- 实现广度优先搜索、支撑判断和断边。`Cut` 先遍历全图寻找受影响旧分量，再对该区域重算，玩法层根据返回分组重建几何。
- 用节点 10 的四条边手算一次分裂，再用第 11 章的 `GraphTests` 对照局部返回范围、全图结果与重复断边。

**完成标志：** 能解释节点、边、锚点与块归属的区别；独立测试覆盖初始连通、全部断开、连续断边和局部结果对照。输出分组交给第 08 章建立碎片。

## 阶段二 时间与同步核心

**按顺序阅读：** [03 编码协议](MVP编码教程/03-编码协议.md) → [04 快照与恢复](MVP编码教程/04-快照与恢复.md) → [11 自动验证](MVP编码教程/11-自动验证.md)。扩展查 [时间轴与插值](MVP编码教程/专项设计/独立快照同步内核.md#时间轴与插值)。

**实施：**

- 实现完整基线、运动快照、位置旋转速度量化、相对指定基线的差量和对象分包，校验身份、数值与长度。
- 实现快照排序、容量限制、插值与固定目标缓冲的播放时钟。姿态按版本、业务编号和代次索引，接收器按回合隔离。
- 基线保存同一 Tick 的对象、结构版本、块归属、局部坐标与断边。缺少解码基线的运动包进入有界队列，基线到达后重放。
- 按第 11 章运行固定种子的到达队列实验，覆盖延迟变化、丢包、乱序和重复，以最终完整基线验证恢复。

**完成标志：** 控制台断言覆盖编解码往返、量化与差量边界、分包、截断数据、缺失基线、身份代次、离散状态生效时间、队列上限和回合隔离；播放时钟保持单调。

## 阶段三 Mirror 接入

**按顺序阅读：** [05 Mirror 接入](MVP编码教程/05-Mirror接入.md)。接口选择查 [Mirror 网络 API 总览](MVP编码教程/Mirror网络API总览.md)，工程调用查 [现有角色接入](MVP编码教程/专项设计/现有角色与本地表现接入.md)，组件练习查 [状态与界面绑定](MVP编码教程/专项设计/状态与界面绑定.md) 和 [集合公共对象与消息](MVP编码教程/专项设计/集合公共对象与消息.md)。

**实施：**

- 用 `MvpNetwork : NetworkManager` 建立连接、玩家创建和断线入口，用 `MvpBody : NetworkBehaviour` 保存业务身份。
- 用 `NetworkMessage` 承载输入、完整基线、运动、恢复请求和爆炸事件。输入、基线、恢复与爆炸使用可靠通道，运动使用非可靠通道。
- 服务器从发送连接的 `identity` 找到玩家。输入只携带回合、序号、方向和按钮，玩法层校验序号、频率、数值和动作条件。
- 客户端通过 `MvpBody.ClientBodies` 关联业务编号与网络身份，`Replica` 保存世界状态，显示端在身份满足条件时组装对象。
- 启动时注册处理器，停止时重置显示副本、身份索引与世界缓存。教程 KCP 配置按第 10 章组装，正式工程参数查权威配置。

**完成标志：** 能追清“连接 → 玩家身份 → 输入校验 → 服务器状态 → 消息 → 客户端副本”的调用。第 05—09 章共同组成 Unity 编译单位，场景接线与运行检查集中在阶段五。

## 阶段四 服务器玩法闭环

**按顺序阅读：** [06 服务器世界](MVP编码教程/06-服务器世界.md) → [07 角色与动态支撑](MVP编码教程/07-角色与动态支撑.md) → [08 爆炸与回合](MVP编码教程/08-爆炸与回合.md)。扩展查 [动态支撑](MVP编码教程/专项设计/结构破坏与动态碎片.md#动态支撑) 和 [爆炸物与命中裁决](MVP编码教程/专项设计/爆炸物与命中裁决.md)。

**实施：**

- 按第 06 章顺序执行：增长 Tick、同步 Transform、移动角色、消费到期与碰撞爆炸队列、同步新几何、推进一次物理、判断回合、采样发送。
- 实现移动、朝向、跳跃、重力、落地、外部击退与掉落。动态支撑保存碎片编号、代次和局部接触点，跟随根的平移与旋转，跳离时继承接触点速度。
- 按连接中点与爆心距离选取断边，重建固定块和动态碎片。再次断裂先保存块的世界位置、旧根旋转与点速度，再换算新根局部坐标。
- 完成投掷、引信、范围伤害、碎片撞击、连锁爆炸与回合重开。引信移除取得一次结算资格，表现事件保存回合、编号、Tick、直接来源和爆心。
- 明确碰撞回调与队列阶段的先后：本次刚体模拟产生的碰撞入队，在下一 Tick 消费；引信与消费循环内产生的连锁在本步结算。

**完成标志：** 服务器能推进“投掷 → 断边 → 碎片 → 撞击或连锁 → 伤害与回合”链路。生命归零与跌落共用伤害入口；回合重开恢复地形、生命与输入状态，保留玩家对象编号和累计分数。

## 阶段五 双客户端 MVP

**按顺序阅读：** [09 客户端显示](MVP编码教程/09-客户端显示.md) → [10 场景与构建](MVP编码教程/10-场景与构建.md) → [12 运行验收](MVP编码教程/12-运行验收.md)。运行前完成 [11 自动验证](MVP编码教程/11-自动验证.md)，协议扩展查 [六类网络逻辑](MVP编码教程/专项设计/独立快照同步内核.md#六类网络逻辑)。

**实施：**

- 按第 10 章创建统一 `MvpBody` Prefab、材质、相机、主光源和 `MvpArena`。服务器代码生成角色、炸弹及平台碰撞形状，普通客户端生成显示几何。
- 核对管理器、世界、显示器、网络 Prefab 与材质引用，完成客户端和服务器构建。启动一个服务器与两个独立客户端，并单独检查 Host。
- 按第 12 章完成移动跳跃、结构断裂、伤害重开、连锁去重、动态支撑、中途加入、重连和缺基线恢复实验。
- 界面读取回合、播放时间、对象数、生命、分数与业务字节；事件、支撑和恢复队列按章节指定断点读取。

联机闭环按以下六类检查：

| 网络逻辑 | 检查内容 |
| --- | --- |
| 请求裁定 | 从连接识别玩家，检查回合、序号、数值、频率与投掷条件 |
| 地形协议 | 完整基线保存断边、块归属与局部坐标，按拓扑版本和播放 Tick 应用 |
| 碎片生命周期 | Mirror 管网络身份，自写基线管成员与姿态，检查创建、再次断裂和销毁 |
| 批量快照 | 检查量化、差量基线、对象分包、包长上限和周期完整采样 |
| 加入恢复 | 用当前完整基线加入，缺解码基线时暂存运动并请求恢复 |
| 回合隔离 | 过滤旧回合数据，重置副本、事件、显示几何与角色输入状态 |

**完成标志：** 独立核心断言与第 12 章运行实验分别记录结果；两个客户端看到一致的结构、生命和回合，中途加入与恢复能接续当前世界。性能记录区分业务载荷、实际 UDP 流量和服务器耗时。

## 阶段六 手感与玩法扩展

**阅读：** [结构破坏与动态碎片](MVP编码教程/专项设计/结构破坏与动态碎片.md)、[输入与恢复协议](MVP编码教程/专项设计/独立快照同步内核.md#六类网络逻辑)。接入现有工程时查 [角色切换与玩家移动](MVP编码教程/专项设计/现有角色与本地表现接入.md) 和 [投掷物接管](MVP编码教程/专项设计/投掷物预测与权威接管.md)。

**实施：**

- 增加跳跃和冲刺输入缓冲、跳跃宽限、空中控制，以及冲刺的启动、持续、恢复、冷却阶段。配置转向、速度、伤害、击退与单次命中限制，高速运动使用连续碰撞检测或分段查询。
- 身体接触、冲刺、爆炸与碎片撞击共用作用记录，保存作用者、目标、类型、伤害、冲量、Tick、事件和归属期限。直接伤害按有效来源计分，推挤掉落按时间窗内最近作用者计分，环境作用进入环境统计；复活清理来源记录。
- 加入炸弹刷新、拾取、持有、投掷、踢动、爆炸与回收，校验持有者唯一性。药水覆盖刷新、拾取、使用、生效、结束与回收，配置颜色、持续时间、数值、叠加、覆盖和来源；饮用后揭示加速、中毒或致盲效果。
- 道具按配置随机刷新或掉落。地图从便于推搡的小平台展开到包含障碍与多条路线的大平台，用站位、投掷距离和退路组织不同对抗方式。
- 酸雨按预警、生效、结束推进，配置安全区和伤害间隔；怪物等全局事件沿同一事件入口扩展。机器人生成同一格式的输入，优先脱离危险、选择稳定支撑和安全区，再接近目标、冲刺和使用道具。
- 扩展为等待、倒计时、对局、回合结果、比赛结果与重开。配置目标分数、最大回合数、时限、复活次数、延迟、保护和同分规则。每次有效淘汰给归属玩家加一分，同 Tick 按稳定顺序结算。复活位置考虑支撑、边缘、其他玩家和危险区域。
- 将设备输入、运动与表现职责分别接入现有控制器。服务器推进 `CharacterMotor`，客户端相机读取显示位置，模型和动画读取同一播放时间的状态；角色请求与编号沿用工程入口。统一清理计时器、延迟任务、持有关系、效果、刚体、碰撞体、粒子、音效、订阅和预反馈，对象池复用增加代次。
- 扩展连接强度、爆炸遮挡、块到分量索引和撞击作用记录。分量索引缩小旧区域发现范围，局部结果持续与完整遍历对照；表现飞屑与参与伤害、站立的实体碎片分别配置。
- 为休眠、唤醒、再次断裂与回收设置明确状态转换，发送调度读取这些状态；按连接筛选对象与优先级的机制沿同步内核专项设计。

**完成标志：** 先以真人与机器人检查完整规则，再扩展到 2～5 客户端。连续完成 10 局，覆盖同时冲刺、连续接触、同时拾取、持有物时死亡、药水中死亡、酸雨中复活、同 Tick 多人淘汰、复活点占用和连续重开。

- 按同步内核专项扩展往返测时、时间偏移估计、自适应缓冲、每连接优先级与发送预算。休眠发送最终状态并保留低频校验，唤醒先提供完整状态。

- 保存输入、预测前后完整状态和发送时间，对比同一确认 Tick。恢复位置、速度、动作阶段、计时、冷却、输入缓冲、击退与支撑关系，移除已终结输入，按原 Tick 重演剩余输入。
- 重演查询对应 Tick 的碎片姿态、速度、组成、接触和生命周期，Unity 适配器提供该时刻的碰撞上下文。共享碎片沿服务器结果模拟，本地角色使用历史支撑。

### 弱网矩阵

RTT 表示往返时延。每档记录模拟配置与实际连接测量，覆盖加入、核心对抗、道具、断裂、连锁爆炸、动态站立、结算和重开。

| 场景 | RTT | 抖动 | 丢包 | 通过重点 |
| --- | ---: | ---: | ---: | --- |
| 基线 | 0ms | 0ms | 0% | 功能与指标基线 |
| 常见网络 | 80ms | 10ms | 1% | 本地响应、校正、远端插值 |
| 较差网络 | 150ms | 30ms | 3% | 整局完成、结果一致、队列有界 |
| 压力条件 | 200ms | 50ms | 5% | 体验边界与插值、校正退化 |

动态支撑覆盖平移、旋转、静止、行走、边缘跳离、角速度继承、切换、再次断裂和销毁。协议覆盖恢复期间爆炸、乱序重复、基线缺失、快照先于创建、复用、旧回合消息、最终丢弃输入、确认缺失、断线与场景重载。

**测量与验收：** 记录线上字节、消息大小、输入与快照频率、确认延迟、恢复次数、缓冲、插值误差、位置和速度误差、支撑误差、校正次数与原因、重演数量、结构和物理耗时、Tick 总耗时、碎片数量、CPU、内存及帧率。相同条件下对比逐对象与批量发送、完整与量化差量、持续发送与休眠调度，结合结构实验展示取舍。

基线、常见与较差网络完成整局，2～5 人连续运行 15 分钟，分数、胜者和淘汰顺序一致。Host 是同一进程运行服务器和客户端的主机模式，与专用服务器覆盖相同玩法和恢复边界，Host 每 Tick 复用一次服务器模拟结果。双客户端视频、架构图和指标图使用验收结果。
