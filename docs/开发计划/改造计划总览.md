# 物理派对游戏开发路线

## 目标与顺序

技术主线贯穿同一场景：爆炸切断结构连接，地形失去支撑并分组坍塌，碎片撞击玩家和炸弹，触发击退与连锁爆炸，玩家在运动碎片上站立、行走和跳离。自己编写结构算法与快照同步内核，通过正确性测试和性能实验展示编码能力。

先完成双客户端 MVP，也就是可运行的最小玩法闭环：移动、跳跃、投掷、结构破坏、动态支撑、伤害、回合重开和中途加入。阶段一至五按 [MVP 编码教程](MVP编码教程/README.md) 编写，阶段五交付可运行构建。

阶段六至八扩展为 2～5 人短回合物理乱斗，加入冲刺推挤、2～3 种颜色药水、可拾取和踢动的炸弹、酸雨、基础机器人、完整比赛规则、角色预测与校正，完成演示视频、README 和架构图。

## 工程基础与技术职责

Mirror 是项目使用的 Unity 网络框架，负责连接、网络对象身份、权限、消息收发和对象创建销毁。正式交付使用自写快照与插值内核，Mirror 组件示例用于学习与测量对照。

| 部分 | 职责 |
| --- | --- |
| 独立结构核心 | 爆炸作用、连接断裂、支撑检测、碎块分组、局部更新 |
| 独立同步核心 | 编码压缩、差量、快照缓冲、时间处理、插值、发送预算、模拟网络 |
| Unity 适配层 | 碰撞与遮挡查询、刚体模拟、角色接触、视觉表现 |
| Mirror 接入层 | 连接、身份、请求权限、消息、网络对象生命周期 |
| 服务器玩法层 | 请求裁定、伤害、击退、支撑关系、淘汰、计分、回合结算 |

两个独立核心使用普通 C# 数据和业务编号，在独立程序中测试。Unity 组件引用保存在适配层。真人、机器人、回放和网络接收器统一生成 `InputFrame` 输入帧，服务器写入玩法状态，表现层读取状态与事件。

玩法模拟以 30Hz 起步，Tick 表示一次固定步长的模拟。模拟、网络发送和渲染分别配置频率。角色采用受约束胶囊运动，共享刚体和碎片由服务器模拟，每个 Tick 通过一个入口推进物理。爆炸、破裂和碎片运动共用服务器 Tick 与客户端播放时间。

## 阶段一 规则与结构核心

**按顺序阅读：** [01 数据与职责](MVP编码教程/01-数据与职责.md) → [02 结构图](MVP编码教程/02-结构图.md)。结构扩展查 [结构数据与算法](联机系统教学/专项设计/结构破坏与动态碎片.md#结构数据)。

**实施：**

- 使用教程的双人竞技场规则，集中配置移动、跳跃、生命、投掷冷却、引信、爆炸半径、回合时长和重开间隔。
- 定义回合、业务对象编号、代次、输入与状态。地形块和连接使用稳定编号，连接保存强度，固定支撑保存为图节点属性。
- 实现爆炸影响连接、断边、支撑遍历、失去支撑的连通分组与局部更新。Unity 提供距离与遮挡查询，结构核心处理普通数据。
- 区分参与伤害和站立的大块碎片与表现用飞屑，确定活动、休眠、唤醒、再次断裂和销毁规则。

**完成标志：** 炸断支柱与炸掉边角得到对应分组；局部更新与完整遍历结果一致，连续爆炸和碎片再次断裂有测试用例。

## 阶段二 时间与同步核心

**按顺序阅读：** [03 编码协议](MVP编码教程/03-编码协议.md) → [04 快照与恢复](MVP编码教程/04-快照与恢复.md) → [11 自动验证](MVP编码教程/11-自动验证.md)。扩展查 [时间轴与插值](联机系统教学/专项设计/独立快照同步内核.md#时间轴与插值)。

**实施：**

- 实现完整基线、运动快照、位置与旋转量化、差量和基线标识。按优先级分配字节预算，周期完整状态提供恢复入口。
- 实现快照排序、容量限制、播放缓冲、插值、时间校准和回合隔离。爆炸事件与运动读取同一播放时间。
- 基线保存确定 Tick 的结构版本、块归属、局部坐标与对象状态。恢复期间缓存后续变更，基线应用后接续事件和快照。
- 用可重复的模拟网络验证延迟、抖动、丢包、乱序和重复，记录原始轨迹、解码误差、插值误差与队列长度。

**完成标志：** 核心测试覆盖编解码、量化误差、差量基线缺失、时间跳变、缓冲上限、活动休眠和回合重置；两份核心可在普通 C# 程序中运行。

## 阶段三 Mirror 接入

**按顺序阅读：** [05 Mirror 接入](MVP编码教程/05-Mirror接入.md)。接口原理查 [网络对象与职责](联机系统教学/01-网络对象与职责.md)、[状态与事件的编码](联机系统教学/05-状态与事件的编码.md) 和 [集合公共对象与消息](联机系统教学/06-集合公共对象与消息.md)。

**实施：**

- 用 `NetworkManager` 网络管理器建立连接与玩家创建入口，用 `NetworkIdentity` 网络身份组件标识对象。`KcpTransport` 是项目采用的 KCP 传输组件，参数按工程配置设置。
- 用 `NetworkMessage` 自定义网络消息承载内核字节。`Command` 是客户端向服务器发送对象请求的机制；按连接与对象归属校验请求身份。
- 建立业务编号、代次与网络对象映射，为消息先于对象创建的情况设置有界等待队列。请求携带序号，服务器校验动作、冷却、距离、频率和数值范围。
- 编写消息注册、注销、连接关闭和对象回收入口，保持客户端与服务器协议及组件布局一致。

**完成标志：** 网络适配层能够传递输入、基线和运动包；重复请求按标识消费一次，连接与对象清理有明确入口。Unity 文件按教程顺序编写，在阶段五文件齐备后统一编译与运行。

## 阶段四 服务器玩法闭环

**按顺序阅读：** [06 服务器世界](MVP编码教程/06-服务器世界.md) → [07 角色与动态支撑](MVP编码教程/07-角色与动态支撑.md) → [08 爆炸与回合](MVP编码教程/08-爆炸与回合.md)。扩展查 [动态支撑](联机系统教学/专项设计/结构破坏与动态碎片.md#动态支撑) 和 [爆炸物与命中裁决](联机系统教学/10-爆炸物与命中裁决.md)。

**实施：**

- 按固定顺序选择输入、处理回合边界和到期事件、推进刚体、采集接触、更新角色与支撑、结算碰撞和爆炸、更新结构、结算淘汰、输出状态与事件。每 Tick 只推进一次物理，设置每帧追赶步数上限；新物理实体在下一物理步参与运动。
- 实现移动、朝向、跳跃、重力、落地、外部击退与掉落。主动速度、外部速度和支撑运动分别保存，动态支撑记录碎片身份、接触块、局部点和法线。
- 按坡度、距离和稳定顺序选择支撑，处理平移、旋转、相对行走、跳离时接触点速度继承，以及支撑切换、断裂和销毁。
- 完成投掷、引信、爆炸范围与遮挡、断边、坍塌、撞击伤害、连锁爆炸和回合重开。事件保存编号、发生 Tick、直接触发来源和初始玩家来源，统一结算与播放去重。

**完成标志：** 服务器能够推进“炸断支柱 → 坍塌 → 碎片撞击 → 连锁爆炸 → 玩家淘汰或继续站立”的完整链路，致死伤害和进入 KillZone 共用一次淘汰流程。重开恢复初始结构、对象和支撑关系。

## 阶段五 双客户端 MVP

**按顺序阅读：** [09 客户端显示](MVP编码教程/09-客户端显示.md) → [10 场景与构建](MVP编码教程/10-场景与构建.md) → [12 运行验收](MVP编码教程/12-运行验收.md)。运行前完成 [11 自动验证](MVP编码教程/11-自动验证.md)，协议扩展查 [六类网络逻辑](联机系统教学/专项设计/独立快照同步内核.md#六类网络逻辑)。

**实施：**

- 搭建独立竞技场、玩家与碎片 Prefab、镜头和调试界面，配置出生点、支柱、KillZone 与连锁爆炸测试位置。服务器加载玩法碰撞体并完成就绪检查，客户端装配显示对象。
- 客户端采集意图并上行，服务器计算结果；角色、炸弹与碎片使用自写缓冲和插值显示。界面显示连接、回合、生命、分数、Tick、支撑、恢复状态与流量。
- 生成客户端与专用服务器构建，用两个客户端连续完成 10 局，覆盖移动、投掷、动态站立、淘汰与重开。

联机闭环按以下六类检查：

| 网络逻辑 | 检查内容 |
| --- | --- |
| 请求裁定 | 身份、请求序号、道具、冷却、距离、频率，服务器确定作用位置 |
| 地形协议 | 回合、地形、结构版本、事件、Tick、断裂连接与碎块组成，版本缺口触发完整恢复 |
| 碎片生命周期 | 业务身份与对象映射、代次、活动休眠、唤醒、再次断裂、创建与快照到达顺序 |
| 批量快照 | 位置、旋转、速度、运动状态、优先级、预算、差量基线和周期完整快照 |
| 加入恢复 | 同 Tick 基线、恢复期缓存、恢复期间再次爆炸、后续事件与快照接续 |
| 回合隔离 | 旧消息过滤，地形、映射、事件、缓冲和支撑历史统一重置 |

**完成标志：** 双客户端看到相同结构、伤害和回合结果，中途加入恢复当前地形及相关活动和休眠碎片。重复乱序、基线缺失、对象复用、断线和场景重新进入均有验收记录。此阶段产出可运行 MVP。

## 阶段六 手感与玩法扩展

**阅读：** [结构破坏与动态碎片](联机系统教学/专项设计/结构破坏与动态碎片.md)、[输入与恢复协议](联机系统教学/专项设计/独立快照同步内核.md#六类网络逻辑)。接入现有工程时查 [角色切换](联机系统教学/03-角色切换完整链路.md)、[玩家移动](联机系统教学/04-玩家移动同步.md) 和 [投掷物接管](联机系统教学/09-投掷物预测与权威接管.md)。

**实施：**

- 增加跳跃和冲刺输入缓冲、跳跃宽限、空中控制，以及冲刺的启动、持续、恢复、冷却阶段。配置转向、速度、伤害、击退与单次命中限制，高速运动使用连续碰撞检测或分段查询。
- 身体接触、冲刺、爆炸与碎片撞击共用作用记录，保存作用者、目标、类型、伤害、冲量、Tick、事件和归属期限。直接伤害按有效来源计分，推挤掉落按时间窗内最近作用者计分，环境作用进入环境统计；复活清理来源记录。
- 加入炸弹刷新、拾取、持有、投掷、踢动、爆炸与回收，校验持有者唯一性。药水覆盖刷新、拾取、使用、生效、结束与回收，配置颜色、持续时间、数值、叠加、覆盖和来源；饮用后揭示加速、中毒或致盲效果。
- 酸雨按预警、生效、结束推进，配置安全区和伤害间隔。机器人生成同一格式的输入，优先脱离危险、选择稳定支撑和安全区，再接近目标、冲刺和使用道具。
- 扩展为等待、倒计时、对局、回合结果、比赛结果与重开。配置目标分数、最大回合数、时限、复活次数、延迟、保护和同分规则。每次有效淘汰给归属玩家加一分，同 Tick 按稳定顺序结算。复活位置考虑支撑、边缘、其他玩家和危险区域。
- 将设备输入、运动与表现职责分别接入现有控制器。服务器推进 `CharacterMotor`，客户端相机读取显示位置，模型和动画读取同一播放时间的状态；角色请求与编号沿用工程入口。统一清理计时器、延迟任务、持有关系、效果、刚体、碰撞体、粒子、音效、订阅和预反馈，对象池复用增加代次。

**完成标志：** 先以真人与机器人检查完整规则，再扩展到 2～5 客户端。连续完成 10 局，覆盖同时冲刺、连续接触、同时拾取、持有物时死亡、药水中死亡、酸雨中复活、同 Tick 多人淘汰、复活点占用和连续重开。

**实施：**

- 预测本地角色移动、跳跃、冲刺和相对支撑运动，拾取、投掷、饮用提供可撤销反馈。服务器确认持有、物理、伤害、击退、结构和比赛结果。
- 输入携带序号与目标 Tick，服务器每玩家每 Tick 至多选择一帧。缺帧在有限宽限内沿用持续移动，随后采用中性输入，一次性动作按请求编号消费。确认区分已执行与最终丢弃，用连续终结水位清理客户端历史，确认与状态来自同一次模拟输出。
- 保存输入、预测前后完整状态和发送时间，对比同一确认 Tick。恢复位置、速度、动作阶段、计时、冷却、输入缓冲、击退与支撑关系，移除已终结输入，按原 Tick 重演剩余输入。
- 重演查询对应 Tick 的碎片姿态、速度、组成、接触和生命周期，Unity 适配器提供该时刻的碰撞上下文。共享碎片沿服务器结果模拟，本地角色使用历史支撑。
- 模拟状态立即恢复，视觉子节点按误差大小收敛，相机读取显示位置，一次性效果按事件编号去重。历史索引包含回合、角色与碎片代次，限制历史长度、等待时间、队列与重演预算，历史缺失触发完整恢复。

完整恢复状态包含下表中的后续模拟数据：

| 状态 | 保存内容 |
| --- | --- |
| 玩家与运动 | 姿态、主动与外部速度、接地、动作、计时、冷却、输入缓冲、生命、分数、药水、持有和作用来源 |
| 道具 | 类型、身份、代次、姿态、速度、生命周期、持有者、作用者、引信与效果 |
| 地形与碎片 | 地形编号、结构版本、连接、支撑、块归属、局部坐标、碎片组成、姿态、线速度、角速度、活动状态与寿命 |
| 动态支撑 | 碎片身份、接触块、局部点、法线、接触 Tick、角色相对状态和支撑历史 |
| 回合 | 回合代次、Tick、阶段、分数、胜者、复活队列、随机状态与事件 |

### 弱网矩阵

RTT 表示往返时延。每档记录模拟配置与实际连接测量，覆盖加入、核心对抗、道具、断裂、连锁爆炸、动态站立、结算和重开。

| 场景 | RTT | 抖动 | 丢包 | 通过重点 |
| --- | ---: | ---: | ---: | --- |
| 基线 | 0ms | 0ms | 0% | 功能与指标基线 |
| 常见网络 | 80ms | 10ms | 1% | 本地响应、校正、远端插值 |
| 较差网络 | 150ms | 30ms | 3% | 整局完成、结果一致、队列有界 |
| 压力条件 | 200ms | 50ms | 5% | 体验边界与插值、校正退化 |

动态支撑覆盖平移、旋转、静止、行走、边缘跳离、角速度继承、切换、再次断裂和销毁。协议覆盖恢复期间爆炸、乱序重复、基线缺失、快照先于创建、复用、旧回合消息、最终丢弃输入、确认缺失、断线与场景重载。

**测量与验收：** 记录线上字节、消息大小、输入与快照频率、确认延迟、恢复次数、缓冲、插值误差、位置和速度误差、支撑误差、校正次数与原因、重演数量、结构和物理耗时、Tick 总耗时、碎片数量、CPU、内存及帧率。相同条件下对比逐对象与批量发送、完整与量化差量、持续发送与休眠调度，结合结构实验展示取舍。

基线、常见与较差网络完成整局，2～5 人连续运行 15 分钟，分数、胜者和淘汰顺序一致。Host 是同一进程运行服务器和客户端的主机模式，与专用服务器覆盖相同玩法和恢复边界，Host 每 Tick 复用一次服务器模拟结果。双客户端视频、架构图和指标图使用验收结果。

每阶段保存配置、测试结果和可运行产物，每周推进一个主要交付。求职阶段将项目投入控制在个人有效学习时间的 20%～25%。
