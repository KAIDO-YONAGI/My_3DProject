# 玩家移动同步

本章讲项目玩家的拥有者移动链路。服务器模拟的道具运动见 [运动轨迹与同步选择](08-运动轨迹与同步选择.md)，爆炸对玩家的击退交接见 [爆炸物与命中裁决](10-爆炸物与命中裁决.md)。

## 1. 本地拥有者计算移动

[PlayerCharacterController.cs](../../../Assets/Core/Scripts/Character/Control/PlayerCharacterController.cs) 使用 Input System 读取输入。Input System 是 Unity 的输入系统，项目通过 `CharacterInputReader` 接入。

本地流程是：

```text
本地输入
  → CharacterInputReader
  → CharacterInput
  → PlayerCharacterController
  → CharacterMotor.Tick
  → CharacterController.Move
  → 网络根位置与旋转更新
  → CharacterAnimator 更新本地动画
```

控制器在专用服务器的网络玩家上跳过本地运动处理，在已连接客户端上只允许本地玩家读取输入。

相机引用由表现管理器绑定到 `inputSpace`。运动层使用相机的水平朝向，把输入转换成世界移动方向。

## 2. 上行传递计算结果

`NetworkPlayer.prefab` 中的 `NetworkTransformReliable` 使用 `ClientToServer`，即客户端到服务器的同步方向。

本地拥有者更新网络根后，该组件记录并发送变换快照。位置与旋转在这条链路中独立于角色编号传递。

## 3. 服务器接收，再向远程客户端传递

```text
A 操作甲
  → A 计算甲的网络根变换
  → A 上传变换快照
  → S 接收并缓冲快照
  → S 插值更新甲的网络根
  → S 向其他观察客户端发送变换状态
  → B 缓冲并插值显示甲
```

插值是根据相邻快照计算中间状态，用于平滑显示运动。拥有者继续使用自己的本地运动结果，远程客户端使用接收到的快照。

运动表现通过另一条链路传递。[CharacterMotionSync.cs](../../../Assets/Core/Scripts/Networking/Character/Sync/CharacterMotionSync.cs) 在 `Awake` 设置 `ClientToServer`、可靠同步和 `0.1` 秒同步间隔。拥有者在 `LateUpdate` 将状态标记为待发送，序列化内容为：

| 字段 | 内容 |
| --- | --- |
| `State` | Idle、Run、Sprint、Rising、Falling 对应的单字节状态 |
| `LocalDirection` | 角色局部空间中的二维移动方向 |
| `LocomotionWeight01` | 范围为 0 至 1 的运动权重 |

服务器接收时检查状态枚举、方向长度和权重范围，保存有效状态并转发。远程客户端将收到的状态交给 `ReceiveRemoteMotion`，控制器在 `LateUpdate` 应用当前运动表现。位置由变换快照插值，动画使用最近接受的运动状态。

## 4. 编写移动相关功能时沿用数据方向

当前移动计算位于拥有者，服务器接收和转发变换。角色编号则由服务器校验请求并维护状态。两者体现不同的数据决定规则。

沿用当前移动结构时，在本地运动层处理输入与手感，在 `NetworkTransformReliable` 中使用已有的快照同步能力。

设计服务器决定的运动时，需要同时设计输入上行、服务器运动计算、状态下行和客户端显示。预测是客户端在确认到达前估算结果，校正是确认到达后对齐服务器结果；它们涉及运动算法与时间关系，需要作为一条完整链路处理。

正式交付按 [同步核心](../改造计划总览.md#阶段二-时间与同步核心)、[服务器玩法](../改造计划总览.md#阶段四-服务器玩法闭环) 和 [预测校正](../改造计划总览.md#阶段八-预测校正与弱网验证) 实施。状态编码、时间轴和快照缓冲见 [独立快照同步内核](专项设计/独立快照同步内核.md)，站立碎片与支撑历史见 [结构破坏与动态碎片](专项设计/结构破坏与动态碎片.md#动态支撑)。

## 5. 发送、插值和判定分别设计

NetworkTransform 负责传递变换并平滑显示。发送节奏影响网络数据量，快照缓冲影响平滑度和显示延迟。选择参数时结合实际连接条件验证拥有者、服务器和远程客户端。

玩法判定使用明确的数据来源。例如碰撞造成伤害时，由服务器使用自身的玩家、目标和规则状态判定，再同步生命值和结果。显示平滑度与判定规则分别承担职责。

在拥有者上传变换的结构中加入移动约束时，服务器校验位置范围、时间关系和允许速度，并决定采用的结果。客户端的拥有者资格与上传数据的业务有效性分别检查。

官方依据：[Network Transform](https://mirror-networking.gitbook.io/docs/manual/components/network-transform)、[SyncDirection](https://mirror-networking.gitbook.io/docs/manual/general/syncdirection)。
