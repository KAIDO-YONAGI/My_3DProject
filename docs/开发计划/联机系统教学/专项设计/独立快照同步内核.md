# 独立快照同步内核

实现一个接收状态、时间和字节数据的普通 C# 模块，完成快照编解码、压缩、缓冲、时间处理、插值、预算调度与模拟网络。通过独立程序验证，再由 Mirror 接入真实连接。结构图、物理与动态支撑规则见 [结构破坏与动态碎片](结构破坏与动态碎片.md)。

## 模块接口与数据流

```text
服务器固定 Tick 状态
→ 按连接筛选与预算调度
→ 量化、完整或差量编码
→ 传输适配器
→ 接收验证、基线还原与依赖协调
→ 按身份存入快照缓冲
→ 时间轴采样与插值
→ Unity 表现和角色恢复入口
```

| 模块 | 接口职责 |
| --- | --- |
| 状态模型 | 普通数值、业务身份、Tick、结构版本与运动状态 |
| 编解码器 | 状态和字节互转，验证字段数量、范围与长度 |
| 基线管理 | 每连接和对象身份保存可用基线，处理确认、淘汰与恢复 |
| 发送调度 | 选择对象和字段、估算编码大小、限制每连接预算 |
| 快照缓冲 | 按 Tick 有序保存，去重、修剪与查询相邻状态 |
| 时间控制 | 接收服务器采样与本地时钟，推进单调播放时间 |
| 插值器 | 从相邻状态和目标时间得到显示状态 |
| 依赖协调 | 结构版本、对象创建、完整恢复与事件接续 |
| 模拟网络 | 可重复延迟、抖动、丢包、乱序、重复和断连 |

状态与编解码器通过值、数组或受控缓冲交互，时钟由调用方传入，传输适配器只收发字节。测试程序直接驱动采样和接收，Unity 适配层转换向量与姿态。

## 标识与消息

统一使用回合编号、业务对象编号和代次识别状态。玩家另带角色生命或重置代次，地形另带结构版本。跨消息引用携带完整身份，连接和比赛的上下文参与验证。

| 消息 | 主要字段 |
| --- | --- |
| 输入与操作请求 | 协议版本、回合、角色代次、请求或输入序号、目标 Tick、操作意图 |
| 结构变更 | 回合、地形、旧新版本、事件编号、来源、Tick、断裂连接、碎片及成员块 |
| 碎片生命周期 | 完整身份、类型、创建或结束 Tick、成员与形状版本、初始状态、替代关系 |
| 运动批次 | 回合、快照序号、采样 Tick、基线标识、编码类型、对象数与对象状态 |
| 角色确认 | 角色代次、状态 Tick、连续终结水位、动作结果与完整恢复状态 |
| 恢复控制 | 恢复编号、基线 Tick、结构版本向量、分块索引与总数、确认或重试原因 |
| 完整世界基线 | 当前回合、角色、地形、相关碎片与道具、药水、酸雨和必要事件状态 |

事件使用回合内唯一编号，保存直接来源和服务器 Tick。编码设置最大对象数、成员数、消息长度和恢复分块数，检查数值有限性与范围。协议版本用于双方格式匹配。

## 时间轴与插值

服务器逻辑 Tick 是玩法顺序依据，用固定步长映射到秒。快照保存实际采样 Tick，事件保存实际结算 Tick。客户端为远端对象维护统一播放时间，爆炸、破裂、飞散和远端角色按该时间采样。

核心时钟同步接收带关联编号的请求响应，记录本地发送、服务器采样和本地接收时刻，估计往返时长与服务器时间偏移。过滤异常样本并限制校准速度。Mirror 时间数据可通过适配器作为另一种时钟输入，对照实验使用相同 Tick 映射。

播放时间落后估计服务器时间一段可配置缓冲，按到达间隔统计缓慢调整缓冲长度，设置最小最大值和追赶速度。普通校准保持播放时间单调，回合切换或完整恢复通过明确的时间重建操作处理。

位置按相邻快照线性插值，旋转采用最短路径球面插值。速度用于显示与有界外推；活动状态、组成、形状和身份按 Tick 离散应用。旋转解码后归一化，插值器处理相同 Tick、零时间间隔和边界样本。

样本不足时保持最新状态或在配置范围内外推，超过时限后保持并记录退化。插值缓冲按对象数、样本数与时间范围限制容量。丢失快照后的新样本继续按实际 Tick 插值，结构与生命周期依赖完成后进入显示。

本地角色使用输入目标 Tick 与确认 Tick，角色重演按对应时间查询支撑历史。远端播放时间、本地预测时间和超时计时分别提供，支撑姿态采样与视觉对齐按 [支撑历史规则](结构破坏与动态碎片.md#支撑历史与角色重演) 实施。

## 编码、量化与差量

位置使用地形或量化区域原点与整数刻度编码，明确区域编号和范围。速度按配置上限编码，旋转采用最大分量索引与其余三个分量的压缩形式，统一符号规则并归一化还原。状态枚举和字段存在位使用紧凑编码。

位置量化步长为 `q` 时，单轴舍入误差上限为 `q / 2`，三维位置误差按三轴合成。为位置、速度和角度分别设容差，独立测试统计实际分布。越出编码范围的对象使用扩展完整表示或切换量化区域，消息携带新区域信息。

差量基于已经量化的状态计算字段变化。消息携带基线标识，解码器先定位完整身份和对应基线，再还原完整状态；基线的结构版本和形状版本参与匹配。

按连接维护已确认可用基线，发送端选择接收方确认的基线进行差量。确认丢失时保留已知基线并受容量限制。接收方缺失基线时缓存有界数量的依赖包并请求完整状态。周期完整快照、新观察者和对象唤醒提供恢复入口。基线更新通过显式确认接续，发送和接收侧分别淘汰过期基线。

快照批次按传输可承载大小切分，每个分包可独立解码并携带采样 Tick 与批次信息。单个状态使用完整或差量格式；较大的结构与恢复数据走有界可靠分块协议。预算统计包含包头、身份、字段和基线信息，线上实验另外记录 Mirror 与传输开销。

## 六类网络逻辑

### 1. 请求校验与裁定

Mirror 是项目的 Unity 网络框架。`Command` 将对象上的客户端方法请求送到服务器，`NetworkMessage` 提供按连接收发的消息。接入层从实际发送连接取得玩家身份，再将普通数据送入玩法层。

服务器依次检查连接状态、玩家与回合映射、请求序号、道具库存、冷却、存活与动作条件、操作距离、方向与频率。作用位置按服务器角色状态和规则偏移计算，碰撞与遮挡由服务器查询。

维护有界请求结果表，重复请求返回同一结果；过期和越界请求按规则终结。输入每 Tick 至多执行一帧，持续输入宽限与一次性操作分别处理。模拟完成后确认已执行或最终丢弃的输入，连续终结水位支持客户端清理历史。

### 2. 地形破坏协议

服务器执行结构算法，生成旧版本到新版本的结果，记录断裂连接、掉落分组、碎片身份、事件来源和 Tick。客户端按版本应用给定分组。

接收端按回合与事件编号去重，旧版本对应当前版本时提交；未来版本进入有界等待队列并请求缺口；已覆盖版本按结果记录处理。完整恢复以对应地形的基线版本重建状态，再依次接续更高版本。版本与事件编号分别验证结构连续性和一次结算。

### 3. 碎片生命周期

`NetworkServer.Spawn` 是 Mirror 登记并向客户端创建网络对象的入口，`NetworkServer.Destroy` 负责网络销毁。`netId` 是 Mirror 分配的运行期网络对象编号。接入层维护业务身份到 `netId` 的映射，业务引用使用回合、编号和代次。

创建记录提供成员、形状版本、初始姿态、速度和生效 Tick。快照先到时按身份缓存，等待结构与对象映射；创建后按采样顺序接续。销毁记录保留至迟到包窗口结束，旧身份的后续消息据结束 Tick 终结。

活动、休眠、唤醒与再次断裂均有事件 Tick。拆分原子提交旧实体结束、成员重分配和子实体创建；角色支撑根据接触块迁移。若对象仍依赖图数据或基线，延后其状态应用并设置等待上限。

### 4. 批量快照与发送预算

服务器集中采集对象完整身份、位置、旋转、线速度、角速度和运动状态，自定义内核量化并计算差量。对每条连接按观察范围选择对象，设定每 Tick 字节预算、最大对象数和最大状态年龄。

优先发送本地角色校正、当前支撑、刚创建或唤醒的碎片、临近玩家的碰撞物和高速物体，其余对象按等待年龄提高优先级。预留关键对象额度，预算不足时延迟低优先对象并记录欠发与饥饿次数。创建、销毁和结构结果使用可靠消息，队列同样设置容量与流量限制。

休眠碎片发送最终状态并确认，保留低频校验与完整恢复数据。唤醒先提供完整状态，再进入活动频率。周期完整快照按对象调度，错开发送峰值；差量携带明确基线，接收端按基线规则恢复。

### 5. 中途加入恢复

在模拟 Tick 结束边界冻结一份一致基线，记录恢复编号、Tick、各地形结构版本和事件游标，复制普通状态后分块发送。基线包含回合、玩家、道具、地形及相关活动和休眠碎片，服务器继续模拟并记录边界后的变更。

```text
建立恢复上下文
→ 接收基线分块与对象映射，缓存边界后的变更
→ 检查分块、身份和版本完整性
→ 在暂存状态中应用完整基线
→ 按依赖与 Tick 接续结构和生命周期
→ 解码并接入依赖满足的运动快照
→ 原子切换当前世界状态并确认恢复游标
→ 进入持续状态流
```

后续变更按地形版本与事件依赖顺序应用；同 Tick 顺序采用服务器记录的稳定序号。恢复完成前的新爆炸进入缓存，接续覆盖至已声明游标。双方设置恢复时长、缓存字节和事件数上限，缺块可重传，超限或关键版本断链时建立较新的完整基线。

基线已包含的历史爆炸通过结构和期限状态呈现，边界之后的事件按播放游标处理。播放时间追上已发生的事件时采用统一的晚到策略，持续效果按剩余期限恢复。

Mirror 的 `OnSerialize` 中 `initialState` 表示某个网络对象的初始序列化。世界恢复的冻结边界、分块、缓存和完成确认由上述业务协议协调。

### 6. 回合隔离与复用

所有请求、事件、生命周期、快照和基线携带回合，运行对象引用携带代次。池对象复用先建立新代次，再重置状态、映射和接收上下文。

重开时在一个边界重置地形、碎片、角色代次、输入队列、事件记录、快照、编码基线、恢复上下文和支撑历史，发布新回合完整基准。接收器先验证回合与身份再查缓冲，序号上限通过新代次或新上下文明确处理。

## Mirror 与 Unity 适配

Mirror 接入层处理连接、认证、权限、观察范围、消息通道和网络对象。网络消息承载内核编码后的字节，格式读写位于内核。独立测试直接将同一字节送入解码入口。

结构、生命周期和恢复控制使用可靠通道，高频运动使用非可靠通道。跨通道顺序由 Tick、版本、身份和依赖缓冲协调。观察范围缩小时清理本地显示和相关缓存，重新进入时获取该连接可见对象的完整基线。

Unity 适配层从服务器模拟采样状态，将客户端插值结果写入远端显示，将权威角色状态交给预测校正入口。每个根节点明确一个运动写入入口。Mirror 的 `NetworkTransform` 变换同步组件与 `NetworkRigidbody` 刚体同步组件用于教学和测量对照，使用方式见 [运动同步教学](../08-运动轨迹与同步选择.md)。

## 独立测试与联机验收

| 测试 | 输入与通过条件 |
| --- | --- |
| 编解码 | 边界、随机有效状态和截断包，完整字段还原且异常输入受控拒绝 |
| 量化 | 原始轨迹与解码轨迹，误差满足配置范围，越界表示可恢复 |
| 差量 | 基线确认丢失、缺失、淘汰与换区，等待有界且完整快照恢复 |
| 缓冲 | 乱序、重复、突发和长空档，排序、去重、容量与采样规则稳定 |
| 时间 | 时钟偏差、抖动、暂停和恢复，播放时间与事件顺序满足规则 |
| 生命周期 | 快照先到、短命实体、休眠唤醒、拆分销毁和编号复用，状态绑定正确 |
| 完整恢复 | 分块丢失、恢复时爆炸、缺口与超限，基线与后续变更接续一致 |
| 动态支撑 | 历史样本缺口、旋转、拆分和销毁，角色恢复与对应 Tick 对齐 |
| 回合隔离 | 旧请求、事件、差量与恢复包晚到，新回合状态保持正确 |
| 预算 | 大量活动碎片与唤醒峰值，关键状态时效和总预算可观测 |

模拟网络以独立方向的队列处理上行和下行，用固定种子生成延迟、抖动、丢失与重复。可靠通道模拟有序重传造成的等待，非可靠通道保留丢包和乱序；分别控制实际测试所需的到达序列。基础参数沿用 [弱网矩阵](../../00-改造计划总览.md#弱网矩阵)。

独立测试输出原始轨迹、接收轨迹、显示轨迹、事件游标、缓冲深度、欠发、恢复次数、编码耗时与字节数。插值误差比较同一播放 Tick 的真值，校正误差比较同一确认 Tick 的预测与权威状态。

用相同对象轨迹和频率对照逐对象与批量、完整与压缩、持续与休眠发送，记录编码字节和真实传输字节。联机复现实验采用相同配置，覆盖专用服务器、Host 主机模式、双客户端和五客户端，并保存测量数据与演示画面。
