# 爆炸物与命中裁决

## 什么时候使用

玩家动作会改变公共平台、生成道具或影响回合结果时，输入由玩家发起，服务器决定命中和结果。客户端本地射线可以辅助选中目标，但不能直接写平台状态。

## 开局炸弹规则

开局平台由中心 `3×3` 格组成。`ArenaMatch` 在服务器持续检查携带者与其他存活玩家的距离，预备时间结束后满足接近条件，就让整块开局平台脱落。格子生成、围栏外观和碰撞分别见主线第 06 章。

服务器侧按顺序检查：

1. 当前阶段为进行中，且本回合开局平台尚未脱落。
2. 携带者仍是本回合的存活玩家，且预备时间结束。
3. 另一名本回合存活玩家进入携带者的触发距离。
4. 找到本回合仍然固定的开局平台。
5. 更新固定状态并启用服务器刚体，使平台开始下落。

服务器用 `openingDetached` 保存本回合是否已触发，后续帧据此跳过检查。这个规则由服务器自动执行。

## E 键挖掘

`ArenaPlayerActions` 读取本机 E 键和相机方向，通过玩家 Command 发送方向。服务器使用自己收到的玩家位置作为射线起点，按距离查看命中结果，再检查阶段、玩家存活、回合、使用间隔、道具库存和目标平台。检查通过后，服务器扣除一次使用次数，删除命中范围内的格子，并用四邻接 BFS 找出剩余部分。具体实现沿主线第 05、08 章的 `CmdUse → ServerTryUse → ServerApplyFirstHit → ServerBreak` 查询。

## 同步表现

SyncVar、SyncList 和 NetworkTransform 保持平台的当前状态、格子拓扑和位姿。一次性爆炸音效或视觉效果由服务器确认后发送事件。若本机先播放一次，再通过 ClientRpc 通知其余观察者，设置 `includeOwner = false`，防止本机双播。

`ArenaMatch` 管理服务器回合、胜负和各层道具生成。`ArenaPickup` 每 0.2 秒在服务器检查附近的本回合存活玩家，接近后调用 `ServerAddCharge`，再销毁这个网络道具。使用次数保存在玩家的 `ArenaPlayerActions.Charges` 中，并同步给客户端显示。玩家掉入 Void 后进入观战，最后一名玩家存活时结算。

断裂和连通分组实现见[结构破坏与动态碎片](结构破坏与动态碎片.md)。
