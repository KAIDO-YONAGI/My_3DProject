# 状态与界面绑定

## 什么时候使用

当网络状态需要显示在玩家 HUD、平台标签或观战界面时，先确定数据由谁持有、是否需要晚加入者看到，再选择绑定方式。界面读取网络状态，不负责裁决玩法。

## 状态选择

| 显示内容 | 数据来源 | 绑定方式 |
| --- | --- | --- |
| 本机道具数量、当前回合提示 | 玩家或回合的服务器状态 | 对应 SyncVar hook 或状态刷新 |
| 当前平台层数和是否锚定 | `PlatformChunk` SyncVar | 对象生命周期后绑定，状态变化时刷新标签 |
| 平台格子形状 | `PlatformChunk.Cells` | 订阅 SyncList 变化并从当前集合建立网格 |
| 一次爆炸或命中提示 | 服务器确认的事件参数 | ClientRpc 播放一次，不把 RPC 当作持续状态 |
| 被淘汰玩家的观战列表 | 当前回合存活玩家集合 | 根据服务器同步状态更新列表和可选目标 |

## 怎样绑定

1. 在 `ArenaPlayerPresentation` 中绘制每个玩家的白色标签，只为本机玩家绘制 HUD 和处理观战输入。
2. 网络对象进入客户端生命周期后读取当前 SyncVar、SyncList；在对象禁用或销毁时解除 C# 事件订阅。
3. SyncVar hook 处理字段变化；SyncList `OnChange` 处理集合增删改。首次显示仍从完整当前状态构建。
4. 每个 UI 更新保持单向：网络状态更新界面；界面请求操作时调用玩家 Command，由服务器验证后回写状态。
5. 其他玩家上方的白色标签按已同步的角色和层级状态显示，并配置为穿透平台遮挡；普通客户端只呈现服务器同步的权威结果。

## 观战显示

观战列表依据服务器当前存活状态筛选目标。镜头使用本地代理跟随被观察者位置，再把目标设置为相机跟随对象；避免把可旋转的本地相机控制直接绑定到远端网络 Transform。复活时恢复对本机玩家根节点的跟随。

## 现有例子与边界

[`CharacterIdSync.cs`](../../../../Assets/Core/Scripts/Networking/Sync/CharacterIdSync.cs) 展示 SyncVar hook 更新角色模型。新 HUD 可复用同样的“状态变化后刷新视图”思路。`ClientRpc` 只表达瞬时事件，晚加入状态由 SyncVar、SyncList 或对象当前状态提供。

API 回调签名与 Host 注意事项见 [Mirror 网络 API 总览](../Mirror网络API总览.md)。
