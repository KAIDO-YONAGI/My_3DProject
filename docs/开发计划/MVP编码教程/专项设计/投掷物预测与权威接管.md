# 投掷物预测与权威接管

## 什么时候使用

仅当玩家必须立即看到投掷反馈，且网络往返延迟造成可观察的操作迟滞时，才考虑本地视觉预测。MVP 的开局双人近距炸弹和 E 键挖掘不要求生成飞行投掷物，因此不把预测球纳入主线。

## 机制

预测表现与权威实体分开：拥有者先创建不带 NetworkIdentity 的本地视觉对象；服务器验证请求后创建 Mirror 网络实体。客户端以拥有者身份和请求编号关联本地表现与服务器实体，再平滑调整显示偏差并删除本地表现。

服务器实体始终决定碰撞、爆炸、平台变化和回合结果。预测对象不参与权威碰撞，不写 SyncVar 或平台格子。未收到确认时按明确超时结束本地表现；收到拒绝、回合切换或玩家离开时也清理关联状态。

## 接入当前工程的步骤

1. 先记录现有请求到服务器确认的时间，以及没有预测时玩家能否感知到迟滞。
2. 在现有玩家网络对象上建立请求入口，保留 Mirror 所有权检查；服务器复核玩家状态、道具库存和请求编号。
3. 服务器生成并 Spawn 权威投掷实体，使用 Mirror 同步其位姿和生命周期。
4. 本机预测物只负责可见模型；以请求编号关联确认结果，不在玩家 Prefab 或网络管理器之外创建第二套联机入口。
5. 对照预测与权威实体的位置差、确认时长、拒绝清理和回合切换清理。

## 与快照同步的区别

投掷物预测处理单个动作的即时视觉响应，不是批量状态压缩方案。只有多个持续运动对象的变换同步开销经实测成为问题时，才评估[独立快照同步内核](独立快照同步内核.md)。当前平台网络对象仍使用 Mirror 的 SyncList、SyncVar 和 NetworkTransform。
