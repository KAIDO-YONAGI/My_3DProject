# 集合、公共对象与消息

## 什么时候使用

平台具有格子拓扑和公共状态时，用 SyncList 与 SyncVar 描述对象当前状态；需要生成可独立运动的平台块时，用网络对象生命周期管理它。只有内建对象同步确实不满足批量协议需求时，才考虑 `NetworkMessage`。

## 平台状态划分

| 数据 | 表达方式 | 原因 |
| --- | --- | --- |
| 平台包含哪些格子 | `SyncList<int> Cells` | 表示可重建的平台拓扑，晚加入者需要完整当前集合 |
| 是否仍锚定、是否开洞、所在层、回合编号 | `SyncVar` | 数量有限的当前状态 |
| 平台位置与旋转 | `NetworkTransformReliable` | 连续变化的位姿使用变换同步 |
| 平台刚体、碰撞与断裂裁决 | 服务器 Unity 物理与玩法代码 | 客户端显示服务器结果，不重复裁决 |
| 一次性爆炸表现 | `ClientRpc` 或匹配的网络事件 | 表达单次事件，不替代持久平台状态 |

`SyncList<int>` 的 Mirror 96.11.2 回调是 `Action<Operation, int, T>`。使用时将 `Cells.OnChange` 绑定到三个参数的处理方法；先按现有集合建立网格，再处理后续增删改。所有集合修改由服务器执行。不要以本地 Mesh 是否更新作为服务器拓扑已更新的依据。

## 创建公共网络对象

1. `PlatformChunk` 实现为网络 Prefab，包含 `NetworkIdentity`、平台状态和服务器物理组件。
2. 将 Prefab 放到 `Assets/Core/Prefabs/Gameplay/PlatformChunk.prefab`，并加入当前 `NetworkManager` 使用的 Spawnable Prefabs 注册表。
3. 由现有玩法场景中的 `ArenaSceneBootstrap` 在服务器侧建立平台，设置格子、层数、回合和锚定状态后调用 `NetworkServer.Spawn`。
4. 平台从静态锚定块转为动态块时，服务器更新格子归属、状态和刚体行为；客户端通过同步集合、SyncVar 和变换更新显示。
5. 平台销毁时由服务器调用 `NetworkServer.Destroy`，使所有观察端销毁对应网络对象。

平台对象由服务器生成，但 Command 仍由玩家对象承接。这样保留 Mirror 默认玩家对象所有权校验，不需要把公共平台改成任何客户端拥有的对象。

## 何时使用 NetworkMessage

NetworkMessage 适合连接级请求或真正批量化的自定义传输，需要自行定义消息数据、注册接收处理器并维护两端协议。本 MVP 的玩家动作使用 Command，平台拓扑使用 SyncList，当前字段使用 SyncVar，位姿使用 NetworkTransform，因此没有必要为这些数据再包一层自定义消息。

批量平台快照及基线恢复是独立专题，入口见[独立快照同步内核](独立快照同步内核.md)。详细方法签名和 Join 行为见 [Mirror 网络 API 总览](../Mirror网络API总览.md)。
