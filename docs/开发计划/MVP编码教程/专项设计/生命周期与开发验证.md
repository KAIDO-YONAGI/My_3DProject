# 生命周期与开发验证

## 什么时候使用

增加网络玩法对象、场景生成流程或晚加入显示时，先沿用当前场景链与 `NetworkManager` 生命周期，再检查 Prefab 注册、服务器 Spawn 和客户端初始状态。不要增加平行入口或第二个管理器。

## 当前场景与网络入口

当前场景链为 `InitialScene → PersistentScene → MultiplayerSampleScene`。工程沿用现有 `NetworkManager.prefab`、KCP UDP 7777 和 `AutoStartClient`；服务器启动模式由现有配置控制，普通客户端自动连接 `127.0.0.1`。Mirror 与构建参数以 [Mirror KCP 配置](../../../../Y_MultipleAgentWorkflow/Project/Mirror_KCP_Config.md) 为准。

## 新增平台对象的生命周期

1. 在现有 `MultiplayerSampleScene` 放置 `ArenaSceneBootstrap`，仅服务器创建玩法网络对象。
2. 使用 `PlatformChunk` Prefab，并将它登记到当前 NetworkManager 的 Spawnable Prefabs。
3. Spawn 前填好 `Cells`、锚定状态、层数和回合编号。
4. 服务器通过 `NetworkServer.Spawn` 生成对象；客户端进入对象生命周期时从当前同步状态建立网格、碰撞与标签。
5. `NetworkTransformReliable` 在服务器模拟后向普通客户端发送位姿；客户端动态平台刚体保持 Kinematic。
6. 断裂、道具和回合清理均由服务器销毁网络对象或清除服务端玩法状态。

晚加入验证要覆盖已有锚定平台、已开洞平台和正在运动的动态块。SyncList 与 SyncVar 负责当前业务状态，NetworkTransform 负责持续位姿；初始化状态应在 Spawn 时可用，客户端不能依赖只发生过一次的 RPC 才能构建场景。

## 双客户端验收

- 使用现有入口启动一个服务器和两个客户端，确认两名玩家进入同一玩法场景。
- 检查客户端 E 请求由服务器校验，两个客户端看到相同格子拓扑、平台层级与道具结果。
- 检查平台断裂后的连通分组、动态刚体和位姿；客户端平台不运行重复的动态模拟。
- 第三层及以下按固定频率生成道具，且不超过每层库存上限。
- 玩家落入 Void 后转为观战，观战镜头通过本地代理跟随；最后存活者结束回合。
- 新客户端在回合中途加入时能建立当前平台状态并显示动态平台位姿。
- 编译通过，运行时无 Mirror 对象注册、缺失引用或序列化错误。

这组检查是教程运行验收口径。它与“当前工程已有组件”的事实分开记录；场景内出现配置或脚本并不等于以上玩法链都已实现。
