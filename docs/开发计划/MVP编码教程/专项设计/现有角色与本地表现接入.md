# 现有角色与本地表现接入

本篇把当前项目的网络对象、普通调用、角色切换和移动同步放在同一条链里。先读 [00 从当前项目开始](../00-从当前项目开始.md)，需要查接口时打开 [Mirror 网络 API 总览](../Mirror网络API总览.md)。

读一段代码时，先标出它属于客户端 A、服务器 S，还是观察者客户端 B。相同脚本在多个进程里各有实例；静态 `Instance` 也各自保存本进程的管理器。

## 1. 先区分网络根和本地表现

当前 [NetworkPlayer.prefab](../../../../Assets/Core/Prefabs/NetworkPlayer.prefab) 保存玩家网络身份与运动入口：

```text
NetworkPlayer
  NetworkIdentity              运行身份、连接归属
  CharacterIdSync              角色请求与确认编号
  NetworkTransformReliable     网络根位置和旋转
  CharacterMotionSync          动画需要的运动状态
  PlayerCharacterController    输入、运动与动画组织
  CharacterController          移动碰撞
  角色视觉实例                  客户端按确认编号创建
    CharacterVisual、模型、Animator
    Camera、ThirdPersonCamera、AudioListener
```

服务器 S 和客户端 A、B 中的同一个玩家具有相同 `netId`，分别占用各自进程的内存。Mirror 通过身份和消息对应这些副本。

角色视觉实例由本地表现服务通过普通 `Instantiate` 创建，跟随网络根运动。网络同步的是角色编号，客户端根据编号选择自己资源表中的 Prefab，再绑定 Animator 和相机。

| 内容 | 放在哪里 | 原因 |
| --- | --- | --- |
| 需要多人共同识别的玩家或道具 | 带 `NetworkIdentity` 的独立网络根 | 生命周期与消息需要定位实体 |
| 同步字段与远程调用 | 根上的 `NetworkBehaviour` | Mirror 为它提供网络回调、状态与 RPC |
| UI、相机、模型装配 | 普通 `MonoBehaviour` | 工作内容是本进程内的调用与显示 |
| 输入数据、运动算法、图算法 | 按现有职责划分的普通 C# 类型 | 输入输出明确，便于复用和验证 |

`PlayerCharacterController` 是 `MonoBehaviour`，它读取同根 `NetworkIdentity` 判断本地玩家。挂在网络对象下面的普通组件仍通过显式网络接口传递数据。

## 2. 一次角色切换跨网络的位置

先把功能分成四项：

| 内容 | 具体含义 | 当前入口 |
| --- | --- | --- |
| 请求 | A 希望把自己的角色切到 1 | `CharacterSelectButton`、`SetLocalCharacter` |
| 决定 | S 校验服务器的角色配置 | `CommandSetCharacter` |
| 状态 | S 确认角色编号为 1 | `characterId` |
| 表现 | A、B 为这个玩家装配角色 1 | `ApplyCharacter` |

### 按钮到请求是普通调用

[CharacterSelectButton.cs](../../../../Assets/Core/Scripts/UI/CharacterSelectButton.cs) 点击时通过 `NetworkClient.localPlayer` 查找当前本地玩家的 `CharacterIdSync`。核心关系是：

```csharp
NetworkIdentity localPlayer = NetworkClient.localPlayer;
if (localPlayer != null
    && localPlayer.TryGetComponent<CharacterIdSync>(out var character))
{
    character.SetLocalCharacter(characterId);
}
```

这段成员调用在 A 内部执行。按钮用 `OnEnable` 订阅点击、`OnDisable` 解绑，在点击时取得当前玩家实例。

管理器还提供统一入口 `NetworkCharacterManager.RequestCharacter`：联机时交给本地玩家的 `SetLocalCharacter`，离线时替换场景单机角色。上面的代码展示直接寻找联机玩家的方式。

### Command 把请求交给服务器

打开 [CharacterIdSync.cs](../../../../Assets/Core/Scripts/Networking/Sync/CharacterIdSync.cs)，依次看：

1. `SetLocalCharacter` 检查 `isLocalPlayer`，用本机管理器预检编号。
2. 它调用 `CommandSetCharacter(requestedCharacterId)`。Mirror 生成的发送入口把编号写入网络消息。
3. S 按网络根身份定位组件，检查发送连接的归属，再执行 Command 方法体。
4. 方法体读取 **S 自己的** `NetworkCharacterManager.Instance`，用服务器配置校验编号。
5. 校验通过后把值写入 `characterId`。

当前 `IsValidCharacterId` 检查 `characters` 存在、编号非负且在数组范围内、对应完整角色 Prefab 有效。客户端预检用于交互反馈，服务器检查决定接受的状态。

```csharp
[SyncVar(hook = nameof(OnCharacterIdChanged))]
private int characterId;
```

SyncVar 将当前编号下行。它表示“现在选哪个角色”；每次点击的声音或拒绝提示可分别采用 ClientRpc、TargetRpc，写法见 [状态与界面绑定](状态与界面绑定.md)。

### 接收状态后继续普通调用

`OnCharacterIdChanged` 调用本地 `ApplyCharacter`，随后执行：

```csharp
NetworkCharacterManager.Instance?.ApplyCharacter(this, characterId);
```

Mirror 到这里已经交付了值。A、B 各自的普通表现服务把编号变成自己的 Unity 对象。

完整链路是：

```text
A 的按钮 → A 的 SetLocalCharacter
  → Command 发送编号
S 的 CommandSetCharacter → 校验 → 写 characterId
  → SyncVar 下行当前编号
A、B 的 hook → 本地 ApplyCharacter → 本地模型和相机
```

## 3. 初始角色与后续切换怎样衔接

| 回调 | 当前代码做什么 | 为什么需要它 |
| --- | --- | --- |
| `OnStartServer` | 写入服务器配置的非负默认编号 | 为初始 Spawn 提供服务器初值 |
| `OnStartClient` | 使用已接收编号调用 `ApplyCharacter` | 初值与字段默认值相同时也建立表现 |
| `OnStartLocalPlayer` | 上报本机默认编号，并刷新本地表现 | 将本机选择交给服务器校验，配置本地相机身份 |
| SyncVar hook | 按新的确认编号刷新表现 | 处理运行中的角色变化 |
| `OnStopClient` | `RemoveCharacter` | 回收视觉实例、动画和输入引用 |

本机默认编号通过 `ReportLocalDefaultCharacter → CommandSetCharacter` 上报。服务器按自己的配置接受或保留当前值，客户端依据确认状态装配。

启动回调和 hook 共同调用相同刷新入口。表现服务按玩家、编号、来源 Prefab 缓存实例；相同角色可以复用，身份变化时刷新相机配置。这让重复刷新具有相同结果。

## 4. 一个完整 Prefab 怎样服务本地和远程玩家

打开 [NetworkCharacterManager.cs](../../../../Assets/Core/Scripts/Networking/CharacterPresentation/NetworkCharacterManager.cs) 的 `characters` 与 `TryGetCharacterPrefab`，再看 [CharacterPresentationService.cs](../../../../Assets/Core/Scripts/Networking/CharacterPresentation/CharacterPresentationService.cs)：

1. 按编号从共用的 `characters` 数组取完整角色 Prefab。
2. 校验 `CharacterVisual` 中的模型、动画与相机引用。
3. 在停用层级中创建实例，挂到网络玩家根，对齐局部位置、旋转和缩放。
4. 解除旧实例的输入与动画引用，清理旧实例。
5. 停用视觉实例的单机运动控制器与移动碰撞组件，运动继续由网络根承担。
6. 本地玩家启用该实例的相机、相机控制器和监听器；远程玩家保留视觉与动画。
7. 为网络根绑定 Animator；为本地输入绑定配置的 Camera 参考空间。
8. 保存表现缓存并启用实例。

资源目录是 [Characters](../../../../Assets/Core/Prefabs/Characters)。服务器和客户端对编号使用一致含义，例如编号 1 均表示同一角色条目。每个客户端再依据自己看到的本地身份启停组件。

`CharacterVisual.InputCamera` 是本地引用。网络上传 `characterId` 足以让接收端从资源配置重建这些引用。

## 5. 当前移动与动画是两条数据链

[PlayerCharacterController.cs](../../../../Assets/Core/Scripts/Character/Control/PlayerCharacterController.cs) 组织拥有者输入和运动：

```text
A 的 CharacterInputReader → CharacterInput
  → PlayerCharacterController → CharacterMotor.Tick
  → CharacterController.Move → 网络根位置与旋转
  → A 本地动画
```

专用服务器上的网络玩家跳过本地运动；已连接客户端只为本地玩家读取输入。`inputSpace` 绑定本地相机的 Transform，运动层用其水平朝向将操作转换成世界方向。

### 位置由 NetworkTransformReliable 传递

`NetworkPlayer` 的组件采用 `ClientToServer`：

```text
A 计算自己的变换 → 上传快照
  → S 接收、缓冲并插值更新网络根
  → S 向其他观察客户端转发
  → B 缓冲并插值显示
```

A 持续使用自己的移动结果。S 和 B 上显示的位置来自接收的变换数据。

### 动画读取最近接受的运动状态

[CharacterMotionSync.cs](../../../../Assets/Core/Scripts/Networking/Sync/CharacterMotionSync.cs) 另行采用 `ClientToServer`、可靠同步和 `0.1` 秒间隔。拥有者 `LateUpdate` 调用 `SetDirty`，`OnSerialize` 按顺序写：

| 字段 | 用途 |
| --- | --- |
| 状态字节 | Idle、Run、Sprint、Rising、Falling |
| `LocalDirection` | 角色局部二维方向 |
| `LocomotionWeight01` | 0 至 1 的运动权重 |

S 的 `OnDeserialize` 校验状态范围、方向长度和权重，保存有效数据供转发。B 将有效数据交给 `ReceiveRemoteMotion`，控制器 `LateUpdate` 应用当前动画状态。

**位置使用变换快照插值；动画使用最近接受的三字段状态。** 阅读时分别跟踪这两条链，便于定位“位置正常、动画异常”等现象。

### 与 MVP 的对应关系

| 职责 | 当前项目 | MVP 主线 |
| --- | --- | --- |
| 读取操作 | `CharacterInputReader` | `MvpView.SendInput` |
| 计算角色移动 | 拥有者 `CharacterMotor` | 服务器 `MvpWorld.MovePlayer` |
| 传递运动结果 | `NetworkTransformReliable` | `Wire → MvpMotion` |
| 平滑显示 | Mirror 变换插值 | `Replica.Render → DrawWorld` |
| 绑定模型与相机 | 角色表现服务 | `MvpView` 的独立显示根与固定镜头 |

正式接入时按 [00 导读的接口顺序](../00-从当前项目开始.md#7-怎样把学到的东西接回正式玩法) 分别安排输入、运动写入者、状态和表现。

## 6. 引用与父子关系怎样跨网络重建

角色编号、Mirror `netId`、MVP 业务 `Id` 各自表示资源、运行网络对象和自写世界对象。查找网络副本使用：

```csharp
bool found = NetworkClient.spawned.TryGetValue(targetNetId, out NetworkIdentity target);
```

服务器使用 `NetworkServer.spawned`。客户端按自己的已生成对象表查找；目标可见范围、生成时机和销毁都会影响结果。

需要等待目标时保存完整身份，目标出现后重新解析；目标变化、停止或界面解绑时解除引用。跨回合与池复用的对象同时验证业务回合和代次。

持有物品可以同步 `holderNetId + 挂点编号`，客户端找到持有者的本地模型挂点，再挂接物品表现。挂点编号属于共享数据，具体 Transform 属于本地装配。

## 7. 按这条链逐段排查

用 S、A、B 三个独立进程观察：A 的按钮是否找到 A 的玩家，Command 是否进入 S，S 是否接受编号，A、B 是否收到相同确认值，表现服务是否按该值取到 Prefab，相机是否只对本地玩家启用。

角色切换同时观察网络根 `netId` 保持稳定、模型按编号替换；断开时观察视觉缓存和输入动画引用清理。移动按输入、拥有者变换、服务器变换、远程插值、动画状态依次追踪。
