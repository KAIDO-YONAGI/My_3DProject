# 现有角色与本地表现接入

## 什么时候使用

当玩法需要在现有联机角色上加入输入、支撑平台、HUD 或观战行为时，沿用当前玩家 Prefab 和移动链。不要复制角色 Prefab、替换入口场景或另造 NetworkManager。

## 当前工程链路

| 当前职责 | 工程位置 |
| --- | --- |
| 网络玩家 Prefab | `Assets/Core/Prefabs/NetworkPlayer.prefab` |
| 本机角色移动 | `Assets/Core/Scripts/Character/Movement/CharacterMotor.cs` |
| 玩家位姿同步 | Prefab 上的 `NetworkTransformReliable`，方向为 `ClientToServer` |
| 动画状态 | [`CharacterMotionSync.cs`](../../../../Assets/Core/Scripts/Networking/Sync/CharacterMotionSync.cs) |
| 角色选择和模型装配 | [`CharacterIdSync.cs`](../../../../Assets/Core/Scripts/Networking/Sync/CharacterIdSync.cs) |
| 网络音频 | [`NetworkAudioPlayer.cs`](../../../../Assets/Core/Scripts/Networking/Sync/NetworkAudioPlayer.cs) |
| 相机 | 现有 `ThirdPersonCamera` 与角色目标引用 |

这条玩家移动链由本机拥有者的 `CharacterMotor` 驱动，不能据此声称玩家移动由服务器权威模拟。MVP 将平台破坏、平台动态物理、道具和胜负判定放在服务器，二者的权威边界分别描述。

## 怎样接入玩法组件

1. 在现有 `NetworkPlayer` 上追加 `ArenaPlayerActions`、`PlatformPassenger` 和 `ArenaPlayerPresentation`。
2. 把新增脚本放在 `Assets/Core/Scripts/Gameplay/Mvp`，命名空间使用 `Core.Scripts.Gameplay.Mvp`。
3. 只让本机玩家处理 E 键、HUD 输入与相机控制；玩家意图通过其拥有的网络对象上的 Command 上行。
4. 在现有 `CharacterMotor` 的同一段 `Move` 位移流程中纳入动态支撑的位姿增量，并在跳离时继承接触点速度。保留原有输入、重力、碰撞和移动同步。
5. 复用现有动画同步和音频组件；只为新增状态或表现增加必要绑定。
6. 普通客户端把网络玩家作为观战目标时，确认目标设置不会改写远端玩家旋转。

## 相机与观战目标

当前 `ThirdPersonCamera.SetTarget` 在 `rotateTarget = true` 时会把相机旋转写到目标 Transform。直接将远端网络玩家设为目标，会让观战相机反向修改远端对象的本地表现。

观战应由本机创建的代理 Transform 跟随目标玩家坐标，相机只跟随该本地代理。玩家回到可控状态时，相机目标恢复为本机角色根节点。代理不需要 NetworkIdentity，也不参与网络状态同步。

## 核对方式

在现有玩法场景双客户端运行，确认只有拥有者响应输入；远端角色按已有位姿与动画显示；平台位姿由服务器同步；观战相机不改变远端玩家旋转；恢复控制后相机目标回到本机角色。具体 API 见 [Mirror 网络 API 总览](../Mirror网络API总览.md)。
