# 破坏竞技场 MVP 编码教程

这套教程带你编写一个独立的双人竞技场示例：角色移动、跳跃、投掷炸弹，爆炸切断平台连接，失去支撑的块组成运动碎片，碎片参与碰撞和连锁爆炸，服务器结算生命与回合，客户端显示同一份世界状态。

学习过程围绕一个问题展开：**服务器上的平台炸裂以后，另一台电脑怎样知道哪些块属于哪块碎片，并把它们显示在正确的时间和位置？** 回答这个问题需要先定义数据，再计算结构，再编码与恢复状态，最后接入网络、物理和画面。章节按这条依赖链组织。

## 从哪里开始

阅读前需要能看懂 C# 的类、结构体、数组、字典和方法调用，能在 Unity 中创建 GameObject、添加组件、保存 Prefab 和场景。首次遇到网络和结构算法时，跟着各章的具体例子理解即可。

学习使用两种环境：

| 环境 | 做什么 | 为什么在这里做 |
| --- | --- | --- |
| 普通 .NET 控制台 | 编写和测试第 01 至 04 章的状态、图、协议、快照 | 输入和输出都是普通数据，可以直接断言结果 |
| 当前 Unity 工程中的独立目录与场景 | 编写第 05 至 09 章，按第 10 章搭建竞技场 | 连接、碰撞、物理、输入设备和渲染需要 Unity 运行环境 |

核心测试使用 PowerShell 7 和 .NET SDK，执行步骤见 [第 11 章](11-自动验证.md)。Unity 环境使用本工程的 `2022.3.62f3c1`、Mirror、Input System 和 Universal Render Pipeline。

## 按三个阶段编写

### 第一阶段：把数据和算法跑通

依次阅读第 01、02、03、04 章，编写四个 `Core` 文件，然后跳到第 11 章运行控制台测试。

这一阶段的观察对象是数值。例如：同一个输入序号第二次提交被拒绝，切断全部连接得到 24 个分量，Tick 10 的位置为 0、Tick 20 的位置为 10 时，Tick 15 采样得到 5。先理解这些结果，再接入引擎。

### 第二阶段：把整条服务器和客户端链路接通

依次阅读第 05 至 09 章，编写全部 `Unity` 文件，再按第 10 章配置 Prefab 和场景。

这一组文件共同组成运行程序。`MvpNetwork` 调用 `MvpWorld` 和 `MvpView`，`MvpWorld` 的三个 `partial` 文件共同定义一个类。将整组文件准备齐全后导入 Unity，集中检查 Console 的 C# 编译与 Mirror Weaver 结果。Weaver 为自定义消息和 `SyncVar` 生成网络读写代码。

### 第三阶段：用独立进程检查实际行为

按第 12 章先运行一个服务器和两个客户端，再检查破坏、中途加入、动态支撑和回合重开。用服务器状态确认玩法结果，用客户端画面确认显示，用 Profiler 和传输统计确认耗时与带宽。

## 完整代码放在哪里

每个标记为 `csharp file=...` 的代码块对应一个完整文件。标记中的路径相对于学习目录；正文里的短小例子用于跟踪计算，完整文件以这个标记为准。

Unity 文件布局如下：

```text
Assets/MvpTutorial/

│  ├─ Structure.cs
│  ├─ Wire.cs
│  └─ Replica.cs
├─ Unity/
│  ├─ MvpNetwork.cs
│  ├─ MvpBody.cs
│  ├─ MvpWorld.cs
│  ├─ MvpWorld.Players.cs
```

`Tests/Program.cs` 放在第 11 章创建的独立控制台工程中，与四个核心文件一起编译。Unity 工程只导入 `Core` 与 `Unity` 两组源文件。

每章先讲本章要解决的问题，再说明编写顺序，给出带中文注释的完整代码，最后带你跟踪一次执行和检查结果。阅读代码时先找输入，再找发生状态变化的位置，最后找输出或调用方；这样可以把字段、分支和运行现象连起来。

## 用一次爆炸理解整体链路

假设客户端按下 E，服务器在 Tick 100 接受投掷：

1. `MvpView.SendInput` 把投掷编码成 `Buttons` 的第 2 位，随输入序号发送。
2. `MvpNetwork` 从发送连接的 `identity` 找到服务器玩家，调用 `ReceiveInput`。
3. `InputGate` 校验回合、序号、数值与频率；`MovePlayer` 消费投掷位，`ThrowBomb` 按服务器角色姿态生成炸弹，引信到期 Tick 为 145。
4. Tick 145 时，`FixedUpdate` 把到期炸弹放入队列，`Explode` 选出爆炸范围内的连接，`Structure.Cut` 计算断边后的连通分量。
5. `Fracture` 保存各块当前世界位置，再建立碎片根和局部坐标。服务器增长 `Version`，发布携带块归属的完整基线。
6. 客户端 `Replica` 保存这份基线。播放时间达到相应 Tick 时，`MvpView` 按新归属重建形状，再按姿态快照移动显示根；爆炸事件也按这个播放时间出现。

Mirror 负责把连接、网络对象和消息送达；结构核心决定分组，协议核心决定字节，快照核心决定采样，服务器玩法决定伤害与回合。这些职责在章节之间通过明确的数据连接。

## 经常需要区分的词

| 名称 | 在教程里的含义 | 具体例子 |
| --- | --- | --- |
| 块 | 平台中的一个图节点，编号为 `Node` | 第 9 块随所属碎片运动 |
| 碎片 | 一组脱落的块，共享一个网络根与刚体 | 3 个块属于 `Id=7` 的碎片 |
| 业务编号 `Id` | 示例自己的对象编号 | 输入和快照使用这个编号 |
| Mirror 网络身份 | Mirror 管理网络对象生命周期的身份 | 连接的 `identity` 指向自己的玩家 |
| 回合 `Round` | 隔离一次完整玩法周期 | Round 2 的接收器丢弃 Round 1 的迟到包 |
| 代次 `Generation` | 区分同编号的不同对象身份 | 姿态缓冲以编号和代次共同索引 |
| 拓扑版本 `Version` | 标识块归属及对象集合的变化 | 炸出新碎片时增长 |
| 完整基线 `Baseline` | 指定完整状态采样，供恢复和差量解码 | 同一拓扑可有多份周期基线 |
| Tick | 服务器模拟步的编号 | Tick 145 到期的炸弹在该步处理 |
| 播放时间 | 客户端用来采样状态的时间，可有小数 | 在 Tick 144 和 146 之间插值 |

## 示例规则与观察尺度

服务器每秒模拟 30 次，每步约 33.3 毫秒；运动每两个 Tick 发送一次，即每秒 15 次。客户端播放时钟以落后最新状态三个 Tick 为目标，约为 100 毫秒，并通过调速适应包到达的抖动。具体启动、追赶和停留行为见第 04 章。

平台由 8×3 共 24 个块、37 条连接组成，两端四个角部节点是支撑。角色初始生命为 100，移动速度为每秒 5 米，跳跃入口的竖直速度为每秒 8 米。投掷冷却是 15 Tick，即半秒；引信是 45 Tick，即 1.5 秒；爆炸半径是 3.5 米。

至少两名玩家时开始计时。剩余人数达到结算条件，或回合计时达到 900 Tick，即 30 秒时结算；90 Tick，即三秒后重开。分数跨回合保留。对象编号在服务器会话中递增，回合重开保留玩家对象并清理临时物体。

普通客户端使用服务器状态插值显示角色与碎片。Host 同时拥有服务器和客户端，画面直接显示服务器物理对象。第 12 章分别检查这两种运行方式。
