# 在当前项目里做破碎平台 MVP

这套教程直接扩展你正在做的游戏。你从 `InitialScene` 启动，用现有的角色移动、跳跃、转相机，在 `MultiplayerSampleScene` 中加入多层平台，再做破坏、掉落、道具和胜负。

第一件能看见的成果是：**现有角色站到你刚生成的平台上。** 随后给同一块平台接入网络，让两名玩家看见同一次破坏。算法和同步原理跟在这些操作后面解释。

## 从这里动手

1. 打开 [00 从当前项目开始](00-从当前项目开始.md)，确认当前场景、玩家和连接入口。
2. 做 [01 在当前场景生成方格平台](01-数据与职责.md)，在现有玩法场景中生成方格平台。
3. 按章节顺序继续。每章都有文件路径、Unity 操作、代码和画面检查。

教程中的“创建脚本”和“添加组件”是你要执行的操作。源码中的当前接入点用现有路径指出；新玩法脚本统一放到 `Assets/Core/Scripts/Gameplay/Mvp/`。

每个新类先给文件骨架，再按小节补方法。“加到类中”表示放在这个类的结束大括号前，已有内容保留；“替换”会指出原来的具体语句。关键判断和状态变化旁有中文注释，代码下面用格子编号、时间或位置举例解释。每章最后回到 Unity 检查组件、对象或画面。同一个类的方法全部补齐后，再处理它的编译结果。

| 沿用的东西 | 继续负责什么 |
| --- | --- |
| `InitialScene`、`PersistentScene`、`MultiplayerSampleScene` | 启动、常驻系统和玩法场地 |
| `NetworkManager.prefab`、KCP、自动连接 | 建立连接、生成玩家，沿用 UDP `7777` |
| `NetworkPlayer.prefab` | 每个玩家的网络身份和控制入口 |
| `PlayerCharacterController`、`CharacterMotor` | 当前窗口的按键、移动和跳跃 |
| 玩家上的 `NetworkTransformReliable` | 玩家位置从拥有者客户端传给服务器，再转给其他人 |
| 角色装配、动画、第三人称相机、音频同步 | 继续表现现有角色 |

新增部分只承担新玩法：平台格子、断裂分组、平台刚体、动态支撑、道具和回合。

## 先看清谁决定什么

例如 A 按 E 攻击 B 脚下的平台：

```text
A 的窗口读取 E 和瞄准方向
  → A 自己的 ArenaPlayerActions 发送 Command
  → 服务器检查 A 是否存活、是否有道具、攻击是否命中平台
  → 服务器删除范围内的格子，再把剩余格子分组
  → Mirror 把结构和碎片对象发给所有客户端
  → 服务器计算碎片运动，客户端显示同步来的运动
```

与此同时，A 按方向键移动仍走现有的 `CharacterMotor`。**这条主线的边界是“玩家拥有者计算移动，服务器裁定平台和对局”。** 服务器根据收到的玩家位置判断接近、拾取和出界，因此位置可信度也受现有移动方案影响。第 05、07 章会解释这个取舍；简历中的“服务器权威”要具体指平台和规则。

先接通可玩的回合，再用测量结果决定是否需要移动预测、校正或批量碎片压缩。这样每项算法都能对应到一个实际问题。
