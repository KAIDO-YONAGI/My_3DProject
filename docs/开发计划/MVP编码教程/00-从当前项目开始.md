# 00 从当前项目开始

你要做的是：让当前游戏中的角色站上可破坏的平台，并且让同一局中的玩家看到一致的破坏结果。

先打开现有工程和场景，认清需要接入的位置。本章只定位；第 01 章开始实际创建平台。

## 1. 在 Unity 中找到这三个资源

在 Project 窗口的搜索框依次查找：

| 资源 | 完整路径 | 你要确认什么 |
| --- | --- | --- |
| 初始场景 | `Assets/Core/Scenes/InitialScene.unity` | 双击后，从这里启动游戏 |
| 玩法场景 | `Assets/Core/Scenes/TestScenes/MultiplayerSampleScene.unity` | 平台、层级原点和玩法启动组件放在这里 |
| 网络玩家 | `Assets/Core/Prefabs/NetworkPlayer.prefab` | 给根物体追加玩法组件，沿用现有控制器和模型 |

“根物体”是 Prefab 最外层那一行 `NetworkPlayer`。展开后能看到的模型、骨骼、相机属于它的子物体。当前角色移动的是网络根，角色装配服务负责在根下面放外观。

再找到 `Assets/Core/Prefabs/NetworkManager.prefab`，打开 Inspector。它负责连接和自动创建玩家。平台 Prefab 要注册到它的 Spawnable Prefabs 列表；玩家的 Player Prefab 继续指向当前 `NetworkPlayer.prefab`。

## 2. 先用当前方式启动一次

1. 打开 `InitialScene`。
2. 按现有方式启动专用服务器。
3. 在 Editor 按 Play，等待自动连接。
4. 在 Hierarchy 展开 `PersistentScene` 和 `MultiplayerSampleScene`，找到运行时的 `NetworkPlayer`。
5. 用当前移动和跳跃按键操作，转动相机，确认你能控制自己的角色。
6. 结束 Play，再编辑场景和 Prefab。

连接与构建操作查 [第 10 章](10-场景与构建.md) 和 [当前 Mirror 配置](../../../Y_MultipleAgentWorkflow/Project/Mirror_KCP_Config.md)。普通客户端当前自动连接本机地址；没有正在监听的服务器时，客户端会重试连接。

Hierarchy 中同时出现多个场景，是当前工程的叠加加载方式：

```text
InitialScene
  → InitialLoad 加载 PersistentScene
      → SceneChanger 加载 MultiplayerSampleScene
      → 常驻的网络管理器负责连接和玩家生成
```

`SceneChanger` 加载场景，`AutoStartClient` 尝试连接。两者分别执行。第 06 章把平台启动组件放在玩法场景中，让它等服务器就绪后再生成平台。

## 3. 你按一次方向键，现有代码怎样工作

打开 [PlayerCharacterController.cs](../../../Assets/Core/Scripts/Character/Control/PlayerCharacterController.cs)，找到 `Update`，读这几句：

```csharp
CharacterInput input = ReadInput();
CurrentMotion = motor.Tick(input, inputSpace, Time.deltaTime);
animationDriver?.Apply(CurrentMotion);
```

它们依次表示：

1. 读当前窗口的移动、奔跑和跳跃操作。
2. 让 `CharacterMotor` 算这一帧怎么移动，并调用 `CharacterController.Move` 完成碰撞移动。
3. 把结果交给当前角色动画。

假设角色站在 `(0, 10, 0)`，按键使这一帧向右移动 `0.1` 米。碰撞允许通过时，角色根到达 `(0.1, 10, 0)`。玩家上的 `NetworkTransformReliable` 再把这个位置交给服务器，服务器转给其他客户端。另一个窗口便看到你往右移动。

这里“本地玩家”指这个窗口拥有的玩家。A 的窗口也看得见 B，但只有 A 的输入控制 A。现有控制器里的身份检查和 Mirror 的所有权判断负责分清这件事。

教程在这条移动链上增加“脚下平台带来的位移”。第 07 章会精确指出要插入的几行，原有方向键、跳跃、动画和相机仍从这些入口工作。

## 4. 平台破坏要接在哪

假设你已经走在平台上，按 E 打坏一部分格子。新增代码分成四件事：

| 新增脚本 | 放在哪里 | 做什么 |
| --- | --- | --- |
| `ArenaPlayerActions` | 现有 `NetworkPlayer` 根 | 本地读取使用道具操作，向服务器提出请求 |
| `PlatformChunk` | 新的平台 Prefab 根 | 保存这片平台包含哪些格子；服务器处理破坏和刚体运动 |
| `ArenaSceneBootstrap` | 现有玩法场景的空物体 | 服务器生成各层平台 |
| `ArenaMatch` | 新的对局网络 Prefab | 决定炸弹携带者、道具、淘汰和胜负 |

你可以把一次请求理解为“我朝这个方向使用道具”。服务器自己检查玩家位置、道具库存和命中结果，再修改平台。

例如格子编号 `39、40、41` 连在一起。服务器删掉中间的 `40` 后，左右两块可能变成两片。它把这两片分别创建成网络平台对象。客户端收到后重建形状，再显示服务器发来的位置。第 02、03 章会用具体格子跟踪整个过程。

## 5. 为什么玩家和平台采用不同的同步方式

当前玩家运动已经有输入、手感、动画、相机和同步入口。MVP 先沿用这部分，把新增玩法接进去。

平台由服务器计算刚体运动。客户端上的平台刚体设为 Kinematic，平台根的位置由服务器同步。这样两台客户端接到同一次爆炸后，都显示服务器决定的碎片；各机帧率和物理计算误差不会分别决定平台最终掉到哪里。

| 对象或决定 | 谁产生结果 | 谁收到结果 |
| --- | --- | --- |
| 玩家移动 | 该玩家的客户端 | 服务器和其他客户端 |
| 平台有哪些格子 | 服务器 | 所有观察该平台的客户端 |
| 平台刚体运动 | 服务器 | 客户端插值显示 |
| 拾取、炸弹触发、淘汰和胜负 | 服务器 | 客户端状态与界面 |
| 相机、按键反馈、标签 | 本机 | 当前窗口 |

所以你在简历和面试里应当说清：“平台物理和对局规则由服务器裁定，玩家移动复用现有拥有者同步方案。”服务器判断拾取和出界时使用收到的玩家位置，完整的位置作弊防护需要额外的移动校验或服务器运动方案。这项取舍对应的是当前实现边界。

## 6. 现在开始建什么

结束 Play 后，在 Project 窗口中：

1. 在 `Assets/Core/Scripts/` 下创建 `Gameplay` 文件夹，再创建 `Mvp` 子文件夹。
2. 在 `Assets/Core/Prefabs/` 下创建 `Gameplay` 文件夹。
3. 双击打开 `MultiplayerSampleScene`，开始第 01 章的平台操作。
4. 编辑完成后保存该玩法场景，运行时再回到 `InitialScene` 按 Play。

所有新增脚本使用 `Core.Scripts.Gameplay.Mvp` 命名空间。新平台和道具的 Prefab 放在 `Assets/Core/Prefabs/Gameplay/`。脚本命名空间只是让 C# 能明确找到类型；Unity 中添加组件时搜索类名即可。
