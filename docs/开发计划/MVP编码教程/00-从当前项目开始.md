# 00 从当前项目开始

这篇先把你工程里已经在运行的东西，与教程中的类对应起来。读完以后，你需要能说清三个问题：现在是谁计算角色移动，教程把计算放在哪里，以及平台炸开以后需要多同步哪些数据。

## 1. 先认清两条运行路线

**当前游戏从 `InitialScene` 进入；教程练习从独立的 `MvpArena` 进入。** 两条路线使用同一个 Unity 工程里的 Mirror、Input System 和 URP，各自组装自己的网络管理器与玩法对象。

| 要找的东西 | 当前游戏 | 教程练习 |
| --- | --- | --- |
| 场景入口 | `Assets/Core/Scenes/InitialScene.unity` | 第 10 章创建 `Assets/MvpTutorial/MvpArena.unity` |
| 常驻系统与玩法场景 | `PersistentScene` 加载 `MultiplayerSampleScene` | 一个竞技场场景容纳教程入口、世界和显示器 |
| 网络管理器 | `Assets/Core/Prefabs/NetworkManager.prefab` | 第 05 章的 `MvpNetwork` |
| 网络玩家模板 | `Assets/Core/Prefabs/NetworkPlayer.prefab` | 第 10 章创建的 `MvpBody.prefab` |
| 运动计算 | 本地拥有者的 `CharacterMotor.Tick` | 服务器的 `MvpWorld.MovePlayer` |
| 位置同步 | `NetworkTransformReliable`，方向为 `ClientToServer` | `WorldState` → `Wire` → `Replica` → `MvpView` |
| 角色外观 | `NetworkCharacterManager` 装配角色 Prefab | 代码生成胶囊、方块、球体 |
| 本机练习端口 | 当前 KCP 配置为 UDP `7777` | 第 10 章将教程 KCP Port 设为 `7787` |
| 构建目录 | `D:/Unity/Releases/3D_MultiplayerGame/` | `D:/Unity/Releases/MvpTutorial/Windows/` |

表里的 `Mvp` 类型是各章完整代码块让你创建的教学类型。找现有实现时打开 `Assets/Core/`；编写教学练习时使用 `Assets/MvpTutorial/`。这样阅读路径与操作路径都有明确落点。

## 2. 当前项目按下 Play 后发生什么

从 [InitialScene](../../../Assets/Core/Scenes/InitialScene.unity) 打开场景，按下面的阅读顺序找入口：

1. [InitialLoad.cs](../../../Assets/Core/Scripts/GamePlayFrameWork/Scripts/Scene/InitialLoad.cs) 的 `Awake` 启动加载协程，将配置的常驻场景叠加加载进来。
2. [PersistentScene](../../../Assets/Core/Scenes/PersistentScene.unity) 承载网络管理器和常驻服务。
3. [SceneChanger.cs](../../../Assets/Core/Scripts/GamePlayFrameWork/Scripts/Scene/SceneChanger.cs) 按配置叠加加载玩法场景 `MultiplayerSampleScene`。
4. [AutoStartClient.cs](../../../Assets/Core/Scripts/Networking/Connection/AutoStartClient.cs) 在客户端发起连接，并按间隔重试。服务器启动与构建配置查阅 [Mirror 与 KCP 配置](../../../Y_MultipleAgentWorkflow/Project/Mirror_KCP_Config.md)。
5. 客户端连接并准备好后，Mirror 根据 [NetworkManager.prefab](../../../Assets/Core/Prefabs/NetworkManager.prefab) 的 Player Prefab 创建 [NetworkPlayer.prefab](../../../Assets/Core/Prefabs/NetworkPlayer.prefab)。

这里的“叠加加载”表示新场景加入当前运行环境，常驻场景继续保留。`SceneChanger` 的场景加载与 `AutoStartClient` 的连接检查分别推进，自动连接每隔三秒检查重试，代码里没有等待玩法场景加载完成的条件。上面的编号帮助你找代码，运行时要分别观察这两条流程。

教程第 10 章直接打开 `MvpArena`，由界面的 Server、Client、Host 按钮启动对应身份。

先在 Hierarchy 找到网络玩家根，再展开角色模型。根负责网络身份和角色控制，模型负责外观、骨骼和相机。读源码时一直区分这两层。

## 3. 用一次按 D 看懂移动链

### 当前项目：本地算出位置，再同步结果

先打开 [PlayerCharacterController.cs](../../../Assets/Core/Scripts/Character/Control/PlayerCharacterController.cs)，只读 `Update`：

```text
本地玩家按 D
  → ReadInput：读取方向
  → CharacterMotor.Tick：计算运动并移动 CharacterController
  → CurrentMotion：保存本帧运动结果
  → CharacterAnimator.Apply：更新本地动画

同一个网络根
  → NetworkTransformReliable：把位置、旋转上行给服务器
  → 服务器转发
  → 其他客户端插值显示这个玩家
```

“本地玩家”就是当前窗口拥有的玩家。两个客户端都看见 A 和 B，但 A 窗口只读取 A 的按键。`Update` 开头的身份判断就是为了确定谁采集输入、谁执行移动。

远程玩家的位置由 `NetworkTransformReliable` 更新；[CharacterMotionSync.cs](../../../Assets/Core/Scripts/Networking/Sync/CharacterMotionSync.cs) 把运动状态、局部平面方向、平面权重送到远端，远端通过 `ReceiveRemoteMotion` 和 `LateUpdate` 驱动动画。**位置同步和动画状态同步是两条配合的链路。**

纯专用服务器在 `PlayerCharacterController.Update` 中提前返回，本地输入和 `CharacterMotor.Tick` 都由这个分支隔开。服务器校验运动表现字段、转发变换的行为，与在服务器求解每次移动属于不同职责。

### 教程：先发送操作，再由服务器算出位置

```text
客户端按 D
  → MvpView.SendInput：发送 X=1、Z=0 和输入序号
  → MvpNetwork：从发送连接查到它自己的玩家
  → ReceiveInput：校验并保存操作
  → 服务器 FixedUpdate → MovePlayer：算出位置
  → Capture → Wire：采样并编码状态
  → 客户端 Replica → DrawWorld：按播放时间显示位置
```

客户端表达的是“我想向右走”，服务器决定“这一步实际走到哪里”。这就是本教程中“服务器权威”的具体含义。碰撞、生命和回合都围绕服务器算出的这份世界结算。

所以，第 07 章的 `MovePlayer` 要与现有 `CharacterMotor` 对照着理解。只把现有 `NetworkTransformReliable` 的同步方向改成 `ServerToClient`，还需要输入上传、服务器运动入口和显示端配合，才能形成上面的完整链。

## 5. 平台破坏为什么多出四章核心代码

普通角色同步主要回答“这个根在哪里”。平台破坏还要回答“哪些块连在一起，属于哪个运动根”。例如节点 10 从固定平台脱落：

1. `Structure.Cut` 算出节点 10 与哪些块仍相连。
2. `Fracture` 为脱落组创建刚体根，把各块记到新根下面。
3. `WorldState.Blocks` 记录块的 `Parent` 和相对根的 `Local` 坐标。
4. `Wire` 把这些数据写成字节，`Replica` 在客户端保存并还原。
5. `MvpView` 在对应播放时刻重建形状，再移动所属的显示根。

“拓扑”在这里就是连接关系和块归属。“基线”是一份完整状态，后续运动包可以以它为参考，只写变化量。“快照”是某个 Tick 的状态记录。“插值”是在前后两份记录之间算出中间姿态。

再看几个容易混淆的编号：

| 发生的事 | 重点观察的字段 | 白话理解 |
| --- | --- | --- |
| 时间前进一模拟步 | `Tick` | 现在演到第几步 |
| 只发布一次周期完整采样 | `Baseline` 增长，`Version` 可以保持 | 换一张完整参照图 |
| 生成炸弹、重组碎片或删除对象 | `Version` 随相应生命周期与结构操作增长 | 世界中对象或拼装关系发生变化 |
| 回合重开 | `Round` 增长，`Tick` 归零 | 开始新的一局 |
| 核心协议区分同编号的新旧身份 | `Generation` | 相同编号下的哪一代对象 |

教程运行时对象编号按服务器会话递增，`MvpBody.Generation` 保持默认代次；核心协议与测试另外验证代次隔离。理解身份规则后，再读第 03、04 章的缓存键。

## 6. 按这个顺序学，每次只抓一件事

第一次读各章，先看“接上当前项目”“先这样读”和手工例子；能解释执行过程后，再逐行看完整代码。协议字段偏移和缓冲边界适合第二遍细读。

| 顺序 | 阅读与操作 | 读完后用自己的话回答 |
| --- | --- | --- |
| 本篇 | 对照现有 `Update` 与两条移动链 | 当前项目与教程分别由谁计算移动？ |
| 第 01 章 | 用纸写一名玩家和一个块的状态 | 哪些是输入，哪些是结果，哪些是身份？ |
| 第 02 章 | 画节点 10 与四个邻居，逐条划掉连接 | 怎样判断它脱离固定支撑？ |
| 第 03 章 | 跟踪 `1.23456` 如何编码并还原为 `1.235` | 运动包依赖哪份完整状态？ |
| 第 04 章 | 跟踪先收到运动、后收到基线的例子 | 收到包与显示这一帧分别做什么？ |
| 第 11 章核心验证 | 执行第一段完整 PowerShell 命令 | 失败断言指向哪一章、哪个函数？ |
| 第 05 至 09 章 | 集齐 Unity 适配代码，再统一导入编译 | 输入怎样到服务器，结果怎样到画面？ |

| 第 12 章 | 两个独立客户端先移动，再投掷、淘汰、重开 | 两端是否在播放同一个服务器世界？ |

核心代码里的 `System.Numerics.Vector3` 保存普通数值，Unity 的 `Vector3` 参与引擎操作；第 06 章 `N`、`U` 方法负责转换。`partial` 表示把同一个 `MvpWorld` 类分到三份文件里，字段和方法仍属于同一个实例。

## 7. 怎样把学到的东西接回正式玩法

独立竞技场承担 [改造计划](../改造计划总览.md) 中数据、同步核心、Mirror 接入、服务器模拟与双客户端验证这条学习主线。把整套代码连同 `MvpRoot` 放进 `PersistentScene`，会同时引入另一套网络管理器、运动入口和全局物理步进；正式整合需要按职责逐项接线。

整合设计按下面顺序考虑，每次明确一个输入和一个输出：

1. **输入接口。** 从现有 `CharacterInputReader` 取得动作，定义上传给服务器的数据。教程的 `MvpInput` 提供字段与校验思路。
2. **运动入口。** 保留 `CharacterMotor` 中适合正式角色的运动能力，为服务器确定唯一调用入口；同时安排拥有者、远程端和服务器各自执行哪些代码。现有 `Update` 的身份分支需要与这个设计一起处理。
3. **结果输出。** 明确位置状态由哪条同步链更新，再把服务器结果转换为正式角色的 `CharacterMotion` 和动画输入。单一根对象的一次移动应有明确的写入者。
4. **结构对象。** 先用教学方块验证图、块归属与刚体根，再对接正式关卡的几何。Unity Terrain 碰撞与 `Structure` 图节点分别按各自的数据组织。
5. **表现与场景。** 将自写快照的显示结果交给正式表现层，并沿用项目的角色选择、相机和场景服务。事件播放时机与快照播放时间一起设计。

这里给出整合时要解决的接口问题。跟着本教程动手时，具体文件仍按 `Assets/MvpTutorial/` 的练习布局创建；正式代码的改动范围由对应整合任务确定。

当前事实的进一步入口：[角色系统](../../../Y_MultipleAgentWorkflow/Character/Character_Guide.md)、[多人系统](../../../Y_MultipleAgentWorkflow/Multiplayer/Multiplayer_Guide.md)、[同步协议](../../../Y_MultipleAgentWorkflow/Multiplayer/Sync_Protocol.md)、[场景系统](../../../Y_MultipleAgentWorkflow/Scene/Scene_Guide.md)。

需要逐段跟踪按钮、角色编号、共用模型 Prefab 与相机绑定时，查 [现有角色与本地表现接入](专项设计/现有角色与本地表现接入.md)。需要决定请求用 Command 还是消息、状态用 SyncVar 还是快照时，查 [Mirror 网络 API 总览](Mirror网络API总览.md)。这些查询入口跟随主线的问题使用。
