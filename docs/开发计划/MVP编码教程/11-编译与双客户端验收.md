# 11 编译并验收双客户端回合

本章在当前工程中检查脚本、Prefab、场景和 Dedicated Server 构建。验收使用现有 Server、Client 构建配置和 `7777` 端口。

## 1. 等待 Unity 编译并检查 Console

脚本保存后等待 Unity 完成编译和 Domain Reload。打开 Console，先清除旧日志，再检查是否出现新的 Error。重点核对：

- `ArenaMatch`、`ArenaMatchBootstrap`、`ArenaPickup` 和 `ArenaPlayerPresentation` 位于 `Core.Scripts.Gameplay.Mvp` 命名空间。
- `PlatformLayout`、`PlatformChunk`、`ArenaSceneBootstrap` 和 `ArenaPlayerActions` 的拼写与前几章一致。
- `ArenaMatch` 的 `Pickup Prefab` 和 `ArenaMatchBootstrap` 的 `Match Prefab` 已在 Inspector 指定。
- 三种网络 Prefab 均加入现有 NetworkManager 的 `Spawnable Prefabs`。
- `NetworkPlayer.prefab` 上的新增组件与原网络、移动、动画和相机组件同在根层级。

编译错误先按 Console 第一条错误定位。常见原因是脚本文件名与 MonoBehaviour 类名不同、脚本尚未保存、Inspector 引用为空或命名空间不一致。

## 2. 分别构建 Server 和 Client

按 [第 10 章](10-场景与构建.md) 打开 `File > Build Settings`，分别切换到 `Dedicated Server` 和 `PC, Mac & Linux Standalone`，构建 Windows 服务器与普通客户端。输出位置沿用：

```text
D:/Unity/Releases/3D_MultiplayerGame/Server
D:/Unity/Releases/3D_MultiplayerGame/Client
```

确认两种构建都包含现有四个场景，且初始场景仍是 `InitialScene`。启动参数、KCP 地址和端口继续沿用当前 `NetworkManager` 与 `AutoStartClient` 配置。每次修改脚本后都重新构建对应程序，避免一端运行旧版本。

## 3. 按服务器、客户端一、客户端二的顺序启动

1. 启动 Dedicated Server。Headless 模式应自动启动服务器，并在服务器日志中进入现有 Additive 玩法场景。
2. 启动第一个普通 Client。它通过 `AutoStartClient` 连接 `127.0.0.1:7777`，随后由现有场景入口进入玩法。
3. 启动第二个普通 Client。等两名玩家都出现后，Match 应从等待切到倒计时，再进入进行中。

预期服务器只生成一份本回合平台与 Match。两个客户端都看到五层平台、两个网络玩家、头顶 `Player{netId}` 名称和同步的阶段与存活人数。

## 4. 验收操作与预期结果

| 操作 | 预期结果 |
| --- | --- |
| 两名玩家移动和跳跃 | 两端看到同一批玩家；现有移动、动画、相机继续工作 |
| 等待第二名玩家连接 | 一名玩家时保持等待；达到两名后进入倒计时 |
| 携带者与另一名玩家接近 | 预备时间结束后，服务器让第一层开局平台整片脱落 |
| 走到第三至第五层并接触道具 | 本机道具计数增加；同一网络道具只被拾取一次 |
| 持有道具按 E 瞄准仍连接的平台 | 服务器扣除一次道具并挖出一片平台格；两客户端看到一致变化 |
| 按 E 时没有道具或不在进行阶段 | 平台不改变，服务器不执行调试射线 |
| 从平台落到 `VoidY` 以下 | 该玩家淘汰，角色停止本机移动，可按 Tab 观战存活玩家 |
| 只剩一名存活玩家 | 进入结算并显示胜者；无人存活时以平局结算 |
| 结算结束 | 回到等待；下一回合重建平台、复位移动状态并重新分配出生位置 |
| 进行中连接第三名玩家 | 新玩家作为观战者留在场景；下一回合再加入比赛 |
| 进行中一名玩家断线 | 服务器重新统计存活人数并按剩余玩家结算 |

## 5. 关闭并排查

先关闭两个客户端，再停止 Dedicated Server。若客户端只有玩家没有平台，检查服务器是否进入 `MultiplayerSampleScene`、`ArenaSceneBootstrap.Ready` 是否建立，以及平台 Prefab 是否注册。若平台可见但不能破坏，检查 `ArenaPlayerActions` 是否挂在现有 NetworkPlayer 根上、`ServerUseRule` 是否由当前 Match 注册、玩家是否持有道具，以及被瞄准格是否仍属于锚定平台。若进入场景后一直等待，先确认两名客户端都已连接并完成玩家生成。

此处的验收步骤描述预期行为；实际结果以本机 Unity Console、构建输出和两客户端运行画面为准。
