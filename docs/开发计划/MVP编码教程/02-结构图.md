# 02 结构图

本章解决爆炸后的一个具体问题：几条连接断开后，哪些块仍连在一起，哪些组还接着固定支撑。创建 `Core/Structure.cs`，用 24 个节点、37 条无向连接描述 8×3 平台。算法的输出是节点分组；第 08 章拿这些分组重建固定块与动态碎片。

贯穿本章的例子是把节点 10 单独切下来。它在网格坐标 `(x=2,z=1)`，初始位置为 `(-2.25,2,0)` 米，邻居是 2、9、11、18。切掉相应四条连接后，原本连通的 24 块分成“另外 23 块”和“节点 10”两组。这里算出的是节点关系；碎片落下、转动后的世界位置由服务器保存。

## 接上当前项目：碰得到平台，与知道平台怎样连接

当前角色的 [CharacterMotor.cs](../../../Assets/Core/Scripts/Character/Movement/CharacterMotor.cs) 借助 `CharacterController` 与场景碰撞体完成移动。碰撞体回答“这一步有没有撞到东西”；本章的 `Structure` 回答“连接断了以后，哪几块还属于同一组”。这两份信息在第 08 章通过重建碰撞形状接起来。

先在纸上画五个圆圈：中间写 10，四周写 2、9、11、18，连上四条线。把圆圈看成平台块，把线看成块之间的连接。划掉四条线以后，10 自己成一组；第 08 章再给脱落组建立刚体。

**“连通分量”就是沿着剩余连线能互相到达的一组块。** `Supported` 再检查这一组里有没有固定支撑节点。场景物体的父子层级、物理接触与这里的连接图各有自己的数据。

先这样读：构造函数看清布局 → `Components` 看队列如何找一组块 → `Supported` 判断支撑 → `Cut` 先记旧区域再断边。局部重算的性能讨论留到能手算节点 10 的例子之后。当前关卡碰撞几何与这张教学图的整合关系见 [00 导读](00-从当前项目开始.md#7-怎样把学到的东西接回正式玩法)。

## 1. 把图术语对应到数组

| 图中的概念 | 本章字段 | 具体含义 |
|---|---|---|
| 节点 | `Rest` 的索引、`BlockState.Node` | 0–23，对应平台中一个块；节点编号保持稳定 |
| 初始布局 | `Rest[n]` | 由网格生成的初始坐标，第 06 章用来创建固定结构 |
| 固定支撑节点 | `Anchor[n]` | 0、7、16、23 为 `true`，位于平台两端的四角 |
| 无向连接 | `Edges[e]` | 保存连接两端 `A`、`B`；`e` 是连接编号 |
| 断边标记 | `Broken[e]` | `true` 表示该连接已经断开，与第 01 章世界状态的数组对应 |
| 邻接表 | `adjacency[n]` | 保存节点关联的边编号，遍历时再从边找到另一端 |
| 连通分量 | `Components` 返回的 `int[]` | 沿未断连接能互相走到的一组节点，数组按编号排序 |
| 遍历范围 | `Components(domain)` 的 `domain` | 允许进入的节点集合；省略时取全图 |
| 受影响旧区域 | `Cut` 中的 `affected` | 断边前，包含任一待切端点的旧连通分量并集 |

节点编号按 `n=x+8*z` 排列。横向连接有 `7*3=21` 条，纵向连接有 `8*2=16` 条，总数为 37。`Broken` 的长度在构造末尾根据 `Edges.Count` 创建，与第 03 章要求的 37 个标记一致。

## 2. 按什么顺序写算法

1. **构造函数先建节点，再建连接。** 第一个循环填写初始位置、支撑标记并分配每个节点的邻接表。第二个循环按节点从小到大，先连右邻居，再连下一行邻居。每条无向边只添加一次，这个顺序同时确定了稳定的边编号。
2. **写 `Add(a,b)`。** 添加前的 `Edges.Count` 就是新边编号；把同一编号分别放入两端邻接表。这样从任何一端都能找回这条连接。
3. **写 `Components(domain)` 的广度优先搜索。** 将 `domain` 去重成 `allowed`，按节点号找尚未访问的起点。每个起点创建一个队列，沿未断的边扩展；另一端必须在允许范围内且首次访问，才加入队列。一个队列处理完就是一个分量。
4. **写 `Supported(nodes)`。** 检查分量中是否存在 `Anchor=true` 的节点。这个方法只回答图上的支撑问题；动态碎片是否能重新算固定结构，还要结合旧父对象。
5. **最后写 `Cut(edgeIds,local)`。** 先去重排序和检查编号，再过滤已断边；用断边前的图找到旧分量，随后写 `Broken=true`，最后按新图重新搜索。先保存旧区域再改断边标记，才能覆盖本次分裂产生的所有小组。

| 方法 | 输入 | 输出与状态变化 |
|---|---|---|
| `Add` | 两个节点号 | 增加一条边，同时更新两端邻接表 |
| `Components` | 可选节点集合 | 返回该范围内的全部连通分量，读取当前 `Broken` |
| `Supported` | 一个分量的节点数组 | 有任一支撑节点则返回 `true` |
| `Cut` | 待切边编号、是否局部重算 | 修改新断边标记；局部模式返回受影响区域的新分量，全图模式返回全图新分量 |

注意 `Cut` 没有新断边时返回空列表。这个结果表示没有重建工作；若要查看当前全图，调用 `Components()`。局部返回结果只包括本次受影响的区域，调用方用它替换相应几何。

## 3. “局部更新”实际花费在哪里

沿着 `Cut` 的调用顺序看：它无条件执行一次 `Components()`，遍历全图找到**断边前的所有分量**；再用端点集合筛选出 `affected`；最后，`local=true` 才调用 `Components(affected)`。因此局部模式的旧区域发现成本仍覆盖全图。

令全图有 V 个节点、E 条边，受影响区域有 Va 个节点，关联邻接项数为 Ea。每次广度优先搜索的访问成本为节点数加邻接项数，此外起点排序和结果节点排序带来排序成本。局部路径约为 `O(V+E+V log V)` 加 `O(Va+Ea+Va log Va)`，还要加待切编号的去重排序和分量筛选。它省下的是第二次搜索和随后几何重建的范围。`Broken` 只使搜索跳过已断连接，邻接表仍保留这些边编号，也仍需要检查它们。

第一次从完全连通的平台切下节点 10 时，旧分量就是全部 24 个节点，`affected` 也为 24：局部路径的两次搜索都覆盖全图。后续再切其余 23 块中的某一块时，第一次仍扫描 24 节点，第二次只搜索那 23 节点。`local=false` 也先计算 `affected`，随后再做一次完整搜索。这里如实讲解现有实现的成本与返回范围，完整遍历作为第 11 章的结果对照。

## 4. 完整代码

```csharp file=Core/Structure.cs
using System;
using System.Collections.Generic;
using System.Linq;
using System.Numerics;

namespace Mvp
{
    public sealed class Structure
    {
        // 固定的 8×3 网格：数组索引就是节点号，Rest 是初始布局。
        public readonly Vector3[] Rest = new Vector3[24];
        // Anchor 记录节点最初是否连接固定支撑。
        public readonly bool[] Anchor = new bool[24];
        // 列表索引是边编号，A/B 是这条无向边的两个端点。
        public readonly List<(int A, int B)> Edges = new List<(int, int)>();
        // 断边只改标记，边和邻接表中的编号保持稳定。
        public readonly bool[] Broken;
        // 每个节点保存关联边编号，方便沿边查询另一端。
        readonly List<int>[] adjacency = new List<int>[24];

        public Structure()
        {
            // 先初始化全部节点，随后 Add 才能使用两端的邻接表。
            for (int n = 0; n < 24; ++n)
            {
                int x = n % 8, z = n / 8;
                // X/Z 间距为 1.5 米，平台中心对齐 X=0、Z=0，高度为 2 米。
                Rest[n] = new Vector3((x - 3.5f) * 1.5f, 2, (z - 1) * 1.5f);
                // 两端的上下两行形成四个支撑节点：0、7、16、23。
                Anchor[n] = (x == 0 || x == 7) && z != 1;
                adjacency[n] = new List<int>();
            }
            // 编号顺序固定为：逐节点，先右边，再下一行。
            for (int n = 0; n < 24; ++n)
            {
                // 最右侧节点不连到下一行的第一个节点。
                if (n % 8 < 7) Add(n, n + 1);
                // 最后一行没有下一行邻居。
                if (n / 8 < 2) Add(n, n + 8);
            }
            // 21 条横边加 16 条纵边，初值 false 表示全部连接完整。
            Broken = new bool[Edges.Count];
        }

        void Add(int a, int b)
        {
            // 边加入列表之前取编号，并把同一个编号写到两端。
            int id = Edges.Count;
            Edges.Add((a, b));
            adjacency[a].Add(id);
            adjacency[b].Add(id);
        }

        public List<int[]> Components(IEnumerable<int> domain = null)
        {
            // 省略 domain 时扫描全图；HashSet 同时去重并提供成员查询。
            var allowed = new HashSet<int>(domain ?? Enumerable.Range(0, Rest.Length));
            // seen 属于本次搜索，保证节点在入队时就标记，避免重复入队。
            var seen = new HashSet<int>();
            var result = new List<int[]>();
            // 起点顺序固定，便于检查分量结果。
            foreach (int start in allowed.OrderBy(x => x))
            {
                if (!seen.Add(start)) continue;
                // 每个尚未访问的起点开启一个新的连通分量。
                var nodes = new List<int>();
                var queue = new Queue<int>();
                queue.Enqueue(start);
                while (queue.Count > 0)
                {
                    int n = queue.Dequeue();
                    nodes.Add(n);
                    foreach (int e in adjacency[n])
                    {
                        // 已断边保留编号，但本次搜索不能沿它走到邻居。
                        if (Broken[e]) continue;
                        var edge = Edges[e];
                        // 同一条无向边从任意一端进入，都能找到另一端。
                        int other = edge.A == n ? edge.B : edge.A;
                        // 局部搜索限制在 allowed 内；seen.Add 返回是否首次访问。
                        if (allowed.Contains(other) && seen.Add(other)) queue.Enqueue(other);
                    }
                }
                // BFS 的到达顺序与结果表示分开，分量内节点按编号排序。
                nodes.Sort();
                result.Add(nodes.ToArray());
            }
            return result;
        }

        // 这里只看图上的支撑标记，是否保留固定根还由玩法层判断旧归属。
        public bool Supported(int[] nodes) => nodes.Any(n => Anchor[n]);

        public List<int[]> Cut(IEnumerable<int> edgeIds, bool local)
        {
            // 先验证全部编号，越界时在修改 Broken 前抛出异常。
            int[] cuts = edgeIds.Distinct().OrderBy(x => x).ToArray();
            if (cuts.Any(e => e < 0 || e >= Edges.Count))
                throw new ArgumentOutOfRangeException(nameof(edgeIds));
            // 重复切已断连接不会触发重建，空返回表示没有新工作。
            cuts = cuts.Where(e => !Broken[e]).ToArray();
            if (cuts.Length == 0) return new List<int[]>();

            // 多条断边可影响多个旧分量，用端点集合一次收集它们。
            var endpoints = new HashSet<int>();
            foreach (int e in cuts) { endpoints.Add(Edges[e].A); endpoints.Add(Edges[e].B); }
            // 在断边前取得旧分量，覆盖断边可能影响的完整范围。
            // 这里的 Components() 仍扫描全图，local 只限制断边后的第二次搜索。
            var affected = Components().Where(c => c.Any(endpoints.Contains))
                                       .SelectMany(c => c).ToArray();
            // 旧区域已经取得，现在修改标记，使后续搜索看到断裂后的图。
            foreach (int e in cuts) Broken[e] = true;
            // 局部模式只返回旧区域中的新分量；全图模式返回所有新分量。
            return local ? Components(affected) : Components();
        }
    }
}
```

## 5. 手工切下节点 10

沿构造顺序核对节点 10 的四条边：

| 边编号 | 端点 | 在构造中何时添加 |
|---|---|---|
| 5 | 2–10 | 节点 2 的下一行连接 |
| 17 | 9–10 | 节点 9 的右侧连接 |
| 19 | 10–11 | 节点 10 的右侧连接 |
| 20 | 10–18 | 节点 10 的下一行连接 |

在一个新 `Structure` 上调用 `Cut`，传入边号 5、17、19、20 并令 `local=true`：

1. 四条边都完整，去重过滤后仍有四条。端点集合为 2、9、10、11、18。
2. 断边前 `Components()` 只有一个 24 节点分量，包含这些端点，所以 `affected` 是全部节点。
3. 四个 `Broken` 标记变为 `true`。第二次搜索从节点 0 开始，可以通过其他道路到达除 10 以外的 23 个节点。
4. 外层搜索轮到 10 时，它尚未访问，四条关联边都断开，于是得到单节点分量 `[10]`。
5. 23 节点组包含四个支撑节点，`Supported` 为 `true`；节点 10 组为 `false`。第 08 章据旧归属保留大组的固定根，并为节点 10 创建动态碎片。

再切下节点 11：提交边号 7、19、21、22。其中 19 已断，本次实际新增断边为 7、21、22。旧分量发现仍扫描全图，此时有 23 节点组与 `[10]`；本次端点都在 23 节点组中，所以第二次只处理这 23 个节点，返回 22 节点组和 `[11]`。原来 `[10]` 的几何留给它原有的碎片根。全图模式在同样断边后返回三组，其中包含 `[10]`。

已经成为动态碎片的组再次断裂时，`Anchor` 仍保存节点最初的标记。因此第 08 章的固定判定同时要求 `Supported(group)` 和该组所有节点的旧 `Parent==0`。这个先后关系保证“含初始支撑节点的动态碎片”继续作为动态对象重建。

## 6. 自检方法与失败检查点

| 怎么检查 | 预期 | 失败时先查什么 |
|---|---|---|
| 新建图，查看长度和支撑节点 | `Rest.Length=24`、`Edges.Count=37`；支撑为 0、7、16、23 | 网格除法、右边界条件和纵边条件 |
| 核对节点 10 的邻接关系 | 四条边是 5、17、19、20 | `Add` 顺序是否稳定，两端是否写入同一个边号 |
| 按上面的四条边执行局部切割 | 返回 23 节点组与 `[10]`；后者无支撑 | 旧区域是否在断边前计算，是否跳过 `Broken` |
| 立即再次切相同四条边 | 返回空列表，断边状态保持 | 已断边过滤与空工作返回 |
| 传入 -1 或 37 | 抛出 `ArgumentOutOfRangeException`，断边状态保持 | 验证是否发生在写标记之前 |
| 在两个新图上切相同所有边 | 全图都成为 24 个单节点组 | 邻接表反向连接与队列访问标记 |
| 连续执行随机断边，对照局部与全图结果 | 局部结果等于全图中受影响旧区域对应的新分量 | 比较区域是否正确，是否误把局部返回当成全图结果 |

第 11 章的 `GraphTests` 用相同断边序列维护局部图与全图，比较断边数组、全图连通关系和本次受影响分量。学习时先复核上面的确定编号例子，再用随机序列覆盖重复边和多次分裂。

本章输出节点分量；第 08 章的 `Fracture` 在改块归属前保存世界位置与旧刚体速度，再按分量重建根对象。第 06 章用节点当前世界位置画未断连接，第 08 章按连接中点到爆炸中心的距离选出待切边。场景操作统一在第 10 章完成。
