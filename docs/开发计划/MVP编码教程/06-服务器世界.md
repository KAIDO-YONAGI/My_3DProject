# 06 在现有玩法场景里生成五层平台

本章把第 01 章看过的场地预览换成真正的网络平台。对象仍在当前 `MultiplayerSampleScene` 中；启动、NetworkManager 和玩家 Prefab 都沿用现有资源。

## 1. 在场景里放五个层级原点

在 Project 窗口双击 `Assets/Core/Scenes/MultiplayerSampleScene.unity`。Hierarchy 中创建空物体 `ArenaSceneBootstrap`，再在它下面创建五个空物体，命名为 `Floor_0` 到 `Floor_4`。

把五个 Floor 物体的局部坐标设为：

| 物体 | X | Y | Z |
| --- | ---: | ---: | ---: |
| `Floor_0` | 0 | 20 | 0 |
| `Floor_1` | 0 | 16 | 0 |
| `Floor_2` | 0 | 12 | 0 |
| `Floor_3` | 0 | 8 | 0 |
| `Floor_4` | 0 | 4 | 0 |

保持 `ArenaSceneBootstrap` 的世界位置和旋转为零，Scale 为 `(1, 1, 1)`，五个 Floor 的 Scale 也保持 `(1, 1, 1)`。在这棵层级下再创建空物体 `PlayerSpawn`，放在第一层上方，例如世界坐标 `(0, 21, 0)`。它保存回合复位高度。

在当前玩法场景的 Hierarchy 搜索 `t:NetworkStartPosition`，把两个已有出生点的世界位置分别设成 `(-1.5, 21, 0)`、`(1.5, 21, 0)`。初次连接由现有 NetworkManager 使用这两个位置，下一局则由 `PlayerSpawn` 和回合脚本安排位置。地下场景物体和 Terrain 如果会挡住玩家落入虚空，在 Hierarchy 关闭它们的激活勾选。

## 2. 创建服务器生成组件

创建 `Assets/Core/Scripts/Gameplay/Mvp/ArenaSceneBootstrap.cs`，先放入下面骨架。`floorOrigins` 保存五层位置，`Ready` 表示平台是否全部生成；回合脚本只有等它为 `true` 才能开始。

```csharp file=Assets/Core/Scripts/Gameplay/Mvp/ArenaSceneBootstrap.cs
using System.Collections.Generic;
using Mirror;
using UnityEngine;
using UnityEngine.SceneManagement;

namespace Core.Scripts.Gameplay.Mvp
{
    public sealed class ArenaSceneBootstrap : MonoBehaviour
    {
        public static ArenaSceneBootstrap Instance { get; private set; }

        [SerializeField] private PlatformChunk platformPrefab;
        [SerializeField] private Transform[] floorOrigins = new Transform[5];
        [SerializeField] private Transform playerSpawn;
        [SerializeField] private float voidY = -8f;

        public bool Ready { get; private set; }
        public uint RoundId { get; private set; }
        public Transform PlayerSpawn => playerSpawn;
        public float VoidY => voidY;
        public IReadOnlyList<Transform> FloorOrigins => floorOrigins;

        private void Awake()
        {
            Instance = this;
        }
    }
}
```

### 等待服务器启动

把下面两个方法加到 `ArenaSceneBootstrap` 类中，放在 `Awake` 后、类的最后一个 `}` 前：

```csharp
        private void Update()
        {
            if (NetworkServer.active && !Ready)
            {
                ServerBuild(1);
            }
        }

        private void OnDestroy()
        {
            if (Instance == this)
                Instance = null;
        }
```

普通客户端的 `NetworkServer.active` 为 `false`，因此不会生成第二套平台。服务器第一次进入场景时 `Ready` 为 `false`，调用 `ServerBuild(1)`；构建成功后变成 `true`，后续帧就不会重复创建。

### 一次生成五层平台

继续在同一个类中加入以下方法。先确认 Inspector 引用完整，再清理旧平台，最后按层配置并 Spawn。这个顺序也供下一局重建场地使用。

```csharp
        public void ServerBuild(uint roundId)
        {
            if (!NetworkServer.active)
            {
                return;
            }

            if (platformPrefab == null || floorOrigins == null || floorOrigins.Length != 5)
            {
                Debug.LogError("[ArenaSceneBootstrap] 请在 Inspector 中指定平台 Prefab 和五个 Floor 原点。", this);
                return;
            }

            // 先检查五层引用，避免生成到一半才发现某层为空。
            foreach (Transform origin in floorOrigins)
            {
                if (origin == null)
                {
                    Debug.LogError("请把五个 Floor 原点全部拖入数组。", this);
                    return;
                }
            }

            Ready = false;
            // 销毁会改动 ServerChunks，所以遍历一份副本。
            foreach (PlatformChunk oldChunk in new List<PlatformChunk>(PlatformChunk.ServerChunks))
            {
                NetworkServer.Destroy(oldChunk.gameObject);
            }

            RoundId = roundId;
            for (int layer = 0; layer < floorOrigins.Length; layer++)
            {
                Transform origin = floorOrigins[layer];
                int[] cells = layer switch
                {
                    0 => PlatformLayout.CreateOpeningCells(),
                    1 => PlatformLayout.CreateCells(centerHole: true),
                    _ => PlatformLayout.CreateCells()
                };

                ServerCreateLayer(origin, cells, layer, roundId);
            }

            Ready = true;
        }
```

`layer=0` 取九个中心格，`layer=1` 取带中心洞的 72 格，其他层取完整 81 格。下面把“生成一层”单独写成方法，仍加到同一个类中：

```csharp
private void ServerCreateLayer(Transform origin, int[] cells, int layer, uint roundId)
{
    GameObject instance = Instantiate(
        platformPrefab.gameObject, origin.position, origin.rotation);

    // 物体归属于当前玩法场景，随这份场景一起卸载。
    SceneManager.MoveGameObjectToScene(instance, gameObject.scene);
    PlatformChunk chunk = instance.GetComponent<PlatformChunk>();
    chunk.ServerConfigure(cells, true, layer == 0, layer, roundId);
    NetworkServer.Spawn(instance);
}
```

`ServerBuild` 只在服务器上运行。`floorOrigins[0]` 是开局平台中心，`floorOrigins[1]` 是带洞的第二层，其余是完整平台。每层根对象通过 `NetworkServer.Spawn` 注册，之后才由 Mirror 发给客户端。

服务器生成对象时把它放进当前加法加载的玩法场景。这样玩法场景卸载时对象的场景归属清楚。`Ready` 表示五层平台都已创建；回合系统等它为真再开始倒计时。

## 3. 把组件接到场景并填 Inspector

1. 选中 Hierarchy 的 `ArenaSceneBootstrap` 根对象。
2. 点击 `Add Component`，添加 `ArenaSceneBootstrap`。
3. 把第 04 章制作的 `PlatformChunk.prefab` 拖到 `Platform Prefab`。
4. 将 `Floor_0` 到 `Floor_4` 按顺序拖进 `Floor Origins`，数组大小设成 `5`。
5. 把刚创建的 `PlayerSpawn` 拖进 `Player Spawn`。
6. 保存场景。
7. 删除或关闭第 01 章创建的临时格子预览。

场景的 `NetworkManager` 位于 `PersistentScene`。打开 `Assets/Core/Prefabs/NetworkManager.prefab`，确认平台 Prefab 已经按第 04 章加入 `Spawnable Prefabs`。

## 4. 观察服务器与客户端的区别

保存场景和脚本，等 Unity 编译完成。按 [第 10 章的构建步骤](10-场景与构建.md) 重新构建 Dedicated Server，关闭原先运行的服务器，再启动本次构建的程序。服务器生成平台，所以这里需要把本章脚本和场景包含进服务器构建。

回到 Editor，打开 `InitialScene` 并按 Play，让现有 `AutoStartClient` 连接服务器。先用“独立服务器 + Editor 客户端”观察这一章；使用独立客户端程序时，也要重新构建客户端，使两端使用相同的网络脚本和 Prefab。接通后检查 Editor 的 Hierarchy：

- 服务器生成五个 `PlatformChunk` 并拥有它们的 Rigidbody 模拟。
- 客户端收到相同格子结构和网络平台对象。
- 普通客户端只显示平台，不独立计算平台下落。
- 现有 `NetworkPlayer` 仍由当前移动和玩家同步组件控制。

如果 Hierarchy 中有玩家却没有平台，先看服务器 Console 是否出现 Prefab 缺失、Floor 引用为空或 Spawnable Prefabs 未注册。玩家能移动但脚下没有平台，通常是 `ArenaSceneBootstrap` 没放进玩法场景，或服务器没有进入这份场景。

## 5. 五层尺寸和开局形状

平台按 `PlatformLayout` 的编号放置。9×9 格子、单格边长 1.5 米；开局平台是中心 3×3 格，第二层是 9×9 但挖掉中心 3×3。开局平台从 `Floor_0` 整片脱落后，玩家有时间跳到第二层周围的平台面。

| 层 | 生成内容 |
| --- | --- |
| `Floor_0` | 中心 3×3 开局平台地面，炸弹触发后整片脱落 |
| `Floor_1` | 9×9 方格，中间留 3×3 洞 |
| `Floor_2` 至 `Floor_4` | 完整 9×9 方格，之后由道具造成缺口 |

本章生成开局平台的九格地面。围栏外观与碰撞要作为独立场景设计来搭建，并跟随开局平台根节点；先以这个九格地面检查下落和跳跃。

这些高度和尺寸给你一个能观察下落和跳跃的起点。先运行检查角色能从开局平台跳到第二层，再调层间距、重力和炸弹预备时间。
