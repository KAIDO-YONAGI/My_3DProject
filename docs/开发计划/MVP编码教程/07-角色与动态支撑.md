# 07 角色与动态支撑

## 本章解决的问题

角色站在旋转碎片上，为什么光加碎片中心的平移速度还不够？按一下跳跃怎样只参与一次移动？本章把网络输入转成服务器角色状态，再把支撑位移、主动移动、重力和击退合成一次 `CharacterController.Move`。

编写 `Unity/MvpWorld.Players.cs`。它与第 06、08 章合成同一个 `MvpWorld`，直接使用 `bodies`、`Tick`、`endTick`、`Shape` 和 `ThrowBomb`。第 05 章的网络管理器调用 `AddPlayer / RemovePlayer / ReceiveInput`，`MvpBody` 则把控制器接触交给 `CharacterImpact`。

## 接上当前项目：对照 CharacterMotor 看一次 Move

先看现有 [CharacterMotor.cs](../../../Assets/Core/Scripts/Character/Movement/CharacterMotor.cs) 的 `Tick`，找到输入方向、重力和最后的 `CharacterController.Move`。教程 `MovePlayer` 也把各种贡献合成一次移动；执行者换成第 06 章的服务器固定步。

| 观察点 | 当前角色 | 教程角色 |
| --- | --- | --- |
| 输入来源 | `CharacterInputReader` 提供 `CharacterInput` | `ReceiveInput` 保存网络收到的方向和按钮 |
| 方向参考 | `inputSpace`，通常是本地角色相机 | 世界 X/Z 轴，配固定总览相机 |
| 时间步 | `PlayerCharacterController.Update` 传入 `Time.deltaTime` | `Rules.Step`，每步 `1/30` 秒 |
| 输出 | 本地运动结果与 `CurrentMotion` | 服务器姿态、速度、生命等，供 `Capture` 采样 |

先想象自己站在一块慢慢转动的木板边缘：即使脚下没有主动行走，也会随接触点移动。`carry` 记录这一小步被带走的距离；跳起时 `pointVelocity` 再决定继承多少速度。距离直接加到移动量，速度乘步长才变成移动量。

先这样读：`AddPlayer` 看控制器怎样建立 → `ReceiveInput` 看操作怎样保存 → `MovePlayer` 先跟踪普通地面上的行走和跳跃 → 再读动态支撑 → 最后读伤害。**先算通静止地面的跳跃，再算旋转碎片的例子。** 两条完整移动链见 [00 导读](00-从当前项目开始.md#3-用一次按-d-看懂移动链)。

## 数据与职责

| `Player` 数据 | 含义 | 写入与使用 |
|---|---|---|
| `Body / Controller` | 网络业务根与服务器胶囊控制器 | 添加玩家时建立，`MovePlayer` 移动 |
| `Gate / LastInput` | 输入校验状态与最后接收 Tick | `ReceiveInput` 校验并更新时间 |
| `Move / Buttons` | 最近方向与待消费的跳跃、投掷位 | 方向按新输入覆盖，按钮按位累积，每次移动末尾清零 |
| `Vertical / External` | 竖直速度与水平击退速度 | 重力、跳跃、爆炸和撞击共同写入 |
| `Velocity` | 本次主动方向、水平外力、竖直速度之和 | 传给 `Move`，也供快照、投掷和撞击计算使用 |
| `Support / SupportGeneration` | 当前支撑碎片的编号与代次 | 每步先检查旧支撑，移动后重新探测 |
| `LocalPoint / PreviousPoint` | 碎片局部接触点与上次世界接触点 | 同一个局部点转换后的差产生携带位移 |
| `Health / Score` | 生命与跨回合累计分数 | `Damage`、回合结算和状态采样 |
| `LastThrow / LastImpact` | 上次投掷和受碎片撞击 Tick | 第 08 章投掷节流与本章接触节流 |

`carry` 是位置差，单位为米；`pointVelocity` 是速度，单位为米每秒。携带位移直接加到 `Move` 参数；跳离速度先写入 `Vertical / External`，再乘 `Rules.Step` 转成移动量。把这两种量分清，就能读懂旋转支撑和跳跃继承。

## 编写步骤

1. 写 `Player` 运行状态与添加玩家流程，服务器动态添加 `CharacterController`，填写身体身份后登记字典。
2. 写 `ReceiveInput`。接受条件来自第 01 章 `InputGate`：当前回合、递增序号、有限方向、有效按钮位与速率。
3. 写 `MovePlayer` 的旧支撑检查，利用局部点计算 `carry`，再探测本步起始位置是否接地。
4. 写跳跃、重力和主动移动，组合后调用一次 `Move`；处理撞顶和水平外力衰减。
5. 写移动后的支撑重新登记、投掷位消费和按钮清零。
6. 写统一 `Damage` 和碎片接触伤害，核对它们与第 08 章爆炸、落场规则的调用关系。

旧支撑记录在本步移动结束后的探地阶段。第 06 章随后执行刚体物理，碎片的位置和旋转因此发生变化；下一步移动开头重新变换相同 `LocalPoint`，与 `PreviousPoint` 相减，就能取得这段物理运动的携带量。

跳跃速度的实际采样位置是 `t.position + carry`，也就是角色跟随旧支撑位移后的脚部根位置；`GetPointVelocity` 会包含该位置相对刚体中心的角速度贡献。保存的 `LocalPoint` 用于位移追踪，代码在取速度时使用上述角色位置。

## 完整代码

```csharp file=Unity/MvpWorld.Players.cs
using Mirror;
using UnityEngine;

namespace Mvp
{
    public sealed partial class MvpWorld
    {
        // 服务器运行状态，和网络快照中的 BodyState 分开保存。
        sealed class Player
        {
            // 身份根持有 Transform，控制器只在服务器角色上添加。
            public MvpBody Body;
            public CharacterController Controller;
            // 每个玩家各有一个输入门；回合重开重新建立，输入序号重新校验。
            public InputGate Gate = new InputGate();
            // Move 是持续方向，Velocity 是本步求解速度，External 是衰减的水平外力。
            public Vector3 Move, Velocity, External;
            // 跳跃位 1 与投掷位 2 可累积到同一固定步，消费后清零。
            public byte Buttons;
            // 时间均为服务器 Tick；方向超时、投掷与碰撞节流各自使用对应字段。
            public uint LastInput, LastThrow, LastImpact;
            public short Health = 100, Score;
            // 支撑仅登记动态碎片；编号与代次共同防止使用错误身份。
            public uint Support;
            public ushort SupportGeneration;
            // 局部接触点跟随旋转，PreviousPoint 是上次登记时对应的世界点。
            public Vector3 LocalPoint, PreviousPoint;
            // 独立保存竖直速度，跳跃、重力、撞顶与伤害都在此合并。
            public float Vertical;
        }

        // Mirror 添加玩家前调用，先建立服务器角色、填写同步身份并登记字典。
        public void AddPlayer(MvpBody body)
        {
            body.Id = Allocate(); body.Round = Round; body.Kind = BodyKind.Player;
            body.transform.position = SpawnPoint(players.Count);
            // 根位置表示脚部；控制器中心上移 1 米，总高度 2 米。
            var cc = body.gameObject.AddComponent<CharacterController>();
            cc.center = new Vector3(0, 1, 0); cc.height = 2; cc.radius = .35f;
            cc.skinWidth = .03f; cc.stepOffset = .2f; cc.minMoveDistance = 0;
            // 胶囊网格只显示，实际角色碰撞由 CharacterController 提供。
            Shape(PrimitiveType.Capsule, body.transform, Vector3.up, Vector3.one,
                  players.Count % 2 == 0 ? Color.cyan : Color.magenta, false);
            bodies.Add(body.Id, body);
            players.Add(body.Id, new Player { Body = body, Controller = cc });
            ++Version; dirty = true;
        }

        // 根据登记顺序交替选择左右出生点；坐标取教程固定平台的世界布局。
        static Vector3 SpawnPoint(int index) => new Vector3(index % 2 == 0 ? -4.5f : 4.5f, 3, 0);

        // 断线时移除业务登记；Mirror 基类随后处理玩家网络对象的销毁。
        public void RemovePlayer(MvpBody body)
        {
            if (body == null) return;
            players.Remove(body.Id); bodies.Remove(body.Id);
            ++Version; dirty = true;
        }

        // id 已由服务器连接身份取得，此处校验状态和输入本身。
        public void ReceiveInput(uint id, MvpInput input)
        {
            if (!players.TryGetValue(id, out var p) || p.Health <= 0 ||
                !p.Gate.Accept(input.Round, Round, input.Sequence, input.X, input.Z, input.Buttons, Tick))
                return;
            // 对角输入长度可大于 1，在服务器统一限制为单位长度。
            p.Move = Vector3.ClampMagnitude(new Vector3(input.X, 0, input.Z), 1);
            // 方向覆盖，按钮累积；同一 Tick 多包到达也保留一次按钮意图。
            p.Buttons |= input.Buttons; p.LastInput = Tick;
        }

        // 每个存活玩家每 Tick 调用一次，整合全部位移后只调用一次控制器 Move。
        void MovePlayer(Player p)
        {
            // 已淘汰角色停止移动，也清理积存按钮。
            if (p.Health <= 0) { p.Buttons = 0; return; }
            var t = p.Body.transform;
            Vector3 carry = Vector3.zero, pointVelocity = Vector3.zero;
            // 旧支撑身份仍匹配才追踪局部点；失效后按无支撑状态继续探地。
            if (p.Support != 0 && bodies.TryGetValue(p.Support, out var support) &&
                support.Generation == p.SupportGeneration && support.Kind == BodyKind.Fragment)
            {
                // 同一个局部点的新世界位置减去旧位置，包含平移和旋转产生的位移。
                carry = support.transform.TransformPoint(p.LocalPoint) - p.PreviousPoint;
                // 速度在携带后的角色脚部根位置采样，包含刚体角速度贡献。
                pointVelocity = support.GetComponent<Rigidbody>().GetPointVelocity(t.position + carry);
            }
            else p.Support = 0;

            // 在跟随支撑后的位置做地面探测，下降且接地时给一个小的向下速度。
            bool grounded = Ground(t.position + carry, out var hit);
            if (grounded && p.Vertical < 0) p.Vertical = -1;
            // 跳跃必须同时有按钮位与地面，离地按钮在本次消费后仍会清零。
            bool jump = (p.Buttons & 1) != 0 && grounded;
            if (jump)
            {
                // 竖直基础跳速为 8；水平支撑速度并入外力，随后按统一速度移动。
                p.Vertical = 8 + pointVelocity.y;
                p.External += new Vector3(pointVelocity.x, 0, pointVelocity.z);
                p.Support = 0;
            }
            // 本步跳跃也先扣掉本步重力，再用于本次 Move。
            p.Vertical -= 20 * Rules.Step;
            // 最后输入距当前 Tick 至多 6 步时保留方向，超过则停止主动行走。
            Vector3 direction = Tick - p.LastInput <= 6 ? p.Move : Vector3.zero;
            if (direction.sqrMagnitude > .01f) t.rotation = Quaternion.LookRotation(direction);
            // Velocity 不含 carry/Step；网络采样记录的是这里求解的速度。
            p.Velocity = direction * 5 + p.External + Vector3.up * p.Vertical;
            var flags = p.Controller.Move(carry + p.Velocity * Rules.Step);
            // 顶到天花板只清掉向上速度；水平外力每步向零衰减 0.1 米每秒。
            if ((flags & CollisionFlags.Above) != 0 && p.Vertical > 0) p.Vertical = 0;
            p.External = Vector3.MoveTowards(p.External, Vector3.zero, 3 * Rules.Step);

            // 本步后重新登记支撑，跳跃时跳过该登记以保持脱离。
            p.Support = 0;
            if (!jump && p.Vertical <= 0 && Ground(t.position, out hit))
            {
                p.Vertical = -1;
                var body = hit.collider.GetComponentInParent<MvpBody>();
                if (body != null && body.Kind == BodyKind.Fragment)
                {
                    // 将本次地面命中点保存到碎片局部空间，为下一步 carry 提供基准。
                    p.Support = body.Id; p.SupportGeneration = body.Generation;
                    p.LocalPoint = body.transform.InverseTransformPoint(hit.point);
                    p.PreviousPoint = body.transform.TransformPoint(p.LocalPoint);
                }
            }
            // 投掷在移动后使用角色的新姿态；按钮不随方向持续保留。
            if ((p.Buttons & 2) != 0) ThrowBomb(p);
            p.Buttons = 0;
        }

        // 从脚部上方做向下球形探测，忽略触发器；接受普通地形或碎片。
        bool Ground(Vector3 feet, out RaycastHit hit)
        {
            if (!Physics.SphereCast(feet + Vector3.up * .3f, .25f, Vector3.down,
                                    out hit, .25f, ~0, QueryTriggerInteraction.Ignore)) return false;
            // 带 MvpBody 的玩家和炸弹无法成为本入口认可的地面。
            var body = hit.collider.GetComponentInParent<MvpBody>();
            return body == null || body.Kind == BodyKind.Fragment;
        }

        // 爆炸、碎片撞击与落场共用伤害入口；回合结算等待期冻结伤害。
        void Damage(Player p, int amount, Vector3 impulse)
        {
            if (p.Health <= 0 || endTick != 0) return;
            // 水平冲击累加到外力；竖直部分只累加向上的分量。
            p.Health = (short)Mathf.Max(0, p.Health - amount);
            p.External += new Vector3(impulse.x, 0, impulse.z);
            p.Vertical += Mathf.Max(0, impulse.y);
            if (p.Health == 0)
            {
                // 淘汰保留网络身份与分数，禁用控制器并把实物移到场下。
                p.Controller.enabled = false;
                p.Support = 0; p.Body.transform.position = new Vector3(0, -20, 0);
            }
        }

        // 在 CharacterController.Move 的接触回调中检查高速碎片对角色的撞击。
        public void CharacterImpact(MvpBody body, ControllerColliderHit hit)
        {
            if (!players.TryGetValue(body.Id, out var p) || hit.rigidbody == null ||
                Tick - p.LastImpact < 6) return;
            // 当前支撑碎片、其他类别和非刚体接触跳过；每玩家至少相隔 6 Tick。
            var other = hit.rigidbody.GetComponent<MvpBody>();
            if (other == null || other.Kind != BodyKind.Fragment || other.Id == p.Support) return;
            Vector3 relative = hit.rigidbody.GetPointVelocity(hit.point) - p.Velocity;
            // 使用沿接触法线靠近角色的速度，站立和沿表面滑动保持接触。
            float speed = Mathf.Max(0, Vector3.Dot(relative, hit.normal));
            // 法线靠近速度不足 6 时保持普通接触；伤害至多 35，击退至多 8。
            if (speed < 6) return;
            p.LastImpact = Tick;
            Damage(p, Mathf.Min(35, (int)(speed * 2)), relative.normalized * Mathf.Min(8, speed));
        }
    }
}
```

## 手工追踪一次输入与普通跳跃

设输入在 `Tick=100` 到达，上一序号为 40，本包为 `Round=2, Sequence=41, X=1, Z=1, Buttons=1`。`InputGate` 接受后，方向限制为约 `(0.7071,0,0.7071)`，`LastInput=100`，按钮位为 1。

Tick 101 在静止地面上移动，假设当前无外力：

1. `carry=0`，`pointVelocity=0`，探地成功，跳跃成立。
2. `Vertical` 先置为 8，再扣 `20/30`，得到约 `7.3333`。
3. 方向距最后输入只有一 Tick，主动水平速度为 `(3.5355,0,3.5355)`。
4. `Velocity` 为约 `(3.5355,7.3333,3.5355)`，本次 `Move` 参数为约 `(0.1179,0.2444,0.1179)` 米，实际位移还由控制器碰撞约束。
5. 跳跃步跳过支撑登记，末尾 `Buttons=0`。后续 Tick 持续使用方向；Tick 106 的差为 6，方向有效，Tick 107 的差为 7，主动方向归零。

同一 Tick 内多次到达跳跃位，按位或的结果仍是 1。一次移动消费一个跳跃意图；具体是否跳起取决于该步地面检测。输入每包的序号去重与每步按钮消费是两个不同的检查。

## 手工追踪旋转碎片上的跳离

设碎片 20 的代次为 1，上次根位置为 `(9,2,0)`、旋转为单位旋转，刚体质心与根位置重合。接触点 `LocalPoint=(1,0.25,0)`，因此 `PreviousPoint=(10,2.25,0)`，角色脚部也位于这个点。

本次读取碎片时，根位置为 `(9.02,2,0)`，绕 Y 轴转过约 `0.066667` 弧度。该局部点的新世界坐标约为 `(10.017779,2.25,-0.066617)`，所以 `carry≈(0.017779,0,-0.066617)`。位移里同时有中心平移与旋转。

若此刻刚体线速度为 `(0.6,0,0)`，角速度为 `(0,2,0)`，在携带后的脚部点计算 `v + ω × r`，得到 `pointVelocity≈(0.466766,0,-1.995558)` 米每秒。Unity 的 `GetPointVelocity` 提供这一结果。

假设地面检测成功、收到跳跃位、主动方向为零、原水平外力为零：`External` 取得约 `(0.466766,0,-1.995558)`，重力后竖直速度为 `7.3333`。本次 `Move` 参数约为 `carry + Velocity/30 = (0.033338,0.244444,-0.133136)` 米。函数随后衰减水平外力，并保持 `Support=0`。本次跳跃既消费了已产生的支撑位移，也取得了跳离时的支撑点速度。

## 预期与排查

| 检查动作 | 代码对应的预期 | 优先检查位置 |
|---|---|---|
| 输入重复或序号倒退 | `InputGate` 拒绝，按钮与方向保持原状态 | `ReceiveInput` 的 `Gate.Accept` |
| 方向消息停止 | 超过 6 Tick 后主动方向归零，重力与外力仍求解 | `Tick - LastInput` 与 `Velocity` |
| 站在旋转碎片上 | 局部接触点产生平移和旋转携带量 | `LocalPoint / PreviousPoint`、支撑代次 |
| 跳离动态支撑 | 点速度写入水平外力和竖直跳速，本步清掉支撑 | `pointVelocity`、地面命中与 `jump` |
| 旧支撑销毁 | 旧编号查找失败，清掉记录并重新探地 | `bodies.TryGetValue`、移动后的 `Ground` |
| 玩家被高速碎片撞击 | 按靠近法线速度计算伤害并受 6 Tick 节流 | `CharacterImpact` 的支撑排除、法线点积 |
| 生命归零 | 控制器关闭，业务身份和分数仍参与基线 | `Damage`、第 06 章 `Capture` |

固定地面没有支撑业务编号，携带量为零。每次 `Ground` 都取球形探测的实际命中，确认命中类型与控制器脚部位置，比只看 `CharacterController.isGrounded` 更贴近本章代码的判断依据。
