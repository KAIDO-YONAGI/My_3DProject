# 12 运行验收

用一个服务器与两个独立客户端完成以下流程。每次记录构建、运行配置和结果，教程中的程序负责输出 Tick 耗时、协议字节、对象数量与当前回合。

## 玩法闭环

| 动作 | 通过条件 | 记录 |
| --- | --- | --- |
| 两名玩家连接 | 出生于平台两端，各自输入控制对应角色 | 两个客户端画面 |
| 移动和跳跃 | 地面移动、跳跃、落地连续 | 操作录屏 |
| 两颗炸弹投向中央 | 引信爆炸产生断边，随后触发相邻炸弹 | 事件 Tick、编号与来源 |
| 连续轰炸平台 | 块按连通分量组成碎片，块归属唯一 | Gizmos 连接图、碎片数 |
| 再次轰炸旋转碎片 | 新块保持原世界位置与方向，速度继承连续 | 爆炸前后逐帧画面 |
| 碎片撞击玩家 | 服务器扣血与击退，客户端生命一致 | 生命变化与位置 |
| 淘汰玩家 | 最后存活者得分，三秒后开始新回合 | 连续十局结果 |

## 动态支撑

对运动碎片分别执行站立、行走、跳离和爆炸销毁。检查角色随局部接触点平移与旋转，跳离速度包含接触点速度，换碎片时重新记录支撑身份，支撑销毁后进入下落。

在 Scene 视图中选择碎片 Rigidbody，记录线速度和角速度，再比较角色跳离第一 Tick 的速度。给碎片施加缓慢旋转，确认角色脚下轨迹随局部点移动。跳离后从服务器状态读回角色运动，两个客户端使用同一状态显示。

## 恢复与时序

| 场景 | 通过条件 |
| --- | --- |
| 平台破坏后连接第三客户端 | 断边、块归属、生命和活动碎片恢复 |
| 恢复期间继续投掷炸弹 | 后续基线与运动包衔接，当前拓扑正确 |
| 运动包先到、对象稍后创建 | 缓存状态保留，对象到达后建立正确形状 |
| 同一个爆炸重复触发 | 服务器结算一次，客户端播放一次 |
| 新回合收到旧包 | 回合身份隔离，当前地形和玩家保持正确 |
| 缺少差量基线 | 请求完整状态并恢复，待处理队列保持上限 |
| 断线再连接 | 新连接取得当前基线，输入对应新的拥有者身份 |

自动测试复现协议乱序、重复与丢包。传输实验沿用 [弱网矩阵](../00-改造计划总览.md#弱网矩阵)，同时记录传输配置。专用服务器和 Host 各运行一轮。

## 测量

固定场景、玩家脚本、爆炸次数与运行时长，比较以下数据。取样前运行 30 秒，每组采集 60 秒，至少重复三次。

| 指标 | 采集方法 |
| --- | --- |
| 结构计算耗时 | 在 `Structure.Cut` 前后使用 `Stopwatch`，同一断边序列比较局部与完整遍历 |
| 服务器模拟耗时 | 记录 `LastStepMs`，并用 Unity Profiler 分别查看角色与 PhysX |
| 协议字节 | 用 `BytesSent` 与 `BytesReceived` 的时间差分计算每秒字节 |
| 实际网络带宽 | 用传输统计或抓包工具记录每连接字节，包含 Mirror 与 KCP 开销 |
| 对象与碎片数量 | 同时记录 `WorldState.Bodies` 和 `Fragment` 数量 |
| 位置与旋转误差 | 编码前后比较量化误差；客户端播放 Tick 对齐服务器采样后比较插值误差 |
| 恢复次数 | 在 `RequestRecovery` 的实际发送位置增加计数，记录每分钟请求数 |
| 发送策略对比 | 同一 `WorldState` 分别逐对象完整编码、批量差量编码，比较总字节与编码耗时 |

教程的累计字节计数统计每次广播构造的业务载荷。广播发送到多个连接时，按连接数汇总实际流量，传输层统计作为带宽验收依据。

MVP 验收由自动测试通过、Unity 与 Weaver 编译通过、上述双客户端玩法与恢复流程通过三部分组成。提交运行构建、录屏、测试输出和测量表，用这些材料说明自写结构算法与同步内核的实际行为。
