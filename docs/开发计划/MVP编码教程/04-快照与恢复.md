# 04 制作网络平台 Prefab

这一章在 Unity 里制作一个网络平台 Prefab，并把它登记到现有 NetworkManager。服务器生成这个 Prefab 后，客户端才能知道“应该创建哪种物体”。

一个平台要同步两类东西：它在哪里，以及它还剩哪些格子。前者交给 `NetworkTransformReliable`，后者保存在 `SyncList<int> Cells` 中。客户端按收到的编号创建 Cube；中途加入的玩家也从当前编号列表恢复形状。

## 1. 在现有 Prefabs 目录创建网络平台

在 Project 窗口展开 `Assets/Core/Prefabs`。如果还没有 `Gameplay` 子目录，右键 `Prefabs` 并选择 `Create > Folder`，命名为 `Gameplay`。

在 Hierarchy 里创建一个空物体，命名为 `PlatformChunk`。它只作为 Prefab 制作模板，不要添加 Cube 子物体。依次添加以下组件：

1. `NetworkIdentity`
2. `Rigidbody`
3. `NetworkTransformReliable`
4. `PlatformChunk`

`PlatformChunk` 的 `RequireComponent` 也会要求前三种组件存在；添加完成后检查根节点上各组件各有一个。不要给子格子分别添加 Rigidbody 或 NetworkIdentity。

选中根 `Rigidbody`，设置 `Use Gravity` 为开启、`Is Kinematic` 为开启。Prefab 的初始状态必须是运动学刚体：锚定平台由服务器保持固定；`ServerConfigure(... anchored:false ...)` 会在服务器 Spawn 前将它切换为动态刚体。所有客户端上的平台刚体由 `PlatformChunk.OnStartClient` 设为运动学刚体。

选中 `NetworkTransformReliable`，确认 `Target` 指向根 Transform，`Sync Position` 和 `Sync Rotation` 开启，`Sync Scale` 关闭，位置与旋转插值开启。将 `Sync Direction` 设成 **Server To Client**。该方向意味着平台位姿由服务器发出，客户端只接收；不要把现有玩家 Prefab 上的 Client To Server 设置照搬到平台。

选中 `PlatformChunk` 组件，把 `Assets/Plugins/Mirror/Examples/Room/Materials/PlayArea.mat` 拖到 `Cell Material`。先把当前 Hierarchy 中的根物体拖到 `Assets/Core/Prefabs/Gameplay/`，生成 `PlatformChunk.prefab`。选中新 Prefab 资源，把它自身拖到 `Fragment Prefab` 字段。这个自引用让服务端分裂时始终从无生成子物体的干净模板创建新组。

Prefab 保存后删除 Hierarchy 中制作模板用的临时物体。打开 Prefab 检查根节点仍无 Cube 子物体；Cube 只会由 `ServerConfigure` 在运行时按 `Cells` 生成。

## 2. 注册到现有 NetworkManager

在 Project 窗口打开 `Assets/Core/Prefabs/NetworkManager.prefab` 的 Prefab Mode。选中带 `NetworkManager` 组件的根节点，在 Inspector 找到 `Spawnable Prefabs` 列表，点 `+` 并把 `Assets/Core/Prefabs/Gameplay/PlatformChunk.prefab` 拖入新槽位。保存 Prefab。

保留当前 NetworkManager、KCP Transport、端口 `7777`、现有 `NetworkPlayer` 和自动创建玩家配置。NetworkPlayer 上原有的 `NetworkTransformReliable` 继续使用 Client To Server；平台 Prefab 单独使用 Server To Client。角色的 `CharacterMotor`、相机、动画和音频组件都不需要替换。

## 3. 理解物理与网络状态各自负责什么

服务器上的锚定平台由运动学 Rigidbody 固定。`ServerBreak` 产生的非锚定组使用动态 Rigidbody，服务器在物理步进中计算重力和碰撞。服务器把每组根节点位置、旋转发送给客户端，客户端根 Rigidbody 始终是运动学的，由 `NetworkTransformReliable` 插值位姿，不会在本地再算一遍下落。

根 Transform 表示“整片平台现在在哪里、朝哪边转”；`Cells` 表示“这片平台还剩哪些格子”。假设一块平台原来有 81 格，被打掉 9 格后，新玩家才连接：服务器发给他的对象已经保存着剩余格子。他的 `OnStartClient` 直接遍历当前列表生成 Cube，就能看到当前形状。

这里要区分“状态”和“事件”。“剩下哪些格子”是状态，加入时必须能读到；“刚才发生过一次爆炸”是事件，适合播一次音效或特效。只发爆炸 RPC 的话，后加入的人收不到过去那次调用，也就无法靠它还原平台。

平台注册后，格子运行时创建、分组、同步和碰撞都由 `PlatformChunk` 处理。本教程此处不另建测试场景或生成器；主线第 06 章的 `ArenaSceneBootstrap` 会在现有玩法场景创建五层平台，把每个实例移动到当前 `gameObject.scene`，再配置并 Spawn。保存并检查 Prefab 后，继续使用项目现有 `InitialScene → PersistentScene → MultiplayerSampleScene` 启动链。
