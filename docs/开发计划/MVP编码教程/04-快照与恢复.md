# 04 快照与恢复

## 本章要解决的问题

运动包可能先于它引用的完整基线到达，也可能乱序、重复或丢失。第 03 章只负责把字节还原成状态，本章让客户端知道何时解码、把状态放进哪个对象的缓冲，以及在哪个播放 Tick 使用哪套结构。创建 `Core/Replica.cs`。

贯穿例子仍是回合 2、版本 4、基线 7。玩家 `Id=5`、`Generation=1` 在 Tick 120 的 X 为 1、生命为 100；Tick 122 的运动包解码后 X 为 1.235、生命为 35。假设运动包先到，客户端应暂存它；收到 Tick 120 的基线后解码，再在播放 Tick 121 采样出 X=1.1175、生命=100，在 Tick 122 切到生命 35。

另一个问题是块 `Node=10` 的归属：版本 4 中它挂在碎片 9 上，版本 5 中改挂碎片 12。结构与对象姿态都按播放时间切换；跨版本的两份玩家或碎片状态进入各自缓冲。

## 三类对象各自负责什么

| 类型或字段 | 输入 | 输出或职责 |
| --- | --- | --- |
| `PoseBuffer.Push` | Tick 与一个 BodyState | 排序保存这个身份的快照，重复 Tick 覆盖，至多 32 帧 |
| `PoseBuffer.Sample` | double 播放 Tick | 一个 BodyState，在相邻 Tick 间插值，边界外保持端点 |
| `PlaybackClock.Observe` | Round、消息 Tick、本地秒数 now | 记录最新观测时刻；首次启动或新回合设置播放 Tick |
| `PlaybackClock.Advance` | 本地秒数 now、帧耗时 dt | 一个 double 播放 Tick，供 Render 采样 |
| `Replica.ReceiveBaseline` | 完整基线字节 | 解码状态，更新缓存和结构时间线，并重放暂存运动包 |
| `Replica.ReceiveMotion` | 一个运动包字节 | 找基线、检查版本、解码并逐对象追加姿态 |
| `Replica.Render` | double 播放 Tick | 一份用于显示的 WorldState；没有时间线时返回 null |
| `baselines` | Baseline 编号 → WorldState | 解码运动包用的原点，最多保留 8 个编号 |
| `timeline` | 基线 Tick → WorldState | 决定该时刻使用哪套对象集合、Blocks 和 Broken，最多 8 个 Tick |
| `poses` | `(Version, Id, Gen)` → PoseBuffer | 每个版本、对象编号、代次分别保留姿态 |
| `pending` | 暂缺基线或属于未来回合的运动包 | 按到达顺序暂存，最多 `Rules.MaxPending=128` 包 |

`Round` 由整个 `Replica` 管理，切换回合时清理旧世界。姿态键是 **`(Version, Id, Gen)`**，其中 Gen 对应 `BodyState.Generation`。Baseline 编号不在键中：同版本、同 Id、同 Gen 的周期基线继续往同一个缓冲放帧。一个包里的每个对象也各自放帧，接收端按对象独立采样。

因此 12 对象分包中的第一包到达后，其中对象即可更新；另一包里的对象仍用自己的已有帧。`Replica` 没有等待整个 Tick 的全部分包收齐的组装步骤。

## 先写姿态缓冲

1. 用 `SortedList<uint, BodyState>` 表达 Tick 到状态的有序映射。`Push` 使用索引赋值，同 Tick 到达两次时后一条覆盖前一条；超过 32 帧就删除最小 Tick。
2. 写 `Sample` 的空缓冲分支，直接抛出异常，避免把默认零状态当作有效姿态。
3. 播放时间早于或等于第一帧时返回第一帧。随后从第二帧开始寻找第一条 Tick 大于或等于播放时间的帧。
4. 若恰好命中帧 Tick，直接返回这一帧；否则计算两帧间比例，调用第 01 章的 `Rules.Mix`。连续量插值，Health、Sleeping、Score 等离散量使用左帧。
5. 播放时间超过最后一帧时返回最后一帧。即使最后帧 Velocity 非零，位置也保持最后位置。

缓冲自身没有检查 Version、Id、Generation。调用者通过 `poses` 的键保证身份隔离。乱序旧帧按 Tick 插入；若容量已满且它比现存帧都旧，插入后可能立即被删掉。

## 再写播放时钟，按实际公式理解延迟

`now` 和 `dt` 的单位是秒，`Rules.Rate=30` 将秒转换成服务器 Tick。`Observe` 首次见到消息或见到更大的 Round 时，直接执行 `Tick=tick`，同时记录 newest 和 receivedAt。例子中观测到 Tick 120，起始播放值就是 120。

同回合收到 `tick>=newest` 的消息时刷新 newest 和接收时间，播放 Tick 继续沿用现值。同 Tick 的重复观测也刷新接收时间；更小的 Tick 与更旧回合不会刷新。此处记录消息时间，姿态是否解码、基线是否齐备由 `Replica` 管理。

`Advance` 的目标时间为：

```text
target = newest + max(0, now-receivedAt)×30 - 3
```

公式中的 3 Tick 相当于 100 毫秒的目标延迟。时钟按与 target 的差值选择速度：target 超前超过 1 Tick 时用 1.1 倍，落后超过 1 Tick 时用 0.9 倍，其余用 1 倍；分别相当于每秒前进 33、27、30 Tick。每帧推进后，再把 Tick 限制在 `newest+2` 以内。

目标延迟与实际起始值分别由公式和 `Observe` 决定。时钟不会在首次收到 Tick 120 时直接设为 117，也不会每帧直接跳到 target。下面的停包例子说明实际行为：

| 操作 | target | 实际播放 Tick |
| --- | --- | --- |
| `Observe(2,120,0)` | 尚未 Advance | 120 |
| `Advance(1/30,1/30)` | 118 | 120.9，使用 0.9 倍速 |
| `Advance(2/30,1/30)` | 119 | 121.8，使用 0.9 倍速 |
| `Advance(3/30,1/30)` | 120 | 原推进到 122.7，经封顶得到 122 |

继续停包时，即使 target 随本地时间增长，Tick 仍被 `newest+2=122` 封顶。与此同时，只有 Tick 120 姿态的对象继续显示 Tick 120 的最后状态。时钟允许有限前进和姿态保持端点是两层行为。

同回合随后收到 Tick 200，只刷新 newest 和 receivedAt，下一帧按调速规则继续推进；新回合到达则按 `Observe` 分支重置播放 Tick。第 09 章接收入口会观测运动包头部，即使该包正由 `Replica` 暂存，时钟也可能先看到它的 Tick。

## 最后写副本与恢复顺序

1. 声明四个集合和可观察属性。`PendingCount` 统计暂存包，`BufferedIdentities` 统计姿态键数量，便于第 11 章核对边界行为。
2. 写私有 `Push`，用 `(version,s.Id,s.Generation)` 查找或创建缓冲，再压入这一帧。基线和运动包共用入口，周期基线自然保留已有帧。
3. 写 `ReceiveBaseline`。先调用 `Wire.ReadBaseline`，旧回合返回 null；新回合清理基线、姿态和时间线，只保留属于新回合的 pending。
4. 把解码基线分别存入 baselines 和 timeline，把其中每个对象压入对应姿态缓冲。基线编号超过 8 个时删除最小编号；时间线超过 8 个 Tick 时删除最小 Tick。随后按时间线仍包含的 Version 回收整个旧版本的姿态键。
5. 清除 `NeedsBaseline`，将 pending 复制到临时数组后清空队列，再逐条调用 `ReceiveMotion`。仍缺少所引用基线的包会重新进入队列，并把 NeedsBaseline 重新设为 true。
6. 写 `ReceiveMotion`。先读 Header，忽略旧回合；若回合尚未应用或指定基线不存在，就暂存，满 128 时淘汰最先到达的包。基线存在后，再检查 Version 是否仍在时间线中，最后调用 `Wire.ReadMotion` 并逐对象 Push。
7. 写 `Render`。从最早基线出发，寻找播放 Tick 之前最新的基线，得到该时刻的对象清单和块结构；逐对象从匹配 Version、Id、Gen 的缓冲采样。

顺序影响恢复行为：指定基线已被淘汰的包先进入 pending，版本检查在找到基线之后执行。同 Tick 的基线会覆盖时间线中的旧条目；播放 Tick 早于最早基线时，Render 仍采用最早基线。缓存保存近期历史，能够回看的范围受保留数量限制。

Render 创建新的 Bodies 数组，Blocks 和 Broken 直接引用选中基线的数组，显示端按只读数据使用。输出 `WorldState.Tick` 将非负播放值转换成 uint，例如 121.5 写为 121；每个对象的 `Sample` 仍收到 double 121.5。

## 完整代码

```csharp file=Core/Replica.cs
using System;
using System.Collections.Generic;
using System.IO;
using System.Linq;

namespace Mvp
{
    public sealed class PoseBuffer
    {
        // 单个姿态身份的有序帧；身份隔离由 Replica 的字典键负责。
        readonly SortedList<uint, BodyState> frames = new SortedList<uint, BodyState>();
        // 当前帧数，最多 32；供自检观察缓冲容量。
        public int Count => frames.Count;
        // 按 Tick 插入，重复 Tick 使用最新到达状态，超限删最早 Tick。
        public void Push(uint tick, BodyState state)
        {
            frames[tick] = state;
            while (frames.Count > 32) frames.RemoveAt(0);
        }
        // 采样连续播放时间，端点外保持端点，区间内调用 Rules.Mix。
        public BodyState Sample(double tick)
        {
            if (frames.Count == 0) throw new InvalidOperationException("快照缓冲为空");
            // 播放时间在第一帧之前也返回第一帧。
            if (tick <= frames.Keys[0]) return frames.Values[0];
            for (int i = 1; i < frames.Count; ++i)
                if (tick <= frames.Keys[i])
                {
                    // 离散状态在采样到其 Tick 时生效，生命与休眠状态使用该帧值。
                    if (tick == frames.Keys[i]) return frames.Values[i];
                    // 例如帧 120 和 122，采样 121 时比例为 0.5。
                    float t = (float)((tick - frames.Keys[i - 1]) /
                                      (frames.Keys[i] - frames.Keys[i - 1]));
                    return Rules.Mix(frames.Values[i - 1], frames.Values[i], t);
                }
            // 没有后续帧时保持完整末帧状态，Velocity 不参与位置外推。
            return frames.Values[frames.Count - 1];
        }
    }

    public sealed class PlaybackClock
    {
        // 当前观测回合；新回合的 Tick 可以从零重新开始。
        public uint Round { get; private set; }
        // 显示端实际使用的连续 Tick。
        public double Tick { get; private set; }
        // 最新观测消息 Tick，以及它在本地被观测到的秒数。
        uint newest;
        double receivedAt;
        // 区分尚未观测消息与已经启动的时钟。
        bool started;

        // 消息时间观测独立于 Replica 的基线恢复和姿态解码。
        public void Observe(uint round, uint tick, double now)
        {
            if (started && round < Round) return;
            if (!started || round > Round)
            {
                Round = round; newest = tick; receivedAt = now;
                // 首次启动或新回合直接从消息 Tick 起步。
                Tick = tick; started = true; return;
            }
            // 同 Tick 也刷新 receivedAt；乱序更旧 Tick 保持现有观测。
            if (tick >= newest) { newest = tick; receivedAt = now; }
        }
        // dt 和 now 都使用秒；target 只决定调速，最后还有 newest+2 封顶。
        public double Advance(double now, double dt)
        {
            if (!started) return Tick;
            // 估计服务器当前 Tick，再减去 3 Tick 作为追随目标。
            double target = newest + Math.Max(0, now - receivedAt) * Rules.Rate - 3;
            // 限制追赶速度，让抖动通过缓冲和温和调速消化。
            double rate = target > Tick + 1 ? 1.1 : target < Tick - 1 ? 0.9 : 1.0;
            Tick += Math.Max(0, dt) * Rules.Rate * rate;
            // 停包时只允许时钟有限前进，姿态是否可插值由各缓冲决定。
            Tick = Math.Min(Tick, newest + 2.0);
            return Tick;
        }
    }

    public sealed class Replica
    {
        // 解码原点缓存：按 Baseline 编号找完整状态，保留至多 8 个编号。
        readonly Dictionary<uint, WorldState> baselines = new Dictionary<uint, WorldState>();
        // 按版本、编号、代次分别保存姿态；Baseline 变化不改变这个键。
        readonly Dictionary<(uint Version, uint Id, ushort Gen), PoseBuffer> poses =
            new Dictionary<(uint, uint, ushort), PoseBuffer>();
        // 尚缺对应基线的原始运动包，按到达顺序淘汰，最多 128 包。
        readonly List<byte[]> pending = new List<byte[]>();
        // 基线 Tick 的结构时间线，渲染按播放 Tick 选取，最多 8 条。
        readonly SortedList<uint, WorldState> timeline = new SortedList<uint, WorldState>();
        // 当前已应用完整基线所属的回合。
        public uint Round { get; private set; }
        // 接收入口据此请求恢复；暂存包在重放后仍缺基线时会重新置为 true。
        public bool NeedsBaseline { get; private set; }
        // 暂存包数量和姿态身份数量供验证观察。
        public int PendingCount => pending.Count;
        public int BufferedIdentities => poses.Count;

        // 应用完整基线：隔离回合、更新缓存、压入姿态，再重放暂存包。
        public WorldState ReceiveBaseline(byte[] bytes)
        {
            var w = Wire.ReadBaseline(bytes);
            if (w.Round < Round) return null;
            if (w.Round > Round)
            {
                // 新回合的编号与 Tick 可以复用，先清空上一回合历史。
                Round = w.Round; baselines.Clear(); poses.Clear(); timeline.Clear();
                // 未来回合的包可以先到；留下对应回合再进行解码。
                pending.RemoveAll(p => Wire.Header(p).Round != Round);
            }
            // 两种索引分别服务解码和渲染；同编号或同 Tick 使用覆盖赋值。
            baselines[w.Baseline] = w;
            timeline[w.Tick] = w;
            // 同 Version、Id、Generation 的周期基线继续使用原缓冲。
            foreach (var s in w.Bodies) Push(w.Version, s, w.Tick);
            // 基线按最小编号淘汰，时间线按最早 Tick 淘汰。
            while (baselines.Count > 8) baselines.Remove(baselines.Keys.Min());
            while (timeline.Count > 8) timeline.RemoveAt(0);
            // 时间线已不再引用的整个版本，其所有姿态键一起回收。
            var liveVersions = new HashSet<uint>(timeline.Values.Select(v => v.Version));
            foreach (var key in poses.Keys.Where(k => !liveVersions.Contains(k.Version)).ToArray())
                poses.Remove(key);
            // 先清空原队列再重放；未能恢复的包可重新入队并再次请求基线。
            NeedsBaseline = false;
            byte[][] replay = pending.ToArray(); pending.Clear();
            foreach (var p in replay) ReceiveMotion(p);
            return w;
        }

        // 基线和运动包共用的逐对象入口，保证姿态不跨版本或代次混合。
        void Push(uint version, BodyState s, uint tick)
        {
            var key = (version, s.Id, s.Generation);
            if (!poses.TryGetValue(key, out var buffer))
            {
                // 新版本或新代次创建独立缓冲，其他身份继续保留已有帧。
                buffer = new PoseBuffer(); poses.Add(key, buffer);
            }
            buffer.Push(tick, s);
        }

        // 单包处理：先按头定位基线，满足条件后解码并逐对象更新。
        public void ReceiveMotion(byte[] bytes)
        {
            var h = Wire.Header(bytes);
            if (h.Round < Round) return;
            // 未来回合和缺失基线先暂存；这一分支发生在版本时间线检查之前。
            if (h.Round != Round || !baselines.TryGetValue(h.Baseline, out var basis))
            {
                // 满额淘汰最先到达的一包，保留较新的恢复机会。
                if (pending.Count == Rules.MaxPending) pending.RemoveAt(0);
                pending.Add(bytes); NeedsBaseline = true; return;
            }
            // 过期拓扑的迟到包可以解码；已经退出时间线的版本直接丢弃。
            if (!timeline.Values.Any(w => w.Version == h.Version)) return;
            // Wire 再核对回合、版本、基线编号及对象身份。
            var packet = Wire.ReadMotion(bytes, basis);
            // 每对象独立压帧，其他分包的到达情况不影响本包应用。
            foreach (var s in packet.Bodies) Push(packet.Version, s, packet.Tick);
        }

        // 按播放时间选结构，再从该结构版本的每个身份缓冲里采样。
        public WorldState Render(double tick)
        {
            if (timeline.Count == 0) return null;
            // 播放时间早于第一条基线时，使用第一条；其余选不晚于 tick 的最新条目。
            WorldState basis = timeline.Values[0];
            for (int i = 1; i < timeline.Count && timeline.Keys[i] <= tick; ++i)
                basis = timeline.Values[i];
            // Bodies 新建；Blocks、Broken 共享基线数组，显示端按只读使用。
            var output = new WorldState { Round = basis.Round, Tick = (uint)Math.Max(0, tick),
                Version = basis.Version, Baseline = basis.Baseline,
                Blocks = basis.Blocks, Broken = basis.Broken, Bodies = new BodyState[basis.Bodies.Length] };
            for (int i = 0; i < output.Bodies.Length; ++i)
            {
                var s = basis.Bodies[i];
                // 使用原 double tick 采样，输出世界 Tick 的整数转换不影响插值比例。
                output.Bodies[i] = poses[(basis.Version, s.Id, s.Generation)].Sample(tick);
            }
            return output;
        }
    }
}
```

## 手工跟踪：先恢复，再沿时间线播放

给各基线补齐合法 Blocks 和 Broken 数组，节点 10 在版本 4 中属于碎片 9。下面的 X 和生命仅列出玩家 5，其余对象各自使用自己的姿态缓冲。

| 接收顺序 | 消息内容 | 内部变化 |
| --- | --- | --- |
| 1 | 运动包：R2、V4、B7、T122，玩家 X=1.235、HP=35 | 基线 7 尚未到达，pending=1，NeedsBaseline=true |
| 2 | 基线 7：R2、V4、T120，玩家 X=1、HP=100 | 应用回合 2；建立姿态键 `(4,5,1)` 的帧 120；重放运动并加入帧 122 |
| 3 | 周期基线 8：R2、V4、T124，玩家 X=2、HP=35 | 同一姿态缓冲变为帧 120、122、124，基线 7 和 8 均可作为解码原点 |
| 4 | 迟到运动：R2、V4、B7、T123，玩家 X=1.5 | 用仍保留的基线 7 解码，将帧 123 插入同一缓冲 |
| 5 | 结构基线 9：R2、V5、T126，玩家 X=2.5，节点 10 改属碎片 12 | 建立 `(5,5,1)` 和版本 5 的碎片姿态；版本 4 的历史仍供此前 Tick 播放 |

收到第二条消息后，`NeedsBaseline=false`、`PendingCount=0`。在帧 120 和 122 之间：

```text
Render(121)
基线：Tick 120 的基线 7，Version 4
玩家姿态键：(4,5,1)
t=(121-120)/(122-120)=0.5
X=1+(1.235-1)×0.5=1.1175
Health=100，取左帧离散状态

Render(122)
精确命中帧 122
X=1.235，Health=35
```

碎片 9 若只有 Tick 120 基线帧，它在同一 Render 调用中继续保持自己的最后姿态。玩家的新帧已经应用，碎片的末帧也仍有效，这体现按对象独立采样。

收到周期基线 8、尚未收到迟到帧 123 时，`Render(123)` 在帧 122 和 124 之间采样，玩家 X 为 `(1.235+2)/2=1.6175`。迟到帧 123 到达后，同样的 `Render(123)` 精确返回 X=1.5。乱序帧补充历史，基线编号 7 只决定解码原点，结构依然由播放时间选择。

收到结构基线 9 后，`Render(125)` 选择基线 8 的版本 4 和 `Parent=9`。若版本 4 玩家最后一帧是 124，它保持 X=2。`Render(126)` 选择版本 5 的基线 9，节点 Parent 切到 12，玩家从新姿态键采样出 X=2.5。两版本之间直接按时间线切换各自缓冲。

若接着收到回合 3、Tick 0 的完整基线，Replica 清空回合 2 的基线、时间线和姿态；pending 仅保留回合 3 的包。PlaybackClock 观测新回合后也从 Tick 0 起步。随后到达的回合 2 消息被回合检查忽略。

## 自检方法与失败检查点

按第 11 章的独立测试方式，用 `Wire.Baseline`、`Wire.Motion` 制造消息，再依表调用接收与采样方法。测试乱序时比较相同 Tick 集合的采样；测试同 Tick 覆盖时使用不同状态，核对后到状态确实生效。

| 操作 | 预期结果 | 不符合时先检查 |
| --- | --- | --- |
| 未收基线时调用 Render | 返回 null | timeline 的空集合分支 |
| 先运动 T122 后基线 T120 | pending 从 1 回到 0，Render(121) X≈1.1175、HP=100 | 是否重放队列、是否分别建立帧 120 和 122 |
| 直接 Sample(122)，再 Sample(122.5) | 命中 122 时 HP=35；没有后帧时保持完整末帧 | 精确 Tick 返回分支、末帧分支 |
| 相同两帧按 122、120 与 120、122 顺序 Push | Sample(121) 结果相同 | 是否使用 SortedList 按 Tick 排序 |
| 同 Tick 两次 Push 不同位置 | Count 不增加，采样返回后到的位置 | 索引覆盖赋值 |
| 同 V4、Id5、Gen1 应用周期基线 8 | 继续使用同一缓冲；早于基线 8 的 Tick 仍可采样旧帧 | poses 键是否错误包含 Baseline，是否错误清空缓冲 |
| 新版本 V5 中沿用 Id5、Gen1 | 新建 `(5,5,1)`；125 与 126 按时间线使用各自版本 | Render 所选 Version 和 Push 的键 |
| 同版本里用 Gen2 的合法基线替换 Id5 | Gen1、Gen2 对应独立键，按所选基线的 Gen 采样 | 是否只按 Id 查姿态 |
| 另一对象没有新运动帧 | 它保持末帧，已有新帧的玩家独立更新 | 是否错误等待整批分包或使用整包共享姿态 |
| 缺基线的运动连续到达 129 包 | PendingCount=128，第一包被淘汰，NeedsBaseline=true | 队列满额删除位置与 Rules.MaxPending |
| 给一个 PoseBuffer 连续 Push Tick 0 至 32 | Count=32；最早保存 Tick 为 1，Sample(0) 返回帧 1 | RemoveAt(0) 和端点采样 |
| 同回合连续应用 9 个递增编号、递增 Tick 的基线 | 解码缓存和时间线各保留 8 条；退出时间线的版本姿态被回收 | 两处淘汰规则和 liveVersions |
| 新 PlaybackClock 观测 Tick 120 | Tick 立即为 120；三次上述 Advance 后约为 122 | 起始赋值、调速条件和 newest+2 封顶 |
| 只收一帧且长期停包 | 时钟封顶，姿态保持最后位置 | 时钟 Advance 与 PoseBuffer.Sample 的职责是否混淆 |
| 基线只恢复部分 pending 所需编号 | 其他包重新入队，NeedsBaseline 再次为 true | 重放是否再次经过 ReceiveMotion |

容量需要逐项解释：baselines 至多 8 个编号、timeline 至多 8 个 Tick、每个 PoseBuffer 至多 32 帧、pending 至多 128 包。`poses.Count` 统计版本与身份组合，代码按退出时间线的版本回收，没有单独按身份总数执行固定容量淘汰。同版本内不断引入新身份时，旧身份键仍随该版本保留。服务器的对象预算与生命周期版本管理由第 06、08 章负责。
