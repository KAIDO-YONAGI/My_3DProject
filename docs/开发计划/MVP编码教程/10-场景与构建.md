# 10 场景与构建

本章把 01 至 09 章的代码连接成可运行的教程场景。完成后，用一个有窗口的服务器和两个独立客户端验证连接，再进入第 12 章的实验。

操作环境为 Unity `2022.3.62f3c1`、Input System `1.14.2`、URP `14.0.12` 和工程内的 Mirror。教程资产统一放在 `Assets/MvpTutorial/`；构建放在 `D:/Unity/Releases/MvpTutorial/Windows/`。独立目录让教程场景、运行日志和工程玩法有明确的对应位置。

## 先对上当前工程的配置

先停止 Play，保存正在编辑的场景。当前游戏采用 `InitialScene` → `PersistentScene` → `MultiplayerSampleScene` 的启动链，教程直接打开独立 `MvpArena`，由按钮选择 Server、Client 或 Host。

| 配置项 | 当前游戏 | 本章练习 |
| --- | --- | --- |
| 网络管理器与玩家 | `Assets/Core/Prefabs/NetworkManager.prefab`、`NetworkPlayer.prefab` | 新建 `MvpRoot` 与 `MvpBody.prefab` |
| 输入后端 | `Input System Package (New)` | 沿用该配置，教学按键使用 `Keyboard.current` |
| KCP 端口 | UDP `7777` | 在教程组件上设为 UDP `7787`，三进程一致 |
| 渲染管线 | 工程已有 URP 配置 | 沿用管线，单独创建教学材质 |
| 构建场景 | 当前游戏的四个场景 | 构建教程时启用 `MvpArena`，完成后恢复原列表 |
| 输出位置 | `D:/Unity/Releases/3D_MultiplayerGame/` | `D:/Unity/Releases/MvpTutorial/Windows/` |

`MvpRoot` 的每个组件都来自前面章节的完整文件。现有 `NetworkManager.prefab` 带有自己的自动连接逻辑；教学场景只放下文创建的管理器与组件。两套运行职责对照见 [00 导读](00-从当前项目开始.md)。

## 1. 确认代码与输入设置

1. 在 Project 窗口创建 `Assets/MvpTutorial/Core` 和 `Assets/MvpTutorial/Unity` 两个文件夹。
2. 把 01 至 04 章标记为 `Core/` 的四个完整文件放入前一个目录。把 05 至 09 章标记为 `Unity/` 的完整文件放入后一个目录，包括 `MvpWorld.cs`、`MvpWorld.Players.cs` 和 `MvpWorld.Gameplay.cs`。这三个文件共同声明同一个 `partial` 类，Unity 编译时需要同时存在。
3. `Tests/Program.cs` 放在第 11 章的系统临时工程中。它的 `Main` 是控制台入口，与 Unity 场景组件分别编译。
4. 打开 `Window > General > Console`，开启 Error 显示，等待脚本编译结束。从第一条红色错误开始处理，双击进入对应文件。一次修正后等编译完成，再检查下一条。
5. 打开 `Window > Package Manager`，在 `In Project` 中检查 Input System 和 Universal RP 的版本。Mirror 使用工程内的插件。
6. 打开 `Edit > Project Settings > Player > Other Settings > Configuration`，确认 `Active Input Handling` 保持当前工程的 `Input System Package (New)`。教学代码和现有角色输入都使用这个后端。

**检查点：** Console 没有 C# 编译与 Mirror Weaver 错误；Project 中可以找到 `MvpNetwork`、`MvpWorld`、`MvpView` 和 `MvpBody`。角色按键由 `Keyboard.current` 读取，Input System 提供这条输入链所需的设备。

详细的核心测试与 Unity 编译检查见 [自动验证](11-自动验证.md)。先通过编译，再配置组件，能避免把缺失类型误判为 Inspector 配置错误。

## 2. 创建统一网络 Prefab

这个 Prefab 提供网络身份。角色、炸弹、碎片共用它，形状和服务器物理组件由代码按 `BodyKind` 创建。

1. 在 Hierarchy 空白处右键，选择 `Create Empty`，命名为 `MvpBody`。
2. 选中对象，在 Transform 组件菜单选择 `Reset`。确认 Position 为 `0, 0, 0`，Rotation 为 `0, 0, 0`，Scale 为 `1, 1, 1`。
3. 点击 `Add Component`，添加 Mirror 的 `Network Identity`，再添加教程的 `MvpBody`。
4. 检查 `Network Identity` 的 `Server Only` 保持关闭。客户端需要收到对象身份，随后才能为它建立显示根。
5. 保持 `MvpBody.Generation` 为 `1`。`Id`、`Round` 和 `Kind` 由服务器在生成前赋值，Inspector 中的初始值保持默认。
6. 将 Hierarchy 的对象拖到 Project 的 `Assets/MvpTutorial/` 目录，生成 `MvpBody.prefab`。
7. 双击 Prefab 进入 Prefab Mode，检查根对象上的组件为 Transform、Network Identity、MvpBody。根对象的一个网络身份覆盖它的运行时形状。
8. 退出 Prefab Mode，删除 Hierarchy 中用于制作 Prefab 的实例，保留 Project 中的 Prefab 资产。

**为什么采用空根：** `AddPlayer` 给玩家添加 `CharacterController`，`ThrowBomb` 与 `Fracture` 给物理对象添加 `Rigidbody`。空根让每种对象只得到自己的控制方式。客户端通过完整基线创建显示形状，代码关闭这些显示形状的碰撞器。

对照现有 `NetworkPlayer.prefab`，可以看到它还承担正式角色运动、变换同步、角色编号、运动表现和音频同步。本教程采用空根模板，把运动交给服务器 `MvpWorld`，把位置显示交给 `MvpView`。按本节从空对象制作模板，才能让各对象使用教程规定的控制链。

**检查点：** Project 中存在 `MvpBody.prefab`，场景中没有制作时的实例。Prefab 根上只有一个 Network Identity，且 `MvpBody` 脚本引用有效。

## 3. 创建场景和入口

1. 选择 `File > New Scene`，使用 Basic 场景。保留 Main Camera 和 Directional Light。选择 Empty 模板时，手动通过 `GameObject > Camera` 与 `GameObject > Light > Directional Light` 创建它们。
2. 选择 `File > Save As`，保存为 `Assets/MvpTutorial/MvpArena.unity`。
3. 在 Hierarchy 创建空对象 `MvpRoot`，Reset Transform。
4. 给 `MvpRoot` 添加 `MvpNetwork`、`MvpWorld`、`MvpView` 和 `KcpTransport` 四个组件。`MvpNetwork` 继承 NetworkManager，承担连接和生成玩家的工作。
5. 按下表拖拽组件或资产。组件引用从 Hierarchy 拖入 `MvpRoot`，Unity 按字段类型取得组件；Prefab 引用从 Project 拖入资产。

| 组件与字段 | 填法 | 含义与检查点 |
| --- | --- | --- |
| `MvpNetwork.World` | `MvpRoot` 的 `MvpWorld` | 服务器启动后调用这个世界的 `Begin`，生成平台并推进模拟 |
| `MvpNetwork.View` | `MvpRoot` 的 `MvpView` | 客户端启动后把网络消息交给这个显示器 |
| `MvpNetwork.BodyPrefab` | `MvpBody.prefab` | 服务器创建玩家、炸弹、碎片时实例化的模板 |
| 继承的 `Player Prefab` | 同一个 `MvpBody.prefab` | Mirror 为连接准备玩家身份并注册玩家模板 |
| 继承的 `Transport` | `MvpRoot` 的 `KcpTransport` | 管理器通过该传输收发网络消息 |
| `MvpView.Manager` | `MvpRoot` 的 `MvpNetwork` | 界面的 Client、Host、Server 按钮调用这个管理器 |
| `Network Address` | `localhost` | Client 按钮连接的服务器地址，本机三个进程使用此值 |
| `KcpTransport.Port` | `7787` | 教程 UDP 监听与连接端口，三个进程保持一致 |
| `Auto Create Player` | 勾选 | 客户端 Ready 后请求添加玩家，服务器调用 `OnServerAddPlayer` |
| `Offline Scene`、`Online Scene` | 留空 | 启动连接时继续使用当前竞技场 |

逐个点击引用字段，确认指向本教程资产。名称相似时，查看 Project 路径比只看对象名称更可靠。

**不会拖引用时这样区分：** `World`、`View`、`Manager`、`Transport` 都要场景中的组件，拖 Hierarchy 的 `MvpRoot`；`BodyPrefab` 和 `Player Prefab` 要可实例化模板，拖 Project 中的 `MvpBody.prefab`。字段为 None 时，先看它要求的类型，再找对应对象。

### Prefab 注册的具体检查

1. 选中 `MvpRoot`，展开 `MvpNetwork` 的玩家和 Spawn 配置区域。
2. 确认 `Player Prefab` 指向 `MvpBody.prefab`。Mirror 在客户端启动时注册 Player Prefab。
3. `Registered Spawnable Prefabs` 用于其他网络模板。本教程的三种类别共用 Player Prefab，因此该列表保持空即可。
4. 若列表中放入同一个 `MvpBody.prefab`，从列表移除重复项，保留 `Player Prefab` 字段的引用。
5. 运行时若 Console 提示找不到 Spawn Prefab 或 assetId，先核对客户端构建使用的场景与 Prefab，再核对 Player Prefab 引用。

**检查点：** 所有引用字段都有效；Hierarchy 中只有一个教程网络管理器。`MvpRoot` 的 Transform 保持单位变换，服务器固定地形与客户端显示使用同一套坐标。

## 4. 配置 URP 材质与镜头

### 材质和渲染管线

1. 打开 `Edit > Project Settings > Graphics`，查看 `Scriptable Render Pipeline Settings` 引用的 URP Pipeline Asset。
2. 打开 `Edit > Project Settings > Quality`，选择运行构建使用的质量等级，检查它的 `Render Pipeline Asset`。该字段有引用时覆盖 Graphics 的设置；留空时继承 Graphics。
3. 在 Project 的 `Assets/MvpTutorial/` 目录右键，选择 `Create > Material`，命名 `MvpArenaMaterial`。
4. 选中材质，在 Shader 下拉框选择 `Universal Render Pipeline/Lit`，Surface Type 使用 Opaque，Base Map 的颜色设为白色。
5. 选中 `MvpRoot`，把材质拖入 `MvpWorld.ArenaMaterial`。

白色材质作为公共基础。代码通过 `MaterialPropertyBlock` 设置各形状的 `_BaseColor`：固定块使用灰色与绿色，碎片使用黄色，炸弹使用红色。场景对材质的直接引用也让构建收集这个材质及着色器。

前两步用于确认当前管线引用；教学材质使用工程已有的 URP。保留 Graphics、Quality 与正式角色材质的现有配置，教材的材质引用只填到 `MvpWorld.ArenaMaterial`。

**检查点：** Inspector 中材质预览正常，Arena Material 引用有效。运行画面出现粉色时，按 Shader、Graphics 管线资产、当前 Quality 管线资产的顺序检查。运行画面全黑时，检查 Directional Light、Camera 的 Culling Mask 与实际渲染管线。

### 灯光和摄像机

1. 选中 Directional Light，Rotation 填 `50, -30, 0`，确认对象和 Light 组件启用。
2. 选中 Main Camera，Position 填 `0, 13, -15`，Rotation 填 `38, 0, 0`。
3. Camera 的 Projection 选择 Perspective，Field of View 填 `60`，Clipping Planes 的 Near 填 `0.1`、Far 填 `100`。
4. Culling Mask 选择 Everything，Target Display 选择 Display 1。在 URP 相机的 Environment 设置中，Background Type 选择 Solid Color，背景设为浅灰。
5. 打开 Game 窗口，比例选择 `16:9`。平台在启动服务器后由代码生成，此时先检查摄像机视角与背景。
6. 保存场景。

平台中心约在世界坐标 `0, 2, 0`，两名玩家从平台两端出生。这个镜头向下覆盖整个平台。界面固定在窗口左上角，建议构建窗口至少 `960 × 540`，便于同时查看数据和操作。

## 5. 在编辑器做一次 Host 检查

1. 确认打开的是 `MvpArena`，点击 Play。
2. 在 Game 窗口左上角点击 `Host`。Host 同时运行服务器和本地客户端，便于确认组件引用。
3. 等待角色落到平台，先按 A、D 小幅移动，再点按空格。点按 E 后，观察红色炸弹和爆炸闪光。
4. 打开 Console，查看本次运行产生的第一条错误。若出现 `NullReferenceException`，双击调用栈定位具体字段，再回到第三节逐项核对引用。
5. 停止 Play，保存场景。

**检查点：** Host 能生成平台与玩家，键盘可以控制角色。Host 的本地画面直接显示服务器几何；两个独立 Client 的显示与网络链路在下一节检查。

## 6. 构建到独立输出目录

Build Settings 和 Player Settings 属于整个 Unity 工程。先记录下表及当前窗口、后台运行、Development Build、Script Debugging、构建平台设置，再配置教学构建。`EditorBuildSettings.asset` 当前启用的场景顺序如下：

| 顺序 | 当前启用场景 |
| --- | --- |
| 0 | `Assets/Core/Scenes/InitialScene.unity` |
| 1 | `Assets/Core/Scenes/PersistentScene.unity` |
| 2 | `Assets/Core/Scenes/MultiplayerSampleScene.unity` |
| 3 | `Assets/Core/Scenes/MultiplayerSampleScene 1.unity` |

1. 打开 `File > Build Settings`，核对并记录实际的场景顺序与勾选状态。
2. 使用 `Add Open Scenes` 加入 `MvpArena`，将它放在列表最前面并勾选，取消其他场景的勾选。exe 从唯一启用的竞技场进入教程按钮界面。
3. Platform 选择 `PC, Mac & Linux Standalone`，Target Platform 选择 Windows，Architecture 选择 `x86_64`。需要切换平台时点击 `Switch Platform`，等资源导入与编译结束。
4. 点击 `Player Settings`。在 `Resolution and Presentation` 中设置 Fullscreen Mode 为 Windowed，默认宽高为 `960` 和 `540`，勾选 `Run In Background`。切换到另一个窗口时，后台进程继续模拟和接收消息。
5. 回到 Build Settings，勾选 `Development Build`。需要第 12 章的变量断点时同时勾选 `Script Debugging`。Profiler 连接开发构建后可以记录真实运行的物理和脚本耗时。
6. 点击 `Build`，在独立目录 `D:/Unity/Releases/MvpTutorial/Windows/` 中指定 `MvpTutorial.exe`。
7. 等 Build 完成，检查该目录内同时存在 exe、`MvpTutorial_Data` 与 Unity 的相关运行库。运行与复制构建时保持这些文件一起。
8. 按构建前的记录恢复 Scenes In Build 的场景顺序和勾选状态，以及本节调整的 Player Settings、开发构建选项与平台。恢复后的正式项目入口是 `InitialScene`；已经生成的教程 exe 仍从打包进去的 `MvpArena` 启动。继续做编辑器教程实验时，直接打开 `MvpArena`。

学习用服务器与客户端使用同一个有窗口的 Windows 构建，通过启动界面选择身份。Server 按钮调用 `StartServer`。命令行 `-batchmode` 会使教程 `OnGUI` 跳过按钮界面；本章采用窗口化三进程操作。

正式项目的专用服务器构建与启动方式见 [Mirror 与 KCP 配置](../../../Y_MultipleAgentWorkflow/Project/Mirror_KCP_Config.md)。本章生成的是通过按钮启动的教学 Windows 程序，启动方式以本节和下一节为准。

## 7. 启动一个 Server 和两个 Client

打开 PowerShell 7，完整执行以下命令。重复实验前先关闭上一组窗口。`-logFile` 为每个进程分别保存 Unity 日志，便于确认哪一个进程发生错误。

```powershell
$ErrorActionPreference = 'Stop'
$buildDir = 'D:/Unity/Releases/MvpTutorial/Windows'
$exe = Join-Path $buildDir 'MvpTutorial.exe'
if (-not (Test-Path -LiteralPath $exe)) { throw "找不到构建：$exe" }
$logDir = Join-Path $buildDir 'Logs'
New-Item -ItemType Directory -Path $logDir -Force | Out-Null
$processes = foreach ($name in @('server', 'client-a', 'client-b')) {
    $log = Join-Path $logDir "$name.log"
    Start-Process -FilePath $exe -WorkingDirectory $buildDir `
        -ArgumentList @('-screen-fullscreen', '0', '-screen-width', '960',
                        '-screen-height', '540', '-logFile', "`"$log`"") -PassThru
}
$processes | Select-Object Id, ProcessName
```

1. 保留终端中的三个进程 ID。把窗口移开，使每个窗口的左上角都能看到。
2. 在第一个窗口点击 `Server`，将它标为 S。观察它显示 `Send ... B / Step ... ms`，服务器画面出现固定平台。纯 Server 的 `Round/Tick` 顶行来自客户端接收器与播放时钟；服务器实际时间从调试器读取 `MvpWorld.Round` 和 `Tick`。
3. 在第二个窗口的地址框填 `localhost`，点击 `Client`，将它标为 A。等平台、一个玩家和该玩家的 HP 行出现。
4. 在第三个窗口重复地址与 Client 操作，将它标为 B。两个客户端应都显示两名玩家的 HP/Score 行。
5. 点击 A 窗口让它获得键盘焦点，按 A 或 D 小幅移动。B 也能看见同一个玩家移动。再切换到 B，控制它自己的玩家。
6. 记录玩家编号与窗口的对应关系。独立客户端的角色都显示青色，用 `Player <Id>` 和移动响应辨认拥有者。

### 连接失败时按顺序检查

1. **服务器是否启动：** S 上有 `Send/Step`，查看 `Logs/server.log` 的第一条异常。打开窗口后需要点击 Server 才开始监听。
2. **地址与端口是否一致：** 本机使用 `localhost`，所有教程构建的 Kcp Port 使用 `7787`。当前正式项目使用 `7777`，核对正在运行的窗口和构建路径。跨电脑时填服务器电脑的局域网 IPv4，并让系统防火墙允许构建的 UDP 通信。
3. **是否有玩家：** 客户端 Receive 值增长但缺少玩家时，检查 Auto Create Player、Player Prefab 和服务器 AddPlayer 调用栈。
4. **是否只有图形异常：** 客户端能显示玩家数据却看不到模型时，检查相机、材质与日志中的 Spawn 错误。
5. **是否只有输入异常：** 先点客户端窗口取得焦点，再检查 Active Input Handling、`Keyboard.current` 和 `NetworkClient.localPlayer`。

查看某个进程日志时执行：

```powershell
Get-Content -LiteralPath 'D:/Unity/Releases/MvpTutorial/Windows/Logs/client-a.log' -Tail 80
```

关闭程序使用窗口关闭按钮。运行验收后再次修改代码或场景时，重新构建并使用同一组新构建启动三进程。
