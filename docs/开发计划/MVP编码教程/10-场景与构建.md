# 10 接入现有启动场景并设置构建

本章把玩法接进现有启动链。保留 `InitialScene`、`PersistentScene`、`MultiplayerSampleScene` 及工程现有的第四个构建场景；不新建启动场景，不更换 NetworkManager、NetworkPlayer、端口或角色。

## 1. 保持现有启动链

在 Project 窗口确认当前启动顺序：

1. `InitialScene` 通过 `InitialLoad` 进入 `PersistentScene`。
2. `PersistentScene` 中的现有 `SceneChanger` 以 Additive 方式加载 `MultiplayerSampleScene`。
3. 玩法对象 `ArenaSceneBootstrap`、`ArenaMatchBootstrap` 和五个 `Floor` 原点都放在 `MultiplayerSampleScene`。
4. `NetworkManager` 继续由 `PersistentScene` 中现有的 `NetworkManager.prefab` 提供。

打开 `MultiplayerSampleScene`，在 Hierarchy 的搜索框输入 `t:NetworkStartPosition`，找到两个现有出生点。把它们分别放到开局平台上方，例如 `(-1.5, 21, 0)` 和 `(1.5, 21, 0)`。Mirror 首次生成玩家时使用这些位置；回合开始后，服务器再通过 `ArenaPlayerActions.ServerReset` 将玩家分散到开局平台的中心 3×3 格。

## 2. 清理会接住玩家的场景地面

打开 `Assets/Core/Scenes/TestScenes/MultiplayerSampleScene.unity`。在 Hierarchy 找出原先的测试地板、Terrain 或带 Collider 的场景地面。如果它们位于五层平台下方并会挡住角色，应在 Inspector 关闭对应 GameObject 的激活勾选。保留需要的灯光、天空和其他视觉环境；不要删除项目素材。

检查五个层级原点的高度依次为 20、16、12、8、4，`ArenaSceneBootstrap.PlayerSpawn` 在第一层上方。`VoidY` 设在最底层以下，例如 `-8`，并确认关闭地面后玩家能落出场景。

## 3. 连接场景组件和 Prefab

在 `MultiplayerSampleScene` 的 `ArenaSceneBootstrap` 根物体上确认：

- `ArenaSceneBootstrap` 的 `Platform Prefab` 指向第 04 章的 `PlatformChunk.prefab`。
- `Floor Origins` 按 `Floor_0` 到 `Floor_4` 顺序放入五个子物体。
- `Player Spawn` 指向第一层上方的出生点。
- `ArenaMatchBootstrap` 的 `Match Prefab` 指向 `ArenaMatch.prefab`。
- `ArenaMatch.prefab` 上 `ArenaMatch.Pickup Prefab` 指向 `ArenaPickup.prefab`。

打开现有 `NetworkManager.prefab`：

- `Player Prefab` 保持 `Assets/Core/Prefabs/NetworkPlayer.prefab`。
- `Spawnable Prefabs` 包含 `PlatformChunk.prefab`、`ArenaMatch.prefab` 和 `ArenaPickup.prefab`。
- `KcpTransport` 继续使用端口 `7777`。
- `NetworkManager.Network Address` 保持本机练习地址 `127.0.0.1`，`AutoStartClient` 从管理器读取该地址并连接。
- Dedicated Server 继续使用现有 Headless 启动配置自动调用 `StartServer`。

网络玩家 Prefab 保留现有 `NetworkIdentity`、`NetworkTransformReliable`、`PlayerCharacterController`、角色模型和相机；本教程只在根对象追加游戏组件。玩法场景中不放第二个 NetworkManager，也不另建玩家 Prefab。

## 4. 保留构建场景与输出位置

当前项目使用 Unity 2022.3。在顶部菜单打开 `File > Build Settings`，确认 `Scenes In Build` 中勾选工程已有的四个场景，并保留原有顺序：

1. `Assets/Core/Scenes/InitialScene.unity`
2. `Assets/Core/Scenes/PersistentScene.unity`
3. `Assets/Core/Scenes/TestScenes/MultiplayerSampleScene.unity`
4. `Assets/Core/Scenes/TestScenes/MultiplayerSampleScene 1.unity`

普通客户端继续从排在第一位的 `InitialScene` 进入。两种程序分别输出到：

```text
D:/Unity/Releases/3D_MultiplayerGame/Server
D:/Unity/Releases/3D_MultiplayerGame/Client
```

### 构建服务器

1. 保存修改过的场景和 Prefab，等待 Console 中没有编译错误。
2. 在 `Build Settings` 左侧选择 `Dedicated Server`，目标平台选 `Windows`。
3. 点击 `Switch Platform`，等待 Unity 完成切换。
4. 点击 `Build`，输出到上面的 `Server` 目录。构建前关闭正在运行的旧服务器，避免输出文件被占用。

### 构建客户端

1. 在同一窗口左侧选择 `PC, Mac & Linux Standalone`，目标平台选 `Windows`。
2. 点击 `Switch Platform`，等待切换完成。
3. 再检查四个场景都已勾选，点击 `Build`，输出到上面的 `Client` 目录。

服务器和客户端都使用刚保存的场景、脚本和网络 Prefab。涉及网络组件的修改完成后，重新构建两端，再启动游戏。启动配置、地址和端口的位置见 [Mirror_KCP_Config.md](../../../Y_MultipleAgentWorkflow/Project/Mirror_KCP_Config.md)；本机练习沿用 `127.0.0.1:7777`。
