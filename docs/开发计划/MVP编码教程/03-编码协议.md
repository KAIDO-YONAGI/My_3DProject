# 03 网络平台与破坏

本章把格子列表接到 Mirror 网络对象上。你会做出一个 `PlatformChunk`：一份格子数据对应一个平台根物体，根物体带一个 Rigidbody，格子 Cube 作为它的子物体。

先记住运行分工：

- 服务器修改格子列表、固定状态和 Rigidbody。
- 每个客户端根据收到的格子列表创建可见 Cube。
- 平台根物体的位置和旋转由服务器同步给客户端。

## 1. 建立平台对象和需要保存的数据

在 `Assets/Core/Scripts/Gameplay/Mvp/` 创建 `PlatformChunk.cs`。先声明对象组件、网络数据和运行时引用：

普通 Unity 组件继承 `MonoBehaviour`；这里继承 Mirror 的 `NetworkBehaviour`，因为平台需要网络生命周期和字段同步。`RequireComponent` 告诉 Unity，这个脚本所在的同一个物体上还需要哪些组件。

```csharp
using System.Collections.Generic;
using Mirror;
using UnityEngine;
using UnityEngine.SceneManagement;

namespace Core.Scripts.Gameplay.Mvp
{
    [RequireComponent(
        typeof(NetworkIdentity),
        typeof(Rigidbody),
        typeof(NetworkTransformReliable))]
    public sealed class PlatformChunk : NetworkBehaviour
    {
        // Cells 是这片平台当前保留的格子编号。
        public readonly SyncList<int> Cells = new SyncList<int>();

        // 固定平台为 true；脱落后改为 false，由服务器刚体计算下落。
        [SyncVar] public bool Anchored = true;
        // 开局九格小平台整片脱落，其余平台按命中范围删格子。
        [SyncVar] public bool IsOpening;
        // 从 0 开始数楼层：0 是第一层，2 是第三层。
        [SyncVar] public int Layer;
        // 新一局换编号，规则据此区分本局平台与其他对象。
        [SyncVar] public uint RoundId;

        // 每个 PlatformChunk 启动或停止服务器生命周期时登记、移除自己。
        public static readonly HashSet<PlatformChunk> ServerChunks =
            new HashSet<PlatformChunk>();

        [SerializeField] private Material cellMaterial;
        [SerializeField] private PlatformChunk fragmentPrefab;

        private readonly List<GameObject> generatedCells = new List<GameObject>();
        private Rigidbody body;
        private bool clientShapeDirty;
        private bool retiring;

        public Rigidbody Body
        {
            get
            {
                if (body == null)
                    body = GetComponent<Rigidbody>();

                return body;
            }
        }
    }
}
```

这些字段各有一个用途：`Cells` 说清这片平台由哪些格子组成；`Anchored` 说它是否仍固定；`Layer` 和 `RoundId` 供对局规则辨认楼层与局数。`Body` 缓存根节点的 Rigidbody，后面乘客和碎片代码都会用它。

`ServerChunks` 是服务器当前平台集合，供后续对局规则查找平台。它只在网络对象进入或离开服务器时维护。`generatedCells` 则只记录本机创建的 Cube，清理时不会误删这个物体下其他组件创建的对象。

## 2. 让客户端从格子编号画出平台

客户端加入时，Mirror 会先把服务器当前的 `Cells` 状态放到网络对象上，然后调用 `OnStartClient`。所以初始化形状要遍历当前列表；后续格子变化才由 `OnChange` 监听。

把下面这些成员加进 `PlatformChunk` 类中，放在 `Body` 属性后、类的最后一个 `}` 前：

```csharp
public override void OnStartServer()
{
    ServerChunks.Add(this);
    ApplyPhysicsMode();
}

public override void OnStopServer()
{
    ServerChunks.Remove(this);
}

public override void OnStartClient()
{
    if (isServer)
        return;

    // 客户端只显示服务器物理结果，不自行计算平台下落。
    Body.isKinematic = true;
    RebuildClientShape();
    Cells.OnChange += OnCellsChanged;
}

public override void OnStopClient()
{
    Cells.OnChange -= OnCellsChanged;
}

private void OnCellsChanged(SyncList<int>.Operation operation, int index, int item)
{
    // 一帧可能删掉多个格子，先记下“需要刷新”，到帧末只重建一次。
    clientShapeDirty = true;
}

private void LateUpdate()
{
    if (!isServer && clientShapeDirty)
    {
        clientShapeDirty = false;
        RebuildClientShape();
    }
}
```

`OnChange` 只把 `clientShapeDirty` 设成 `true`，不在每次网络列表变动时立刻重画。一次分裂可能连续移除多个格子；集中到 `LateUpdate` 重建，可以避免同一帧反复销毁和创建 Cube。

接着把形状生成与清理方法也加在类中：

```csharp
private void RebuildClientShape()
{
    ClearGeneratedCells();

    foreach (int cellId in Cells)
    {
        GameObject cell = GameObject.CreatePrimitive(PrimitiveType.Cube);
        cell.name = $"Cell_{cellId:00}";
        cell.transform.SetParent(transform, false);
        cell.transform.localPosition = PlatformLayout.PositionOf(cellId);
        cell.transform.localScale = new Vector3(
            PlatformLayout.CellSize,
            PlatformLayout.Thickness,
            PlatformLayout.CellSize);
        cell.GetComponent<MeshRenderer>().sharedMaterial = cellMaterial;
        generatedCells.Add(cell);
    }
}

private void ClearGeneratedCells()
{
    foreach (GameObject cell in generatedCells)
    {
        if (cell != null)
            Destroy(cell);
    }

    generatedCells.Clear();
}
```

服务器配置平台时也要创建同样的 Cube，因为服务器需要这些 Collider 来处理落地和射线命中。为避免两端写两套生成逻辑，稍后由服务器配置方法调用 `RebuildClientShape`；这个方法的名字可以理解为“按当前格子数据重建形状”，并不只供客户端调用。

`GameObject.CreatePrimitive(Cube)` 会创建 MeshRenderer 和 BoxCollider。每个 Cube 都是根物体的子物体，格子位置使用局部坐标；整组平台移动时只需同步根节点。

## 3. 在 Spawn 前设置服务器状态

`ArenaSceneBootstrap` 会先在服务器实例化 Prefab，再配置它，最后 `NetworkServer.Spawn`。这段顺序很重要：客户端第一次看到对象时，格子数据和 SyncVar 已经准备好。

在 `PlatformChunk` 类中加入：

```csharp
public void ServerConfigure(
    IEnumerable<int> cells,
    bool anchored,
    bool opening,
    int layer,
    uint round)
{
    // 格子编号和初始状态在 Spawn 前准备好，客户端首次收到就是完整形状。
    Cells.Clear();
    foreach (int cellId in cells)
        Cells.Add(cellId);

    Anchored = anchored;
    IsOpening = opening;
    Layer = layer;
    RoundId = round;

    // 服务端也要有 Collider；客户端收到数据后会各自创建外观。
    RebuildClientShape();
    ApplyPhysicsMode();
    Body.ResetCenterOfMass();
    Body.ResetInertiaTensor();
}

private void ApplyPhysicsMode()
{
    Body.useGravity = true;
    Body.isKinematic = Anchored;
}
```

调用顺序必须是：

```csharp
PlatformChunk chunk = Instantiate(platformPrefab, position, rotation);
chunk.ServerConfigure(cells, anchored, opening, layer, roundId);
NetworkServer.Spawn(chunk.gameObject);
```

`anchored=true` 时，`Rigidbody.isKinematic` 为 `true`，平台固定不受重力影响；`anchored=false` 时，刚体由服务器物理模拟。`SyncList` 和 `[SyncVar]` 会把状态发送给各客户端。

把 `fragmentPrefab` 在 Inspector 指向稍后制作的同一个 `PlatformChunk.prefab`。服务器每次分裂都用这个干净 Prefab 创建新碎片，而不是复制当前已有的 Cube 子物体。

## 4. 先实现整片平台脱落

开局平台是一个整体。玩家靠近触发炸弹后，不需要挖掉格子，服务器只要把它从固定状态切换为动态刚体。

把下面方法加入类中：

```csharp
[Server]
public void ServerDetach()
{
    Anchored = false;
    ApplyPhysicsMode();
}
```

`[Server]` 表示这是服务器逻辑。调用后，`Anchored` 同步到所有客户端；真正的重力和碰撞只在服务器计算，客户端的刚体仍保持 Kinematic。

## 5. 找出爆炸范围内的格子

普通平台被道具命中时，服务器把每个格子的中心换成世界坐标，再和爆炸中心比较。把这个方法先加入类中：

```csharp
[Server]
public void ServerBreak(Vector3 center, float radius)
{
    if (IsOpening)
    {
        ServerDetach();
        return;
    }

    if (retiring)
        return;

    float radiusSquared = radius * radius;
    var remainingCells = new List<int>();

    foreach (int cellId in Cells)
    {
        Vector3 worldCenter = transform.TransformPoint(
            PlatformLayout.PositionOf(cellId));

        if ((worldCenter - center).sqrMagnitude > radiusSquared)
            remainingCells.Add(cellId);
    }

    // 一个格子都没打中时，不创建碎片，也不改网络状态。
    if (remainingCells.Count == Cells.Count)
        return;

    ServerSplit(remainingCells);
}
```

`center` 是命中点，`radius` 是道具范围。使用平方距离比较，可以避免对每个格子调用开平方。比如范围是 `2` 米，就把距离平方和 `4` 比较：某格中心的距离平方是 `2.25`，它被移除；另一个是 `9`，它保留。`remainingCells` 里只留下没有被击中的格子。

`IsOpening` 是开局那片整块平台的标记。它被命中时整片脱落；其他平台才进入格子移除和分组流程。

## 6. 用图搜索创建新碎片

把下面方法加入类中。它把剩余格子分成多个连通组，每组创建一个新的网络平台对象：

```csharp
private void ServerSplit(List<int> remainingCells)
{
    List<List<int>> groups = PlatformGraph.Split(remainingCells);
    Rigidbody oldBody = Body;

    foreach (List<int> group in groups)
    {
        bool anchored = Anchored && ContainsAnchor(group);
        PlatformChunk fragment = Instantiate(
            fragmentPrefab,
            transform.position,
            transform.rotation);

        SceneManager.MoveGameObjectToScene(fragment.gameObject, gameObject.scene);
        fragment.ServerConfigure(group, anchored, IsOpening, Layer, RoundId);
        NetworkServer.Spawn(fragment.gameObject);

        if (!anchored)
        {
            // 新碎片继承旧平台在自身质心处的运动速度。
            fragment.Body.velocity =
                oldBody.GetPointVelocity(fragment.Body.worldCenterOfMass);
            fragment.Body.angularVelocity = oldBody.angularVelocity;
        }
    }

    // 同一帧关掉旧碰撞体，避免旧平台与新碎片重叠受力。
    retiring = true;
    foreach (Collider collider in GetComponentsInChildren<Collider>())
        collider.enabled = false;

    NetworkServer.Destroy(gameObject);
}
```

再把这个小方法加入类中，用来判断一组里是否有外边缘格子：

```csharp
private static bool ContainsAnchor(List<int> group)
{
    foreach (int cellId in group)
    {
        if (PlatformLayout.IsAnchor(cellId))
            return true;
    }

    return false;
}
```

一组格子继续固定需要同时满足两个条件：旧平台原本固定，且新组里还剩一个外边缘锚点。原本已经掉落的平台不会因为碎片后来碰到边缘就重新固定。

碎片根物体先沿用旧平台的位置和旋转，所以子格子留在原本的世界位置。每个动态碎片再继承旧刚体在自己质心处的速度和旧角速度；若只复制旧平台中心速度，旋转中的平台边缘会出现不自然的速度跳变。

## 7. 在 Unity 中接好并检查

本章脚本依赖 Prefab 上的 `NetworkIdentity`、`Rigidbody` 和 `NetworkTransformReliable`。第 04 章会逐步创建 Prefab、设置同步方向并注册到当前 `NetworkManager`。完成注册后，再由第 06 章的服务器场景脚本创建平台。

检查本章最终代码时，能沿着这条调用顺序找到每一步：

```text
ServerConfigure → 设置格子和刚体
ServerBreak → 找出被移除的格子
PlatformGraph.Split → 把剩余格子分组
ServerSplit → 为每组创建网络碎片
NetworkTransformReliable → 同步服务器算出的根节点运动
```

不要把 `ServerBreak` 直接挂到按键上。第 05 章会让现有玩家把操作请求发给服务器，再由服务器验证和调用破坏逻辑。
