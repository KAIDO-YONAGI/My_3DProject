# 08 爆炸与回合

## 本章解决的问题

同一炸弹既到期又被连锁触发，怎样保证只结算一次？旋转中的碎片再次断裂，块怎样保持世界位置？回合结束后，玩家身份、生命与分数各怎样处理？本章把投掷、爆炸队列、结构重建和回合规则连接起来。

编写 `Unity/MvpWorld.Gameplay.cs`，它是 `MvpWorld` 的第三个分部。投掷由第 07 章移动末尾调用；刚体碰撞由第 05 章转发；队列消费和回合结算由第 06 章按固定顺序调用。

## 接上当前项目：从一次性音频事件理解爆炸事件

现有 [NetworkAudioPlayer.cs](../../../Assets/Core/Scripts/Networking/Sync/NetworkAudioPlayer.cs) 通过 `CommandPlayAudio` 与 `RpcPlayAudio` 传递一次播放动作。可以借它理解“某件事发生了一次”：本章 `MvpExplosion` 记录一次爆炸，第 09 章按事件编号去重，并在播放 Tick 到达时显示闪光。

爆炸还会改变持续状态：玩家 HP 减少、连接断开、碎片出现。这些结果写进服务器世界，再随完整基线和运动状态同步。**事件告诉客户端“播放这次爆炸”，状态告诉客户端“爆炸以后世界是什么样”。**

先这样读：

1. `ThrowBomb`：按服务器玩家姿态生成炸弹，记下引信时间。
2. `Explode`：先消费引信，再断连接、重组碎片、结算作用，最后发事件。
3. `Fracture`：先保存旧世界位置，再建立新根和局部坐标。
4. `FinishTick / ResetRound`：看谁获胜、何时重开、保留哪些玩家数据。

遇到 `Structure.Cut` 回第 02 章看分组，遇到 `NewBody / RemoveBody` 回第 06 章看生命周期，遇到 `Damage` 回第 07 章看生命变化。首次阅读可先跳过 `Fracture` 中速度继承的细节，把投掷到回合重开的调用链走通。教学职责与正式工程的对应关系见 [00 导读](00-从当前项目开始.md)。

## 数据与职责

| 数据或函数 | 具体职责 | 时间与归属 |
|---|---|---|
| `ThrowBomb` | 由角色姿态计算出生位置与初速度 | 玩家本步移动后执行 |
| `fuses` | 炸弹编号 → 引信到期 Tick；同时充当单次结算门 | 投掷写入，`Explode` 先移除 |
| `bombSources` | 炸弹编号 → 投掷者编号 | 投掷登记，移除炸弹时清理 |
| `causes` | 炸弹编号 → 当前触发来源 | 投掷者初始化；碎片或连锁炸弹覆盖 |
| `Impact` | 高速碎片撞击炸弹时修改来源并入队 | `Physics.Simulate` 中的碰撞回调 |
| `Explode` | 断边、伤害、刚体冲量、连锁、可靠事件、移除炸弹 | 队列消费阶段 |
| `Fracture` | 保存世界状态、移除旧根、按新分量重建归属 | 爆炸中的结构步骤 |
| `roundStart / endTick` | 回合计时起点与重开时刻 | `FinishTick` 在物理模拟后更新 |

`bombSources` 保存投掷者，`causes` 保存触发来源，`MvpExplosion.Source` 从 `causes` 取值。回合分数由最后存活者取得，伤害入口接收伤害量与冲击向量；这两张来源字典在当前代码中承担记录与事件展示职责。

## 编写步骤

1. 写 `ThrowBomb` 的四项限制：结算等待期、15 Tick 间隔、16 枚引信上限和对象预算余量。
2. 写炸弹的服务器位置、形状、刚体和初速度，填写引信及来源，然后调用 `NetworkServer.Spawn`。
3. 写 `Impact`，只把有效炸弹编号送入队列；与第 06 章的物理前后顺序对照。
4. 写 `Explode`，第一条检查先移除引信；在重建结构之后遍历当前对象，最后发送事件并移除炸弹。
5. 写 `Fracture`，严格保持“保存世界状态 → 删除旧根 → 创建新根与局部坐标 → 重建固定形状”的顺序。
6. 写 `FinishTick / ResetRound`，区分保留的玩家根与移除的临时物体。

## 完整代码

```csharp file=Unity/MvpWorld.Gameplay.cs
using System.Collections.Generic;
using System.Linq;
using Mirror;
using UnityEngine;

namespace Mvp
{
    public sealed partial class MvpWorld
    {
        // 至少两名玩家登记后开始计时；0 表示尚未建立回合计时起点。
        uint roundStart;
        // 触发来源可由碎片或连锁炸弹覆盖，与原始投掷者记录分开。
        readonly Dictionary<uint, uint> causes = new Dictionary<uint, uint>();

        // 消费投掷位时调用；服务器根据当前角色姿态决定炸弹初始状态。
        void ThrowBomb(Player p)
        {
            // 等待重开、冷却未到、引信过多或碎片预算余量不足，都跳过本次投掷。
            if (endTick != 0 || Tick - p.LastThrow < 15 || fuses.Count >= 16 ||
                bodies.Count >= Rules.MaxBodies - 25) return;
            p.LastThrow = Tick;
            var t = p.Body.transform;
            // 从脚部上方 1.2 米、前方 0.8 米处出生；客户端没有提交生成坐标。
            var b = NewBody(BodyKind.Bomb, t.position + Vector3.up * 1.2f + t.forward * .8f);
            Shape(PrimitiveType.Sphere, b.transform, Vector3.zero, Vector3.one * .45f, Color.red, true);
            // 球形刚体的投掷初速叠加角色本步求解速度，采用连续动态碰撞检测。
            var rb = b.gameObject.AddComponent<Rigidbody>();
            rb.mass = .6f; rb.collisionDetectionMode = CollisionDetectionMode.ContinuousDynamic;
            rb.velocity = t.forward * 7 + Vector3.up * 4 + p.Velocity;
            // 45 Tick 引信约为 1.5 秒；最初触发来源与投掷者相同。
            fuses[b.Id] = Tick + 45; bombSources[b.Id] = p.Body.Id; causes[b.Id] = p.Body.Id;
            // 身份、形状、刚体与字典都建立后，再生成 Mirror 网络对象。
            NetworkServer.Spawn(b.gameObject);
        }

        // 刚体碰撞只改来源并入队，爆炸结算由世界的队列阶段统一执行。
        public void Impact(MvpBody body, Collision collision)
        {
            if (body.Kind != BodyKind.Bomb || !fuses.ContainsKey(body.Id)) return;
            // 只接受仍有引信的炸弹与碎片的高速碰撞；普通地面碰撞保留引信。
            var other = collision.collider.GetComponentInParent<MvpBody>();
            if (other != null && other.Kind == BodyKind.Fragment && collision.relativeVelocity.magnitude > 4)
            {
                causes[body.Id] = other.Id;
                explosions.Enqueue(body.Id);
            }
        }

        // 引信移除成功代表取得本枚炸弹的唯一结算资格，重复队列项直接返回。
        void Explode(uint id)
        {
            if (!fuses.Remove(id) || !bodies.TryGetValue(id, out var bomb)) return;
            Vector3 center = bomb.transform.position;
            // 来源优先取当前触发记录，事件记录其编号；中心取服务器当前实物位置。
            uint source = causes.TryGetValue(id, out var cause) ? cause : id;
            causes.Remove(id);
            // 从当前服务器几何取得爆炸范围，动态碎片采用其当前世界位置。
            // 用尚未断开的连接中点到中心的距离选边，严格小于 3.5 米才切断。
            var cuts = Enumerable.Range(0, graph.Edges.Count).Where(e =>
            {
                var edge = graph.Edges[e];
                return !graph.Broken[e] &&
                       Vector3.Distance((NodePosition(edge.A) + NodePosition(edge.B)) * .5f, center) < 3.5f;
            }).ToArray();
            // 先断裂重建，再对重建后的当前根对象计算范围与作用。
            Fracture(cuts);
            // 遍历副本以稳定本次列表；当前炸弹本身跳过，范围按根位置计算。
            foreach (var b in bodies.Values.ToArray())
            {
                if (b.Id == id) continue;
                float distance = Vector3.Distance(b.transform.position, center);
                if (distance >= 3.5f) continue;
                // 距离线性衰减用于玩家伤害和冲击，方向加入 0.7 米的向上偏置。
                float strength = 1 - distance / 3.5f;
                Vector3 direction = (b.transform.position - center + Vector3.up * .7f).normalized;
                if (players.TryGetValue(b.Id, out var p))
                    Damage(p, Mathf.CeilToInt(65 * strength), direction * (12 * strength));
                // 刚体使用 Unity 爆炸冲量入口，与玩家的数值伤害分支分别处理。
                else if (b.TryGetComponent<Rigidbody>(out var rb))
                    rb.AddExplosionForce(400, center, 3.5f, 1, ForceMode.Impulse);
                if (b.Kind == BodyKind.Bomb && fuses.ContainsKey(b.Id))
                {
                    // 连锁来源改为当前炸弹编号；世界 while 循环在本步继续消费。
                    causes[b.Id] = id;
                    explosions.Enqueue(b.Id);
                }
            }
            // 可靠事件只记录发生事实；客户端按播放 Tick 触发展示。
            NetworkServer.SendToAll(new MvpExplosion { Round = Round, Event = ++eventId,
                Tick = Tick, Source = source, Position = center }, Channels.Reliable, true);
            // 事件发出后移除当前炸弹，标记拓扑变化，步末完整基线反映最终结果。
            RemoveBody(id);
        }

        // 修改块归属前先保存世界状态，防止旧父根销毁后丢失坐标和速度依据。
        void Fracture(int[] cuts)
        {
            if (cuts.Length == 0) return;
            // Cut 在断边前取旧分量范围，再返回这些节点断边后的新分量。
            var groups = graph.Cut(cuts, true);
            if (groups.Count == 0) return;
            // affected 包含受影响旧分量的全部节点，每个节点都参与保存和重新归属。
            int[] affected = groups.SelectMany(g => g).ToArray();
            var positions = affected.ToDictionary(n => n, NodePosition);
            var oldParents = affected.ToDictionary(n => n, n => blocks[n].Parent);
            // 固定节点速度为零；动态节点保存旧刚体在该世界点的线速度与角速度。
            var velocity = affected.ToDictionary(n => n, n =>
                blocks[n].Parent == 0 ? Vector3.zero :
                bodies[blocks[n].Parent].GetComponent<Rigidbody>().GetPointVelocity(positions[n]));
            var angular = affected.ToDictionary(n => n, n =>
                blocks[n].Parent == 0 ? Vector3.zero :
                bodies[blocks[n].Parent].GetComponent<Rigidbody>().angularVelocity);
            // 保存旧根旋转，新动态根沿用同一姿态再计算 Local。
            var rotation = affected.ToDictionary(n => n, n =>
                blocks[n].Parent == 0 ? Quaternion.identity : bodies[blocks[n].Parent].transform.rotation);
            // 一个旧分量的节点全部进入重建，再释放它的旧根对象。
            // Distinct 保证同一旧根只移除一次；RemoveBody 立即停用旧几何。
            foreach (uint parent in oldParents.Values.Where(p => p != 0).Distinct())
                RemoveBody(parent);

            foreach (int[] group in groups)
            {
                // 有支撑节点且原本全部固定才继续固定；已经脱落的根继续动态化。
                bool fixedGroup = graph.Supported(group) && group.All(n => oldParents[n] == 0);
                if (fixedGroup)
                {
                    foreach (int n in group)
                        blocks[n] = new BlockState { Node = n, Parent = 0, Local = N(positions[n]) };
                    continue;
                }
                // 新根位于各节点世界位置的平均值，质量按每块 2 计算。
                Vector3 center = group.Aggregate(Vector3.zero, (sum, n) => sum + positions[n]) / group.Length;
                var body = NewBody(BodyKind.Fragment, center);
                body.transform.rotation = rotation[group[0]];
                foreach (int n in group)
                {
                    // 继承旧根旋转，再把世界点转换到新根，保持每个块的姿态。
                    Vector3 local = body.transform.InverseTransformPoint(positions[n]);
                    // blocks 写新父编号，碰撞块用同一 Local 放在新根下。
                    blocks[n] = new BlockState { Node = n, Parent = body.Id, Local = N(local) };
                    Shape(PrimitiveType.Cube, body.transform, local, new Vector3(1.45f, .5f, 1.45f),
                          Color.yellow, true);
                }
                var rb = body.gameObject.AddComponent<Rigidbody>();
                rb.mass = group.Length * 2;
                // 新根线速度取组内旧节点点速度的平均，角速度取该组首节点旧值。
                rb.velocity = group.Aggregate(Vector3.zero, (sum, n) => sum + velocity[n]) / group.Length;
                rb.angularVelocity = angular[group[0]];
                rb.collisionDetectionMode = CollisionDetectionMode.ContinuousDynamic;
                NetworkServer.Spawn(body.gameObject);
            }
            // 新旧根操作已分别增长版本，这里再登记结构归属变化并重建固定形状。
            ++Version; dirty = true;
            RebuildFixed();
        }

        // 物理模拟结束后判落场，再判回合胜负与是否到重开时刻。
        void FinishTick()
        {
            // 场下存活者走同一伤害入口；结算等待期由 Damage 拦住伤害。
            foreach (var p in players.Values)
                if (p.Body.transform.position.y < -6 && p.Health > 0)
                    Damage(p, 100, Vector3.zero);
            // 至少两名玩家才建立计时起点；判存活时使用 Health。
            if (players.Count >= 2 && roundStart == 0) roundStart = Tick;
            if (roundStart == 0) return;
            var alive = players.Values.Where(p => p.Health > 0).ToArray();
            // 仅剩至多一人或已计时 900 Tick，进入 90 Tick 的结算等待期。
            if (endTick == 0 && (alive.Length <= 1 || Tick - roundStart >= 900))
            {
                // 恰有一名存活者加 1 分，分数保存在 Player 中跨回合保留。
                if (alive.Length == 1) ++alive[0].Score;
                endTick = Tick + 90;
                dirty = true;
            }
            if (endTick != 0 && Tick >= endTick) ResetRound();
        }

        // 保留玩家网络根，移除炸弹和碎片，恢复连接图、生命与出生姿态。
        void ResetRound()
        {
            // 按非玩家编号列表移除临时根，列表副本避免遍历中修改字典。
            foreach (uint id in bodies.Keys.Where(id => !players.ContainsKey(id)).ToArray()) RemoveBody(id);
            // 新回合重置 Tick 和事件编号；玩家分数、业务编号与基线编号继续保留。
            ++Round; Tick = 0; ++Version;
            endTick = 0; roundStart = 0; lastRecovery = 0; eventId = 0;
            graph = new Structure(); explosions.Clear(); causes.Clear();
            // 全部节点重新归固定根，新的 Structure 提供全部未断连接。
            for (int n = 0; n < 24; ++n)
                blocks[n] = new BlockState { Node = n, Parent = 0, Local = graph.Rest[n] };
            RebuildFixed();
            int index = 0;
            foreach (var p in players.Values)
            {
                // 改出生位置时临时关闭控制器，完成角色状态重置后再启用。
                p.Controller.enabled = false;
                p.Body.Round = Round; p.Body.transform.position = SpawnPoint(index++);
                p.Body.transform.rotation = Quaternion.identity;
                p.Health = 100; p.Vertical = 0; p.External = Vector3.zero; p.Move = Vector3.zero;
                p.Support = 0; p.Buttons = 0; p.Velocity = Vector3.zero;
                // 清掉输入门、冷却时间和移动状态，Health 恢复 100，Score 保持原值。
                p.Gate = new InputGate(); p.LastInput = 0; p.LastThrow = 0; p.LastImpact = 0;
                p.Controller.enabled = true;
            }
            dirty = true;
        }
    }
}
```

## 手工追踪一次投掷与爆炸

设 `Tick=30`，玩家 7 的 `LastThrow=0`，脚部位置为 `(0,3,0)`，面向 `(0,0,1)`，本步 `Velocity=(0,0,5)`。预算和引信数量均允许投掷：

1. 炸弹出生于 `(0,4.2,0.8)`，初速为 `(0,4,12)`，引信到期 Tick 为 75。
2. `bombSources[id]=7`，初始 `causes[id]=7`。若在 Tick 74 的物理模拟中撞到碎片 20，且相对速度大于 4，来源变为 20，并进入队列。
3. Tick 75 的角色阶段之后，引信又把同一编号入队。第一次取出时 `fuses.Remove` 成功，保存中心与来源 20；重复项因引信已移除而返回。
4. 先根据当前连接中点切断范围内的边，再用重建后的当前根位置计算玩家和刚体作用。
5. 假设玩家 8 距中心 `1.75` 米，衰减为 `1-1.75/3.5=0.5`，伤害为 `Ceil(65×0.5)=33`，生命从 100 变为 67。传入 `Damage` 的冲击长度为 `12×0.5=6`，水平分量累加外力，向上分量累加竖直速度。
6. 范围内另一枚仍有引信的炸弹把来源设为本炸弹编号并入队，当前队列循环继续消费。每枚实际结算的炸弹各发出一个递增 `Event` 的可靠事件，再移除自身。

碰撞触发与队列消费分别位于物理模拟中、下一 Tick 物理模拟前。距离恰好为 `3.5` 米时，断边和对象作用的严格距离条件均排除该项。玩家距离取脚部根位置，刚体距离取对象根位置。

## 手工追踪一次旋转碎片断裂

设受影响的旧碎片根 20 包含相邻节点 11、12，根位置为 `(10,2,3)`，绕 Y 轴旋转 90 度。两个块的旧局部坐标分别为 `(-0.75,0,0)`、`(0.75,0,0)`。连接切断后形成两个单节点组。

1. `positions` 先保存世界坐标：节点 11 为 `(10,2,3.75)`，节点 12 为 `(10,2,2.25)`。`oldParents` 均为 20；`rotation` 均保存旧根的 90 度旋转。
2. 若旧线速度为 `(1,0,0)`，角速度为 `(0,2,0)`，旧节点点速度分别为 `(2.5,0,0)` 与 `(-0.5,0,0)`。这些值在旧根仍存在时写进 `velocity`。
3. `RemoveBody(20)` 移除业务登记并立即停用旧形状，之后 Mirror 销毁旧网络根。
4. 假设 `nextId=21`，两个新根分别取得 21、22，位置取各自单节点的世界坐标，旋转沿用 90 度。每个节点相对自己的新根 `Local=(0,0,0)`，重建块的世界位置和姿态保持一致。
5. 两个新刚体质量各为 2，线速度分别为上述两点速度，角速度均为 `(0,2,0)`。新根配置齐备后调用 `Spawn`。
6. 本例一次旧根移除、两次新根创建和末尾结构登记让 `Version` 共增加 4；`dirty` 请求本步末尾发布完整基线。

若新组仍含支撑节点，只有该组所有节点的旧父编号都为零才保持固定。动态碎片上的支撑节点编号仍属于结构图数据，代码同时检查旧父归属，保持已经脱落的组为动态根。

## 手工追踪回合结算

设两名玩家使 `roundStart=10`，Tick 100 时只剩玩家 7 存活。`FinishTick` 给玩家 7 加一分，并令 `endTick=190`。这 90 Tick 内 `ThrowBomb` 和 `Damage` 通过 `endTick` 条件限制投掷与伤害，世界的物理模拟、引信与爆炸队列仍按 `FixedUpdate` 执行。

Tick 190 到达重开条件后，移除全部非玩家根，`Round` 增长，`Tick` 归零，连接图恢复，玩家生命回到 100，输入门与冷却归零。玩家网络根、`Id` 和 `Score` 保留，玩家 `Round` 更新。当前 `FixedUpdate` 随后发布新回合 Tick 0 的完整基线；因为 0 是偶数，运动发送条件也成立。

## 预期与排查

| 检查动作 | 代码对应的预期 | 优先检查位置 |
|---|---|---|
| 相同炸弹多次入队 | 一次伤害、一次事件、一次根移除 | `Explode` 首句的引信移除 |
| 普通地面碰撞 | 炸弹保持引信；高速碎片碰撞才入队 | `Impact` 的类别与相对速度条件 |
| 连锁爆炸 | 来源变为上一枚炸弹编号，同步进入本步队列消费 | `causes` 与 `explosions.Enqueue` |
| 旋转碎片再次断裂 | 节点世界位置保持，新根继承旧旋转和点速度 | 保存字典必须位于旧根移除之前 |
| 旧形状与新形状交替 | 旧形状立即停用，本步模拟新几何 | `RemoveBody / ClearShapes` 的 `SetActive(false)` |
| 回合重开 | 临时物体移除，全部连接恢复，生命恢复，分数保留 | `ResetRound`、玩家 `Round` 与输入门 |
