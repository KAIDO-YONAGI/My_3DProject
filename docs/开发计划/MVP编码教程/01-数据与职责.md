# 01 数据与职责

本章解决两个具体问题：怎样用一份数据描述玩家、炸弹、碎片和平台块；怎样让服务器判断一条操作请求能否进入模拟。创建 `Core/Model.cs`，把下面的完整代码放入文件。`Core/` 是教程的源文件分组，核心使用 `System.Numerics`，可以直接交给第 11 章的独立测试程序。

先按 01–04 完成数据、结构、编码和恢复，再进入第 11 章运行核心验证。Unity 接入按 05–09 集齐文件后统一编译，场景与组件配置集中在第 10 章。本章的自检先用于纸面跟踪和核对代码职责。

## 1. 用一组数值认识状态

贯穿核心四章的网络例子是：回合 `Round=2`，服务器模拟到 `Tick=120`，当前拓扑 `Version=4`，完整基线 `Baseline=7`。玩家的 `Id=5`、`Generation=1`，位置为 `(1,3,0)` 米、生命值为 `100`、分数为 `2`。两 Tick 后玩家位置变成 `(1.23456,3,0)`，生命值变成 `35`。第 03 章用这次移动解释量化，第 04 章用两帧解释插值与生命值生效时间。

平台块使用另一套编号：`Node=10` 是平台中的第 10 号节点。若它的 `Parent=9`，而 9 号对象是碎片，则这个块归属于碎片根。设碎片根位置为 `(10,2,0)`、旋转为单位四元数，块的 `Local=(1.5,0,0)`，块的世界位置就是 `(11.5,2,0)`。根旋转时，计算过程是先旋转局部偏移，再加根的位置。

玩家 5、碎片 9 和节点 10 各有自己的用途。把节点号当成业务对象号，会使结构算法和物体查找混在一起；这里让 `Node` 查平台图，让 `Id` 查玩家、炸弹或碎片。

## 2. 术语落到哪个字段

| 术语 | 字段与类型 | 谁填写、谁使用 |
|---|---|---|
| 业务对象编号 | `BodyState.Id : uint` | 服务器分配；编码器与客户端据此查找对象 |
| 同编号的代次 | `Generation : ushort` | 对象身份的一部分；同一编号换代时区分新旧状态 |
| 对象类别 | `Kind : BodyKind` | 区分玩家 1、炸弹 2、碎片 3；编码占一个字节 |
| 连续运动量 | `Position`、`Rotation`、`Velocity` | 保存世界位置、世界旋转和米每秒速度；播放时插值 |
| 离散状态 | `Sleeping`、`Health`、`Score` | 表示休眠、生命和分数；到对应帧的 Tick 才切换 |
| 图节点 | `BlockState.Node : int` | 范围为 0–23；第 02 章建立节点与连接 |
| 块归属 | `Parent : uint` | 0 表示固定根；其他值指向一个碎片的 `Id` |
| 块局部坐标 | `Local : Vector3` | 相对于所属根的坐标；客户端按根变换还原几何 |
| 回合 | `WorldState.Round` | 隔离整局状态；服务器重开时增长 |
| 模拟时刻 | `Tick` | 每次服务器固定步进增长；30 Tick 对应一秒 |
| 拓扑版本 | `Version` | 对象集合或结构归属改变时增长；决定使用哪套几何与姿态缓冲 |
| 完整基线编号 | `Baseline` | 每次完整采样增长；运动包用它找到差量解码原点 |
| 已断连接 | `Broken` | 数组索引对应第 02 章的边编号，`true` 表示断开 |

`Round` 保存在整份 `WorldState` 上；一个 `BodyState` 单独拿出来时并不携带回合。第 04 章先由 `Replica` 隔离回合，再用 `Version/Id/Generation` 区分姿态。`Baseline` 只负责找解码原点，周期采样时它增长，`Version` 可以保持 4。

`BodyState` 与 `BlockState` 是值类型，给变量赋值会复制字段。`WorldState` 是包含数组的引用类型；其中数组仍由调用方管理。第 06 章的 `Capture` 复制块数组和断边数组，保存采样时的结构，避免后续模拟直接改掉这份采样。

## 3. 按职责编写类型和方法

1. **先写 `BodyKind`、`BodyState` 与 `BlockState`。** 只保存编号、数值和归属。玩家的胶囊控制器、碎片的刚体、网络连接由 05–09 的适配层持有。测试程序因此可以用几组数值构造玩家和碎片。
2. **再写 `WorldState`。** 把回合、时间、版本和三个数组放在同一份状态里。一次完整基线需要对象姿态、块归属和断边，单独发送玩家位置无法恢复平台。
3. **写 `Rules` 的预算和工具方法。** `Rate=30` 给出模拟频率，`Step=1/30` 给出步长；`MaxBodies=96`、`PacketBodies=12`、`MaxPacket=900` 分别限制世界对象数、单个运动包对象数和运动载荷字节数。`MaxPending=128` 用于第 04 章的恢复队列。
4. **先实现数值有效性，再实现插值。** `Finite(float)` 拒绝 `NaN` 和正负无穷，向量版本逐轴检查。向量 `Mix` 计算 `a+(b-a)*t`。对象 `Mix` 先复制左状态 `a`，然后只替换位置、旋转和速度；生命与身份保留左状态，精确到达右帧时由第 04 章直接返回右状态。
5. **最后写 `InputGate.Accept`。** 一次调用按“内容合法性 → 时间窗口刷新 → 额度 → 提交序号”的顺序执行。拒绝内容无效的请求时，窗口、额度和 `LastSequence` 都不变；只有通过请求才占一次额度并提交新序号。

| 方法 | 输入 | 输出与副作用 |
|---|---|---|
| `Finite` | 一个数或一个向量 | 返回是否全为有限数 |
| `Mix(Vector3, Vector3, float)` | 两个向量与插值比例 | 返回计算出的向量 |
| `Mix(BodyState, BodyState, float)` | 同一身份的左右状态与比例 | 返回连续量插值、离散字段来自左状态的副本 |
| `Accept` | 消息回合、预期回合、序号、方向、按钮、服务器 Tick | 返回 `bool`；通过时增长额度并更新 `LastSequence` |

`Mix` 本身不检查身份，也不把 `t` 限制在 0–1。它的使用条件由第 04 章负责：同一身份的缓冲内，找出夹住采样时刻的两帧，算出区间内比例。

## 4. 完整代码

```csharp file=Core/Model.cs
using System;
using System.Numerics;

namespace Mvp
{
    // 类别的数值进入网络协议，字段类型 byte 对应一个字节。
    public enum BodyKind : byte { Player = 1, Bomb = 2, Fragment = 3 }

    // 一份对象状态只包含可采样的数据，适配层负责实际模拟和显示。
    public struct BodyState
    {
        // Id 标识业务对象，Generation 与 Id 一起区分同编号的新旧身份。
        public uint Id;
        public ushort Generation;
        // 决定对象是玩家、炸弹还是碎片。
        public BodyKind Kind;
        // 位置和旋转处于世界空间，速度单位为米每秒。
        public Vector3 Position;
        public Quaternion Rotation;
        public Vector3 Velocity;
        // 这些离散量随帧生效；插值过程中沿用左侧帧的值。
        public bool Sleeping;
        public short Health, Score;
    }

    // 每个块都有一个稳定节点号，归属和局部坐标随断裂重建改变。
    public struct BlockState
    {
        // Node 用于查结构图，Parent 用于查业务对象，两种编号分别使用。
        public int Node;
        // Parent 为 0 时使用固定根；其他值是所属碎片的 Id。
        public uint Parent;
        // Local 相对于所属根，根的平移和旋转共同决定块的世界位置。
        public Vector3 Local;
    }

    // 完整采样把时间、对象和拓扑放在一起，供编码器与恢复器使用。
    public sealed class WorldState
    {
        // Round 隔离回合；Tick 排序帧；Version 隔离拓扑；Baseline 标识解码基准。
        public uint Round, Tick, Version, Baseline;
        // 空数组让新状态具备可枚举的集合，实际内容由采样或解码填写。
        public BodyState[] Bodies = Array.Empty<BodyState>();
        public BlockState[] Blocks = Array.Empty<BlockState>();
        // 数组索引就是边编号；true 表示连接已断。
        public bool[] Broken = Array.Empty<bool>();
    }

    public static class Rules
    {
        // 模拟每秒 30 次，所有基于 Tick 的窗口共用这个频率。
        public const int Rate = 30;
        public const float Step = 1f / Rate;
        // 世界对象总数与运动包内对象数分别限制。
        public const int MaxBodies = 96;
        // 这里计数的是 Wire 返回的运动载荷，Mirror 与传输层另有封装。
        public const int MaxPacket = 900;
        public const int PacketBodies = 12;
        // 等待完整基线时，最多保留 128 个运动包。
        public const int MaxPending = 128;

        // 先拒绝非有限数，再由使用它的入口检查范围。
        public static bool Finite(float x) => !float.IsNaN(x) && !float.IsInfinity(x);
        public static bool Finite(Vector3 p) => Finite(p.X) && Finite(p.Y) && Finite(p.Z);
        // t 由采样器按左右 Tick 计算；t=0 取 a，t=1 取 b。
        public static Vector3 Mix(Vector3 a, Vector3 b, float t) => a + (b - a) * t;

        // 调用方把同一对象身份的两帧交给这里，避免跨身份平滑。
        public static BodyState Mix(BodyState a, BodyState b, float t)
        {
            // 身份和生命值使用已经生效的状态；连续量在同一身份内插值。
            var s = a;
            s.Position = Mix(a.Position, b.Position, t);
            // 四元数使用球面插值，位置与速度使用线性插值。
            s.Rotation = Quaternion.Slerp(a.Rotation, b.Rotation, t);
            s.Velocity = Mix(a.Velocity, b.Velocity, t);
            return s;
        }
    }

    public sealed class InputGate
    {
        // 每个服务器玩家各持有一个门禁，保存最后通过的输入序号。
        public uint LastSequence;
        // windowTick 是当前额度窗口的起点，accepted 是本窗口已通过的次数。
        uint windowTick;
        int accepted;

        // round/sequence/方向/按钮来自消息；expectedRound/serverTick 来自服务器。
        public bool Accept(uint round, uint expectedRound, uint sequence,
                           float x, float z, byte buttons, uint serverTick)
        {
            // 序号必须严格增长；每个方向轴在 [-1,1]；只允许按钮低两位。
            // 按钮位 1 表示跳跃，位 2 表示投掷，值 3 表示两者同时请求。
            if (round != expectedRound || sequence <= LastSequence ||
                !Rules.Finite(x) || !Rules.Finite(z) ||
                Math.Abs(x) > 1 || Math.Abs(z) > 1 || (buttons & ~3) != 0)
                return false;
            // 通过内容检查后才刷新窗口；30 个服务器 Tick 对应一秒。
            if (serverTick - windowTick >= Rules.Rate)
            {
                windowTick = serverTick;
                accepted = 0;
            }
            // 每秒允许 60 次输入，覆盖 30Hz 输入和短暂批量到达。
            if (accepted >= 60) return false;
            // 提交放在所有拒绝条件之后，失败请求不消耗额度或序号。
            ++accepted;
            LastSequence = sequence;
            return true;
        }
    }
}
```

## 5. 跟踪一次输入，再跟踪一次插值

对回合 2 的玩家创建新的 `InputGate`，在服务器 `Tick=120` 依次调用 `Accept`：

| 请求 | 经过的分支 | 返回值与保存结果 |
|---|---|---|
| 序号 41，方向 `(1,1)`，按钮 3 | 内容通过；120 距初始窗口 0 超过 30，窗口设为 120 | `true`，额度 1，`LastSequence=41` |
| 再次发送序号 41 | `sequence <= LastSequence` | `false`，额度仍为 1 |
| 序号 42，X 为 `NaN` | 数值检查失败 | `false`，最后序号仍为 41 |
| 序号 42，方向 `(1,0)`，按钮 0 | 内容通过且窗口有额度 | `true`，额度 2，最后序号为 42 |
| 继续通过序号 43–100 | 同一窗口内各占一次额度 | 额度达到 60，最后序号为 100 |
| Tick 149 发送合法序号 101 | 距窗口起点只有 29 Tick，额度已满 | `false`，最后序号仍为 100 |
| Tick 150 再发合法序号 101 | 距起点达到 30 Tick，额度清零后接收 | `true`，新窗口额度 1 |

这是一种按服务器 Tick 刷新的固定窗口。它在新窗口重新给出 60 次额度；相邻窗口边界两侧的请求可以集中到达。窗口依据服务器时刻，客户端无法靠修改消息时间补充额度。

`(1,1)` 通过门禁，因为两个轴分别合法。第 07 章的 `ReceiveInput` 再调用 `Vector3.ClampMagnitude`，把长度大于 1 的方向缩到单位长度。连接归属由第 05 章从 `conn.identity` 取得；炸弹出生位置由第 08 章用服务器角色姿态计算。`Accept` 的成功结果表示请求合规，实际移动、跳跃和投掷在模拟 Tick 中消费。

再看插值：左状态的位置为 `(1,3,0)`、生命为 100，右状态的位置为 `(1.23456,3,0)`、生命为 35。直接调用 `Rules.Mix(a,b,0.5f)`，X 是 `1+(1.23456-1)*0.5=1.11728`，生命仍为 100。第 03 章把右位置量化为 1.235，第 04 章据解码结果采样，中点 X 则为 1.1175。生命在右帧 Tick=122 精确生效。

## 6. 自检方法与失败检查点

| 怎么检查 | 预期 | 失败时先查什么 |
|---|---|---|
| 同一门禁连续提交同一合法序号两次 | 第一次通过，第二次拒绝 | `LastSequence` 是否只在通过后写入，门禁是否被每条消息重新创建 |
| 将消息回合改为 1，服务器仍为 2 | 拒绝且不提交序号 | `round` 与 `expectedRound` 是否来自各自正确的一方 |
| 将 X 改为 `NaN`、无穷或 1.01 | 都拒绝 | 数值有效性与每轴范围检查是否完整 |
| 按钮依次给 0、1、2、3、4 | 前四种合法，4 拒绝 | `buttons & ~3` 是否保留了高位检查 |
| 按上表填满窗口并在 150 再试 | Tick 149 拒绝，150 恢复额度 | 窗口依据的是否是服务器 Tick，拒绝是否误改了序号 |
| 对两份同身份状态做中点插值 | 连续量居中，生命与分数取左帧 | 是否误把离散字段也插值，是否用错左右帧 |
| 重开回合后检查玩家门禁 | 玩家持有新 `InputGate` | 第 08 章 `ResetRound` 中门禁、输入和 Tick 的重置位置 |

序号使用普通无符号大小比较；服务器 Tick 在一轮内按顺序推进。回合重开时新建门禁，让新一轮的序号和额度窗口与上一轮隔离。第 11 章的 `InputTests` 自动检查重复、旧回合、非法方向、按钮和窗口额度；本章数据还被其协议与恢复测试共同使用。
