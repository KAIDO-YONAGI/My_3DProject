# 09 客户端显示

## 本章解决的问题

为什么收到网络对象销毁消息后，旧碎片还能在画面中短暂保留？可靠爆炸消息一到达就播放，会怎样与插值画面错开？本章让所有客户端状态使用同一播放 Tick，并区分网络身份、独立视觉根和 Host 的服务器实物显示。

编写 `Unity/MvpView.cs`。输入使用 Input System `Keyboard.current`，服务器身份通过第 05 章连接检查取得；状态解码和播放时钟来自第 04 章 `Replica / PlaybackClock`。本文件与第 05～08 章和第 01～04 章核心代码共同提供完整编译依赖。

## 接上当前项目：从角色模型层看到独立显示根

现有 [NetworkCharacterManager.cs](../../../Assets/Core/Scripts/Networking/CharacterPresentation/NetworkCharacterManager.cs) 在网络玩家根下面装配角色 Prefab，并绑定动画和本地相机。根的位置由现有同步链更新，模型随根运动。

本章普通客户端把网络身份和可见物体分开保存：`MvpBody` 负责 Mirror 身份，`View-<Id>` 负责播放姿态与形状。独立显示根按 `Replica.Render` 的结果更新，因此能够保留播放时间尚未走完的旧碎片。

| 要追踪的动作 | 先看哪个方法 | 看完需要知道什么 |
| --- | --- | --- |
| 我按 D，谁收到操作 | `SendInput` | WASD 读成世界 X/Z 方向，服务器从连接找玩家 |
| 收到状态包 | `ReceiveBaseline / ReceiveMotion` | 保存状态和观测消息时间 |
| 这一帧画什么 | `Update` → `Replica.Render` → `DrawWorld` | 同一个播放 Tick 决定结构与姿态 |
| 爆炸什么时候出现 | `ReceiveExplosion` 与 `Update` 的事件循环 | 先去重入队，达到发生 Tick 再播放 |

当前工程的 `CharacterInputReader` 使用动作配置；教学代码直接读取 `Keyboard.current`，两者都使用已配置的 Input System。教程镜头固定，WASD 对应世界方向，空格跳跃，E 投掷。

**先用两个独立 Client 理解插值显示。** Host 直接看服务器物理实物，界面和爆炸事件仍走播放副本，下面的运行路径表解释这一区别。现有表现链对照见 [00 导读](00-从当前项目开始.md#4-现有角色相关类怎样对应教程)。

## 把状态、事件和界面接到同一份结果

角色编号使用 SyncVar 时，界面绑定先读当前值，再订阅 hook 转出的本地事件。这里的界面采用相同原则：每帧读 `displayed` 中的生命、分数与回合；新 UI 接入时先显示当前播放状态，再在状态刷新后更新。本地事件只是同一客户端内通知 UI 的方法。

爆炸则是一条带 Tick 的事件。接收时先按 `(Round, Event)` 去重并排队，播放时间到达后创建闪光。把包到达直接当作爆炸播放时机会让特效领先于插值中的地形。

| 表现需求 | 本章采用的来源 | 读代码时观察什么 |
| --- | --- | --- |
| 现在剩多少生命、得多少分 | `displayed` | `OnGUI` 怎样读取当前播放状态 |
| 当前形状由哪些块组成 | `Replica.Render` 的块归属 | `DrawWorld` 怎样按拓扑版本重建 |
| 一次爆炸应该何时显示 | 可靠事件的发生 Tick | 事件循环怎样等待播放时钟 |
| 对象离开后怎样清理 | 播放状态中的对象集合 | `visuals` 的移除条件 |

需要把数值绑定到正式 UI 时，参考 [状态与界面绑定](专项设计/状态与界面绑定.md) 的初始读取、订阅和解绑。Command、RPC、SyncVar 的选择见 [API 总览](Mirror网络API总览.md)；本章继续使用主线的快照和事件接收链。

## 数据与职责

| 数据或入口 | 保存的内容 | 使用方式 |
|---|---|---|
| `replica` | 基线、拓扑时间线与姿态缓冲 | 接收数据后按播放 Tick 输出 `WorldState` |
| `clock` | 当前回合播放时钟 | 由成功接收路径观察包时间，`Update` 推进 |
| `events / seen` | 待播放爆炸与已见回合事件键 | 去重后排队，播放 Tick 到达再建闪光 |
| `MvpBody.ClientBodies` | 已生成的 Mirror 身份索引 | 首次建立视觉根时核对业务编号、回合、代次 |
| `visuals` | 业务编号 → 独立视觉根 | 在播放端设置姿态，按播放拓扑移除 |
| `built / fixedVersion` | 动态与固定形状所用拓扑版本 | 版本变化才清理并重建网格 |
| `visualRound` | 当前显示回合 | 新回合清空动态视觉根与建形状记录 |
| `buttons / sequence / nextInput` | 输入边沿缓存、发送序号与下一发送时间 | 最多按 `Rules.Step` 间隔发送当前方向和缓存按钮 |
| `nextRecovery` | 客户端下次允许恢复请求的时间 | 每 0.5 秒最多一次可靠恢复请求 |
| `displayed` | 本帧采样出的播放状态 | 纯客户端绘制世界，界面显示生命与分数 |
| `BytesReceived / InvalidPackets` | 接收路径的数组长度累计与指定异常次数 | 调试界面展示 |

## 编写步骤

1. 写字段与 `ResetClient`，明确副本、事件和视觉根都属于一次客户端连接的显示状态。
2. 写三个接收入口。基线和运动交给 `Replica`，爆炸按 `(Round, Event)` 去重。
3. 写 `RequestRecovery`，连接 ready 且本地节流允许时发送当前副本回合。
4. 写 `Update`：发送输入、检查恢复、推进时钟、采样世界、绘制、消费到期事件。
5. 写 `SendInput`，将每帧按钮边沿与固定间隔发送分开，方向在发送时读取。
6. 写 `DrawWorld`，先处理回合与固定拓扑，再按业务身份创建独立视觉根，最后移除播放状态中消失的对象。
7. 写 `OnGUI`，启动按钮和数值都直接对应下面完整代码中的对象与计数器。

## 网络身份与显示根

普通 Client 中，网络 Prefab 提供 `MvpBody` 身份，`new GameObject($"View-{s.Id}")` 提供独立视觉根。这个创建语句没有把视觉根设为网络对象的子物体。首次创建时检查 `ClientBodies`、`body.Round` 与 `body.Generation`；根已存在后，每帧按播放状态更新姿态。

因此，网络身份先销毁时，其客户端索引会移除，已有视觉根仍保留。只有播放端的 `w.Bodies` 不再包含该编号，末尾清理循环才销毁对应根。完整基线先到而身份稍后到时，副本保留状态；绘制分支跳过尚未匹配的对象，身份到达后再建根。

| 运行路径 | 物理与几何 | 输入、事件和界面 |
|---|---|---|
| 普通 Client | `NetworkServer.active` 为假，`DrawWorld` 建无碰撞视觉形状并播放快照 | ready 后发送输入，可靠事件按播放 Tick 显示，界面读取 `displayed` |
| Host | 服务器建立物理形状，本地直接看服务器实物；`DrawWorld` 分支跳过 | 本地客户端仍收消息、发送输入、推进播放时钟、显示事件与副本界面 |
| 仅 Server | 服务器模拟与广播，客户端 `Update` 因不 ready 返回 | 图形环境可显示服务器统计；批处理模式跳过 `OnGUI` |

Host 的实物画面跟随服务器实时物理，爆炸闪光与生命界面仍使用客户端播放链。核对普通 Client 插值与拓扑时，应使用普通客户端实例观察 `DrawWorld` 路径。

## 完整代码

```csharp file=Unity/MvpView.cs
using System;
using System.Collections.Generic;
using System.IO;
using System.Linq;
using Mirror;
using UnityEngine;
using UnityEngine.InputSystem;

namespace Mvp
{
    public sealed class MvpView : MonoBehaviour
    {
        // 提供连接按钮与服务器统计入口，引用场景中的 MvpNetwork。
        public MvpNetwork Manager;
        // 副本负责协议、基线和姿态；时钟负责同一帧全部对象的采样时间。
        Replica replica = new Replica();
        PlaybackClock clock = new PlaybackClock();
        // 爆炸事实先缓存，按回合与事件编号去重，按发生 Tick 播放。
        readonly List<MvpExplosion> events = new List<MvpExplosion>();
        readonly HashSet<(uint Round, uint Event)> seen = new HashSet<(uint, uint)>();
        // built 标记业务对象形状使用的版本，visuals 保存独立于网络根的显示根。
        readonly Dictionary<uint, uint> built = new Dictionary<uint, uint>();
        readonly Dictionary<uint, Transform> visuals = new Dictionary<uint, Transform>();
        // 固定地形单独建根；版本与回合决定何时重建。
        Transform fixedRoot;
        uint fixedVersion = uint.MaxValue, visualRound;
        // 每次实际发送增长输入序号；按钮边沿可跨渲染帧等待下次发送。
        uint sequence;
        double nextInput, nextRecovery;
        byte buttons;
        // 指定解码异常累计次数；接收字节按下面两条状态接收路径计数。
        public int InvalidPackets { get; private set; }
        public long BytesReceived { get; private set; }
        // 当前播放采样用于普通客户端绘制，也用于 Host/Client 的生命与分数界面。
        WorldState displayed;

        // 连接开始与停止共用重置入口，清理副本、事件、视觉根及本地计数。
        public void ResetClient()
        {
            replica = new Replica(); clock = new PlaybackClock(); events.Clear(); seen.Clear(); built.Clear();
            // 独立视觉根需显式销毁，它们不随 Mirror 网络根一起回收。
            foreach (var root in visuals.Values) if (root != null) Destroy(root.gameObject);
            visuals.Clear();
            if (fixedRoot != null) Destroy(fixedRoot.gameObject);
            fixedRoot = null; fixedVersion = uint.MaxValue; visualRound = 0;
            sequence = 0; nextInput = 0; nextRecovery = 0; buttons = 0;
            displayed = null; InvalidPackets = 0; BytesReceived = 0;
        }

        // 完整基线可能改变回合与拓扑；Replica 返回 null 表示旧回合基线被过滤。
        public void ReceiveBaseline(byte[] bytes)
        {
            try
            {
                var w = replica.ReceiveBaseline(bytes);
                if (w == null) return;
                // 只有返回有效 WorldState 后才计数，并把收到的模拟时间交给时钟。
                BytesReceived += bytes.Length;
                clock.Observe(w.Round, w.Tick, Time.realtimeSinceStartupAsDouble);
            }
            // 只统计这两类异常；恢复请求还需经过 ready 与本地时间节流。
            catch (Exception e) when (e is IOException || e is InvalidDataException)
            { ++InvalidPackets; RequestRecovery(); }
        }

        // 缺基线的运动包可暂存；本入口在 Replica 返回后读取头部并观察时间。
        public void ReceiveMotion(byte[] bytes)
        {
            try
            {
                replica.ReceiveMotion(bytes);
                var h = Wire.Header(bytes);
                // 无异常返回即计数，包含内部暂存或按规则过滤的运动数组。
                BytesReceived += bytes.Length;
                clock.Observe(h.Round, h.Tick, Time.realtimeSinceStartupAsDouble);
            }
            catch (Exception e) when (e is IOException || e is InvalidDataException)
            { ++InvalidPackets; RequestRecovery(); }
        }

        // 可靠传输保证送达链路，业务去重与按 Tick 播放仍由这里承担。
        public void ReceiveExplosion(MvpExplosion e)
        {
            // 老回合事件直接过滤；同一回合事件编号已见时跳过。
            if (e.Round < replica.Round || !seen.Add((e.Round, e.Event))) return;
            events.Add(e);
            // 待播放事件至多 128；去重键超过 256 时按回合和编号移除最早 128 项。
            while (events.Count > 128) events.RemoveAt(0);
            if (seen.Count > 256)
                foreach (var key in seen.OrderBy(k => k.Round).ThenBy(k => k.Event).Take(128).ToArray())
                    seen.Remove(key);
        }

        // 时间用真实运行秒数，避免每帧缺基线都发出恢复消息。
        void RequestRecovery()
        {
            double now = Time.realtimeSinceStartupAsDouble;
            if (!NetworkClient.ready || now < nextRecovery) return;
            nextRecovery = now + .5;
            NetworkClient.Send(new MvpRecover { Round = replica.Round }, Channels.Reliable);
        }

        // 每帧先输入与恢复，再用同一 tick 采样所有对象和到期事件。
        void Update()
        {
            if (!NetworkClient.ready) return;
            double now = Time.realtimeSinceStartupAsDouble;
            SendInput(now);
            if (replica.NeedsBaseline) RequestRecovery();
            // 时钟按 unscaledDeltaTime 推进，Render 选择此时间生效的基线与姿态。
            double tick = clock.Advance(now, Time.unscaledDeltaTime);
            displayed = replica.Render(tick);
            // Host 使用服务器实物形状，因此只普通 Client 创建插值显示世界。
            if (displayed != null && !NetworkServer.active) DrawWorld(displayed);
            // 到达播放时刻才显示；可靠消息提前到达时保持在 events 中等待。
            foreach (var e in events.Where(e => e.Round == replica.Round && e.Tick <= tick).ToArray())
            {
                // 闪光是无碰撞球体，0.2 秒后销毁；已播放项从待播列表移除。
                var flash = MvpWorld.Shape(PrimitiveType.Sphere, null, e.Position,
                                          Vector3.one * 2.5f, Color.red, false);
                Destroy(flash, .2f); events.Remove(e);
            }
            // 新回合建立后清理旧回合待播项，未来回合项保持等待。
            events.RemoveAll(e => e.Round < replica.Round);
        }

        // 每个渲染帧捕获按键边沿，达到发送间隔时才读取持续方向并发包。
        void SendInput(double now)
        {
            var keyboard = Keyboard.current;
            // 需要键盘设备和本地玩家身份；服务器接收时再次由连接确认玩家。
            if (keyboard == null || NetworkClient.localPlayer == null) return;
            // 先缓存边沿再检查时间，短按发生在两次发送之间也能保留。
            if (keyboard.spaceKey.wasPressedThisFrame) buttons |= 1;
            if (keyboard.eKey.wasPressedThisFrame) buttons |= 2;
            if (now < nextInput) return;
            // 每次实际发送安排下一时间点；本实现不补发错过的输入时间槽。
            nextInput = now + Rules.Step;
            float x = (keyboard.dKey.isPressed ? 1 : 0) - (keyboard.aKey.isPressed ? 1 : 0);
            float z = (keyboard.wKey.isPressed ? 1 : 0) - (keyboard.sKey.isPressed ? 1 : 0);
            // 当前按住状态形成方向；按钮和方向以递增序号一起走可靠通道。
            NetworkClient.Send(new MvpInput { Round = replica.Round, Sequence = ++sequence,
                X = x, Z = z, Buttons = buttons }, Channels.Reliable);
            // 已交付本次意图，下一包仅携带期间新捕获的按钮边沿。
            buttons = 0;
        }

        // w 是播放时间选出的世界状态，形状归属与对象消失都按它处理。
        void DrawWorld(WorldState w)
        {
            if (visualRound != w.Round)
            {
                // 回合隔离清掉动态视觉根，固定形状也强制在新回合重建。
                visualRound = w.Round; fixedVersion = uint.MaxValue; built.Clear();
                foreach (var root in visuals.Values) if (root != null) Destroy(root.gameObject);
                visuals.Clear();
            }
            // 固定视觉根采用世界单位变换，Local 与服务器固定块的坐标约定一致。
            if (fixedRoot == null) fixedRoot = new GameObject("ClientFixedStructure").transform;
            if (fixedVersion != w.Version)
            {
                // 拓扑版本变化只保留 Parent=0 的固定块，视觉形状关闭碰撞。
                MvpWorld.ClearShapes(fixedRoot);
                var graph = new Structure();
                foreach (var block in w.Blocks.Where(b => b.Parent == 0))
                    MvpWorld.Shape(PrimitiveType.Cube, fixedRoot, MvpWorld.U(block.Local),
                        new Vector3(1.45f, .5f, 1.45f), graph.Anchor[block.Node] ? Color.green : Color.gray, false);
                fixedVersion = w.Version;
            }
            foreach (var s in w.Bodies)
            {
                if (!visuals.TryGetValue(s.Id, out var root))
                {
                    // 首次建根等待 Mirror 身份，并核对业务回合和代次。
                    if (!MvpBody.ClientBodies.TryGetValue(s.Id, out var body) ||
                        body.Round != w.Round || body.Generation != s.Generation) continue;
                    // 创建独立世界根，不挂在 MvpBody 下，以保留播放时间中的旧对象。
                    root = new GameObject($"View-{s.Id}").transform;
                    visuals.Add(s.Id, root);
                }
                // 网络身份先销毁时，显示根继续存在到播放时间对应的拓扑生效。
                root.SetPositionAndRotation(MvpWorld.U(s.Position), MvpWorld.U(s.Rotation));
                // 每帧先更新姿态，版本相同则复用网格；版本变化再重建形状。
                if (built.TryGetValue(s.Id, out uint version) && version == w.Version) continue;
                MvpWorld.ClearShapes(root);
                // 碎片块 Local 属于该根，玩家胶囊和炸弹球体使用各自固定外形。
                if (s.Kind == BodyKind.Fragment)
                    foreach (var block in w.Blocks.Where(b => b.Parent == s.Id))
                        MvpWorld.Shape(PrimitiveType.Cube, root, MvpWorld.U(block.Local),
                            new Vector3(1.45f, .5f, 1.45f), Color.yellow, false);
                else
                    MvpWorld.Shape(s.Kind == BodyKind.Player ? PrimitiveType.Capsule : PrimitiveType.Sphere,
                        root, s.Kind == BodyKind.Player ? Vector3.up : Vector3.zero,
                        s.Kind == BodyKind.Player ? Vector3.one : Vector3.one * .45f,
                        s.Kind == BodyKind.Player ? Color.cyan : Color.red, false);
                built[s.Id] = w.Version;
            }
            // 只有播放状态不再包含业务编号，才销毁该编号的独立显示根。
            foreach (uint id in built.Keys.Where(id => !w.Bodies.Any(s => s.Id == id)).ToArray())
            {
                built.Remove(id); Destroy(visuals[id].gameObject); visuals.Remove(id);
            }
        }

        // 即时界面提供连接入口和数值观察；Headless 批处理直接跳过。
        void OnGUI()
        {
            if (Application.isBatchMode) return;
            if (!NetworkClient.active && !NetworkServer.active)
            {
                // 无活动端时配置目标地址，并启动 Client、Host 或仅 Server。
                Manager.networkAddress = GUI.TextField(new Rect(10, 10, 180, 25), Manager.networkAddress);
                if (GUI.Button(new Rect(200, 10, 90, 25), "Client")) Manager.StartClient();
                if (GUI.Button(new Rect(300, 10, 90, 25), "Host")) Manager.StartHost();
                if (GUI.Button(new Rect(400, 10, 90, 25), "Server")) Manager.StartServer();
                return;
            }
            GUILayout.BeginArea(new Rect(10, 10, 400, 260));
            // Round/Tick 来自客户端副本和播放时钟；服务器统计直接读取 World。
            GUILayout.Label($"Round {replica.Round} / Tick {clock.Tick:F1}");
            GUILayout.Label($"Receive {BytesReceived} B / Invalid {InvalidPackets}");
            if (NetworkServer.active)
                GUILayout.Label($"Send {Manager.World.BytesSent} B / Step {Manager.World.LastStepMs:F2} ms");
            if (displayed != null)
            {
                // 对象数量、生命与分数来自播放状态，Host 也显示同一副本口径。
                GUILayout.Label($"Bodies {displayed.Bodies.Length} / Fragments " +
                    displayed.Bodies.Count(s => s.Kind == BodyKind.Fragment));
                foreach (var s in displayed.Bodies.Where(s => s.Kind == BodyKind.Player))
                    GUILayout.Label($"Player {s.Id}: HP {s.Health} / Score {s.Score}");
            }
            GUILayout.EndArea();
        }
    }
}
```

## 手工追踪一次短按

设客户端 ready 且有本地玩家，当前 `sequence=42`，`nextInput=10.020` 秒。在 `now=10.000` 的渲染帧按下空格，`buttons` 先置为 1；发送时间未到，函数返回。即使 `10.010` 秒已松开，缓存仍为 1。

`10.025` 秒再次执行时，读取当时的方向。假设只按住 W，则 `X=0, Z=1`，发送 `Sequence=43, Buttons=1` 与当前 `replica.Round`。随后清空按钮，下一发送时间设为约 `10.058333` 秒。服务器通过连接身份取得玩家编号，由第 07 章在下一次角色移动时消费这次跳跃意图。

方向表示发送时的按住状态，按钮表示两次实际发送之间积存的边沿。这里每次允许发送时只发一包，运行帧率决定实际检查时刻。

## 手工追踪插值、身份销毁与事件

设同回合的旧拓扑版本 5 在 Tick 100 含碎片 20，其两个姿态快照为：Tick 100 位置 `(0,2,0)`，Tick 102 位置 `(2,2,0)`。在播放 Tick 101.5，插值系数为 `(101.5-100)/(102-100)=0.75`，输出位置 `(1.5,2,0)`。

再设 Tick 104 的新基线版本 6 删除碎片 20，爆炸事件也发生于 Tick 104。客户端已经收到新基线、身份销毁通知和爆炸消息，但本帧播放 Tick 为 103：

1. `MvpBody.OnStopClient` 移除身份索引；已经建立的 `View-20` 是独立根，仍然存在。
2. `Replica.Render(103)` 选择此时生效的旧拓扑，`w.Bodies` 仍含 20；`DrawWorld` 更新已有根，末尾清理保留它。
3. 事件条件 `104 <= 103` 为假，闪光等待。重复到达同一 `(Round, Event)` 的事件由 `seen` 过滤。
4. 播放 Tick 到达 104 时，`Render` 选择版本 6，`w.Bodies` 不含 20，清理循环销毁 `View-20`。
5. 同帧的事件条件成立，在记录位置建立红色球体闪光，安排 0.2 秒后销毁，并移除待播事件。

可靠性描述消息交付，`Tick` 描述发生时间；两者共同支持这里的显示链。`events` 按到达顺序保存，每帧筛出符合时间条件的项；多个事件在同一帧到期时，按列表中的顺序消费。待播放列表只保留最多 128 项，去重集合也按代码有界保留。未来回合事件可先进入列表，匹配副本回合且到达播放 Tick 才显示。

若碎片 21 的状态先到而网络身份未到，首次建根分支直接跳过；随后 `ClientBodies[21]` 就绪且回合、代次匹配，本帧重新采样时建立视觉根。身份检查只位于首次创建分支，已有根的生命周期取决于播放状态。

## 字节统计的真实口径

| 界面数值 | 本代码实际累计条件 | 读数含义 |
|---|---|---|
| `Receive` | 有效基线返回非空后加 `bytes.Length`；运动接收与头读取无指定异常后加 `bytes.Length` | 状态数组累计长度，运动内部暂存或过滤后正常返回也计数 |
| `Invalid` | 接收基线或运动时捕获 `IOException / InvalidDataException` | 指定解码异常次数，恢复请求受 ready 与 0.5 秒节流 |
| `Send` | 第 06 章每份基线和运动数组广播时加一次长度 | 服务器状态编码产量，连接数不参与乘法 |
| `Step` | 第 06 章 `FixedUpdate` 入口到末尾的实际耗时 | 移动、模拟、规则、采样与发送调用的总耗时 |

例如服务端广播一份长度 600 的基线和两份各 200 的运动数组，`Send` 增加 1000；两个普通客户端各完整接收时，各自 `Receive` 增加 1000。某客户端的旧回合基线被 `Replica` 返回空值过滤时，这份基线不计入其 `Receive`；运动路径正常返回的内部过滤项仍计入。

输入、恢复、爆炸事件、Mirror 对象生成销毁与 `SyncVar` 消息不在这两个状态数组计数器中。Mirror 外层消息头、数组长度前缀、批处理与底层传输协议开销也有独立口径。使用这些数字比较教程编码成本时，应保持对象状态和采样条件一致。

## 预期与排查

| 检查动作 | 代码对应的预期 | 优先检查位置 |
|---|---|---|
| 两次发送间短按空格或 E | 边沿保留到下一实际输入包，发送后清零 | `Keyboard.current`、本地玩家、`buttons` 与 `nextInput` |
| 基线先到、身份后到 | 状态保存，匹配后建立视觉根 | `ClientBodies`、回合、代次、首次建根分支 |
| 网络身份提前销毁 | 已有视觉根保持到播放拓扑删除它 | `visuals` 的独立根与末尾清理循环 |
| 爆炸可靠事件提前到 | 等播放 Tick；已见键范围内重复事件过滤 | `events / seen`、回合条件与 `e.Tick <= tick` |
| 普通客户端显示碎片 | 独立根插值移动，形状 Collider 立即禁用 | `DrawWorld`、`Shape(..., false)` |
| Host 观察位置与界面 | 位置显示服务器实物，界面与事件走播放副本 | `NetworkServer.active` 分支与 `displayed` |
| 缺基线或指定解码异常 | 条件允许时发恢复请求，服务器统一发布新基线 | `NeedsBaseline`、两端节流与第 06 章 `Recover` |
