## 常用编码链路怎样选择

RPC 是 Remote Procedure Call 的缩写，指远程过程调用。Mirror 的 Command、ClientRpc 和 TargetRpc 都把方法参数发送到另一侧，再执行接收侧方法体。

API 是 Application Programming Interface 的缩写，指框架提供的调用接口。

| 需要表达的内容 | 采用的机制 | 数据方向 | 后加入者如何获得内容 |
| --- | --- | --- | --- |
| 玩家发起对象上的操作 | `Command` | 客户端到服务器 | 从操作形成的状态读取 |
| 当前角色、生命值、准备状态 | `SyncVar` | 按组件同步方向，本项目角色编号为服务器到客户端 | 对象初始状态 |
| 房间名单、物品编号集合 | `SyncList`、`SyncDictionary` | 按组件同步方向 | 集合初始内容 |
| 一次性的音效、动作或特效通知 | `ClientRpc` | 服务器到对象观察客户端 | 根据当前状态展示，事件按发送时机接收 |
| 单个客户端的操作提示 | `TargetRpc` | 服务器到指定连接 | 按该连接的业务状态处理 |
| 独立于某个网络对象的请求或通知 | `NetworkMessage` | 按发送 API 决定 | 通过业务请求或保存的状态取得 |
| 连续位置、旋转 | `NetworkTransformReliable` | 按组件配置 | 初始变换与持续快照 |
| 限制普通方法的执行侧 | `[Server]`、`[Client]` | 当前进程内调用 | 由调用链决定 |

### 1. 状态用于表达“现在是什么”

角色编号适合 SyncVar。后加入者需要知道当前角色，客户端表现也需要当前值。

同步前多次修改同一个 SyncVar，接收端可能直接得到发送时的最终值。用它表达当前状态，用专门的事件通知表达每次动作。

写回相同值通常不会产生变化回调。初始化表现时先读取当前值，再接收后续变化。

多个数值共同描述一份状态时，可以组成结构体作为一个 SyncVar。修改时构造新值并对字段整体赋值，使变化进入生成的写入逻辑。

同步集合中的结构体采用对应索引替换。普通对象中的嵌套数据也按完整状态值写回。这样状态写入位置明确，变化记录与业务处理保持一致。

同一份相关状态的显示使用统一刷新方法。RPC 通知携带本次表现需要的参数，客户端按通知参数处理。跨对象、跨组件的数据按自己的接收时机组织，必要时用业务序号对应一次结果。

### 2. 事件用于表达“发生了一次什么”

ClientRpc 适合服务器确认后发送一次表现通知。它发送给对象的就绪观察者，默认包含拥有者。

扩展练习：在 `NetworkCharacterSync` 中增加角色切换确认通知。状态继续使用 `characterId`，通知用于一次性的音效或特效。

```csharp
public event System.Action<int> CharacterSwitchConfirmed;

[ClientRpc]
private void RpcCharacterSwitchConfirmed(int confirmedCharacterId)
{
    CharacterSwitchConfirmed?.Invoke(confirmedCharacterId);
}
```

在服务器确认编号有效且与当前编号不同时，先更新状态，再发出通知：

```csharp
if (characterId == requestedCharacterId)
{
    return;
}

characterId = requestedCharacterId;
RpcCharacterSwitchConfirmed(requestedCharacterId);
```

用这段代码替换 `CommandSetCharacter` 服务器校验之后的原赋值语句。

```text
服务器确认切换
  → characterId 保存当前角色
  → SyncVar 负责状态下行与初始恢复
  → ClientRpc 通知当前观察客户端播放一次表现
  → 本地订阅者按通知参数处理
```

通知携带它需要的编号，接收代码按参数处理。相关 SyncVar 的实际发送与应用时机单独管理。

本地表现组件绑定当前网络玩家时订阅 `CharacterSwitchConfirmed`，解绑时解除订阅。服务器规则保留在请求处理里，音效与特效代码位于客户端表现层。

### 3. 单个客户端的结果使用 TargetRpc

扩展练习：给角色选择的发起者返回无效编号提示，在 `NetworkCharacterSync` 中增加：

```csharp
public event System.Action<int> CharacterRequestRejected;

[TargetRpc]
private void TargetCharacterRequestRejected(
    NetworkConnectionToClient target,
    int requestedCharacterId)
{
    CharacterRequestRejected?.Invoke(requestedCharacterId);
}
```

`NetworkConnectionToClient` 是服务器侧指向一个客户端的连接类型。TargetRpc 的第一个连接参数选择接收者，业务参数由网络传递，客户端方法体使用业务参数处理提示。

在 Command 的校验失败分支中发送：

```csharp
if (connectionToClient != null)
{
    TargetCharacterRequestRejected(connectionToClient, requestedCharacterId);
}

return;
```

`connectionToClient` 是该网络对象的拥有者连接。当前角色选择 Command 使用默认归属检查，因此它可以对应本次请求的发起者。

界面在本地订阅拒绝事件并显示提示。提示只发给这条连接，角色状态仍按原下行链路同步。

### 4. 对象内的服务器方法使用 Server

`[Server]` 在编译处理中为普通方法加入服务器活动状态检查。调用仍然发生在当前进程。

扩展功能时，可以将业务处理提取成服务器方法，让 Command 和服务器自己的游戏流程共用：

```csharp
[Command]
private void CommandSetCharacter(int requestedCharacterId)
{
    ServerSetCharacter(requestedCharacterId);
}

[Server]
public void ServerSetCharacter(int requestedCharacterId)
{
    if (NetworkCharacterManager.Instance == null
        || !NetworkCharacterManager.Instance.IsValidCharacterId(requestedCharacterId))
    {
        return;
    }

    characterId = requestedCharacterId;
}
```

这是原角色处理的另一种组织方式，适合服务器也需要主动设置角色的功能。

```text
客户端操作 → Command → ServerSetCharacter
服务器流程 → 普通方法调用 → ServerSetCharacter
ServerSetCharacter → 写状态 → 下行同步
```

`[Client]` 同样限制普通方法在客户端活动时执行。远程发送使用 Command 或 RPC，执行侧特性用于保护当前进程内的方法调用。

官方依据：[Remote Actions](https://mirror-networking.gitbook.io/docs/manual/guides/communications/remote-actions)、[SyncVars](https://mirror-networking.gitbook.io/docs/manual/guides/synchronization/syncvars)、[Synchronization](https://mirror-networking.gitbook.io/docs/manual/guides/synchronization)。

## 把新状态接入网络玩家

扩展练习：在玩家网络根上增加准备状态。准备状态采用服务器到客户端的同步方向，拥有者提交请求，客户端 UI 读取状态并接收本地变化事件。

下面是一个完整组件示例：

```csharp
using System;
using Mirror;

public sealed class NetworkReadyState : NetworkBehaviour
{
    [SyncVar(hook = nameof(OnReadyChanged))]
    private bool ready;

    public bool Ready => ready;
    public event Action<bool> ReadyChanged;

    public void RequestReady(bool requestedReady)
    {
        if (!isLocalPlayer)
        {
            return;
        }

        CommandSetReady(requestedReady);
    }

    [Command]
    private void CommandSetReady(bool requestedReady)
    {
        ServerSetReady(requestedReady);
    }

    [Server]
    public void ServerSetReady(bool requestedReady)
    {
        ready = requestedReady;
    }

    public override void OnStartClient()
    {
        base.OnStartClient();
        ReadyChanged?.Invoke(ready);
    }

    private void OnReadyChanged(bool previousReady, bool currentReady)
    {
        ReadyChanged?.Invoke(currentReady);
    }
}
```

这个示例表达准备状态的传递。项目接入时按以下职责编写：

1. 将组件放在 `NetworkPlayer` 网络根，设置 `ServerToClient`。
2. 在 `ServerSetReady` 中加入房间阶段、玩家状态等具体规则。
3. 本地准备按钮取得当前玩家的 `NetworkReadyState`，调用 `RequestReady`。
4. UI 绑定组件时读取 `Ready`，立刻显示当前状态。
5. UI 订阅 `ReadyChanged`，处理后续状态变化。
6. UI 解绑、玩家停止或界面停用时解除订阅。
7. 构建使用同一组件布局的客户端与服务器。

本地变化事件用于同一客户端内的通信。网络传递由 SyncVar 完成。

若使用 Unity `Toggle` 显示确认状态，状态回填使用 `SetIsOnWithoutNotify`，用户点击事件调用 `RequestReady`。这样可以将“显示服务器确认值”和“发起操作”分别处理。

下面的本地组件把这条界面链路接起来。`Toggle` 是 Unity 的开关控件，组件挂在准备界面的对象上，并在 Inspector 中绑定开关引用。Inspector 是 Unity 查看和配置组件的面板。

```csharp
using UnityEngine;
using UnityEngine.UI;

public sealed class ReadyStateView : MonoBehaviour
{
    [SerializeField] private Toggle readyToggle;

    private NetworkReadyState boundState;

    private void OnEnable()
    {
        readyToggle.interactable = false;
        readyToggle.onValueChanged.AddListener(OnUserChangedReady);
    }

    private void OnDisable()
    {
        readyToggle.onValueChanged.RemoveListener(OnUserChangedReady);
        Bind(null);
    }

    public void Bind(NetworkReadyState state)
    {
        if (boundState != null)
        {
            boundState.ReadyChanged -= OnConfirmedReadyChanged;
        }

        boundState = state;
        readyToggle.interactable = boundState != null && boundState.isLocalPlayer;

        if (boundState != null)
        {
            OnConfirmedReadyChanged(boundState.Ready);
            boundState.ReadyChanged += OnConfirmedReadyChanged;
        }
        else
        {
            readyToggle.SetIsOnWithoutNotify(false);
        }
    }

    private void OnUserChangedReady(bool requestedReady)
    {
        if (boundState != null)
        {
            boundState.RequestReady(requestedReady);
            OnConfirmedReadyChanged(boundState.Ready);
        }
    }

    private void OnConfirmedReadyChanged(bool confirmedReady)
    {
        readyToggle.SetIsOnWithoutNotify(confirmedReady);
    }
}
```

界面与玩家的绑定由本地界面组织代码负责。界面启用且本地玩家可用时，取得该玩家的 `NetworkReadyState` 并调用 `ReadyStateView.Bind`。玩家停止时调用 `Bind(null)`；界面重新启用时重新绑定当前玩家。

用户点击后，界面提交请求并继续显示当前确认值。服务器接受请求后，SyncVar 下行触发本地事件，再更新开关。状态回填使用 `SetIsOnWithoutNotify`，让收到状态的过程保持为显示更新。

这两个组件之间的 `Bind`、`RequestReady` 和 `ReadyChanged` 都是当前进程内的调用。跨网络的部分是 Command 参数发送和 SyncVar 状态接收。
