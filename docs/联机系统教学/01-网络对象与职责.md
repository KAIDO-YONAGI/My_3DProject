# 网络对象与职责

## 先把一个功能分成请求、状态和表现

以角色切换为例：

| 内容 | 含义 | 负责的代码 |
| --- | --- | --- |
| 请求 | 玩家希望切换到编号 1 | `CharacterSelectButton`、`SetLocalCharacter` |
| 决定 | 服务器检查编号并接受请求 | `CommandSetCharacter` |
| 状态 | 当前角色编号为 1 | `characterId` |
| 表现 | 使用编号 1 的模型、动画和本地相机 | `NetworkCharacterManager` |

这四部分有各自的运行位置：

```text
客户端 A
  按钮点击
    → 本地玩家的 SetLocalCharacter
    → 把请求编号发给服务器

服务器 S
  接收甲的请求
    → 校验角色编号
    → 更新甲的 characterId
    → 把确认状态发给观察甲的客户端

客户端 A
  收到甲的 characterId
    → 装配甲的本地角色表现

客户端 B
  收到甲的 characterId
    → 装配甲的远程角色表现
```

上行是客户端向服务器发送数据，下行是服务器向客户端发送数据。本项目角色切换的上行发送请求，下行发送服务器确认的状态。

编写每个联机功能前，先回答五个问题：

1. 这个功能属于哪个对象？
2. 哪个客户端可以发起请求？
3. 谁决定最终结果？
4. 哪些客户端需要收到结果？
5. 后加入的客户端需要恢复哪些状态？

角色切换的答案是：属于玩家网络根，拥有者发起，服务器决定，观察该玩家的客户端接收，后加入者读取当前角色编号。

## 网络对象与本地对象怎样划分

### 1. 网络对象表示多人共同认识的实体

`NetworkIdentity` 是 Mirror 的网络身份组件。服务器生成一个网络对象时为它分配 `netId`，这是本次网络生命周期中的对象编号。客户端使用相同编号找到这个实体在自己进程中的副本。

一个网络实体的层级使用一个根 `NetworkIdentity`。该实体的子对象使用根身份，独立网络实体使用独立的网络根。项目将网络组件放在玩家根上，视觉子对象承担模型、动画和相机职责。

网络身份确定“这是哪个实体”，同步组件确定“这个实体的哪些数据需要传递”。编写网络对象时，分别配置生命周期、同步状态和表现。

甲在三个进程中的对象关系如下：

```text
服务器 S：甲的 NetworkPlayer，netId = X
客户端 A：甲的 NetworkPlayer，netId = X
客户端 B：甲的 NetworkPlayer，netId = X
```

这三个 Unity 对象分别占用各自进程的内存。它们通过网络消息对应同一个玩家。

本项目的 [NetworkPlayer.prefab](/D:/Unity/Projects/My_3DProject/Assets/Core/Prefabs/NetworkPlayer.prefab) 是玩家网络根。Prefab 是 Unity 保存对象结构与组件配置的预制体资源。

网络根上的组件分工如下：

| 组件 | 职责 |
| --- | --- |
| `NetworkIdentity` | 标识玩家、保存连接归属和网络生命周期 |
| `NetworkCharacterSync` | 接收角色选择请求、保存角色编号、通知本地装配 |
| `NetworkTransformReliable` | 同步网络根的位置和旋转 |
| `CharacterController` | 提供角色移动与碰撞接口 |
| `PlayerCharacterController` | 组织输入、运动、动画和骨骼表现 |

网络根保持稳定，具体角色表现随编号替换。这使玩家身份、连接归属和网络组件保持连续。

开发道具、机关或房间状态时，也先判断它是否需要独立的网络身份：多个客户端需要共同识别它、服务器需要管理它的生命周期、消息需要指向它，这些条件适合使用网络对象。

### 2. 本地对象负责当前进程的实现和表现

本地对象通过普通 C# 调用与本进程中的其他对象通信。UI 是 User Interface 的缩写，指用户界面。按钮、相机、动画组件和视觉实例属于本地实现。

`Camera` 是 Unity 的相机组件，`Animator` 是 Unity 的动画组件。

项目的运行层级可以理解为：

```text
NetworkPlayer                     网络根
  NetworkIdentity
  NetworkCharacterSync
  NetworkTransformReliable
  PlayerCharacterController
  CharacterController
  角色视觉实例                     当前客户端本地创建
    模型
    Animator                       Unity 动画组件
    本地角色相机                   按当前客户端身份启用

角色选择界面                       当前客户端本地对象
  Button
  CharacterSelectButton

NetworkCharacterManager           当前进程的普通管理器
```

视觉实例的父对象拥有网络身份，这让模型跟随网络根移动。子对象的创建、字段和组件状态仍由本地代码管理，跨进程传递的数据需要明确的同步通道。

本项目使用普通 `Instantiate` 在客户端创建视觉实例。发送到客户端的是角色编号，客户端从自身的资源数组找到对应 Prefab。

因此，网络中保存“甲使用角色 1”，客户端保存“角色 1 对应哪个模型、哪个 Animator、哪台相机”。

### 3. 按职责选择 MonoBehaviour 与 NetworkBehaviour

`MonoBehaviour` 是 Unity 组件脚本的基础类型。`NetworkBehaviour` 继承它，并加入 Mirror 的身份访问、网络回调、同步字段和远程调用能力。

| 要编写的内容 | 类型选择 | 本项目例子 |
| --- | --- | --- |
| 同步字段、对象上的远程调用 | `NetworkBehaviour` | `NetworkCharacterSync` |
| 按钮、相机、模型装配 | `MonoBehaviour` | `CharacterSelectButton`、`NetworkCharacterManager` |
| 本地运动组织，需要读取网络身份 | `MonoBehaviour`，显式读取 `NetworkIdentity` | `PlayerCharacterController` |
| 纯计算、输入数据、配置和运行时状态 | 普通 C# 类型 | `CharacterMotor`、`CharacterInput`、`CharacterMotion` |

`PlayerCharacterController` 挂在网络对象上，仍是普通 `MonoBehaviour`。它通过 `NetworkIdentity.isLocalPlayer` 决定是否读取输入。

开发时把网络边界放在少量 `NetworkBehaviour` 中。本地 UI 和表现调用这些组件提供的公开入口，运动算法和资源装配沿用自身的普通代码。

官方依据：[GameObjects](https://mirror-networking.gitbook.io/docs/manual/guides/gameobjects)、[NetworkIdentity](https://mirror-networking.gitbook.io/docs/manual/components/network-identity)、[NetworkBehaviour](https://mirror-networking.gitbook.io/docs/manual/components/networkbehaviour)。

## 对象归属、数据决定权和执行位置

### 1. 三件事分别判断

对象归属回答“哪条客户端连接拥有这个对象”。

Mirror 将对象的控制归属称为 Authority。分配归属后，客户端可以按对象权限提交操作；各项游戏数据的决定规则继续分别设计。

数据决定权回答“谁有权确定这个数据的最终值”。

执行位置回答“这段代码正在服务器还是客户端运行”。

本项目玩家属于一个客户端连接，角色编号由服务器决定，位置与旋转由本地拥有者计算后上传。同一个对象上的不同数据可以采用不同规则。

Command 是 Mirror 的客户端到服务器方法调用机制。客户端提交参数，服务器在对应网络对象上执行开发者编写的方法体。

SyncDirection 是组件的状态同步方向。`ServerToClient` 表示服务器向客户端发送状态，`ClientToServer` 表示拥有者客户端向服务器发送状态，再由服务器传给其他观察客户端。

| 数据或引用 | 当前写入或计算位置 | 跨网络传递的内容 | 接收后的用途 |
| --- | --- | --- | --- |
| `characterId` | 服务器 | 整数角色编号 | 各客户端选择角色资源 |
| 网络根位置与旋转 | 本地拥有者 | 变换快照 | 服务器与远程客户端更新网络根 |
| 本地输入 | 本地拥有者 | 移动链路传递计算出的变换 | 本地运动计算 |
| Camera 引用 | 当前客户端 | 由客户端自行绑定 | 视角和移动参考方向 |
| Animator 引用 | 当前客户端 | 由客户端自行绑定 | 模型动画 |
| `presentations` 字典 | 当前客户端 | 由客户端自行维护 | 记录视觉实例和组件缓存 |

快照是某个时刻的数据记录。变换快照保存对象的位置、旋转及相关时间信息，接收端据此平滑显示运动。

扩展命中、得分、拾取等玩法时，把“客户端希望做什么”和“服务器认定发生什么”分开。客户端提交目标和操作意图，服务器结合自己的游戏状态计算结果。

### 2. 使用身份属性时先确定问题

| 属性 | 回答的问题 | 合适的用途 |
| --- | --- | --- |
| `isLocalPlayer` | 这个对象是否为当前客户端的玩家？ | 玩家输入、自己的角色选择、本地玩家 UI |
| `isOwned` | 当前客户端是否拥有这个对象？ | 拥有者控制的玩家、宠物或其他网络实体 |
| `isServer` | 这个对象是否已进入服务器侧网络生命周期？ | 对象上的服务器逻辑 |
| `isClient` | 这个对象是否已进入客户端侧网络生命周期？ | 对象上的客户端表现 |
| `NetworkServer.active` | 本进程的服务器是否启动？ | 进程级服务管理 |
| `NetworkClient.active` | 本进程的客户端是否启动，包括连接过程？ | 连接管理 |
| `NetworkClient.isConnected` | 本进程的客户端是否连接成功？ | 联机表现模式 |

`isLocalPlayer` 面向玩家身份，`isOwned` 面向对象归属。开发拥有者控制的其他实体时，按照该实体的归属判断权限。

`NetworkClient.active` 是进程级状态。连接管理可以使用它阻止重复连接；玩家输入需要继续判断具体对象的身份。

### 3. 单例也属于各自进程

`NetworkCharacterManager.Instance` 是静态属性，服务器和每个客户端分别拥有自己的值。

客户端预检编号时，读取客户端的角色配置。服务器处理 Command 时，读取服务器的角色配置。两次调用可以使用相同源码，执行对象和内存各自独立。

因此两套角色数组的下标含义需要在客户端与服务器之间保持一致：

```text
编号 0 → 同一个角色的本地资源与远程资源
编号 1 → 同一个角色的本地资源与远程资源
```

### 4. 对象归属检查与业务检查各有职责

Mirror 默认检查 Command 发送者是否拥有目标网络对象。这项检查确认请求来自该对象的拥有者。

服务器业务代码继续检查请求本身：

- 编号或目标是否有效。
- 当前玩家状态是否允许操作。
- 操作是否满足距离、冷却、资源等规则。
- 请求频率是否在业务允许的范围内。

本项目 `CommandSetCharacter` 使用 `IsValidCharacterId` 检查编号。这项检查要求编号非负、位于两套数组范围内，而且两个位置都有有效 Prefab。

客户端同样做预检，用于及时过滤无效操作。服务器校验负责确定网络世界中的结果。

### 5. 归属由服务器分配，数据方向单独配置

玩家通过 `NetworkServer.AddPlayerForConnection` 与连接建立归属。扩展需要客户端控制的其他实体时，服务器可以在生成时指定拥有者：

```csharp
NetworkServer.Spawn(entity, ownerConnection);
```

这里的 `entity` 是服务器创建、带有 `NetworkIdentity` 的实例，`ownerConnection` 是服务器确认的拥有者连接。这行属于服务器生成流程。

已经生成的普通网络实体可以由服务器调用 `AssignClientAuthority` 分配归属，使用 `RemoveClientAuthority` 收回归属。本地控制组件在 `OnStartAuthority` 启用，在 `OnStopAuthority` 停用，并使用 `isOwned` 检查当前控制资格。

这些方法管理对象与连接的关系。角色编号的 `ServerToClient` 和移动的 `ClientToServer` 分别管理组件数据的传递方向，两种配置一起决定功能的工作方式。

玩家身份的替换使用 `NetworkServer.ReplacePlayerForConnection`，服务器同时安排旧玩家对象的生命周期与业务状态交接。

拥有者连接断开时，Mirror 清理该连接拥有的对象。分配归属前一起确定实体的存续规则。长期存在的公共机关由服务器管理，玩家通过请求操作它；拾取归属可以保存为服务器业务状态。

官方依据：[Authority](https://mirror-networking.gitbook.io/docs/manual/guides/authority)、[SyncDirection](https://mirror-networking.gitbook.io/docs/manual/general/syncdirection)、[Remote Actions](https://mirror-networking.gitbook.io/docs/manual/guides/communications/remote-actions)。
