# 爆炸物与命中裁决

[返回目录](README.md)

本章沿第 09 章的权威投掷物继续编写。服务器负责运动、碰撞和结算，客户端使用收到的位置、阶段与事件更新模型、声音和界面。

## 1. 运动状态、结算状态与表现事件分开

| 信息 | 数据形式 | 更新与接收 |
| --- | --- | --- |
| 位置与旋转 | 刚体变换快照 | S 模拟，A、B 插值 |
| 飞行、落地、爆炸阶段 | SyncVar 状态 | S 修改，客户端读取初始值并响应变化 |
| 引信期限 | 网络绝对时间 | S 决定，客户端显示剩余时间 |
| 生命值与持续受伤状态 | 目标对象的同步状态 | S 结算，客户端更新表现 |
| 一次爆炸闪光与声音 | ClientRpc 事件 | S 通知观察者，客户端本地播放 |
| 持续烟雾与危险区域 | 有生命周期的网络状态或实体 | S 创建与结束，后加入者恢复当前效果 |

SyncVar 表达当前状态。一次赋值后又立即赋值，客户端可能只接收最终值。需要明确收到每次爆炸时，使用事件传递该次爆炸参数；阶段状态负责恢复当前对象处于什么阶段。

一个基础阶段定义是：

```csharp
public enum ProjectilePhase : byte
{
    Flying,
    Resting,
    Exploded
}
```

`Resting` 表达规则认可的静止状态。判断可以采用接触持续时间与速度阈值，避免每次短暂接触都改变阶段。弹起时按规则回到 `Flying`。

## 2. 弹跳与碰撞轨迹如何同步

服务器刚体设置初速度后，让重力、碰撞体和物理材质推进后续运动。物理材质配置摩擦与弹性，决定滑动、滚动和反弹。

```text
服务器物理步计算碰撞和弹跳
  → 权威根的位置与旋转改变
  → 快照组件发送运动结果
  → 客户端插值显示新的运动
```

这种链路把复杂碰撞后的轨迹直接作为结果传递。投掷者的视觉预测在接管前估算自由飞行，接管后同样使用服务器结果。

持续外力放在服务器物理入口中处理。发射速度在初始化时设置，物理步中的受力与碰撞继续改变速度。

### 高速投掷物怎样降低穿透风险

连续碰撞检测称为 CCD，全称 Continuous Collision Detection，用于改善高速物体越过较薄碰撞体的问题。

Unity 的 `Rigidbody.collisionDetectionMode` 提供离散与连续检测模式。对高速球形投掷物，按碰撞对象与性能预算选择 `ContinuousDynamic` 或相应模式，并使用适合的球体、胶囊或盒形碰撞体。

验证包含最高速度、最薄墙体、动态目标和物理步频。检测模式只是碰撞方案的一部分，碰撞层、形状、速度和出手位置一起决定效果。

规则需要额外的扫掠判定时，可以在服务器对相邻两个已完成物理状态之间的线段做 `Physics.SphereCast`。扫掠用球形体积沿路径检查命中，适合给高速球增加路径检测。

使用扫掠时明确三件事：

1. 起点已经重叠的情况单独做重叠查询。SphereCast 的起点重叠有独立处理要求。
2. 查询半径、碰撞层和触发器规则与玩法形状一致。
3. 碰撞回调与扫掠结果进入同一个命中入口，用结算阶段避免重复处理。

Unity 在 `FixedUpdate` 后推进物理模拟。保存“已完成的两个物理状态”时，按这一顺序安排采样，避免把还未发生的物理步当成已完成位置。

## 3. 引信采用服务器期限

第 09 章的发射状态保存：

```text
LaunchTime：服务器接受并发射的未缩放网络时间
DetonateAt：服务器决定的爆炸期限
```

服务器比较 `NetworkTime.unscaledTime` 与 `DetonateAt`，达到期限后进入爆炸入口。定时检查放在服务器 `Update` 时，未缩放期限沿真实时间推进。

服务器模拟场景通常保持 `Time.timeScale = 1`。玩法加入暂停时，明确物理运动与引信是否同时暂停；采用随游戏暂停的引信时，发射时间、期限和显示一起改用缩放时间基准。

客户端显示剩余时间：

```csharp
double remaining = System.Math.Max(
    0d, projectile.Launch.DetonateAt - NetworkTime.unscaledTime);
```

本工程客户端的 `NetworkTime.unscaledTime` 属于插值时间线，因此倒计时与客户端当前看到的投掷物状态对应。服务器爆炸事件负责触发最终效果。

后加入者从当前发射状态恢复剩余时间，计时器与本地模型按初始数据直接建立。

## 4. 先结束阶段，再查询伤害

把引信、碰撞触发和其他引爆条件统一到一个服务器方法。方法首先检查阶段，随后将阶段设为 `Exploded`，最后执行结算与通知。

下面是补入 `NetworkProjectileState` 的成员摘录：

```csharp
[SyncVar(hook = nameof(OnPhaseChanged))]
private ProjectilePhase phase;

[SerializeField] private ExplosionWorld explosionWorld;
[SerializeField] private float explosionRadius = 4f;

[Server]
public void ServerConfigureExplosion(ExplosionWorld world, float radius)
{
    explosionWorld = world;
    explosionRadius = radius;
}

private void Update()
{
    if (isServer && phase != ProjectilePhase.Exploded
        && NetworkTime.unscaledTime >= launch.DetonateAt)
    {
        ServerExplode();
    }
}

[Server]
private void ServerExplode()
{
    if (phase == ProjectilePhase.Exploded)
    {
        return;
    }

    phase = ProjectilePhase.Exploded;
    var burst = new ExplosionEvent
    {
        ProjectileNetId = netId,
        ThrowerNetId = launch.ThrowerNetId,
        RequestId = launch.RequestId,
        Sequence = 1,
        ItemId = launch.ItemId,
        Position = body.position,
        Radius = explosionRadius,
        ServerTime = NetworkTime.unscaledTime
    };

    explosionWorld.ServerResolveExplosion(burst);
    NetworkServer.Destroy(gameObject);
}

private void OnPhaseChanged(
    ProjectilePhase oldValue, ProjectilePhase newValue)
{
    ApplyPhasePresentation(newValue);
}

private void ApplyPhasePresentation(ProjectilePhase value)
{
    // 按当前阶段更新模型、尾迹和引信表现。
}
```

`ExplosionWorld` 是下一节定义的稳定网络对象上的结算与通知组件。动态 Prefab 的场景服务引用在服务器生成时注入。

在第 09 章的 `ThrowPlan` 中增加 `public float ExplosionRadius`，由规则服务从服务器道具配置填写。在 `NetworkThrowAbility` 中增加 `private ExplosionWorld serverExplosionWorld`，由服务器玩家初始化流程绑定当前房间服务；规则批准投掷前确认房间服务可用。生成后按下面的顺序初始化：

```csharp
NetworkProjectileState projectile = Instantiate(
    plan.Prefab, plan.Origin, Quaternion.identity);
projectile.ServerInitialize(launch);
projectile.ServerConfigureExplosion(serverExplosionWorld, plan.ExplosionRadius);
NetworkServer.Spawn(projectile.gameObject);
```

玩家的房间服务绑定入口可以写成：

```csharp
[Server]
public void ServerBindExplosionWorld(ExplosionWorld world)
{
    serverExplosionWorld = world;
}
```

服务器房间创建与玩家加入流程调用该普通服务器方法，然后开放投掷请求。`[Server]` 限定方法在服务器执行，调用者与被调用者都处于同一服务器进程。

`explosionRadius` 从服务器道具配置确定，初始化时按对应规则值设置。规则服务检查半径为有限正数，并限制最大值。

`OnStartClient` 除第 09 章的表现接入，还调用 `ApplyPhasePresentation(phase)`，建立初始阶段表现。hook 用于后续阶段变化，二者共同覆盖初始化与运行期更新。

`ApplyPhasePresentation` 是本地模型更新接入点，按阶段启停模型、尾迹与计时显示。爆炸特效使用下面的独立事件入口播放。

一个一次性投掷物的爆炸序号固定为 1。实体能产生多次脉冲时，服务器递增 `Sequence`，接收端按实体编号与序号区分各次事件。

## 5. 用稳定网络对象通知爆炸

短命投掷物可能在客户端显示前已经结束。爆炸事件使用房间中持续存在的网络对象发送，让该事件的接收入口与投掷物生命周期分别成立。

`ExplosionWorld` 放在有 `NetworkIdentity` 的房间网络对象上，通过场景网络对象或服务器 Spawn 建立。客户端进入房间后接收此对象，它的观察者范围覆盖需要知道爆炸的玩家。

事件带完整位置和道具参数，客户端收到后可以直接播放世界效果，也可以按投掷匹配键清理预测视觉球。

```csharp
public struct ExplosionEvent
{
    public uint ProjectileNetId;
    public uint ThrowerNetId;
    public uint RequestId;
    public uint Sequence;
    public int ItemId;
    public Vector3 Position;
    public float Radius;
    public double ServerTime;
}
```

后面的 `ExplosionWorld` 同时给出服务器结算和客户端事件入口。它使用普通 C# 事件把网络消息交给本地表现层。

本地爆炸表现组件在启用时订阅 `ClientExplosion`，停用时解绑。处理顺序是：

1. 按 `ProjectileNetId + Sequence` 去重。
2. 用 `ThrowerNetId + RequestId` 结束对应预测记录。
3. 在事件世界位置生成本地闪光、粒子、声音与镜头效果。
4. 按各效果自己的时长清理。

爆炸特效放在独立的本地对象上，生命周期由效果自身管理。投掷物网络根销毁后，已经播放的效果继续完成。

所有需要恢复的持续效果，例如持续燃烧、烟雾或地面危险区域，使用期限状态或独立网络实体。客户端进入观察范围时，根据初始状态恢复当前效果。

## 6. 范围伤害先找到目标，再按目标去重

玩家模型可能有多个碰撞体。一次重叠查询返回多个碰撞体时，结算目标采用同一玩家根的身份，每个目标承受一次本次爆炸。

扩展练习使用 `ExplosionDamageReceiver` 表达目标的服务器受击接口：

```csharp
[RequireComponent(typeof(NetworkIdentity))]
public abstract class ExplosionDamageReceiver : MonoBehaviour
{
    [SerializeField] private Transform damagePoint;

    public NetworkIdentity Identity => GetComponent<NetworkIdentity>();
    public Vector3 DamagePosition =>
        damagePoint != null ? damagePoint.position : transform.position;

    public abstract void ApplyServerExplosion(
        uint throwerNetId, int damage, Vector3 pushVelocity);
}
```

这个组件放在目标网络根，子碰撞体通过 `GetComponentInParent` 找到它。`DamagePosition` 是规则规定的受击采样点。

`ApplyServerExplosion` 由下面的服务器结算入口调用。目标实现负责服务器生命值、队伍关系、免疫、归因以及击退交接，`pushVelocity` 表达规则希望施加的外部速度。

```csharp
using System;
using System.Collections.Generic;
using Mirror;
using UnityEngine;

[RequireComponent(typeof(NetworkIdentity))]
public sealed class ExplosionWorld : NetworkBehaviour
{
    [SerializeField] private LayerMask damageLayers;
    [SerializeField] private int maximumDamage = 50;
    [SerializeField] private float maximumPushSpeed = 8f;

    public event Action<ExplosionEvent> ClientExplosion;

    [Server]
    public void ServerResolveExplosion(ExplosionEvent burst)
    {
        Collider[] overlaps = Physics.OverlapSphere(
            burst.Position, burst.Radius,
            damageLayers, QueryTriggerInteraction.Ignore);
        var visited = new HashSet<uint>();

        foreach (Collider hit in overlaps)
        {
            ExplosionDamageReceiver receiver =
                hit.GetComponentInParent<ExplosionDamageReceiver>();
            if (receiver == null)
            {
                continue;
            }

            NetworkIdentity target = receiver.Identity;
            if (target == null || !target.isServer || !visited.Add(target.netId))
            {
                continue;
            }

            Vector3 delta = receiver.DamagePosition - burst.Position;
            float distance = delta.magnitude;
            if (distance > burst.Radius)
            {
                continue;
            }

            float attenuation = 1f - distance / Mathf.Max(0.001f, burst.Radius);
            int damage = Mathf.RoundToInt(maximumDamage * attenuation);
            Vector3 direction = distance > 0.001f ? delta / distance : Vector3.up;
            receiver.ApplyServerExplosion(
                burst.ThrowerNetId, damage,
                direction * maximumPushSpeed * attenuation);
        }

        RpcExplosion(burst);
    }

    [ClientRpc]
    private void RpcExplosion(ExplosionEvent burst)
    {
        ClientExplosion?.Invoke(burst);
    }
}
```

查询采用服务器物理场景中的当前位置。玩家的服务器位置来自本项目已接受的移动上行，因此命中精度与这条位置链路相关。引入历史位置判定时，为它明确保存历史与选择判定时间的规则。

这份基础示例使用线性距离衰减。固定伤害、分段衰减、穿墙与遮挡都在服务器规则中定义。需要遮挡时，在爆心与采样点之间查询指定环境层，确认可达后再应用伤害。

示例用 `Physics.OverlapSphere` 表达完整候选查询。需要降低频繁查询的分配时，再用 `OverlapSphereNonAlloc` 配合复用缓冲。该接口返回数量等于缓冲长度时，缓冲可能已经装满，需要扩大后重查或采用完整查询兜底。

爆炸半径、伤害与推力按服务器配置限制范围。本例把伤害参数放在房间组件，接入多种道具时，由服务器道具目录按 `ItemId` 提供对应规则。

## 7. 生命值与击退怎样接到项目玩家

生命值由服务器目标组件维护，扣血后通过 SyncVar 下行。界面与受伤表现读取初始值，并订阅变化。

刚体道具与本项目玩家采用不同运动入口：

| 目标 | 运动入口 | 爆炸后的处理 |
| --- | --- | --- |
| 服务器模拟的刚体箱子或道具 | `Rigidbody` | 服务器施加冲量或 `AddExplosionForce`，快照同步运动 |
| 本项目玩家 | `CharacterMotor` 与 `CharacterController.Move` | 服务器确认击退，拥有者将外部速度交给 Motor |

`CharacterController` 是 Unity 的角色碰撞移动组件。工程内 [CharacterMotor.cs](/D:/Unity/Projects/My_3DProject/Assets/Core/Scripts/Character/Runtime/CharacterMotor.cs) 计算位移，[PlayerCharacterController.cs](/D:/Unity/Projects/My_3DProject/Assets/Core/Scripts/Character/Runtime/PlayerCharacterController.cs) 组织输入与移动，拥有者移动结果再上行。

沿当前玩家移动方向接入击退时，设计以下接口和数据：

```text
S 结算击退
  → 保存目标、事件序号、外部速度与持续规则
  → TargetRpc 通知目标拥有者
  → 拥有者按序号接收一次
  → PlayerCharacterController 把外部速度交给 CharacterMotor
  → Motor 将主动移动与外部速度合成，经 CharacterController.Move 执行
  → 拥有者的位置快照上行，再下行到其他客户端
```

Motor 的外部速度入口保存击退速度，在每次移动 Tick 中按衰减、重力和碰撞规则推进，再与主动移动合成。它是运动状态的一部分，输入层只描述玩家主动操作。

击退事件携带序号，用于避免重复应用；服务器保存被击退期限或相关状态，用于限制操作与校验玩家移动。目标自身的生命值和控制限制仍由服务器状态决定。

这种接入沿用拥有者计算玩家位置的模式。服务器加强裁决时，对上行位置检查速度、可达范围和击退期间约束；选择服务器计算玩家运动时，玩家上行输入，服务器 Motor 执行输入与外部速度，快照改为服务器下行。

服务器直接修改玩家根位置时，拥有者下一次位置上行可能继续写入旧运动结果。因此运动决定者、Motor 状态与变换同步方向要一起设计。

## 8. 命中、爆炸与销毁的完整链路

```text
S 模拟飞行、弹跳和滚动
  → 引信到期或满足引爆规则
  → S 将阶段设为 Exploded
  → S 按实际刚体位置查询目标
  → S 去重并结算生命值、击退与归因
  → 目标同步字段下行当前状态
  → 稳定房间对象发送爆炸事件
  → A、B 清理预测并播放本地效果
  → S 调用 NetworkServer.Destroy
  → A、B 停止投掷物网络副本并清理接管记录
```

状态、事件和实体销毁是不同消息。客户端处理器各自能够独立读取完整数据，并允许结束清理重复调用。

短命投掷物先爆炸后显示、爆炸事件晚到、对象先停止，都按事件数据与预测结束记录收尾。固定房间广播同样受观察者范围影响，房间对象的接收范围应覆盖需要该效果的玩家。

投掷者离开后的伤害归因使用服务器保存的玩家或比赛身份。运行期 `netId` 适合关联当前实体，跨离开与重新加入的计分使用稳定的业务身份。

## 9. 按哪些场景验证

| 场景 | 观察点 |
| --- | --- |
| 两人分别投掷 | 服务器各生成一次，两端轨迹与归因正确 |
| 手雷连续弹跳 | 服务器持续模拟，客户端接管后沿快照显示 |
| 高速球击中薄墙 | 物理模式与扫掠规则覆盖实际速度范围 |
| 一个玩家有多个碰撞体 | 每次爆炸只对该目标结算一次 |
| 引信与碰撞同帧引爆 | 阶段保护让爆炸、伤害和事件各发生一次 |
| 投掷后立刻爆炸 | 预测球清理，世界效果完整播放 |
| 高延迟与消息抖动 | 接管过渡有界，快照和结束记录正确收尾 |
| 中途加入 | 飞行位置、阶段与剩余引信从当前状态恢复 |
| 命中角色与刚体道具 | 两类目标分别沿 Motor 与刚体入口运动 |
| 投掷者离开 | 投掷物与归因按服务器规则继续处理 |
| 房间结束或场景退出 | 网络实体、预测记录、订阅和特效按生命周期清理 |
