本节对应 [NetworkCharacterSync.cs](/D:/Unity/Projects/My_3DProject/Assets/Core/Scripts/Networking/NetworkCharacterSync.cs)。

## 1. 同步组件保存服务器确认的状态

```csharp
public sealed class NetworkCharacterSync : NetworkBehaviour
{
    [SyncVar(hook = nameof(OnCharacterIdChanged))]
    private int characterId;

    public int CharacterId => characterId;
    public bool IsLocalPlayerCharacter => isLocalPlayer;
}
```

这是类中与编号相关的声明摘录。

`[Command]`、`[SyncVar]` 这类方括号标记在 C# 中叫 Attribute，中文通常称为特性。特性给方法或字段附加元数据，Mirror 在编译阶段读取这些元数据并生成网络代码。

`SyncVar` 表示参与同步的字段。这个组件在 Prefab 中使用 `ServerToClient`，即服务器到客户端的同步方向。服务器维护 `characterId`，拥有者与其他观察客户端接收它。

`hook` 是同步值变化后的回调配置。本字段指定 `OnCharacterIdChanged`，方法接收旧值和新值。`nameof` 取得方法名称，重命名时由 C# 工具保持名称关联。

观察者是服务器允许接收这个网络对象的客户端连接。对象状态和面向观察者的通知都以这组连接为发送范围。

## 2. 上行入口运行在发起操作的客户端

源码中的公开入口是：

```csharp
public void SetLocalCharacter(int requestedCharacterId)
{
    if (!isLocalPlayer
        || NetworkCharacterManager.Instance == null
        || !NetworkCharacterManager.Instance.IsValidCharacterId(requestedCharacterId))
    {
        return;
    }

    CommandSetCharacter(requestedCharacterId);
}
```

这个方法执行本地检查，然后提交请求。此时参数表示“希望使用的编号”。

它适合提供给按钮、键盘操作或其他本地控制代码。调用者只传编号，网络组件集中处理身份和发送。

## 3. Command 方法体编写服务器处理逻辑

源码中的 Command 是：

```csharp
[Command]
private void CommandSetCharacter(int requestedCharacterId)
{
    if (NetworkCharacterManager.Instance == null
        || !NetworkCharacterManager.Instance.IsValidCharacterId(requestedCharacterId))
    {
        return;
    }

    characterId = requestedCharacterId;
}
```

这个方法体负责服务器处理请求：

1. 读取服务器自己的管理器。
2. 按服务器配置校验编号。
3. 将有效编号写入服务器自己的玩家对象。

普通客户端调用 `CommandSetCharacter` 时执行 Mirror 生成的发送入口。服务器收到消息后执行这里写出的业务方法体。

服务器上赋值完成后，`characterId` 进入这个组件的下行状态同步。Command 的职责到此结束，客户端装配由下行链路驱动。

`CommandSetCharacter` 的名字便于阅读。让方法具备 Command 网络行为的条件是：它属于有效网络对象上的 `NetworkBehaviour`，带有 `[Command]`，签名满足 Mirror 要求，而且调用时具有可用的客户端连接和权限。

## 4. 下行接收把状态转成客户端表现

源码中的变化回调是：

```csharp
private void OnCharacterIdChanged(int _, int __)
{
    ApplyCharacter();
}

private void ApplyCharacter()
{
    NetworkCharacterManager.Instance?.ApplyCharacter(this, characterId);
}
```

Mirror 反序列化后先更新字段，再在值变化时调用 hook。这里读取更新后的 `characterId`，把玩家和编号交给管理器。

服务器在生成玩家时确定初始编号。源码中的初始化入口是：

```csharp
public override void OnStartServer()
{
    base.OnStartServer();

    characterId = NetworkCharacterManager.Instance != null
        ? Mathf.Max(0, NetworkCharacterManager.Instance.DefaultCharacterId)
        : 0;
}
```

这里读取服务器管理器的默认编号，将结果写入服务器玩家。初次发送对象时，Mirror 序列化这个当前值。

客户端首次生成也需要装配：

```csharp
public override void OnStartClient()
{
    base.OnStartClient();
    ApplyCharacter();
}

public override void OnStartLocalPlayer()
{
    base.OnStartLocalPlayer();
    ApplyCharacter();
}
```

初始状态通过 Spawn 数据接收。Spawn 是 Mirror 建立网络对象生命周期、向客户端描述对象及其初始状态的过程。

`OnStartClient` 使用当前值建立表现，覆盖初始值与字段默认值相同的情况。`OnStartLocalPlayer` 处理本地玩家启动时的表现和相机归属。

同一个装配入口可能由初始 hook 和启动回调调用。管理器的缓存负责复用相同实例、编号、来源 Prefab 和身份的装配结果。这种写法具有幂等性，即相同条件下重复调用保持相同结果。

## 5. 停止时清理本地引用

```csharp
public override void OnStopClient()
{
    NetworkCharacterManager.Instance?.RemoveCharacter(this);
    base.OnStopClient();
}
```

管理器先解除网络根上的动画和输入引用，再销毁视觉实例并移除缓存。资源释放跟随这个玩家的客户端生命周期。

## 6. 把上下行合起来读

```text
上行
  A 的 CharacterSelectButton.OnClick
    → A 的甲.SetLocalCharacter(1)
    → A 执行生成的 Command 发送代码
    → S 接收消息并检查甲的对象归属
    → S 执行甲.CommandSetCharacter 的业务方法体
    → S 校验编号并写 characterId = 1

下行
  S 序列化甲的 characterId
    → A、B 接收甲的状态
    → 各自的甲.characterId 更新为 1
    → 各自执行 OnCharacterIdChanged
    → A 为甲选择 localCharacterPrefabs[1]
    → B 为甲选择 characterPrefabs[1]
```

新客户端进入时，Spawn 初始状态携带当前编号。已连接客户端接收后续状态变化。两种接收时机最终进入同一个本地装配入口。
