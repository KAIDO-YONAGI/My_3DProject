## 1. 集合状态使用同步集合

`SyncList<T>` 是 Mirror 的同步列表，`SyncDictionary<TKey, TValue>` 是同步字典。它们记录集合操作，并提供完整初始内容与后续变化同步。

扩展练习：房间名单属于一个房间网络对象，由服务器维护。名单保存玩家的网络编号。

```csharp
using System;
using Mirror;

public sealed class NetworkRoomRoster : NetworkBehaviour
{
    public readonly SyncList<uint> PlayerIds = new SyncList<uint>();
    public event Action RosterChanged;

    private bool rosterRefreshPending;

    [Server]
    public void ServerAddPlayer(uint playerNetId)
    {
        if (!NetworkServer.spawned.ContainsKey(playerNetId)
            || PlayerIds.Contains(playerNetId))
        {
            return;
        }

        PlayerIds.Add(playerNetId);
    }

    [Server]
    public void ServerRemovePlayer(uint playerNetId)
    {
        PlayerIds.Remove(playerNetId);
    }

    public override void OnStartClient()
    {
        base.OnStartClient();
        PlayerIds.OnChange += OnRosterChanged;
        RosterChanged?.Invoke();
    }

    public override void OnStopClient()
    {
        PlayerIds.OnChange -= OnRosterChanged;
        rosterRefreshPending = false;
        base.OnStopClient();
    }

    private void LateUpdate()
    {
        if (isClient && rosterRefreshPending)
        {
            rosterRefreshPending = false;
            RosterChanged?.Invoke();
        }
    }

    private void OnRosterChanged(
        SyncList<uint>.Operation operation,
        int index,
        uint item)
    {
        rosterRefreshPending = true;
    }
}
```

房间网络对象采用 `ServerToClient`。把 `NetworkRoomRoster` 与 `NetworkIdentity` 放在房间 Prefab 根上，注册 Prefab，再由服务器为房间生成一个实例。服务器在确认玩家加入或退出房间时调用增删方法，房间 UI 绑定客户端的房间实例，读取 `PlayerIds` 并订阅 `RosterChanged`。

集合在 `OnStartClient` 前已经接收初始内容，所以启动时按当前集合刷新一次。后续集合操作触发回调，再更新界面。

示例将集合变化标记为待刷新，在 `LateUpdate` 按已经完成操作的集合统一重读名单。同一帧的变化合并成一次刷新。需要局部更新时，可以使用 `OnAdd`、`OnSet`、`OnRemove` 等对应操作回调，并处理各回调提供的索引和元素。

`SyncList` 通过自身机制记录变化，字段声明保留同一个集合实例。集合元素为结构体时，先修改取出的值，再写回对应索引，让集合记录替换操作。

## 2. 公共对象的操作优先从玩家发起

开发拾取或机关交互时，可以把 Command 放在玩家网络根上：

```text
本地输入选中目标
  → 自己玩家的请求方法，传入目标网络编号
  → 玩家 Command
  → 服务器根据 netId 找目标
  → 校验玩家状态、目标状态和距离
  → 更新目标或玩家状态
  → 状态下行，必要时补充表现通知
```

这条链路沿用玩家的连接归属。服务器可以从当前玩家和 `connectionToClient` 确定请求者。

另一种写法是在公共对象上接收 Command。公共对象面向多个客户端开放请求时，可以使用：

```csharp
[Command(requiresAuthority = false)]
private void CommandRequestInteraction(NetworkConnectionToClient sender = null)
{
    if (sender == null || sender.identity == null)
    {
        return;
    }

    NetworkIdentity requestingPlayer = sender.identity;
    // 后续业务根据 requestingPlayer 校验距离、资格和目标状态。
}
```

这是一段公共对象接收入口示例。`requiresAuthority = false` 允许非拥有者提交请求，Mirror 在服务器侧填入实际发送连接。

采用这条链路时，服务器把 `sender` 作为请求身份来源，并编写完整的业务校验。客户端传入的数据描述意图，资格与结果由服务器判断。

对同一个拾取目标，服务器在一次请求处理内检查可用状态、确定归属、更新结果。后续请求读取更新后的状态，这样多个玩家竞争时共用同一决定点。

## 3. 独立网络实体由服务器生成和销毁

为道具等独立实体创建 Prefab，在根上配置 `NetworkIdentity` 和需要的 `NetworkBehaviour`。客户端通过 `NetworkManager` 的 `Spawn Prefabs` 列表注册对应 Prefab。

Spawn Prefabs 是 Mirror 的网络预制体注册列表，客户端据生成消息中的资源标识找到本地资源。

服务器侧创建流程可以写为：

```csharp
[Server]
private void ServerSpawnItem(UnityEngine.GameObject itemPrefab, UnityEngine.Vector3 position)
{
    UnityEngine.GameObject item = Instantiate(
        itemPrefab,
        position,
        UnityEngine.Quaternion.identity);

    NetworkServer.Spawn(item);
}
```

这段方法属于服务器侧的生成组件，`itemPrefab` 来自已经配置并注册的网络 Prefab。

```text
服务器 Instantiate
  → 创建服务器实例
  → NetworkServer.Spawn
  → 建立网络身份与初始状态
  → 客户端创建对应副本
  → 客户端执行网络启动回调
```

独立网络实体的服务器销毁使用 `NetworkServer.Destroy(item)`，由 Mirror 通知客户端处理对应对象。

项目的角色视觉实例采用另一条生命周期：客户端管理器 `Instantiate`，客户端管理器 `Destroy`。开发时根据对象是否需要独立网络身份选择生成方式。

## 4. 场景实体与动态实体怎样接入

Mirror 使用两种方式找到客户端对应的实体：

| 实体来源 | 定位依据 | 接入方式 |
| --- | --- | --- |
| 运行时生成的网络 Prefab | `assetId`，预制体的资源标识 | 注册 Prefab，由服务器生成 |
| 已保存在场景中的网络对象 | `sceneId`，场景对象标识 | 两侧加载匹配场景，由服务器管理激活与状态 |

两类对象进入网络生命周期后都使用运行期 `netId`，同步状态、归属和远程调用沿用相同原则。

开发场景机关时，将网络身份和状态组件保存在场景对象上，安排两侧的场景加载与服务器生成流程。客户端收到对应场景对象的生成消息后应用当前状态，再执行客户端启动回调。

开发运行时生成的道具时，使用注册的网络 Prefab 和服务器生成入口。给晚加入者恢复状态时，由 Spawn 提供当前完整数据。

本项目通过常驻场景组织管理器，通过 `SceneChanger` 加载玩法场景。接入场景网络实体时，把场景加载完成、服务器登记和客户端就绪安排为明确的先后步骤。

## 5. 连接级数据使用 NetworkMessage

`NetworkMessage` 是 Mirror 的消息接口，适合连接级请求与通知。它通过消息类型识别处理器，调用位置与某个网络对象的生命周期分开管理。

扩展练习：客户端向服务器发送带请求编号的状态查询：

```csharp
public struct RoomStatusRequest : Mirror.NetworkMessage
{
    public uint RequestId;
}

public struct RoomStatusResponse : Mirror.NetworkMessage
{
    public uint RequestId;
    public int ConnectedPlayerCount;
}
```

下面的管理器示例包含注册、请求、接收和解除注册：

```csharp
using System;
using Mirror;

public sealed class RoomStatusNetworkManager : NetworkManager
{
    public event Action<uint, int> RoomStatusReceived;

    public override void OnStartServer()
    {
        base.OnStartServer();
        NetworkServer.RegisterHandler<RoomStatusRequest>(OnRoomStatusRequest);
    }

    public override void OnStartClient()
    {
        base.OnStartClient();
        NetworkClient.RegisterHandler<RoomStatusResponse>(OnRoomStatusResponse);
    }

    public override void OnStopServer()
    {
        NetworkServer.UnregisterHandler<RoomStatusRequest>();
        base.OnStopServer();
    }

    public override void OnStopClient()
    {
        NetworkClient.UnregisterHandler<RoomStatusResponse>();
        base.OnStopClient();
    }

    public void RequestRoomStatus(uint requestId)
    {
        if (!NetworkClient.isConnected
            || NetworkClient.connection == null
            || !NetworkClient.connection.isAuthenticated)
        {
            return;
        }

        NetworkClient.Send(new RoomStatusRequest { RequestId = requestId });
    }

    private void OnRoomStatusRequest(
        NetworkConnectionToClient connection,
        RoomStatusRequest request)
    {
        int playerCount = 0;
        foreach (NetworkConnectionToClient client in NetworkServer.connections.Values)
        {
            if (client.identity != null)
            {
                playerCount++;
            }
        }

        connection.Send(new RoomStatusResponse
        {
            RequestId = request.RequestId,
            ConnectedPlayerCount = playerCount
        });
    }

    private void OnRoomStatusResponse(RoomStatusResponse response)
    {
        RoomStatusReceived?.Invoke(response.RequestId, response.ConnectedPlayerCount);
    }
}
```

这里统计建立玩家身份的连接。房间业务可以在相同入口读取自己的房间名单，构造对应响应。

接入这个扩展练习时，用 `RoomStatusNetworkManager` 承担场景中现有管理器的位置，保留项目的 Transport、玩家 Prefab 和连接配置。它继承 `NetworkManager`，沿用连接与玩家创建流程。

本地界面取得这个管理器实例，订阅 `RoomStatusReceived`，再调用 `RequestRoomStatus`。每个待处理查询使用自己的请求编号。响应到达时，界面用编号对应查询并显示人数，解绑时解除事件订阅。

处理器默认要求 Mirror 连接完成认证。开发者继续检查业务权限、消息内容和请求频率。

示例的请求入口同时检查连接与认证状态。界面按连接状态安排查询时机，消息响应继续通过本地事件交接。

请求编号用于对应异步响应。客户端发出请求后继续运行，响应到达时再更新本地界面。

消息字段使用公开的可序列化数据。发送以连接为基础，处理器以消息类型为基础；认证、房间资格和业务阶段由对应入口检查。
