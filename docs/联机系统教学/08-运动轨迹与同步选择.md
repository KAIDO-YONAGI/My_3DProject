# 运动轨迹与同步选择

[返回目录](README.md)

本章解决一个问题：多人都要看到某个对象运动时，到底需要同步哪些数据？

先区分三项职责：模拟产生运动结果，同步传递运动数据，表现将接收的数据显示出来。碰撞、伤害和得分再使用明确的游戏规则处理。

## 1. 按运动性质选择方案

| 对象或运动 | 计算运动的位置 | 主要传递内容 | 客户端怎样显示 |
| --- | --- | --- | --- |
| 本项目玩家移动 | 拥有者客户端 | 网络根的位置与旋转快照，上行后转发 | 拥有者使用本地结果，远程客户端插值 |
| 会弹跳、滚动、撞击道具的手雷 | 服务器 | 权威位置与旋转快照、道具阶段、引信期限 | 插值显示，投掷者短暂使用本地预测 |
| 固定重力、无中途轨迹变化的抛物运动 | 服务器确定发射与命中 | 起点、初速度、加速度、开始时间，必要时补充修正 | 按同一公式和网络时间重建轨迹 |
| 追踪弹、移动平台、受力机关 | 服务器或规则指定的控制者 | 当前运动状态与快照 | 插值，按需要做受限外推 |
| 射线命中武器 | 服务器计算命中 | 命中位置、目标、结果和表现参数 | 播放本地弹道线与命中特效 |
| 烟雾、爆炸闪光、碎屑 | 客户端表现层 | 触发事件和需要持续恢复的状态 | 本地播放效果 |

射线命中指一次射线查询确定结果，常用于即时命中的武器。对确实有飞行时间的投掷物，使用有生命周期的实体模拟。

本项目的派对投掷玩法采用服务器物理模拟，加上投掷者的短暂视觉预测作为基础方案。这样可以把弹跳、滚动和动态碰撞统一交给一个决定点，同时让投掷动作立即有视觉反馈。

## 2. 连续位置使用快照

服务器物理投掷物的基本下行是：

```text
S 的 Rigidbody 产生当前位置与旋转
  → 变换同步组件发送快照
  → A、B 将快照放入缓冲
  → A、B 按显示时间线插值
  → 模型跟随接收端网络根
```

`Rigidbody` 是 Unity 的刚体组件，负责受力、速度和物理运动。`FixedUpdate` 是 Unity 按固定物理步长调用的入口，刚体相关的持续力和物理规则按这个节奏组织。

渲染帧率、物理步频和网络发送频率分别承担职责。提升渲染帧率改善显示采样，提升物理步频改变模拟精度，提升发送频率增加网络状态更新。

快照插值使用一段缓冲时间，让客户端有相邻的状态可以计算。缓冲更充足时更容易承受抖动，也增加显示延迟。

抖动指消息到达间隔的变化。丢包指传输中某些消息没有到达，可靠通道通过重传恢复数据。

### 工程内的组件选择

工程内的 `NetworkRigidbodyReliable` 继承 `NetworkTransformReliable`，利用其变换同步，并在非模拟侧将刚体设置为运动学模式。

运动学模式对应 `Rigidbody.isKinematic = true`，该刚体的位置由脚本控制。它仍可能通过碰撞影响其他刚体，是否参与客户端碰撞需要按用途设置。

服务器模拟投掷物时，将这个组件设置为：

| 配置 | 值或规则 |
| --- | --- |
| Sync Direction | `ServerToClient` |
| Sync Mode | `Observers` |
| Target | 投掷物网络根的 Transform |
| Sync Position | 开启 |
| Sync Rotation | 需要旋转表现时开启 |
| Sync Scale | 固定尺寸的投掷物保持关闭 |
| 服务器 Rigidbody | 动态模拟，初速度由服务器设置 |
| 客户端 Rigidbody | 运动学，位置由快照驱动 |
| 客户端玩法碰撞 | 通过碰撞层或 `detectCollisions` 按显示需求隔离 |

这个组件已经包含变换同步职责。同一根的位置与旋转由这一套同步组件写入，避免多个同步组件同时改写同一目标。

初速度和角速度由投掷规则初始化。需要客户端额外读取速度用于尾迹、姿态或有限外推时，在业务状态中明确传递速度与采样时间。

源码依据：[NetworkRigidbodyReliable.cs](/D:/Unity/Projects/My_3DProject/Assets/Plugins/Mirror/Components/NetworkRigidbody/NetworkRigidbodyReliable.cs)、[NetworkTransformReliable.cs](/D:/Unity/Projects/My_3DProject/Assets/Plugins/Mirror/Components/NetworkTransform/NetworkTransformReliable.cs)。

### 可靠与非可靠变换同步

可靠同步通过重传保证数据到达，适合作为基础配置。连续快照更重视时效时，可以比较工程内的 `NetworkRigidbodyUnreliable`，它使用非可靠变换同步。

切换组件时，同时检查 Prefab 两端布局、同步方向、带宽、快照缓冲和弱网表现。道具生成、规则请求、爆炸结算与连续位置更新分别选择适合自己的机制。

先用可靠组件建立完整链路，再依据延迟、抖动和流量测量选择连续运动通道。服务器发送率和组件的 `sendIntervalMultiplier` 一起影响快照节奏。

## 3. 简单轨迹可以同步发射参数

固定加速度的轨迹可以写成：

```text
经过时间 t = 当前显示网络时间 - 发射时间

位置 p(t) = 起点 p0 + 初速度 v0 × t + 0.5 × 加速度 g × t²
速度 v(t) = 初速度 v0 + 加速度 g × t
```

扩展练习中的纯轨迹函数是：

```csharp
using UnityEngine;

public static class BallisticPath
{
    public static Vector3 Evaluate(
        Vector3 origin,
        Vector3 initialVelocity,
        Vector3 acceleration,
        double elapsedSeconds)
    {
        float t = (float)System.Math.Max(0d, elapsedSeconds);
        return origin + initialVelocity * t + 0.5f * acceleration * t * t;
    }
}
```

函数只做计算，适合用于预测视觉球、抛物线预览或规则确定的轨迹显示。网络绝对时间使用 `double`，只把这一段短持续时间转换成 `float` 进行 Unity 向量运算。

服务器同步：

```text
道具类型
起点与初速度
加速度或运动配置编号
发射时间
当前阶段
```

客户端收到后按同一公式重建当前位置。后加入者使用当前时间与发射时间的差值，直接显示进行中的轨迹。

### 公式的适用范围

固定重力与自由飞行适合这个公式。阻力、弹跳、滚动、追踪和外力会改变后续轨迹，这些行为需要对应的运动模型或权威修正。

Unity 刚体按离散物理步模拟，解析公式按连续时间计算。两者承担不同用途，视觉预测允许小范围误差，命中与后续运动以服务器结果为准。

弹跳后继续采用参数轨迹时，服务器发送新的轨迹段，包含段编号、段起点、段初速度和段开始时间。客户端只应用有效的新段，并处理晚到的旧段。

多个动态刚体连续互相碰撞时，服务器快照能直接表达复杂运动结果，适合作为基础。

## 4. 时间先统一，再比较位置

工程中的网络时间由 [NetworkTime.cs](/D:/Unity/Projects/My_3DProject/Assets/Plugins/Mirror/Core/NetworkTime.cs) 提供：

| 时间 | 在本工程中的用途 |
| --- | --- |
| `NetworkTime.localTime` | 当前进程的未缩放时间，适合本地预测等待与超时 |
| `NetworkTime.time` | 缩放后的网络时间；服务器取自身时间，客户端取插值时间线 |
| `NetworkTime.unscaledTime` | 未缩放的网络时间；客户端同样使用插值时间线 |
| `NetworkTime.predictedTime` | 面向输入预测的时间估计，考虑请求到达服务器的时间关系 |
| `NetworkTime.rtt` | 客户端到服务器再返回的平均往返时间 |

时间缩放指 `Time.timeScale` 对游戏推进速度的影响。倒计时随游戏暂停时采用缩放时间；实际时间继续推进的引信采用未缩放时间。服务器与客户端使用相同时间基准。

本教程的投掷练习用 `NetworkTime.unscaledTime` 保存发射与引信期限，客户端按同一时间线显示。本地预测从按键当刻开始，用本地未缩放时间计算经过时间。

因此“预测球当前位置”和“收到的权威当前位置”可能属于不同时间线。服务器开始模拟的时刻、网络传输和客户端缓冲都会产生可见差距。

接管时按权威显示根建立视觉过渡。需要持续预测时，为每个预测样本保存时间，再按服务器状态的采样时间比较、校正和重放。

把请求时间直接作为服务器发射时间，会涉及历史玩家位置、历史碰撞世界和延迟补偿规则。基础方案以服务器接受请求的时刻开始权威模拟。

延迟补偿指服务器按定义的历史时间恢复判定所需状态。它是独立的规则和历史数据设计。

## 5. 预测的强度按玩法需要选择

| 做法 | 保存的数据 | 校正方式 | 合适的用途 |
| --- | --- | --- | --- |
| 短暂视觉预测 | 本地预测实例、请求编号和创建时间 | 权威副本到达后切换视觉 | 本教程的投掷起手 |
| 有限外推 | 最新位置、速度和采样时间 | 新快照到达后平滑或直接纠正 | 飞行显示短暂缺少后续快照 |
| 持续输入预测 | 输入序号、状态历史和确认进度 | 对齐历史状态后重放未确认输入 | 强依赖即时操控的角色或载具 |
| 共享物理预测 | 刚体历史及相关交互数据 | 按既定算法校正预测运动 | 需要预测推挤与动态物理交互的玩法 |

外推指根据已有速度等状态估算后续运动。外推时设定持续时间上限，碰撞和最终状态仍使用权威结果。

Mirror 官方的预测文档说明客户端即时模拟、历史比较和校正的原理，也提供 `PredictedRigidbody` 相关示例。选用持续物理预测时，一起验证碰撞引用、模拟对象、显示对象和校正方式。

本教程用短暂视觉预测解决投掷起手反馈，随后进入统一的权威快照显示。下一章将这一选择接到项目的网络玩家结构中。
