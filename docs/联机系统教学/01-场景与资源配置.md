# 场景与资源配置

## 1. 构建场景顺序

当前 Build Settings 启用以下场景：

1. `Assets/Core/Scenes/InitialScene.unity`
2. `Assets/Core/Scenes/PersistentScene.unity`
3. `Assets/Core/Scenes/MultiplayerSampleScene.unity`

场景顺序决定构建启动入口。场景之间的职责由脚本和资源引用共同决定。

## 2. InitialScene

`InitialScene` 的根对象是 `Bootstrapper`，挂载 `Assets/FrameWork/Scripts/Scene/InitialLoad.cs`。

`InitialLoad` 的作用：

1. 读取 `persistentScenes` 列表。
2. 调用 `PersistentSceneRegistry.Register` 登记常驻场景名称。
3. 使用 `SceneManager.LoadSceneAsync(sceneName, LoadSceneMode.Additive)` 加载常驻场景。
4. 等待每个场景加载完成后继续处理列表。

当前 `persistentScenes` 指向 Persistent Scene 配置，因此 `PersistentScene` 会在初始场景之后加入运行时。

`InitialLoad` 不创建玩家，不启动 Mirror，不创建 Camera。它只负责把常驻场景加载进来，并告诉场景框架哪些场景不能被内容场景切换卸载。

## 3. PersistentScene

`PersistentScene` 是网络和单机共用的常驻层，主要层级如下：

```text
PersistentScene
├─ Managers
│  ├─ NetworkManager
│  ├─ NetworkCharacterManager
│  ├─ SceneChanger
│  └─ TimeManager
├─ EventSystem
├─ LocalPlayer
├─ NetworkPlayerSpawn_A
└─ NetworkPlayerSpawn_B
```

### Managers/NetworkManager

场景中使用 `Assets/Core/Prefabs/NetworkManager.prefab` 的实例。它包含：

- Mirror `NetworkManager`
- Mirror `NetworkManagerHUD`
- `kcp2k.KcpTransport`
- `AutoStartClient`

这个对象提供连接入口、服务端监听入口、玩家 Prefab 配置和 KCP 参数。

### Managers/NetworkCharacterManager

这是当前工程唯一的网络角色表现装配中心。它保存两套角色数组：

| 角色编号 | 本地数组 | 远程数组 |
|---|---|---|
| `0` | `CharactersForLocal/娜娜莉（华丽飞踢）.prefab` | `CharactersForSync/娜娜莉（华丽飞踢）_Sync.prefab` |
| `1` | `CharactersForLocal/娜娜莉（学园之星）.prefab` | `CharactersForSync/娜娜莉（学园之星）_Sync.prefab` |

数组下标就是网络传输的角色编号。两套数组需要保持下标对齐，服务器和客户端的资源配置需要表达同一张编号表。

### Managers/SceneChanger

`SceneChanger` 的 `firstSceneToLoad` 引用 `MultiplayerSampleSceneSO`。它在 `Start` 中调用 `RequestSceneLoad`，随后：

1. 广播场景加载事件。
2. 暂停时间和输入。
3. 保留 Persistent Scene。
4. 以 Additive 模式加载玩法场景。
5. 将 `LocalPlayer` 设置到场景资源配置的初始位置。
6. 广播场景完成事件。
7. 恢复输入和时间。

Mirror 的 `onlineScene` 为空，因此玩法场景由 `SceneChanger` 管理。这样 NetworkManager、NetworkCharacterManager、LocalPlayer 和 EventSystem 可以继续留在常驻场景。

### LocalPlayer

`LocalPlayer` 是单机开发角色。它在编辑器中已经存在于场景层级，包含本地角色视觉、移动入口、Camera、`ThirdPersonCamera` 和 `AudioListener`。

无服务端时，`LocalPlayer` 提供可直接运行的移动和相机环境。客户端连接完成后，`NetworkCharacterManager` 收起它，避免场景单机角色与 Mirror 网络玩家同时显示。

### NetworkPlayerSpawn_A 与 NetworkPlayerSpawn_B

这两个对象只挂载 Mirror `NetworkStartPosition`，作用是为服务器生成的 `Player_Network` 提供候选出生 Transform。

当前配置：

```text
NetworkPlayerSpawn_A = (-2.63, -9.3075, -31.27)
NetworkPlayerSpawn_B = (-0.63, -9.05172, -31.27)
playerSpawnMethod = Random
```

出生点不负责持续修正玩家高度。网络根生成后，`CharacterController` 和 `CharacterMotor` 根据地形碰撞与重力计算实际落地过程。

## 4. MultiplayerSampleScene

`MultiplayerSampleScene` 是玩法环境层，主要提供：

- Terrain
- TerrainCollider
- Directional Light
- Terrain 分组与默认环境对象

场景中的 `Camera` 对象保持停用。运行时相机来自：

- 单机状态的 `LocalPlayer`。
- 联机状态的本地拥有者角色表现。

远程角色表现不使用玩法场景 Camera，也不启用远程视觉 Prefab 中的本地相机。

## 5. 场景加载关系

```text
InitialScene
  └─ InitialLoad
      └─ Additive 加载 PersistentScene

PersistentScene
  └─ SceneChanger
      └─ Additive 加载 MultiplayerSampleScene
```

`PersistentSceneRegistry` 保存常驻场景名。`SceneChanger` 卸载内容场景时先检查注册表，因此 Persistent Scene 会持续存在。

## 6. 资源引用关系

```text
NetworkManager.prefab
  └─ playerPrefab
      └─ Player_Network.prefab

Player_Network.prefab
  ├─ NetworkIdentity
  ├─ NetworkTransformReliable
  ├─ CharacterController
  ├─ PlayerCharacterController
  └─ NetworkCharacterSync

PersistentScene/Managers/NetworkCharacterManager
  ├─ localCharacterPrefabs[]
  └─ characterPrefabs[]
```

NetworkManager 只引用网络根。角色模型由 NetworkCharacterManager 根据网络根的身份和角色编号在客户端装配。

## 7. 场景配置检查

打开工程后按以下顺序检查：

1. Build Settings 包含三个当前场景。
2. InitialScene 的 `InitialLoad.persistentScenes` 指向 Persistent Scene。
3. PersistentScene 中只有一个 `NetworkManager` 和一个 `NetworkCharacterManager`。
4. SceneChanger 的 `firstSceneToLoad` 指向 MultiplayerSampleScene。
5. `NetworkManager.onlineScene` 为空。
6. `NetworkManager.playerPrefab` 指向 `Player_Network.prefab`。
7. 两个 `NetworkStartPosition` 在 PersistentScene 中。
8. NetworkCharacterManager 的本地数组和远程数组按编号配对。
9. MultiplayerSampleScene 的地形和 TerrainCollider 已加载。
