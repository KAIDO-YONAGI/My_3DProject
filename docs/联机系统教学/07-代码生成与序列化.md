## 1. 生成发生在编译阶段

IL 是 Intermediate Language 的缩写，指 C# 编译后的中间语言。程序集保存编译后的类型、方法和代码。

Mirror 的 Weaver 是程序集处理器。它通过 Unity 的 `ILPostProcessor` 编译后处理接口，使用 Mono.CecilX 读取和修改程序集。

```text
编写 C# 源码与特性
  → C# 编译为程序集
  → Unity 调用 ILPostProcessor
  → Mirror Weaver 扫描 NetworkBehaviour 与网络数据类型
  → 生成发送入口、接收入口和序列化代码
  → 输出处理后的程序集
  → 编辑器与构建程序使用处理后的代码
```

源码入口是 [ILPostProcessorHook.cs](/D:/Unity/Projects/My_3DProject/Assets/Plugins/Mirror/Editor/Weaver/EntryPointILPostProcessor/ILPostProcessorHook.cs)。

这条机制使源码中的普通方法调用获得网络行为。特性提供处理依据，Weaver 完成具体改写。

## 2. Command 源码对应发送与接收两部分

[MethodProcessor.cs](/D:/Unity/Projects/My_3DProject/Assets/Plugins/Mirror/Editor/Weaver/Processors/MethodProcessor.cs) 把开发者编写的方法体移到生成的 `UserCode_...` 方法中。[CommandProcessor.cs](/D:/Unity/Projects/My_3DProject/Assets/Plugins/Mirror/Editor/Weaver/Processors/CommandProcessor.cs) 为原入口生成发送代码，为接收端生成反序列化与调用代码。

针对项目的 `CommandSetCharacter(int requestedCharacterId)`，执行关系可以按下面的示意理解：

```text
客户端发送入口 CommandSetCharacter
  序列化 requestedCharacterId
  调用 SendCommandInternal
  发送对象编号、组件索引、方法标识和参数字节

服务器接收入口
  定位目标对象与组件
  检查发送连接的对象归属
  反序列化 requestedCharacterId
  调用保存原业务方法体的 UserCode_... 方法

原业务方法体
  检查服务器角色配置
  写入 characterId
```

客户端发送实现位于 [NetworkBehaviour.SendCommandInternal](/D:/Unity/Projects/My_3DProject/Assets/Plugins/Mirror/Core/NetworkBehaviour.cs:367)，服务器接收检查位于 [NetworkServer.OnCommandMessage](/D:/Unity/Projects/My_3DProject/Assets/Plugins/Mirror/Core/NetworkServer.cs:353)。

Command 消息中的字段分工是：

| 字段 | 用途 |
| --- | --- |
| `netId` | 定位目标网络对象 |
| `componentIndex` | 定位对象上的 NetworkBehaviour |
| `functionHash` | 定位注册的远程方法 |
| `payload` | 保存序列化后的参数 |

## 3. 方法标识依赖方法完整名称

Mirror 计算方法标识时使用方法完整名称，其中包含声明类型、名称、返回类型和参数类型。Weaver 将它转换成稳定的 16 位哈希值。哈希是将这段名称映射成固定长度数字的计算。

客户端发送这个标识，服务器使用自己注册的标识查找处理函数。方法名和参数类型属于网络约定的一部分。

开发时把以下内容一起管理：

- Command 和远程调用的类型、名称及参数。
- NetworkBehaviour 的组件布局与索引顺序。
- 同步字段和网络结构体的序列化格式。
- 客户端识别的网络 Prefab。
- 角色等资源编号的含义。

这些网络约定变动后，为客户端和服务器构建匹配的程序，并启动对应构建。运行中的服务器执行自身已加载的代码。

## 4. SyncVar 生成字段更新和序列化逻辑

源码中的：

```csharp
characterId = requestedCharacterId;
```

经过 Weaver 处理后，赋值接入生成的同步 setter。Setter 是字段对应的写入逻辑，它比较新旧值，并在变化时记录 dirty bit。Dirty bit 是标识哪个同步字段发生变化的位标记。

```text
服务器字段赋值
  → 比较新旧值
  → 标记变化字段
  → Mirror 按发送节奏序列化
  → 客户端反序列化
  → 更新字段
  → 值变化时调用 hook
```

初次 Spawn 序列化完整状态，后续同步使用变化标记组织状态更新。

相关生成逻辑位于 [SyncVarAttributeProcessor.cs](/D:/Unity/Projects/My_3DProject/Assets/Plugins/Mirror/Editor/Weaver/Processors/SyncVarAttributeProcessor.cs) 和 [NetworkBehaviourProcessor.cs](/D:/Unity/Projects/My_3DProject/Assets/Plugins/Mirror/Editor/Weaver/Processors/NetworkBehaviourProcessor.cs)。

## 5. 服务器构建也使用项目脚本

客户端与专用服务器从同一 Unity 工程编译项目脚本和 Mirror。专用服务器运行自己的场景、NetworkManager 和网络玩家，收到角色请求后执行其程序集中的 `CommandSetCharacter` 业务逻辑。

代码放在哪个文件夹主要用于组织职责。实际执行位置由进程的启动模式、网络回调、调用链和执行条件决定。

在项目中：

- `OnStartServer` 初始化服务器玩家状态。
- Command 接收入口在服务器执行请求处理。
- `OnStartClient` 初始化客户端表现。
- `OnStartLocalPlayer` 初始化本地玩家表现。
- 普通 `Update` 通过明确的条件区分输入与远程表现。

这让同一个网络组件能够描述两侧的交接规则。

## 6. 普通数据结构与自定义读写怎样编写

Weaver 为消息参数和状态数据生成读写代码时，处理支持类型的公开实例字段。使用自动生成时，把传输数据写成明确的小型结构体；需要排除的字段使用 `[System.NonSerialized]` 标记。

属性的取值逻辑属于 C# 代码。需要通过属性组织传输数据时，提供自定义读写方法，明确实际发送的内容。

扩展练习：一次选择同时携带角色编号和外观编号，使用属性保存数据，并编写对应序列化：

```csharp
using Mirror;

public readonly struct CharacterChoice
{
    public int CharacterId { get; }
    public byte AppearanceId { get; }

    public CharacterChoice(int characterId, byte appearanceId)
    {
        CharacterId = characterId;
        AppearanceId = appearanceId;
    }
}

public static class CharacterChoiceSerialization
{
    public static void WriteCharacterChoice(this NetworkWriter writer, CharacterChoice value)
    {
        writer.WriteInt(value.CharacterId);
        writer.WriteByte(value.AppearanceId);
    }

    public static CharacterChoice ReadCharacterChoice(this NetworkReader reader)
    {
        int characterId = reader.ReadInt();
        byte appearanceId = reader.ReadByte();
        return new CharacterChoice(characterId, appearanceId);
    }
}
```

扩展方法是可以使用实例调用形式的静态方法，上面的 `this NetworkWriter` 与 `this NetworkReader` 表明它们扩展的类型。

将类型和读写类放入客户端与服务器共同编译的脚本中。Weaver 识别这些静态读写方法后，可以将 `CharacterChoice` 用作 Command 参数、消息字段或同步数据。

发送顺序是整数编号、字节外观编号，接收按相同顺序和类型读取。服务器收到后继续校验两个业务编号，再决定结果。

本项目的角色请求使用单个 `int`，由 Mirror 内置整数读写处理。角色资源本身通过编号在本地配置中解析。

官方依据：[Serialization](https://mirror-networking.gitbook.io/docs/manual/guides/serialization)、[Data Types](https://mirror-networking.gitbook.io/docs/manual/guides/data-types)。
