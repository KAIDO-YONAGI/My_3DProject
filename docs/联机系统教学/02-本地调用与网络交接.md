## 1. 本地对象调用网络组件的公开入口

项目的 [CharacterSelectButton.cs](/D:/Unity/Projects/My_3DProject/Assets/Core/Scripts/UI/CharacterSelectButton.cs) 在点击时寻找本地玩家：

```csharp
private static NetworkCharacterSync ResolveLocalCharacter()
{
    NetworkIdentity localPlayer = NetworkClient.localPlayer;
    return localPlayer != null && localPlayer.TryGetComponent(out NetworkCharacterSync characterSync)
        ? characterSync
        : null;
}
```

`NetworkClient.localPlayer` 指向当前客户端的玩家网络身份。按钮通过它找到网络根上的角色同步组件，再执行：

```csharp
localCharacter.SetLocalCharacter(characterId);
```

这行代码是同一进程里的普通方法调用。真正跨网络的部分位于 `SetLocalCharacter` 内部调用的 Command。

这是一种可以复用的写法：

```text
本地按钮或输入组件
  → 解析当前玩家
  → 调用玩家的公开请求方法
  → 网络组件检查本地调用条件
  → 发出网络请求
```

本地玩家在运行时生成。项目按钮在点击时解析玩家，这使它能够取得当前实例。按钮在 `OnEnable` 订阅点击，在 `OnDisable` 解除订阅。

需要持续显示状态的界面可以在玩家绑定时读取当前值，再订阅本地变化事件；玩家停止或界面停用时解除绑定。

## 2. 网络组件把接收结果交给本地对象

角色编号下行的终点是：

```csharp
private void ApplyCharacter()
{
    NetworkCharacterManager.Instance?.ApplyCharacter(this, characterId);
}
```

这也是同一客户端进程里的普通方法调用。Mirror 已经完成字段接收，管理器负责将这个值转换成具体表现。

本项目的 [NetworkCharacterManager.cs](/D:/Unity/Projects/My_3DProject/Assets/Core/Scripts/Networking/NetworkCharacterManager.cs) 继续执行：

1. 读取玩家的 `IsLocalPlayerCharacter`。
2. 用编号选择本地或远程 Prefab。
3. 复用匹配的表现实例，或清理旧实例后创建新实例。
4. 把视觉实例挂在网络根下面，并对齐局部变换。
5. 停用视觉实例上的运动与碰撞组件。
6. 给网络根控制器重新绑定 Animator 和角色动画配置。
7. 按本地身份设置相机和音频监听器。
8. 给本地运动绑定相机参考空间。

网络字段保存游戏状态，本地管理器保存 Unity 组件引用，两者通过普通方法交接。

## 3. 跨网络传递可重建的信息

序列化是把数据编码成可发送的字节，反序列化是接收端从字节还原数据。

优先传递这类内容：

- 角色、物品、技能等业务编号。
- 数值、布尔值、方向、位置和时间。
- 已生成网络对象的身份。
- 由这些数据组成的小型结构体。

Camera、Animator 和本地视觉实例的引用由接收端自行建立。网络对象引用通过网络身份对应接收端的副本，使用时需要考虑目标是否已经生成、是否在当前观察范围内、是否仍然存活。

这能让客户端使用适合自己的表现资源，同时保持共同的游戏状态。

## 4. 对象编号与业务编号分别使用

角色编号表示资源表中的角色，`netId` 表示当前运行中的网络实体。两种编号承担不同用途：

```text
characterId = 1
  → 到角色配置中选择资源

targetNetId = X
  → 到当前网络对象表中找目标实例
```

服务器通过 `NetworkServer.spawned` 查找实体，客户端通过 `NetworkClient.spawned` 查找自己已经接收的副本。

扩展练习中的本地查询可以写为：

```csharp
private static bool TryResolveTarget(uint targetNetId, out NetworkIdentity target)
{
    return NetworkClient.spawned.TryGetValue(targetNetId, out target);
}
```

接收目标编号后先查找，查找成功再绑定表现。等待目标生成时保存编号，在对象生成或界面刷新时重新解析；目标销毁、状态换目标或界面解绑时清理引用。

发送已生成的 `NetworkIdentity` 引用时，Mirror 也通过身份信息对应接收端对象。显式使用编号便于把等待、可见范围和引用清理写成清楚的业务流程。

需要保存跨场次的玩家或物品身份时，定义独立的业务编号。运行期 `netId` 用于当前网络生命周期中的对象对应。

## 5. 父子层级关系也通过状态重建

角色视觉实例的挂接由各客户端管理器执行。开发持有物品时，可以采用同样的方式：

```text
服务器保存 holderNetId 和挂点编号
  → 下行同步持有关系
  → 客户端找到持有者的网络根
  → 找到本地模型对应挂点
  → 将物品表现挂到该位置
```

Transform 是 Unity 保存位置、旋转和缩放的组件。挂点编号是双方约定的业务数据，具体挂点 Transform 是各客户端的本地引用。服务器需要碰撞和规则判定时，使用自己的实体与规则数据；客户端根据确认关系建立显示层级。

官方依据：[Data Types](https://mirror-networking.gitbook.io/docs/manual/guides/data-types)、[Authority](https://mirror-networking.gitbook.io/docs/manual/guides/authority)。
