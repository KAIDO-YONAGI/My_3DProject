# 玩家同步与角色装配

## 1. 网络根与角色表现

服务器为每个连接生成一个 `Player_Network`。它是稳定的网络根：

```text
Player_Network
├─ NetworkIdentity
├─ NetworkTransformReliable
├─ CharacterController
├─ PlayerCharacterController
└─ NetworkCharacterSync
```

这个 Prefab 不直接绑定某一个角色模型。每个客户端收到网络根后，根据以下信息本地装配角色：

- `NetworkIdentity.isLocalPlayer`
- `NetworkCharacterSync.characterId`
- `NetworkCharacterManager.localCharacterPrefabs`
- `NetworkCharacterManager.characterPrefabs`

同一个远程玩家在每个客户端都有一个本地 GameObject 副本。这个副本是 Mirror 同步出来的 `Player_Network`，它下面的同步角色模型由该客户端自己的 `NetworkCharacterManager` 实例化。

## 2. NetworkCharacterSync.cs

路径：

`Assets/Core/Scripts/Networking/NetworkCharacterSync.cs`

### characterId

```csharp
[SyncVar(hook = nameof(OnCharacterIdChanged))]
private int characterId;
```

服务器保存最终角色编号。Mirror 将它序列化到客户端。编号变化后调用 `OnCharacterIdChanged`。

### OnStartServer

服务器创建玩家时，`OnStartServer` 从 `NetworkCharacterManager.DefaultCharacterId` 读取默认编号并写入 `characterId`。

服务端只设置编号。具体模型在各客户端本地创建。

### OnStartClient

每个客户端生成这个网络玩家后，`OnStartClient` 调用 `ApplyCharacter`。本地玩家与远程玩家都会执行这一步。

### OnStartLocalPlayer

当前连接拥有的玩家还会调用 `OnStartLocalPlayer`。它再次调用 `ApplyCharacter`，使角色装配在本地身份已经确认后保持正确。管理器会复用已经匹配的表现或重建需要的表现。

### SetLocalCharacter 与 CmdSetCharacter

本地拥有者调用 `SetLocalCharacter(id)`：

1. 检查 `isLocalPlayer`。
2. 检查编号是否同时存在于本地和远程数组。
3. Host 直接更新服务器字段。
4. 普通客户端调用 `CmdSetCharacter(id)`。
5. 服务器再次校验编号。
6. 服务器更新 `characterId`。
7. SyncVar 将结果发送到各客户端。

### OnCharacterIdChanged

Hook 收到新编号后调用 `ApplyCharacter`，再把工作交给 `NetworkCharacterManager`。

## 3. NetworkCharacterManager.cs

路径：

`Assets/Core/Scripts/Networking/NetworkCharacterManager.cs`

管理器位于 `PersistentScene/Managers/NetworkCharacterManager`，是常驻场景中的唯一实例。

### 两套角色数组

```text
localCharacterPrefabs[id]
  → 当前客户端自己的玩家使用

characterPrefabs[id]
  → 当前客户端看到的远程玩家使用
```

数组下标使用同一角色编号。当前配置：

| 编号 | 本地拥有者 | 远程玩家 |
|---|---|---|
| `0` | 娜娜莉 华丽飞踢本地 Prefab | 娜娜莉 华丽飞踢 Sync Prefab |
| `1` | 娜娜莉 学园之星本地 Prefab | 娜娜莉 学园之星 Sync Prefab |

默认编号为 `1`。

### ApplyCharacter

`ApplyCharacter(player, requestedCharacterId)` 是角色表现装配入口。

#### 选择 Prefab

```text
player.IsLocalPlayerCharacter = true
  → TryGetLocalCharacterPrefab
  → localCharacterPrefabs[id]

player.IsLocalPlayerCharacter = false
  → TryGetCharacterPrefab
  → characterPrefabs[id]
```

服务器生成同一种网络根，每个客户端根据自己的本地身份选择不同的视觉 Prefab。

#### 清理旧表现

角色编号变化时，`RemoveCharacter` 会：

1. 清空网络根的 `inputSpace`。
2. 释放网络根对旧 Animator 的引用。
3. 销毁旧视觉实例。
4. 清理实例字典与编号字典。

这一步保证一个网络根只保留一个当前角色模型。

#### 创建新表现

管理器执行：

```csharp
Instantiate(prefab, player.transform)
```

新实例成为 `Player_Network` 的子对象，随后设置：

```text
localPosition = Vector3.zero
localRotation = Quaternion.identity
localScale = Vector3.one
```

网络根的位置和旋转决定玩家在世界中的位置。视觉子对象只提供角色外观。

#### 排除重复移动组件

本地角色 Prefab 和同步角色 Prefab 可以保存自己的 `PlayerCharacterController`、`CharacterController` 和动画配置，便于单独编辑。装配到网络根后，管理器遍历视觉实例并停用：

- `PlayerCharacterController`
- `CharacterController`

这样运行时只有 `Player_Network` 根上的控制器执行移动和碰撞。视觉子对象不会再次读取输入，也不会产生第二套重力和碰撞位移。

#### 绑定 Animator

管理器在视觉实例中查找 Animator 和视觉控制器配置，调用：

```text
player.PlayerController.RebindAnimator
```

网络根继续负责移动，动画驱动改为操作新角色模型的 Animator。Idle、Run、Sprint、Jump 和骨骼跟随配置从当前视觉 Prefab 复制到网络根控制器。

#### 绑定 ThirdPersonCamera

管理器遍历新实例中的 `ThirdPersonCamera`，调用：

```text
cameraController.SetTarget(player.transform)
```

相机组件留在本地角色视觉 Prefab 中，跟随目标改为 `Player_Network` 根。网络根移动时，相机跟随同一个物理位置。

## 4. 本地角色怎样获得相机

`ConfigureLocalCamera` 根据 `player.IsLocalPlayerCharacter` 设置表现：

```text
本地拥有者
  → Camera.enabled = true
  → Camera.tag = MainCamera
  → AudioListener.enabled = true
  → ThirdPersonCamera.enabled = true
  → PlayerCharacterController.inputSpace = 本地 Camera Transform

远程玩家
  → Camera.enabled = false
  → AudioListener.enabled = false
  → ThirdPersonCamera.enabled = false
  → PlayerCharacterController.inputSpace = null
```

`CharactersForLocal` 提供完整本地 Camera。`CharactersForSync` 以模型和 Animator 为主。即使远程资源中带有 Camera 或 AudioListener，装配流程也会根据本地身份将它们关闭。

## 5. 远程角色怎样成为同步角色

假设客户端 A 和客户端 B 都连接服务器。

服务器生成两个网络根：

```text
Player_Network A
Player_Network B
```

客户端 A 的本地装配结果：

```text
Player_Network A
  └─ CharactersForLocal[A.characterId]
      └─ Camera 启用

Player_Network B
  └─ CharactersForSync[B.characterId]
      └─ 只显示远程模型与动画
```

客户端 B 的本地装配结果：

```text
Player_Network A
  └─ CharactersForSync[A.characterId]
      └─ 只显示远程模型与动画

Player_Network B
  └─ CharactersForLocal[B.characterId]
      └─ Camera 启用
```

同一个玩家在自己的客户端使用本地完整角色，在其他客户端使用同步角色。角色编号一致，Prefab 类型由每个客户端的 `isLocalPlayer` 决定。

## 6. 怎样排除场景里的多余角色

`PersistentScene` 中有一个单机 `LocalPlayer`。它服务于无服务端开发。联机连接完成后，`NetworkCharacterManager.Update` 检测：

```csharp
NetworkClient.isConnected
```

状态变化时调用 `ApplyPresentationMode`。

### SetStandalonePlayerEnabled

管理器遍历 `PlayerCharacterController`：

- 父级存在 `NetworkIdentity` 的对象属于网络玩家，保持活动。
- 父级没有 `NetworkIdentity` 的对象属于场景单机角色，联机时关闭，单机时启用。

### SetStandaloneCameraEnabled

管理器遍历 Camera、`ThirdPersonCamera` 和 `AudioListener`：

- 父级存在 `NetworkIdentity` 的组件由网络角色装配规则管理。
- 父级没有 `NetworkIdentity` 的组件属于单机或场景表现，联机时关闭，单机时启用。

### SceneManager.sceneLoaded

管理器订阅 `SceneManager.sceneLoaded`。玩法场景以 Additive 模式加载完成后，它再次应用当前表现模式，因此新场景中的 Camera 不会覆盖本地网络角色相机。

两名玩家连接时，每个客户端的目标活动角色结构为：

```text
2 个 Player_Network
2 个角色表现
1 个本地 Camera
0 个活动单机 LocalPlayer
```

## 7. NetworkTransformReliable

路径：

- `Assets/Mirror/Components/NetworkTransform/NetworkTransformReliable.cs`
- `Assets/Mirror/Components/NetworkTransform/NetworkTransformBase.cs`

当前同步方向为 `ClientToServer`。

### 本地拥有者

本地玩家的 `PlayerCharacterController` 移动网络根。`NetworkTransformReliable.LateUpdate` 检查位置和旋转是否变化，并在同步间隔到达时标记状态。

`OnSerialize` 对位置和旋转进行初始或增量序列化。

### 服务器

服务器在 `OnDeserialize` 中进入 `OnClientToServerSync`，把快照加入 `serverSnapshots`。服务器插值应用这些快照，并将最新状态广播给其他客户端。

### 远程客户端

远程客户端在 `OnServerToClientSync` 中把快照加入 `clientSnapshots`。更新阶段从缓冲区取相邻快照并插值，最终应用到远程 `Player_Network` 根。

## 8. 远程动画

远程玩家不读取本地输入。`PlayerCharacterController.LateUpdate` 检测远程网络玩家后，使用网络根本帧位置与上一帧位置计算速度：

```text
frameVelocity
  → 水平速度
  → 本地移动方向
  → Run 或 Sprint 阈值
  → CharacterMotion
  → CharacterAnimator
```

因此远程模型的移动动画来自 Mirror 插值后的实际位移。

## 9. 角色切换完整链路

```text
本地 UI 或角色选择逻辑
  → NetworkCharacterSync.SetLocalCharacter(id)
  → CmdSetCharacter(id)
  → 服务器验证 id
  → 服务器更新 SyncVar characterId
  → 所有客户端 OnCharacterIdChanged
  → NetworkCharacterManager.ApplyCharacter
  → RemoveCharacter
  → 选择 Local 或 Sync Prefab
  → 创建视觉实例
  → 关闭视觉实例的重复控制器
  → 绑定 Animator
  → 配置本地相机或远程表现
```

## 10. 配置检查

1. `Player_Network` 根包含五个当前组件。
2. 网络根不直接放具体角色模型。
3. 本地与远程数组长度一致。
4. 同一编号在两套数组中表示同一角色。
5. 本地 Prefab 包含需要的 Camera 和 `ThirdPersonCamera`。
6. 远程 Prefab 包含模型、Animator 和动画配置。
7. NetworkCharacterManager 只在 PersistentScene 中存在一个。
8. 场景单机角色的父级没有 `NetworkIdentity`。
9. 联机角色表现始终挂在对应 `Player_Network` 下。
