# 阶段五：三类交互道具

> 上游蓝本：[mirror-physics-interaction-plan.md](../mirror-physics-interaction-plan.md) 第 8 节
> 前置依赖：阶段二、三、四全部完成标准达成
> 编写日期：2026-09-15

## 1. 阶段目标

在已验证的网络物理底座上实现三类道具的最小可玩版本——可推动箱子、可抓取投掷物、拉杆/按钮，全部交互经服务器验证，多客户端结果一致。

## 2. 前置条件

- [ ] 玩家意图移动正常（阶段二）。
- [ ] 服务器权威刚体 + 客户端插值正常（阶段三）。
- [ ] 对象池与重置协议可用（阶段四）。

## 3. 任务清单

### 3.1 通用交互通道

- 定义交互请求：客户端发送「动作按钮 + 目标 `netId`」走可靠通道；服务器验证连接、对象权限、交互距离、冷却。
- 客户端交互提示：准星/距离内高亮（纯表现，不做权威判断）。

### 3.2 可推动箱子

- 复用阶段三模式：服务器动态刚体，玩家碰撞推动（服务器 PhysX 计算）。
- 同步睡眠/唤醒状态；确认多客户端位置一致、静止后不再消耗带宽（睡眠不同步抖动）。

### 3.3 可抓取投掷物

- 状态机（服务器权威）：`Idle → Held(holder) → Thrown → Idle/回收`。
- 抓取：客户端发请求 → 服务器验证距离与空闲 → 置 `holder`；持有期间客户端代理跟随持有者（或由服务器每帧同步）。
- 投掷：服务器释放并施加冲量（AddForce/velocity），客户端表现延迟可接受（蓝本 13.2 处理顺序，本阶段不做预测）。
- 回收：超出场景范围（或掉入 KillZone）→ 服务器 Unspawn 回池 → 按需重新 Spawn；触发阶段四重置协议全流程。

### 3.4 拉杆/按钮

- 服务器验证交互距离后翻转状态（`SyncVar`），所有客户端通过回调播放表现（动画/音效）。
- 验证连续快速交互（冷却/幂等）与 Late Join 后状态正确。

### 3.5 组合场景冒烟

- 在 `PhysicsPrototypeScene.unity` 布置：若干箱子、2-3 个投掷物、1-2 个拉杆，4 人同时操作。

## 4. 完成标准

- [ ] 2-4 人同时推同一箱子，各客户端最终位置一致，无明显抖动。
- [ ] 投掷物抓取/投掷全流程正常：持有者唯一、释放后物理结果服务器权威、越界回收后可再次使用且无旧状态。
- [ ] 拉杆状态在所有客户端一致，Late Join 可看到正确状态。
- [ ] 断线重连（重进）后道具状态与服务器一致；持有者断线时投掷物被正确释放或回收。
- [ ] 所有交互请求经服务器验证：越权（超距离、操作他人持有物）请求被拒绝且有日志。

## 5. 本阶段相关测试项

蓝本第 11 节中：道具运动中玩家离开、道具连续回收和重用、Late Join、主动离开、非正常断开（持有者中途掉线）、网络对象重复 Spawn。

## 6. 风险与回退

| 风险 | 处理 |
|---|---|
| 高延迟下抓取/投掷手感迟钝 | 按蓝本 13.2 顺序：先调输入与插值，再加本地动作表现（如本地手持预览）；预测留到验收后评估 |
| 两人同帧抢同一投掷物 | 服务器以先到达请求为准，后者返回失败；客户端表现「已被拿走」 |
| 持有物与持有者 NetworkTransform 互相覆盖 | 持有期间由持有者状态驱动位置（父子化或跟随逻辑定稿一种），不做双写 |
| 拉杆连点导致状态抖动 | 冷却或状态锁在服务器侧强制执行 |
