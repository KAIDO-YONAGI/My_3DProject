# 阶段六：固定 Tick 与状态模型
> 前置：阶段五完成；交付：可由单机、回放和服务器共同驱动的玩法模拟
## 1. 输入帧与状态
`InputFrame` 包含玩家标识、输入序号、目标 Tick、移动方向、跳跃、冲刺、拾取、投掷、使用药水和瞄准方向。真人采集器、机器人、回放读取器和网络输入接收器统一生成输入帧，玩法模拟只消费输入帧。
`PlayerState` 保存位置、旋转、速度、地面、动作、生命、生存、冲刺、药水、持有道具、最近作用和分数；`ItemState` 保存类型、实例、位置、旋转、速度、生命周期、持有者、作用者和倒计时；`RoundState` 保存阶段、Tick、分数、胜者、复活队列和事件。
## 2. 固定 Tick
以 30Hz 起步。每 Tick 依次读取输入、更新回合、更新角色、处理碰撞与推挤、更新道具、更新药水、更新酸雨、处理死亡与计分、生成事件并输出 `GameState`。模拟时钟统一处理暂停、结算、重开和时间语义。
Unity 表现层只读状态和事件，更新 Transform、动画、粒子、音效、镜头和 UI。表现脚本不直接修改权威状态。
## 3. 随机数与回放
游戏状态保存随机种子和推进状态，道具刷新、药水映射、酸雨触发和安全区选择使用可记录随机数。回放保存初始配置、随机状态、每 Tick 输入、关键事件和周期摘要。
回放不承诺跨机器 PhysX 位级一致，比较回合结束 Tick、淘汰顺序、分数、胜者、关键道具状态和位置误差范围。三局回放的关键结果一致后进入 Mirror 联机阶段。
## 4. 完成标准与测试
□ 30Hz 固定 Tick 推进；
□ 渲染帧率变化不改变关键结果；
□ 玩家、道具、回合和事件使用普通状态；
□ 表现层单向读取；
□ 真人、机器人和回放共享输入帧；
□ 随机状态可记录和恢复；
□ 三局回放结果一致；
□ 状态可脱离 Unity 对象序列化。
测试 30、60、120 渲染帧率、暂停恢复、回合重开、真人替换机器人、真人替换回放、随机结果复现和同 Tick 多事件顺序。逐步迁移玩家、回合、道具和事件，避免一次性抽取造成回归。
