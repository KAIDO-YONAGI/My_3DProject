# 阶段二：单机回合闭环
> 前置：阶段一完成；交付：可连续运行的完整单机比赛流程
## 1. 角色与回合
完成地面移动、朝向、跳跃、重力、落地和掉落。角色状态使用 `Spawning`、`Alive`、`Dead`、`Respawning`、`Result`，每种状态定义可接受输入和转换条件。角色运动采用受约束状态模型，速度、加速度、跳跃高度、下落速度和边界进入配置。单机模式也通过“采集 `InputFrame` → 模拟器更新权威状态 → 表现层读取状态”的边界运行；输入设备不直接写最终位置，后续服务器可使用同一模拟入口。
本阶段先建立轻量输入结构与职责边界，不要求提前完成网络协议、全部状态序列化或可恢复模拟；固定 Tick、完整状态模型和回放在阶段六统一落地。
```text
Waiting → Countdown → Playing → RoundResult → MatchResult → Restart
```
`Waiting` 创建玩家并重置状态；`Countdown` 锁定操作；`Playing` 推进计时、生命、淘汰和复活；`RoundResult` 判断比赛胜利；`MatchResult` 展示排名；`Restart` 清理临时状态并返回倒计时。
## 2. 淘汰与复活
```text
致死伤害或进入 KillZone → 唯一淘汰记录 → 计算归属 → 更新分数
→ 复活或结束回合 → 判断比赛结果
```
复活由比赛模拟统一决定合法出生位置，并重置位置、速度、生命和动作，应用复活保护并显示反馈。复活点筛选考虑边界、其他玩家距离和危险区域；表现层只呈现模拟结果，不自行决定复活位置或状态。
## 3. UI、完成标准与测试
UI 显示倒计时、回合时间、生命、分数、死亡与复活提示、回合结果和比赛结果。完成标准为输入经统一模拟入口驱动移动和跳跃；生命耗尽和掉落各只结算一次；玩家按规则复活或进入结果；比赛可重开；连续完成 10 局后状态正确重置。此阶段是单机实现，不引入 Mirror，也不实现客户端预测或网络校正。
测试倒计时、时间结束、生命恰好归零、重复进入 KillZone、同 Tick 双人淘汰、复活点占用、比赛结果后连续重开、场景退出后再次进入。回合转换集中到唯一控制器，死亡使用唯一记录，重开统一取消计时器和延迟任务。
