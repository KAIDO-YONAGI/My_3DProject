# 阶段二：单机回合闭环

> 前置依赖：阶段一全部完成标准达成
>
> 阶段交付：可连续运行的完整单机比赛流程

## 1. 阶段目标

完成比赛从倒计时、对局、淘汰、复活、计分、回合结算到比赛重开的完整循环。阶段重点是状态正确性和重复运行稳定性。

## 2. 玩家基础动作

### 2.1 移动

- 读取二维移动输入。
- 将输入转换为场地平面方向。
- 应用加速度、减速度和最大速度。
- 更新角色朝向。

### 2.2 跳跃

- 检测地面状态。
- 响应跳跃输入。
- 应用重力和下落速度。
- 触发起跳和落地事件。

### 2.3 状态限制

角色状态包括：

- `Spawning`
- `Alive`
- `Dead`
- `Respawning`
- `Result`

每种状态定义可接受输入和状态转换条件。

## 3. 回合状态机

建议状态：

```text
Waiting
  → Countdown
  → Playing
  → RoundResult
  → MatchResult
  → Restart
```

### 3.1 Waiting

- 创建参赛玩家。
- 重置分数和角色状态。
- 等待开始条件。

### 3.2 Countdown

- 锁定角色操作。
- 显示倒计时。
- 倒计时结束后进入 `Playing`。

### 3.3 Playing

- 接受玩家输入。
- 更新生命、掉落和复活。
- 更新回合计时。
- 判断回合结束条件。

### 3.4 RoundResult

- 锁定角色操作。
- 展示本回合得分变化。
- 判断比赛胜利条件。
- 进入下一回合或比赛结算。

### 3.5 MatchResult

- 展示最终排名和胜者。
- 接受重新开始输入。

### 3.6 Restart

- 清理角色和临时对象。
- 重置回合计时与分数。
- 返回倒计时。

## 4. 淘汰流程

```text
收到致死伤害或进入 KillZone
  → 创建唯一淘汰记录
  → 计算得分归属
  → 更新玩家状态
  → 更新分数
  → 复活或结束回合
```

唯一淘汰记录用于控制同一玩家在一次死亡流程中只结算一次。

## 5. 复活流程

- 从合法复活点集合选择位置。
- 更新位置、速度、生命和动作状态。
- 应用复活保护。
- 显示复活反馈。
- 保护时间结束后恢复完整交互。

复活点选择关注玩家距离、场地边界和危险区域。

## 6. 最小 UI

- 倒计时。
- 回合计时。
- 玩家生命值。
- 当前分数。
- 死亡和复活提示。
- 回合结果。
- 比赛结果。

## 7. 完成标准

- [ ] 玩家可以移动和跳跃。
- [ ] 生命值耗尽触发淘汰。
- [ ] 进入 KillZone 触发淘汰。
- [ ] 每次淘汰只结算一次。
- [ ] 玩家按规则复活或进入回合结果。
- [ ] 达到目标分数后进入比赛结果。
- [ ] 比赛结果后可以重新开始。
- [ ] 连续完成 10 局，分数、计时和角色状态正确重置。

## 8. 测试用例

- 倒计时结束转换。
- 回合计时结束转换。
- 生命值恰好归零。
- 玩家重复进入 KillZone。
- 两名玩家同 Tick 淘汰。
- 复活点被其他玩家占用。
- 比赛结果后连续重开。
- 场景退出后再次进入。

## 9. 风险与控制

| 风险 | 控制 |
|---|---|
| 多个组件直接改变回合状态 | 回合状态转换集中到唯一控制器 |
| 死亡事件重复触发 | 使用唯一淘汰记录和已结算标记 |
| 重开残留计时器 | 状态退出时统一取消计时和延迟任务 |
| 复活位置产生碰撞 | 按安全距离筛选复活点 |
