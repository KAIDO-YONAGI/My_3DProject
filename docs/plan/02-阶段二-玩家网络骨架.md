# 阶段二：玩家网络骨架

> 上游蓝本：[mirror-physics-interaction-plan.md](../mirror-physics-interaction-plan.md) 第 10 节阶段二、第 6.1 节
> 前置依赖：阶段一全部完成标准达成
> 编写日期：2026-09-15

## 1. 阶段目标

建立网络玩家生命周期：Spawn、控制权归属、离开清理、Late Join 可见，并把输入模型从「上传最终 Transform」改为「上传意图」。这是新输入协议取代旧 `ClientProtocol` 模型的关键一步。

## 2. 前置条件

- [ ] 阶段一执行记录已填写，KCP 为默认传输。
- [ ] 冒烟场景可承载玩家对象（先空 Prefab 占位也可）。

## 3. 任务清单

### 3.1 网络玩家 Prefab

- 在 `Assets/Core/Prefabs/Network/` 创建 Player Prefab：`NetworkIdentity` + `NetworkTransform`。
- 本地玩家（`isLocalPlayer`）挂相机跟随与输入采集；远端玩家只做插值表现，不带输入组件。
- Prefab 注册到 NetworkManager 的 Spawn 列表。

### 3.2 生命周期

- 服务器在 `OnServerAddPlayer` 创建玩家；验证连续加入 2-4 人 netId 互不冲突。
- `OnServerDisconnect` / `OnServerRemovePlayer` 清理玩家对象，确认客户端侧对象同步销毁。
- Late Join：后加入客户端能看到所有已存在玩家；已有客户端能看到新玩家。

### 3.3 意图输入协议

- 新增玩家意图消息（Command 或 Message）：移动方向向量 + 动作位 + 序号，**不含最终位置**。
- 服务器收到意图后在自己权威的角色控制器上执行移动，通过 `NetworkTransform` 下发结果。
- 客户端本地玩家不再直接写 Transform 作为网络输入（本地视觉响应可保留，但以服务器校正为准）。
- 阶段内明确：意图校验规则（方向归一化、频率上限）至少留出接口，阶段五前补齐完整校验。

### 3.4 与旧系统的隔离确认

- 新场景不引用 `ClientProtocol.cs`、`SyncCharacter.cs`、`PlayerManager.cs`。
- 旧代码不删除、不修改，仅确认无相互引用。

## 4. 完成标准

- [ ] 2-4 个 ParrelSync 客户端同时进入同一场景，各自看到彼此。
- [ ] 客户端只能控制自己的玩家（远端玩家输入组件不生效）。
- [ ] Late Join 玩家能看到全部已存在玩家，且已存在玩家能看到新玩家。
- [ ] 任一客户端退出后，其玩家对象在服务器与所有客户端上被正确销毁。
- [ ] 移动链路为：客户端发意图 → 服务器执行 → NetworkTransform 同步结果；抓包或日志确认客户端未上传最终位置。

## 5. 本阶段相关测试项

Host 模式、独立 Headless Server、2/4 客户端、Late Join、主动离开、非正常断开（玩家对象清理）。

## 6. 风险与回退

| 风险 | 处理 |
|---|---|
| NetworkTransform 与现有角色控制器直接写 Transform 冲突 | 权威移动只在服务器执行；客户端本地表现层与网络层分离，必要时本阶段先简化控制器 |
| 本地玩家被服务器校正拉扯观感差 | 本阶段只保证正确性；手感优化推迟到阶段六后统一处理，不在本阶段引入预测 |
| Late Join 场景状态不全 | 本阶段只有玩家对象，风险低；阶段三起需复查场景道具对 Late Join 的可见性 |
