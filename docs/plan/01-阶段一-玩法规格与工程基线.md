# 阶段一：玩法规格与工程基线
> 前置：无；交付：冻结规则、集中配置、独立原型场景和可运行工程基线
## 1. 规则冻结
首版比赛采用 2～5 人短回合乱斗。配置确定目标分数、最大回合数、单回合时长、倒计时、复活次数、复活延迟、复活保护和同分处理。每次淘汰只结算一次，生命值耗尽和掉入 KillZone 共用流程；直接伤害使用最近有效攻击者；推挤后在归属时间窗内掉落使用最近有效作用者；酸雨和纯环境伤害进入环境统计；同 Tick 多人淘汰按固定顺序处理。
输入动作确定移动、跳跃、冲刺、拾取、投掷和使用药水，分别定义按下、保持、释放和一次性消费语义，最终统一转换为 `InputFrame`。
## 2. 首版内容
药水从加速、中毒、致盲中选择 2～3 种，配置颜色、效果、持续时间、数值、叠加和覆盖规则。颜色只提供识别信息，使用后揭示效果。
爆炸物配置刷新数量、刷新间隔、拾取距离、倒计时、投掷速度、爆炸半径、伤害、击退和归属。平台作用选择预制平台暂时下降、临时缺口或危险区域中的一种。
酸雨配置触发时间、预警时长、生效时长、伤害间隔、伤害值、安全区数量和位置规则。怪物不进入首版核心验收。
## 3. 原型场景与工程
场景包含圆形或近圆形平台、出生点、复活点、KillZone、道具刷新点、酸雨安全区、基础障碍物、光照、相机和最小调试 UI。回合控制器管理比赛阶段，玩家生成器管理实例，KillZone 只发送掉落事件，UI 只读取状态。
建立 `Gameplay`、`Presentation`、`Networking`、`Pooling` 和测试边界，集中保存配置，记录 Unity 版本和目标平台，配置 Editor、客户端构建和独立场景入口。Mirror 只验证包接入、NetworkManager 启动、KCP 连接和空场景加入离开，不提前接入物理同步。
## 4. 完成标准与测试
□ 规则形成一套明确配置；
□ 输入语义完整；
□ 药水、爆炸物和酸雨具有统一配置入口；
□ 场景可重复运行；
□ 出生点、复活点、刷新点、安全区可视化；
□ 客户端构建可进入原型场景；
□ Mirror 空连接可建立和关闭。
逐个验证出生点、平台边界、KillZone、复活点、刷新点、场景重复加载、Build Settings、Mirror 客户端加入和离开。规则变化只改配置和规则表，网络方案首版只保留 Mirror KCP 链路。
