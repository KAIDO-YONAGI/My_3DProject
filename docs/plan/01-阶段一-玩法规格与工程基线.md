# 阶段一：玩法规格与工程基线

> 前置依赖：无
>
> 阶段交付：完整玩法规格、独立原型场景和可运行工程基线

## 1. 阶段目标

确定首版核心规则和配置边界，建立与现有多人原型分离的物理派对游戏场景。阶段完成后，移动、回合、计分、道具和事件均具有清晰实现口径。

## 2. 玩法规格

### 2.1 比赛参数

确定以下配置：

- 参与人数范围为 2～5 人。
- 目标分数。
- 最大回合数。
- 单回合时长。
- 倒计时时长。
- 复活次数或复活规则。
- 复活延迟。
- 复活保护时长。
- 平局处理。

### 2.2 生命与淘汰

确定以下规则：

- 玩家初始生命值。
- 伤害导致生命值耗尽的流程。
- 掉入 KillZone 的流程。
- 直接伤害归属。
- 推挤后掉落的归属时间窗。
- 环境淘汰统计。
- 同 Tick 多人淘汰顺序。
- 淘汰后的复活和回合结束条件。

### 2.3 输入表

输入动作包括：

- 移动。
- 跳跃。
- 冲刺。
- 拾取或交互。
- 投掷。
- 使用药水。

输入表明确键位、手柄映射、按下、保持和释放语义。

### 2.4 道具与事件参数

药水确定：

- 首版效果集合。
- 颜色集合。
- 颜色与效果的随机映射方式。
- 同类效果的刷新、叠加和覆盖规则。
- 持续时间和表现需求。

爆炸物确定：

- 刷新数量和刷新间隔。
- 倒计时。
- 拾取距离。
- 投掷速度。
- 爆炸半径。
- 伤害和击退。
- 持有者与投掷者归属。

酸雨确定：

- 触发时机。
- 预警时长。
- 持续时间。
- 伤害间隔和伤害值。
- 安全区数量和位置规则。

## 3. 原型场景

### 3.1 场景结构

原型场景包含：

- 圆形或近圆形平台。
- 2～5 个出生点。
- 复活点集合。
- KillZone。
- 道具刷新点。
- 酸雨安全区。
- 基础障碍物。
- 场景光照。
- 基础相机。
- 最小调试 UI。

### 3.2 场景职责

- 场景保存静态布局和生成点。
- 回合控制器管理比赛状态。
- 玩家生成器管理角色实例。
- KillZone 只发送掉落事件。
- UI 只读取状态和显示结果。

## 4. 工程基线

- 配置可运行场景入口。
- 建立玩法、表现、网络和池化目录边界。
- 建立集中配置数据入口。
- 记录 Unity 编辑器版本和目标平台。
- 建立一次 Editor 运行验证。
- 建立一次客户端构建验证。

## 5. 完成标准

- [ ] 比赛、生命、淘汰、复活和胜利规则完整。
- [ ] 输入动作和触发语义完整。
- [ ] 药水、爆炸物和酸雨参数具有统一配置入口。
- [ ] 原型场景可进入、退出和重复运行。
- [ ] 玩家占位体可生成在全部合法出生点。
- [ ] KillZone、复活点、刷新点和安全区具备调试可视化。
- [ ] 客户端构建能够进入原型场景。

## 6. 测试用例

- 逐个验证全部出生点。
- 验证玩家生成位置与平台边界。
- 验证 KillZone 覆盖场地外部。
- 验证复活点和道具点配置数量。
- 验证场景重复加载。
- 验证 Build Settings 启动场景。

## 7. 风险与控制

| 风险 | 控制 |
|---|---|
| 核心规则持续变化 | 首版只冻结必做规则，扩展项进入后续范围 |
| 配置散落在多个脚本 | 使用集中配置数据管理可调参数 |
| 场景组件职责混合 | 回合、生成、区域和 UI 使用独立职责 |
| 原型场景引入现有网络启动逻辑 | 使用独立场景和独立启动入口 |
