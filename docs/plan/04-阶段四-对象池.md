# 阶段四：对象池

> 上游蓝本：[mirror-physics-interaction-plan.md](../mirror-physics-interaction-plan.md) 第 7 节
> 前置依赖：阶段三全部完成标准达成
> 编写日期：2026-09-15

## 1. 阶段目标

把道具的创建/销毁接入两层对象池（服务端池 + 客户端池），通过 Mirror Custom Spawn/Unspawn Handler 与网络生命周期对接，并落地统一的重置协议，保证重用对象无旧状态残留。

## 2. 前置条件

- [ ] 阶段三的网络刚体道具可正常 Spawn/Despawn。
- [ ] 蓝本 7.2 回收重置清单可直接作为本阶段重置协议的核对表。

## 3. 任务清单

### 3.1 服务端对象池

- 在 `Assets/Core/Scripts/Pooling/` 实现基于 `UnityEngine.Pool.ObjectPool<T>` 的服务端池：
  - 预热：每种可复用道具 4 个；最大容量 16 个。
  - 容量不足：输出明确警告（不静默扩容），行为按池配置决定（复用最旧或拒绝 Spawn，本阶段定稿并记录）。
- 取出 → `NetworkServer.Spawn`，归还 → `NetworkServer.UnSpawn`（不 Destroy）。

### 3.2 客户端对象池

- 实现客户端池，注册 Mirror `NetworkClient.RegisterSpawnHandler` / `RegisterUnspawnHandler`。
- Spawn 消息到达时从池取对象并回填 netId 状态；Unspawn 时归还在池中，不 Destroy。
- 池未预热到的 Prefab 首次到达时按需创建并计入池。

### 3.3 重置协议

- 定义统一接口（如 `IPoolableReset`），覆盖蓝本 7.2 全部条目：Transform、刚体速度、`isKinematic`/睡眠/碰撞检测、父节点、Collider/Renderer/粒子、抓取者与持有状态、冷却与临时状态、插值缓存、双端引用。
- 服务器归还时执行服务器侧重置；客户端归还时执行客户端侧重置；两侧共用同一清单核对。
- 增加 Debug 断言或日志：归还对象若速度/持有状态非默认值则报警，防止漏重置。

### 3.4 集成验证

- 用阶段三的测试道具跑完整循环：Spawn → 物理 → Unspawn → 再次 Spawn。
- 模拟异常路径：道具持有中 Unspawn、道具睡眠中 Unspawn、连续快速 Spawn/Unspawn。

## 4. 完成标准

- [ ] 同一道具可连续 Spawn → Unspawn → 再 Spawn，netId 生命周期正确，无双对象、无残留对象。
- [ ] 重用后的道具不继承旧速度、旧父节点、旧持有状态、旧插值缓存（客户端 `velocity ≈ 0`、无父节点、无持有者）。
- [ ] 池容量打满时出现明确警告日志，且行为与定稿配置一致。
- [ ] 客户端不自行创建权威网络对象（池只响应服务器 Spawn/Unspawn）。

## 5. 本阶段相关测试项

道具连续回收和重用、池容量不足、网络对象重复 Spawn（服务器对同一池对象二次 Spawn 的防护）、道具运动中玩家离开（回收归还是否正确）。

## 6. 风险与回退

| 风险 | 处理 |
|---|---|
| Custom Spawn Handler 与 AssetId 匹配错误导致客户端取错池 | 以 Prefab 的 `assetId` 为池 key，增加断言；出现错配立即回退为普通 Destroy/Instantiate 并排查 |
| 重置遗漏造成隐性 Bug（如残留持有者） | 重置协议以蓝本 7.2 清单逐条核对 + 非默认值报警；阶段五每类道具接入时再复核一次 |
| Mirror Unspawn 后客户端隐藏对象与池归还时序冲突 | 明确时序：Spawn/Unspawn 消息回调内完成池操作，池不主动 Destroy 网络对象 |
