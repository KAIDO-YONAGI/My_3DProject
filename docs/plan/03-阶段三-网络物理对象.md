# 阶段三：网络物理对象

> 上游蓝本：[mirror-physics-interaction-plan.md](../mirror-physics-interaction-plan.md) 第 6.2、6.3 节
> 前置依赖：阶段二全部完成标准达成
> 编写日期：2026-09-15

## 1. 阶段目标

建立「服务器唯一真实物理 + 客户端插值表现」的核心模式：服务器运行权威 Rigidbody，客户端远端对象为 Kinematic 表现代理并做快照插值。这是全部三类道具共用的底层能力。

## 2. 前置条件

- [ ] 玩家可正常 Spawn、移动、离开。
- [ ] 服务器物理 Fixed Timestep 已设为 `0.02s`（蓝本 6.2 起点）。

## 3. 任务清单

### 3.1 网络刚体道具 Prefab

- 在 `Assets/Core/Prefabs/Physics/` 创建测试道具 Prefab（先以「球/方块」占位）。
- 服务器侧：非 Kinematic Rigidbody，由 PhysX 真实模拟。
- 客户端侧：同一 Prefab 中 Rigidbody 设为 Kinematic 表现代理（通过 `isServer`/`isClient` 分支初始化，或使用 Mirror `NetworkRigidbody` 组件并明确其行为）。

### 3.2 同步方案

- 位置 + 旋转：`NetworkTransform`，同步间隔对应目标频率 `20-30Hz` 起步。
- 必要扩展状态：线速度、角速度、睡眠状态，用自定义 `SyncVar` 或序列化字段，仅同步服务器权威值。
- 客户端插值：启用 NetworkTransform 的插值缓冲，起点 2-3 个快照；确认无跳变后按手感调整。

### 3.3 服务器权威验证手段

- 服务器日志记录道具关键碰撞事件的权威位置与速度。
- 客户端不回写任何物理结果；确认数据流向是单向「服务器 → 客户端」。
- 测试脚本（可选）：服务器给道具随机 AddForce，观察各客户端最终收敛到同一姿态。

### 3.4 起始参数记录

本阶段必须把以下参数实测后记录到执行记录，作为阶段六压测基线：

- 网络发送频率、NetworkTransform 同步间隔、插值缓冲数、单道具同步字节数（用 Mirror 的统计/Profiler 读取）。

## 4. 完成标准

- [ ] 服务器上道具为真实动态刚体，碰撞、堆叠、下落结果由服务器决定。
- [ ] 客户端远端道具为 Kinematic，不进行独立物理模拟（可在客户端断言 `isKinematic == true`）。
- [ ] 2-4 客户端观察同一道具运动，位置平滑、无长期跳变或无限抖动。
- [ ] 服务器推动道具后，所有客户端在正常延迟下收敛到一致结果。
- [ ] 起始同步参数已记录。

## 5. 本阶段相关测试项

Host 模式、独立 Headless Server、2/4 客户端、Late Join（后加入客户端能看到道具当前状态）、道具运动中玩家离开（观测端表现）。

## 6. 风险与回退

| 风险 | 处理 |
|---|---|
| NetworkTransform 默认参数下远端道具抖动 | 调整同步间隔与插值缓冲；确认客户端没有残余物理力作用 |
| 客户端 Kinematic 代理被场景 Collider 卡住 | 客户端代理层可使用忽略碰撞的图层或仅与静态环境碰撞，记录具体做法 |
| 单道具带宽超预期 | 降低非必要字段同步频率；速度字段仅在超过阈值时同步 |
| Mirror `NetworkRigidbody` 行为与预期不符 | 退回自写「服务器动态/客户端 Kinematic」分支逻辑，不引第三方插件 |
