## 2. 执行顺序与关卡

- 严格按阶段一 → 六顺序推进，前一个阶段的**全部完成标准**未达成前不开工下一个阶段。
- 每个阶段结束时在该阶段文档末尾的「执行记录」小节补记：日期、实际做法、与计划的偏差、遗留问题。
- 某阶段完成标准无法达成时，先回到该阶段文档的「风险与回退」小节处理，不允许带病进入下一阶段。

## 3. 全局不变量（每个阶段都必须遵守）

1. Unity Headless Server 是唯一权威；客户端只发意图，不提交最终 Transform。
2. 旧 `LocalServer` 与 `ClientProtocol` 不参与新玩法，也不修改其业务逻辑。
3. Mirror 与旧 TCP 协议不混入同一场景。
4. 所有新代码进入独立场景 `Assets/Core/Scenes/PhysicsPrototypeScene.unity`，不动现有多人场景。
5. Mirror 锁定 `v96.11.2`，不混用其他版本的 Transport；版本变更必须回写蓝本第 4 节。
6. 首版不引入：预测、回滚、确定性物理、Interest Management、匹配大厅、Addressables 动态网络 Spawn。
7. 保留代码中的中文注释，新增代码注释风格与项目一致。

## 5. 测试环境约定

- 多客户端测试统一使用 ParrelSync。
- 每阶段验收至少覆盖：Host 模式 + 独立 Headless Server + 2 客户端；阶段二起增加 4 客户端与 Late Join。
- 详细测试矩阵见蓝本第 11 节，各阶段文档只列与本阶段直接相关的测试项。
