# 阶段五：展示质量与材料

> 前置依赖：阶段四全部完成标准达成
>
> 阶段交付：可独立运行、可录制、可讲解的单机垂直切片

## 1. 阶段目标

完善角色、道具、事件、镜头、声音和界面反馈，形成稳定构建和完整展示材料。阶段成果能够直接用于试玩、录制和项目讲解。

## 2. 角色表现

### 2.1 动画

- 待机。
- 移动。
- 跳跃。
- 下落。
- 落地。
- 冲刺。
- 受击。
- 持有。
- 投掷。
- 死亡。
- 复活。
- 胜利。

动画由动作状态和事件驱动。玩法结算由模拟状态负责。

### 2.2 音效

- 移动和落地。
- 跳跃和冲刺。
- 命中和受击。
- 拾取和投掷。
- 药水使用和效果。
- 爆炸。
- 酸雨预警和生效。
- 淘汰、复活和结算。

### 2.3 粒子与视觉

- 冲刺轨迹。
- 命中火花。
- 击退方向。
- 药水颜色和持续效果。
- 爆炸范围和冲击。
- 酸雨区域和安全区。
- 复活保护。

## 3. 镜头

镜头具备：

- 平滑跟随。
- 场地边界约束。
- 玩家高速移动时的前视。
- 冲刺和爆炸时的轻量震动。
- 死亡与复活时的过渡。
- 回合结算时的胜者聚焦。

镜头反馈保持短促，持续震动和大幅视角变化由配置控制。

## 4. 界面

### 4.1 对局界面

- 当前生命值。
- 当前分数。
- 回合计时。
- 冲刺冷却。
- 药水效果和剩余时间。
- 爆炸物倒计时。
- 酸雨预警和安全区提示。

### 4.2 结算界面

- 本回合得分变化。
- 淘汰来源。
- 当前排名。
- 比赛胜者。
- 重新开始入口。

### 4.3 调试界面

- 当前回合状态。
- 角色动作状态。
- 当前速度。
- 活跃道具数量。
- 当前事件阶段。

调试界面通过开发配置启用。

## 5. 可运行构建

构建流程覆盖：

- 明确启动场景。
- 明确目标平台。
- 从干净目录生成构建。
- 首次启动。
- 连续完成多局。
- 退出和再次启动。
- 控制方式验证。

构建目录包含运行说明和已知限制。

## 6. 演示视频

视频时长为 60～90 秒，内容顺序：

1. 竞技场和参赛角色。
2. 移动、跳跃和冲刺。
3. 推挤和掉落淘汰。
4. 药水未知效果。
5. 爆炸物拾取、传递和爆炸。
6. 酸雨预警和安全区争夺。
7. 回合结算和比赛结果。

视频画面保持对局信息清晰，镜头优先展示动作结果和局势变化。

## 7. README

README 包含：

- 项目定位。
- 核心玩法循环。
- 操作方式。
- 已实现功能。
- 当前技术结构。
- 关键设计取舍。
- 构建和运行方式。
- 测试方式。
- 后续阶段。

## 8. 架构图

架构图展示：

```text
玩家输入 / 机器人
        ↓
    InputFrame

    玩法系统
  ├─ 玩家
  ├─ 回合
```

联机架构在后续阶段完成后加入同一架构图。

## 9. 完成标准

- [ ] 角色核心动作具有动画、音效和关键视觉反馈。
- [ ] 药水、爆炸物和酸雨具有清晰状态提示。
- [ ] 镜头能够稳定展示主要对抗。
- [ ] 对局和结算 UI 覆盖完整流程。
- [ ] 构建可独立运行并连续完成多局。
- [ ] 60～90 秒视频覆盖完整玩法循环。
- [ ] README 能够指导运行和理解项目。
- [ ] 架构图与实际结构一致。
- [ ] 项目可以在 3～5 分钟内完成清晰讲解。

## 10. 测试用例

- 不同分辨率下的 UI。
- 长文本和多位数分数。
- 多种药水效果同时显示。
- 爆炸和酸雨同时发生。
- 镜头靠近场地边缘。
- 玩家高速击退。
- 连续回合中的音效和粒子清理。
- 构建首次启动和重复启动。

## 11. 风险与控制

| 风险 | 控制 |
|---|---|
| 表现打磨持续扩张 | 以视频镜头和可读性为验收中心 |
| 粒子和镜头影响操作判断 | 保持短时反馈和强度上限 |
| UI 信息过多 | 对局界面只保留实时决策信息 |
| 展示内容领先实际能力 | README、视频和架构图依据可运行结果编写 |
