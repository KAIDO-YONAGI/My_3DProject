# 阶段一：依赖导入与编译验证

> 上游蓝本：[mirror-physics-interaction-plan.md](../mirror-physics-interaction-plan.md) 第 10 节阶段一
> 前置依赖：无（Mirror v96.11.2 已按蓝本第 4 节导入并编译通过）
> 编写日期：2026-09-15

## 1. 阶段目标

在不写任何玩法代码的前提下，证明 Mirror 在当前工程中具备完整可用性：Host 可启动、Headless Server 可独立运行、KCP/Telepathy 均可完成一客户端一服务器的最小连接与断开。

## 2. 前置条件核查

执行前逐项确认，任何一项不满足则先处理再开工：

- [ ] `Assets/Mirror/version.txt` 为 `96.11.2`。
- [ ] `Assets/Mirror/Transports/` 下存在 `KCP`、`Telepathy`、`Latency`。
- [ ] Unity Editor 无 Mirror 相关编译错误（Console 清空后全量重新编译一次确认）。
- [ ] 蓝本第 4.2 节的版本锁定记录（unitypackage SHA-256 等）已存在。

## 3. 任务清单

### 3.1 最小 NetworkRunner 场景

- 在 `Assets/Core/Scripts/Network/Mirror/` 下创建最小 `PrototypeNetworkManager`（继承 `NetworkManager`），不做任何自定义逻辑，仅持有 Transport 引用。
- 创建冒烟场景（可先用临时场景，最终落到 `PhysicsPrototypeScene.unity`），挂载 NetworkManager 与 KCP Transport。
- 场景与旧多人场景完全隔离，不引用 `Assets/Core/Scripts/Client/` 下的任何旧网络代码。

### 3.2 Host 模式验证

- Editor 内启动 Host，确认 NetworkServer 与 NetworkClient 同时就绪、本地客户端已连接。
- 停止 Host 后可重复启动，无残留状态报错。

### 3.3 Headless Server 构建入口

- 配置 Dedicated Server 构建目标（Server Build 子目标），加入构建脚本或菜单项入口。
- 构建产物以批处理参数启动：`-batchmode -nographics -logfile`，确认服务器进程能监听端口并在日志中打印就绪信息。
- 服务器可被 Ctrl+C 或正常退出流程关闭，无卡死。

### 3.4 KCP 端到端连接

- 客户端构建版或 Editor Play 模式连接 Headless Server，确认连接建立。
- 验证断开：客户端主动断开、服务器 kill 两种情况，另一端均能收到断线事件并有日志。

### 3.5 Telepathy 备用链路

- 将 Transport 切换为 Telepathy，重复 3.4 的连接与断开验证。
- 验证完毕切回 KCP 作为默认。

## 4. 完成标准

- [ ] Editor 无 Mirror 编译错误，Weaver 无告警级异常。
- [ ] Host 可启动、可停止、可重复启动。
- [ ] Headless Server 构建可独立启动并监听。
- [ ] KCP：客户端连接 → 收到就绪回调 → 主动断开，双端日志正确。
- [ ] Telepathy：同上。
- [ ] 服务器非正常 kill 后客户端能感知断线并有明确日志。
