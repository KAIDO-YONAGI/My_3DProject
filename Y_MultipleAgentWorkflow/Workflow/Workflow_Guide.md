# 多智能体工作流指南

## 文档编写准则

编写文档时注意

- 除非特别说明，所有文字保持完全的实时性陈述。
- 没有的东西、过时的东西不要特地说明。
- 严禁莫名其妙的版本变更记录。
- 严禁加上修改记录和各种莫名其妙的版本补丁。
- 除非有文档结构要求，否则未完成、未测试等涉及过去、将来性质的过程性描述都严禁出现。
- 避免用括号括出莫名其妙的解释，直接用正文格式解释明白。
- 避免否定和转折句式的滥用。

本准则约束 `Y_MultipleAgentWorkflow/` 下的全部文档，包括 Router、Guide、DeveloperLog 与模板。

## 路由

根据任务触发词、目标路径、运行资源和预期输出选择知识域。任务描述用于定位分类，具体行为以对应 Guide 为准。跨域任务进入所有受影响的知识域。

模型入口文件只负责引导到 `../Router.md`，不得复制整套项目知识形成并行权威来源。

## 知识域

优先复用现有分类。新增顶层分类或修改项目级规则必须获得用户明确确认。每个知识域至少包含：

- `Router.md`：触发词、权威文档、证据路径和并发资源。
- `DeveloperLog.md`：已完成任务的证据、结论、验证和维护计数变化。
- 至少一份 Guide 或 Design：维护实际项目知识。

目录层级不得超过工作流根目录以下五层。需要第六层时，应提升独立子域、合并重复层级或使用 Router 标签。

## 文档语言与证据

- 项目拥有的权威文档统一使用中文。
- 源码标识符、协议字面量、命令和路径保持原样。
- 旧 `docs/` 与未索引文档默认排除，除非用户明确要求纳入。
- 结论优先来自实际代码、资源、运行结果和可复现验证。

## 记录排列

`DeveloperLog.md` 一律最新记录在前：

- 新增条目插入文件开头（第一条记录之后、原有最新记录之前），不追加到文件末尾。
- 同一天的条目按实际完成顺序倒序，最后完成的写在最前面；定序依据是实际完成的先后，不是条目里写的日期。
- 条目内引用其他记录时写出条目标题，不使用「上一条」「下一条」「本文后续」这类依赖排列方向的措辞。

## 维护

只有成功且实质改变业务实现的任务才增加维护计数。失败、取消、租约登记、只读分析和纯文档维护不计数。达到 `5/5` 时，复核实际项目状态，更新权威文档或记录 `reviewed-no-change`，再重置计数。

不得自动截断 `DeveloperLog.md` 历史。只有用户明确确认某条记录冗余或过时后才能删除。

写知识域 Router 或 Log 时使用 `workflow:<知识域>`；改变根结构时才使用 `workflow:root`。
