# UDP 网络与异步模型

文档 ID：`NETWORK-GUIDE`
状态：`Active`
最后核验：`2026-09-20`

## 客户端连接

- `NetManager` 是 `DontDestroyOnLoad` 单例；新连接会先关闭旧连接并递增连接编号。
- `UdpConnection.Connect` 调用 `UdpClient.Connect(ip, port)` 设置默认远端，随后立即报告成功并启动接收循环。
- 连接编号附在异步结果和消息上，旧连接晚到的数据会在主线程因编号不匹配被丢弃。
- 主动 `Disconnect` 尝试发送 `Leave` 后关闭；对象销毁或再次连接时直接关闭，不发送 `Leave`。

## 收发与线程模型

- 双端使用 UTF-8 文本 UDP 数据报。
- 客户端发送由 `SemaphoreSlim` 串行化；接收循环和发送使用异步 API，并通过 `ConfigureAwait(false)` 继续执行。
- 异步回调不直接操作 Unity 对象，而是写入无容量上限的 `ConcurrentQueue`。
- `NetManager.Update` 每帧完全排空连接结果、日志和消息队列，没有单帧预算或背压。
- 服务端接收循环串行等待数据报和业务处理；广播会创建异步任务，但共享发送锁使实际 Socket 发送串行化。

## 地址与身份

客户端固定目标是 `127.0.0.1:8888`，服务端也绑定 `127.0.0.1:8888`。玩家 ID 使用 UDP 端点字符串。该配置只适用于同机通信，且没有身份认证。

## 错误处理

- 客户端连接、发送和接收异常会进入日志队列并关闭连接。
- 接收异常关闭后不会发布“断线”事件，因此上层不会自动恢复。
- 协议解析失败会静默丢弃。
- 事件订阅者和消息监听器外围没有异常隔离，订阅者异常可能中断当前帧后续处理。
- 服务端接收循环记录异常后继续；畸形协议消息通常直接忽略。

## 当前不具备的能力

- 服务端握手、可达性确认和连接超时。
- 确认、重传、序号、乱序处理、去重和分片重组。
- 加密、鉴权、限流、报文长度限制和队列背压。
- 心跳或客户端超时清理。

## 维护触发

修改 Socket 生命周期、地址端口、队列策略、异步边界、异常策略或可靠性机制时更新本文档。
