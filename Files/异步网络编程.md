# 异步网络编程知识要点

---

## CancellationToken 取消令牌

协作式取消：`Source` 能 `Cancel()`（下命令），`Token` 只能检查标志位（听命令）。不是框架停线程，是循环自己检查标志位退出。

```csharp
receiveCancellationTokenSource = new CancellationTokenSource();    // 持有 Source：能 Cancel
_ = ReceiveLoopAsync(socket, receiveCancellationTokenSource.Token); // 传 Token：只能检查
```

为什么传 Token 不传 Source：最小权限，防止接收循环意外调用 Cancel()。

生存周期 = 一次连接的生命周期（不是跟随 Task）。Source 在 CloseSocket() 中 Cancel → Dispose → 置空，先于 Task 死亡。

---

## ConfigureAwait(false)

默认 `await` 恢复时回到 Unity 主线程（通过 UnitySynchronizationContext，下一帧 PlayerLoop 才执行）。加 `false` 跳过调度，直接在线程池线程继续。

网络层用 `false` 因为 `AppendMessages` 只操作 `lock` 和 `ConcurrentQueue`，不需要 Unity API，省去每帧排队的开销。

---

## SemaphoreSlim 异步锁

`lock` 不能配合 `await`（要求同一线程加解锁），`SemaphoreSlim` 用计数器代替线程身份，可以跨 await 持有。

内部：`WaitAsync()` 计数器 1→0 获得锁，`Release()` 0→1 释放。计数器为 0 时别的调用被挂起，不管怎么 await 计数器都不会变，直到显式 Release。

---

## ConcurrentQueue 跨线程队列

被两个线程共享：线程池 Enqueue，主线程 TryDequeue。内部用 CAS（CPU 原子指令）抢占槽位，不用大锁，多个操作可以并行。

---

## fire-and-forget vs await

```csharp
_ = ReceiveLoopAsync(...);        // 不等，立刻继续（长期循环不能用 await，否则卡住后续代码）
await Task.WhenAll(sendTasks);    // 等全部完成才继续（一次性操作）
```

fire-and-forget 切断了 async 向上传染的链路，对外接口保持 `void` 签名。

---

## Task 和 Task\<T\>

`Task`：无返回值。`Task<T>` 继承 `Task`，多了 `Result` 属性。是继承关系，不是重载。

`async` 方法中 `return` 不是返回 Task 对象，而是告诉编译器生成的状态机"完成了"。编译器接管 Task 的创建和返回。

---

## 泛型 vs 重载

重载：手动为每种类型写一份代码，编译期生成多段 IL。
泛型：写一份模板，JIT 运行时按需生成机器码。

JIT 特化规则：值类型参数各生成一份机器码，引用类型参数共享一份（底层都是指针）。

---

## JIT 即时编译

```
C# 源码 → IL 中间代码 → JIT → 机器码
```

第一次调用某个方法时才编译，编译后缓存。能做运行时优化：泛型特化、内联、分支预测。Unity 编辑器用 Mono (JIT)，发布可选 IL2CPP (AOT)。
